# 客户、供应商与联系人主数据合同 / Customer, Supplier and Contact Master Data Contract

本文维护客户、供应商和联系人的当前主数据边界。字段与关系以当前 Ent schema、repository、usecase、API 和测试为准。

## 当前结论

- 客户与供应商是两个独立的主数据真源，不引入通用 `partner` 表或双写别名。
- 联系人是受控主数据，并通过明确关系归属客户或供应商；临时业务文本不能反向覆盖联系人真源。
- 订单、采购、出货和财务对象引用主数据 ID，并按业务需要保存历史快照。
- 客户配置只负责显示、菜单、字段策略和模板差异，不能保存正式客户 / 供应商业务数据。

## 对象职责

| 对象     | 主要职责                                                                                   | 典型下游                                     |
| --- | --- | --- |
| Customer | 客户身份、名称、编码、联系、国家 / 地区、默认收货信息与启停状态                          | 销售订单、出货、应收、打印抬头与搜索         |
| Supplier | 供应商 / 加工方身份、名称、编码、联系、默认付款 / 开票偏好与启停状态                     | 采购订单、收货、委外、应付与打印             |
| Contact  | 某个主体下的联系人及联系方式                                                               | 源单据联系人选择和历史快照                   |

客户与供应商在现实中可能是同一家公司，但系统仍以两个业务角色分别管理；如需关联，必须有明确业务需求和单向、可审计的关系，不能依靠名称猜测合并。

客户和供应商档案至少维护一位联系人，支持按需增加。表单只有一位联系人时自动作为主联系人，多人时通过单选确定一位；移除主联系人后由首位剩余联系人接替。表单读入及保存归一化复用同一主联系人规则，不改联系人归属、权限、历史快照或后端写入入口。复制联系人只复制当前填写内容，不携带持久化 ID 或主联系人资格；备注收起只改变展示，不清空或漏保存内容。

## 真源与快照

1. 主数据 ID 负责稳定关联，名称、电话、邮箱、地址等字段由主数据维护。
2. 已创建的销售订单、采购订单、出货或打印可以保留必要快照，确保主数据后续变化不改写历史业务事实。
3. 新建源单据默认从主数据带值；用户在本单允许修改的字段只影响本单快照，除非有独立且获权的“更新主数据”动作。
4. 切换客户 / 供应商 / 联系人时，必须同步覆盖或清空旧快照，防止残值归属于错误主体。
5. 主数据缺失、停用或关系不匹配时应明确拒绝或进入人工确认，不自动创建、猜测合并或静默回填。

### 当前默认值与快照合同

| 主数据默认值                                           | 新建业务单据如何使用                                     | 保存后的边界                                                                       |
| --- | --- | --- |
| 客户国家 / 地区、默认收货人、默认收货电话、默认收货地址 | 新建销售订单时带出；切换或清空客户时整体覆盖或清空       | 保存为销售订单交货快照，可按本单修改；出货首次选来源时再带出，之后不追随主数据变化 |
| 供应商默认付款周期、默认付款方式、是否需要发票、发票类别 | 新建采购订单时带出；“不需要发票”必须同时清空发票类别     | 保存为采购订单条件，不因供应商档案以后修改而反向变化                               |

客户默认收货信息不是地址簿或多地址模型；供应商默认付款 / 开票偏好也不是财务事实。当前只实现一个低复杂度默认值入口和每张业务单据自己的冻结值，不扩展多地址、混合税率、汇率、物流应付或通用条件引擎。

### 付款方式推荐

付款方式文字仍分别属于客户 / 供应商默认条件及订单快照，不升级为强制枚举。常用方式与有权读取来源中的已保存名称由后端统一查询；候选去除首尾空格、去重，每次最多 50 项，关键词搜索不依赖当前列表页。取消或保存失败不新增候选，选择方式不推断付款周期。

公司共用的 `payment_method_preferences` 只保存名称的推荐状态和并发版本，不替代原字段，也不保存付款周期。维护者从输入框右侧进入“管理付款方式”，停止推荐、恢复或用最近版本撤销；状态与控制面审计同事务保存。停止推荐后仍可直接输入并保存到当前记录，但保存不会恢复推荐；恢复只经管理动作；维护者显式恢复的名称作为公司共用候选保留，原来源后来清空或纠正也不会丢失该恢复结果。原记录、打印快照及未保存表单草稿保持各自原值。权限为 `payment_method.manage`，新初始化的老板 / 管理层模板具备该能力，其他普通录入模板不默认包含；既有客户配置和账号仍按实际有效权限收窄。

当前不预载全部候选或建立后台同步字典，管理查询也以 50 项分批读取；历史来源仍采用字段投影去重，实际规模与查询耗时未作容量验证。增长后若候选读取成为慢查询，应先评估来源查询与索引，再决定是否需要专用候选索引，不能把客户端缓存作为推荐状态真源。


### 收货地址填写

客户档案、销售订单和出货单共用收货信息表单。收货人、电话、国家 / 地区分别填写；国家 / 地区可按中文、英文或代码搜索。新建时默认选中中国大陆；编辑已有记录或从客户、来源单据带入时保留原国家 / 地区及空值，手动清空后不自动补回默认值。

- 中国大陆提供省、市、区县搜索选择，详细地址填写街道、园区、楼栋、门牌或仓库。地区清单没有合适项时允许直接填写完整地址；选择地区后必须补充详细地址。
- 其他国家 / 地区使用完整地址多行输入，保留原文与内部换行，不统一要求州 / 省或邮编。联系电话沿用支持国际区号、座机和分机的现有校验。
- 手动切换或清空国家 / 地区时清空原地址，保留收货人和电话；从客户或销售订单带入时整体应用来源快照。变更省市区只替换所选地区前缀，清空地区保留可编辑的详细文本。
- 仍以现有完整地址字符串为保存真源，省市区仅辅助输入，不另存重复地区字段。重新编辑只拆分与地区字典完全一致的前缀，无法匹配的文本完整保留，不猜测地名或覆盖原文。完整地址总长上限为 512 字符；订单和出货沿用原快照合同。

地区清单使用锁定版本的 `@vant/area-data`，国家 / 地区中文和英文名称来自 `i18n-iso-countries` 的对应语言数据。数据随前端发布，使用时不请求外部地址服务；清单用于录入辅助，不代表承运商派送范围或地址有效性认证。未接入智能文本识别、地图定位或国际快递下单。

## 生命周期与删除

- 主数据默认使用启用 / 停用，而不是通用删除。
- 被源单据或事实引用的客户、供应商和联系人不得物理删除。
- 停用对象保留历史查询和审计能力；新业务是否允许继续选择由 usecase 合同决定。
- 合并重复主体属于独立的数据治理操作，必须先定义引用迁移、冲突、审计和回滚边界。

## 权限与客户差异

- 查看、创建、编辑、停用等动作由服务端 RBAC 控制；页面隐藏不是安全边界。
- 客户简称、编码显示、字段必填、编号规则和打印文案可以进入客户配置，但不得改变对象 owner 或绕过 schema / usecase。
- 真实客户资料、联系人隐私和原始 Excel / PDF 留在客户专属受控存储；Product Core 只保存脱敏合同和通用能力。

## 变更检查

涉及客户、供应商或联系人时，至少覆盖：

1. 新建与重复识别。
2. 编辑、停用和已引用对象。
3. 来源切换后的快照覆盖与清空。
4. 列表、详情、搜索、订单、采购、出货、打印和导出回显。
5. 未登录、无权限、disabled、主体不匹配与历史数据缺值。

通用分层见[主数据、源单据与事实边界](主数据源单据事实边界评审.md)；客户差异见[配置与权限策略](../product/配置与权限策略.md)。

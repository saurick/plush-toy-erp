# 打印模板实现原理 / ERP Print Template Implementation

本文面向维护打印功能的开发人员，说明打开、保存、编辑和输出的唯一实现链路。操作与字段差异见[编辑行为清单](打印模板字段与编辑行为清单.md)；新增模板直接看[接入步骤](#7-新增模板--template-onboarding)。

## 1. 当前结论

- 当前正式模板包括 `采购合同`、`加工合同`、`物料分析明细表`、`色卡`、`作业指导书`。
- 五套正式模板当前通过“打印中心 -> 独立弹窗 -> 右侧纸面 DOM 输出 PDF / 打印”的主链打开。领域页带值打印必须由对应领域模型显式生成打印草稿输入。
- 这条主链已收口为：直接打开模板工作台 URL、窗口级 `state` 隔离结构化草稿、工作台按当前草稿重新渲染纸面；打印入口始终验证登录会话；整窗 HTML 快照已退役，`/print-window-shell.html` 只提示从打印中心或业务单据重新打开。
- 五套正式模板共用顶层 `appendixImages[]` 作为模板末尾附图的唯一真源：管理区支持多选、排序、移除和逐张选择 `自动 / 半宽 / 整行`。普通图片默认两张一行，加工合同自动每行最多三张；长图自动整行，超长图按打印页安全高度分段；不另设业务规则数量，但单次 PDF 仍受浏览器处理 / 存储能力和服务端图片数量、大小及整份请求预算约束。
- 当前正文继续由 React 工作台渲染，不是 builder + 独立静态 runtime，但分页运行时已经统一收口到共享 `printPageMargin` 主链。

## 3. 当前打开链路

### 3.1 从领域页带值打开

当前带值打印只从正式领域模型显式生成打印草稿。采购订单带值打开采购合同，委外订单带值打开加工合同和外发作业指导书，物料清单（BOM）页面带值打开物料分析明细表、色卡和内部 / 工程资料作业指导书。BOM 来源的作业指导书 mapper 单独把产品业务款号和产品名称映射到纸面表头；委外来源沿用源单冻结的产品编号和名称快照，不拿当前产品主档覆盖历史源单。

两条路径都不把编号拼进产品名称；缺少独立打印版次或工序日期真源时对应值槽保持空白。委外单号进入订单号，回货日期、加工厂、来源订单、加工项目、工序和委外数量进入正文上下文，不占用 `版本/版次` 或工序日期值槽，也不把委外明细伪造成生产、质检、库存或 Workflow 事实。

后续如果采购、委外、工程资料、生产、品质或出货领域页需要新增带值打印，必须先定义对应领域模型到打印草稿的字段映射，再调用 `openPrintWorkspaceWindow(templateKey, { entrySource: 'business', initialDraft })` 生成窗口级 `stateID`；各领域不得共享另一套打印草稿真源。


#### 采购批量读取与归并

工程用料汇总表的批量打印带入审批结果中的全部采购订单；采购列表通过表格勾选后复用同一 `usePurchaseOrderContractPrint`。入口重新读取采购表头、对应版本的全部明细、供应商快照和客户买方默认值，最多同时读取四份合同，不截断汇总范围；组件离开时取消未完成的读取。空明细或读取失败阻止打开，业务字段缺值保留为空，进入打印窗口后可直接留白输出。

新打开批量窗口前，`groupMaterialPurchaseContracts` 按供应商编号组织本次选择，再比较币种、付款、开票、交货、双方信息与条款；条件有差异则分别生成合同，并保存差异原因供清单说明。同名不同编号或缺少供应商编号不会合并。每份保留 `sourceOrders`，明细逐行携带原采购单号和产品订单号；不合并相同材料行，不改写来源采购单。

多单合同表头注明单号详见明细，下单及签字日期保留各来源值，不静默采用第一张的日期。每份明细最多 `300` 行，超出时明确阻断并提示减少选择，不截断来源。

批量草稿保存归并后的完整合同数组、来源采购单、分开原因、来源汇总号、逐份选择和当前批次。归并仅在读取业务快照打开新窗口时执行；恢复当前窗口时直接恢复已经编辑的合同，不再次归并覆盖输入。工作台复用单份纸面的字段、明细金额及条款编辑规则，修改仅保存到当前窗口；生成采购单时没有价格则保持空白，不以零或样例金额补造业务值。

左侧清单默认展开并全选，按供应商显示采购单数量、单号及已填数字的格式问题，支持定位合同、取消选择和刷新恢复。按所选合同每 `20` 份分批，纸面及输出 DOM 只包含当前批次，最后一批可为一份；其他批次的草稿和选择继续保留。

当前批次在预览、下载和打印前检查已填写数字的格式与精度、纸面及资源预算，不检查字段必填，也不静默跳过所选合同。字段、部分明细或整行留白均直接按当前纸面输出，无需切换“空白模板”。通过后合并为同一 PDF，每份独立起页，单份合同可以自然续页。共享采购金额计算保持十进制精度；不同单位的数量不混加。同币种金额按行合计。生成输出期间冻结编辑和选择，沿用共享 PDF 请求超时与错误恢复；打印草稿不改写采购事实或放宽已审批采购单的编辑权限。插删行、单元格合并和附图管理继续使用单份工作台。


#### 业务图片与初始草稿

工程资料业务入口在生成草稿前读取产品媒体：产品图 1 / 2 分别使用 `business_attachments` 的 `product + product_image + primary / secondary`，前端通过受控 list / download API 转成 data URL 后再交给 mapper。

物料明细映射为 `header_left / header_right`，作业指导书映射为 `header / header_right`。没有图片是合法空态；读取到已登记图片但下载失败时阻止本次打开并提示错误，不静默打印残缺版本。

产品页选择大源图时会先在浏览器内生成受控打印快照，因此业务入口携带的是压缩后的 data URL，不把原始大图塞进窗口草稿。

若 localStorage 因容量或策略无法写入，`openPrintWorkspaceWindow` 会把初始草稿放进当前弹窗的 `window.name` 一次性通道；打印页首次读取后清空 `window.name`，并在当前窗口内按账号、客户、配置版本、模板和 `stateID` 暂存该初始草稿，仅用于桥接 React 初始化与挂载 effect 的重复读取。

当前草稿一旦成功提交到 IndexedDB，该初始化缓存立即失效，后续重挂载不会用旧草稿遮挡新内容；写入仍失败时才继续保留该桥接。

BOM 本身只有一个 `product_id`，可直接读取该产品图片。委外订单只在全部有效产品行都有同一个 `product_id` 时自动读取；多产品或关联不完整时保持图片槽为空并提示人工核对。图片在打开时已经冻结进当前窗口结构化草稿，之后产品页替换图片不会改写已打开窗口；但关闭后重新打开同一历史 BOM 会重新读取产品主档当前图片。这不是 BOM 激活时的图片版本快照，当前也不保存附件 ID、hash 或图片历史版本。


#### 单位与数量

采购与加工合同的单位、数量精度使用[统一计量口径](product/业务公式与计算口径.md#计量单位与数量精度--units-and-quantity-precision)：PCS / PC / EA / 件归为“个”，Y / YD 归为“码”，kg / 公斤归为“千克”；套、对、片、条、块各自保留。编辑保留有效小数，未知单位或超精度值保留以便修正，输出前阻断并指出行号。

数量最多 6 位、单价最多 6 位；计数单位整数、千克 3 位，码 6 位。混合单位不出数量总和，单价和金额规则不随数量单位改变。原始文档文字与 BOM 耗用系数不当成实际收发数量。

### 3.2 从打印中心打开

`PrintCenterPage` 调用 `openPrintWorkspaceWindow(templateKey, options)`：

1. 生成窗口级 `stateID`
2. 生成实际模板工作台 URL：`/erp/print-workspace/:templateKey?...&state=:stateID`
3. 直接打开工作台 URL，并检查当前有效登录会话
4. 工作台根据当前账号与 `stateID` 读取 / 写入当前窗口专属结构化草稿

这样做的目标有两个：

- 保持浏览器刷新时仍落在真实 React 工作台，由结构化草稿恢复可编辑纸面
- 结构化草稿是恢复真源，不再维护窗口元数据或整窗 HTML 的第二套存储

### 3.3 工作台加载后

各打印工作台都会：

- 根据 `state` 计算当前窗口专属草稿 key
- 根据当前登录会话账号、来源客户、来源配置版本、模板和窗口读取结构化草稿；缺少有效账号时不读写持久化草稿
- 保持当前弹窗地址为 `/erp/print-workspace/:templateKey?...&state=...`，让刷新继续走 React 工作台主路径
- 含图片的结构化草稿由 IndexedDB 保存，不克隆或恢复整窗 HTML
- 退出、换号、会话过期或窗口重新获焦时重新检查会话；账号变化后卸载原纸面并按新账号恢复草稿，不继续展示原账号的内容
- 登录、退出及加载工作台时尽力清理退役的 localStorage 窗口记录和 IndexedDB 整窗快照库；保留原账号的结构化草稿，其他账号无法通过同一窗口地址读取

这意味着：

- 弹窗当前显示的仍是 React 渲染后的工作台 DOM
- 浏览器地址栏保留真实工作台 URL
- 用户刷新当前弹窗时，工作台会重新读取当前窗口级结构化草稿；旧壳页不读取或执行任何已存 HTML

## 4. 草稿与输出真源

### 4.1 草稿真源

- 当前窗口级草稿 key：`__plush_erp_print_workspace_draft__:v3:<customerKey>:<accountKey>:<configRevision>:<templateKey>:<stateID>`
- 独立打印路由通过 `printWorkspaceScope.mjs` 读取当前登录会话账号，不依赖主页面的 Outlet 上下文，也不从 URL 或单独的账号缓存值选择其他账号。
- 来源页面把客户和配置版本传入窗口 URL，刷新保留同一作用域；配置版本只参与草稿隔离，不授予业务权限。服务端 PDF 仍执行实时会话和权限校验。
- 缺少有效账号时不生成草稿 key；客户、账号、配置版本或窗口变化后使用各自的草稿，不回读旧模板级 key。

#### 附图存储与旧草稿读取

- 五套模板都把顶层 `appendixImages[]` 写入当前窗口级草稿；上传、调序、移除和逐张版式切换会同步更新当前窗口草稿，不回写业务附件或其他窗口。加工合同从委外订单打开时，会先读取该订单中未撤销且类型为 `print_appendix` 的图片业务附件，转换成窗口级图片快照后再进入同一数组；普通证据附件不自动进入纸面。
- 单张逻辑图片保存 `layoutMode`、快照宽高，以及一张 `dataURL` 或多段 `segments[]`。超长图只保存分段，不再重复保存一份完整长图；旧草稿只有 `dataURL` 时会归一为 `auto`，尺寸未知时继续按半宽输出，保持旧草稿可读
- 老加工合同的 `attachments['attachment-1', 'attachment-2']` 与老物料明细的 `images.footer_left / footer_right` 仅在读入草稿缺少 `appendixImages` 字段时按原顺序迁移；一旦草稿显式存在 `appendixImages`，包括空数组，它就是唯一真源，旧槽位不得再次复活图片

#### 保存、恢复与编辑提交

- `printDraftStorage.mjs` 是当前结构化草稿存储，`usePersistentPrintWorkspaceDraft` 负责即时 `draftRef`、160ms 合并写入、事务串行和真实保存状态。只有 IndexedDB 事务完成才显示“已保存”；失败显示“未保存”并可重试。旧的同作用域 localStorage 初始草稿只在首次加载时读取，IndexedDB 写入成功后清除；不回读其他账号、配置版本或模板级 key。
- 当前窗口 URL 加载时先恢复对应草稿，再挂载纸面组件。草稿有效期为 24 小时；通过时间索引清理过期记录，不读取其他窗口的图片大对象。缺少存储权限时保持当前页面可编辑，不伪报持久化成功。
- 原地输入立即更新 `draftRef`，静默输入不打断光标；`PrintEditableText` 统一在布局阶段同步非聚焦正文，React 不直接协调可编辑子节点。失焦按模板规则规范化正文与草稿，普通 Enter 主动结束工程字段编辑时清除该字段的焦点恢复请求，输入法确认事件不触发结束动作；失焦 / 输出时刷新 React 视图。预览、下载、打印等待当前写入和视图提交，再读取同一份纸面。

  尚未保存时刷新或关闭会触发浏览器离开保护；强制关闭或浏览器崩溃不能承诺保存仍在排队的输入。

### 4.2 PDF / 打印真源

- 纸面编辑焦点集中在 `web/src/erp/styles/app/print-center.css` 的屏幕样式：普通字段使用跟随当前主色、向外留白的虚线框，表格以当前单元格作为唯一焦点框，1px 虚线使用 -2px 偏移，避免越过表格线；色卡长文本仅在屏幕补足垂直编辑留白，打印沿用原版式；单元格自身可编辑、直接子节点或多层包装的编辑器复用同一规则，嵌套表格只框住最近的单元格。

  标签、编号或标题与字段排列紧凑时，在已有容器标记 `data-print-focus-group`，让整组共用一个外框；合同条款条目的组框外扩限定为 3px，匹配既有条目间隙，避免越过相邻标题或条目文字；该标记不扩大可编辑范围。聚焦只绘制边框与底色，不改变正文 padding、行高或纸面尺寸，避免切换焦点时文字和分页移动；新增模板直接复用共享工作区，不重复定义焦点边框。

  焦点与光标的间距、相邻文字、缩放和打印隔离由 `print-workspace-all-template-edit-focus-clearance` 浏览器场景覆盖。
- 浏览器打印：直接打印当前弹窗里的右侧纸面 DOM
- 在线预览 PDF / 下载 PDF：`printPdf.mjs` 会先 blur 当前焦点元素，再 clone 当前窗口文档、移除运行时脚本和高亮类，并只保留右侧纸面主区域后交给后端 `/templates/render-pdf`
- 后台 PDF 预热通过同一快照入口传入 `preserveEditorFocus`，不执行 blur；正式输出仍先提交输入，再以最新 HTML 计算缓存键。合同跨字段输入、超过预热延迟后继续编辑、主动退出编辑和最终输入输出由 `print-workspace-contract-edit-continuity` 覆盖。

  `print-workspace-editor-input-lifecycle` 进一步覆盖五套模板在草稿刷新期间的文字节点、光标与输入法事件，以及主动结束编辑、失焦规范化、刷新恢复和输出内容。
- PDF 快照只允许静态内容：前端移除脚本、外部 stylesheet 和无打印意义的交互属性，把相关 CSS 规则直接内联且不携带源地址；外链图片由当前已登录页面先读取并栅格化，SVG 在所有输出模式下先转成 PNG / JPEG 类位图。转换失败时直接给出业务提示，不让后端 Chromium 访问外部地址兜底。

#### 图片排列与快照压缩

- 五套模板的末尾附图都会先在前端转成可持久化图片快照，再按 `appendixImages[]` 顺序并入右侧纸面 DOM 末尾，保证刷新恢复、PDF 预览 / 下载和浏览器打印读取的是同一份内容。纸面按显式行模型顺序扫描：连续半宽图片每两张组成一行；加工合同通过 `autoColumns: 3` 将连续自动普通图片排成最多三列，两张时使用两列。手动半宽仍为两列，切换自动 / 手动列数或遇整行图片时先结束当前行，不改变原始图片顺序。
- 同行图片顶部对齐，Grid 行高自然取最高图片，下一行不会按较矮图片提前开始。普通模板图片占满所属列并保持原比例；加工合同普通附图按原件使用 `50mm` 宽、列内居中且不超过列宽。整行图片使用纸面可用宽度，手动 `half / full` 优先于自动判定。
- 上传快照按宽度处理：不放大原图，宽度超过 `1600px` 时才缩到 `1600px`，统一生成 JPEG 质量 `0.9` 的安全内嵌位图。自动版式在高宽比超过 `1.35`（加工合同为 `2`）或宽高比超过 `1.8` 时使用整行；尺寸未知的旧草稿仍使用普通并排布局。
- 目标图高宽比超过 `1.45` 时会连续分段，每段高宽比不超过 `1.25`；分段覆盖原图首尾且不重复保存完整长图。整行分段图片的后续段在打印态从新页开始，分段自身避免被页内裁切；用户手动改为半宽时仍保持分段与原顺序
- 在线 PDF 快照对末尾附图保留上传阶段生成的栅格像素，不再套用普通预览图的二次降分辨率压缩；SVG 和外链安全边界、整份请求预算及服务端 HTML / CSS allowlist 保持不变
- 从产品主档带入的产品图同样先冻结到工程资料草稿，再由物料明细或作业指导书右上角图片槽渲染；PDF、浏览器打印与屏幕预览继续读取同一份右侧纸面 DOM

#### 字段合同与服务端校验

- 正式模板必须在 `printTemplates.mjs` 声明 `fieldRequirements`、`moduleKeys` 和 `factBoundary: read_snapshot_only`；五套模板的字段合同都声明 `appendix_image_snapshots`。字段合同只描述打印草稿需要哪些业务快照，不代表模板可以生成采购、委外、生产、库存、出货、质检或财务事实。
- `/templates/render-pdf` 的请求体只接受 `title`、`file_name`、`template_key` 和 `html`。客户 key 由部署环境决定，客户端不能提交 `customer_key` 或 `base_url` 选择其他客户或资源基址。
- 服务端先走统一管理员认证 middleware，使用实时 session / RBAC，再从同一次 active revision effective session 同时检查打印 action 和模板依赖 module，避免跨 revision 拼接权限。未知模板、无 active revision、无打印 action 或 module 非 `enabled` 都拒绝渲染。前端新增正式模板时，如果没有同步服务端 PDF 模块门禁和字段合同测试，不能视为已接入打印闭环。
- 服务端再次解析 HTML / CSS allowlist，只接受文档内锚点、受限内嵌位图和 WOFF2 字体；脚本执行、缓存和 Chromium 出网均关闭，每次渲染使用独立 browser context。生产镜像以非 root 用户运行并保留 Chromium sandbox；这些静态合同不替代容器 sandbox、受控出网探针和目标环境真实 PDF smoke。
- 输出资源统一受[字体与输出预算](#8-字体与输出预算--fonts-and-output-budget)约束。

### 4.3 条款与结构编辑
- 合同条款的窗口草稿统一使用有序 `clauses[]`，每组保存稳定 `key`、可编辑 `label` 和 `items[]`；顺序由数组决定，标题数字与条目数字只在渲染时计算。

  业务来源及已有正式窗口草稿中的 `delivery / contract / settlement` 在入口由 `normalizeContractClauseGroups` 一次转成该结构，缺少条款时沿用对应模板默认内容；明确的空数组保留为空，不重新补组。纸面、打印中心预览、草稿恢复和采购新窗口归并比较共用该结构；归并比较名称、顺序和条目，不比较窗口分组身份。
- `contractClauseEditor.mjs` 分别维护分组和组内条目操作。分组新增携带一个空条目，删除可到零组；`items: []` 保留可在左侧恢复的空组并隐藏纸面标题，`items: ['']` 保留一条纸面留白。分组名称可在左侧输入和纸面修改，写入同一份窗口草稿；有条目的名称值槽带 `data-print-blank-field`，按该组标题、条目的顺序参与留白导航。

  分组最多 20 个、每组最多 100 条，超限存量不截断，新增和输出明确提示。选择与延后定位均绑定稳定分组身份；用户已主动切换编辑位置、分组或合同后，旧定位不会抢回焦点。
- `printItemOperations.mjs` 按纵向合并关系确定完整行块，调序时同时映射内容和合并坐标，清空时保留合并关系。工程编辑器复用该规则，色卡调序与纸面布局共用 `colorCardLayout.mjs`；作业行携带图片与标注移动并重新编号。作业标题后直接到下一个标题或正文末尾时作为编辑专用行保留，输出快照剔除；保留的空条目仍参与留白计数。
- 结构按钮以 `data-print-structure-action` 标记。共享壳在结构变更前重置留白游标，避免按数组位置复用的编辑节点指向旧条目；填写内容时继续沿原字段位置导航。条目工具、操作反馈与导航均位于纸面外。

### 4.4 留白定位与共享工具

- 五套模板用 `data-print-blank-field` 显式标记可编辑业务值或只包含一个值编辑器的容器，计数和定位共用该标记，不限制字段必须位于表头或表格内。合同正文条款、工程模板业务信息及明细共用同一入口；签字、盖章、签署日期、制表 / 审核等署名、列名、图片占位、非编辑格和合并隐藏格不标记。

  `EngineeringPrintPrimitives.EditableText` 通过 `blankField` 声明业务字段。计数读取编辑值而非标签，通过现有纸面观察器更新，不读取布局。

  `data-print-blank-region` 标记 DOM 顺序与纸面阅读顺序可能不同的双列区域；`printBlankContentNotice.mjs` 仅在点击定位时读取区域字段位置，表格字段按所在单元格位置排序，避免垂直居中改变阅读顺序。其余字段沿纸面 DOM 顺序排列，合同按表头、明细、正文排列。

  `findBlankPrintField` 统一处理第一处、上一处、下一处和最后一处，不参与输出校验。上一处和下一处双向循环，保留上次字段的位置，填好后仍从该位置查找，避免列表缩短跳过相邻留白；游标失效时，向前从末尾、向后从开头查找。共享壳兼容字段自身可编辑或容器内嵌编辑器，两者均定位并聚焦实际值。首次查看前及只剩一处时显示“查看留白”，多处在首次查看后显示四个导航按钮。

  切换模板 / 输出批次或留白清零时重置游标，更新数量与导航不改变输入焦点。数量与游标不写入草稿。顶部轻提示和定位入口位于纸面外，并由编辑专用标记及打印样式排除。采购批量窗口复用同一机制，只扫描当前输出批次。
- 左侧只提供结构、文字、图片和计算工具；业务字段在纸面编辑。各模板使用 `PrintWorkspaceShell` 和同一 `PrintWorkspaceToolSection` 生成有实际操作的分组；后者用原生 `details / summary` 管理折叠，常用表格操作默认展开，附图、计算规则和模板内容默认收起。

  选择状态通过壳层 context 显示在对应子组，收起活动组会清除选区，局部反馈会展开其祖先组。`PrintWorkspaceTools.jsx` 集中提供带图标按钮和图片缩略图工具，附图通过独立 slot 和数量接入；新增模板复用这些入口，不再复制图标、折叠状态或上传栏。工程模板不单独覆盖侧栏宽度、间距和内距。

  原生显示比例控件与空值提示也由共享壳样式管理，提示只在屏幕渲染，不写入草稿或输出 DOM 的正文
- 两套合同在当前纸面高度超过单页 A4 时，会动态把整次浏览器打印与在线 PDF / 下载 PDF 的 `@page` 切到 `margin: 5mm 0 5mm`；未跨页时保持 `0` 页边距，避免本应单页的合同被额外挤出空白尾页。

## 7. 新增模板 / Template onboarding

优先参考最接近的纸面和数据结构，复用共享设施，避免照抄整套工作台。

| 需求                 | 参考实现                                                            | 模板自己负责                                 | 复用能力                                      |
| --- | --- | --- | --- |
| 合同、金额和合并表格 | `MaterialPurchaseContractPaper.jsx` / `ProcessingContractPaper.jsx` | 纸面字段、列、条款、签字、字段映射与金额规则 | 工作区壳、草稿保存、合并算法、图片、分页、PDF |
| 固定工程表与分块表   | `MaterialDetailPaper.jsx` / `ColorCardPaper.jsx`                    | 来源映射、行 / 块结构、专属样式              | 工程可编辑元素、图片槽、结构操作与相同输出链  |
| 可变正文及图片标注   | `WorkInstructionPaper.jsx`                                          | 标题 / 编号 / 文本行和图片标注数据           | 工程编辑规则、共享图片和分页                  |

1. 在 `printTemplates.mjs` 登记唯一 key、`moduleKeys`、`fieldRequirements`、只读事实边界和 `runtime`。`workspace` 决定加载的工作台；`tools` 决定工具区；`fieldRequirements` 描述字段来源与编辑方式，不作为打印必填门槛。新 key 同步服务端模块门禁。
2. 为来源业务对象实现明确的 mapper 和归一化函数，覆盖来源缺失、清空、重选与空数组；客户信息不得硬编码到共享纸面。业务缺失值保持空白，不造“未维护联系人”等打印正文。
3. 在最接近的模板族中新增 / 组合 Paper 组件，样式按模板作用域维护。工作台只编排草稿、选区和操作；共享持久化、弹窗、附图、分页与 PDF 不另写一份。
4. 输出前检查已填写数字的格式与精度、图片可用性、说明框溢出和资源预算；字段或明细留白直接输出，不要求选择“空白模板”。检查提醒在纸面外，不进入 PDF。
5. 加入普通、缺值、长文本、合并 / 插删、附图、刷新和输出的定向验证；用实际输出快照验证后端 PDF 的文字、字体、页数、图像与无空白尾页，不能把 mock PDF 或另一套 HTML 当作最终引擎证据。


### 工程表格复用

物料表的字段、默认表头及源列宽权重集中在 `engineeringPrintTemplates.mjs` 的 `MATERIAL_DETAIL_COLUMNS`，纸面使用同一份列定义生成列宽和表头；仅对最窄列设置阅读下限。表头保留正常文本流，按明确换行居中，避免富文本中的换行元素被 Flex 拆成横向项。屏幕与打印表头行数、完整字符和列宽比例由 `print-workspace-material-header-layout` 覆盖。


### 图片标注复用

作业指导书图片标注的数据与增删算法位于 `workInstructionImageAnnotations.mjs`，编辑器与纸面复用 `WorkInstructionImageAnnotationLayer`。图片草稿的 `annotationLayout` 固定采用右侧说明区或覆盖式布局，与当前说明框数量分离；已有标注未指定布局时按其现有布局解析，避免挪动距离坐标。

新增说明框按空位放置，文字和内距按画布宽度缩放；编辑器内用原生多行输入直接维护同一个 annotation.text，纸面用普通文字输出。移动手柄与文字编辑分离，方向键各自处理位置与光标，不通过拖动事件阻断输入。标注列表外层不参与压缩，列表和设置区各自滚动，避免多标注时内容覆盖。撤销按标注 ID 恢复删除项及顺序，不用旧整图快照覆盖期间编辑；超过每图数量上限时保留当前内容并提示。

`work-instruction-annotation-editing` 覆盖就地输入、拖动、光标、12 个标注的布局、增删、撤销、图片切换、长说明、窄窗口、取消、刷新与输出。

距离文字沿实际画布中线段的法向偏移，`labelOffset` 保存带方向的额外间距，零值保留最小安全间距。共享几何函数按文字宽高计算避让和画布内位置；同一层的 ResizeObserver 只在画布或文字尺寸变化时重新定位，编辑器、草稿纸面与输出快照复用同一位置。拖动文字和方向键只更新间距，端点保持原位。`work-instruction-measurement-labels` 覆盖类型辨识、横竖斜线、边缘、拖动、键盘、零值恢复、窄窗口和打印输出。

## 8. 字体与输出预算 / Fonts and output budget

采购合同、加工合同和作业指导书使用固定版本 `Noto Serif SC Variable`；物料明细和色卡使用 `Noto Sans SC Variable`。合同以原工作簿列宽和纸面样本的字号比例、行距、表格与签字结构排版；原件的宋体字形使用随产品分发的宋体风格字库呈现，不复制未授权系统字体。字体随前端打包，不依赖操作系统中恰好安装的宋体或雅黑。`printFonts.mjs` 只选取当前文字命中的 Unicode 字体分片，并将同一 WOFF2 内嵌到 PDF 快照；字体来源必须同源，加载失败阻止 PDF 并给出提示。

后台 PDF 预热由共享调度器接住已识别的字体准备失败，取消排队预热后不会继续执行；未知编程异常仍进入浏览器运行错误上报。预热失败不写入成功缓存，用户主动预览或导出时仍执行完整字体检查，并按实际结果展示失败提示。

两套字体来自固定的 `@fontsource-variable/*@5.3.0` npm 包，SIL Open Font License 原文与来源说明随 `web/public/fonts` 一起发布；升级字体包时同步这些许可文件。镜像构建将静态产物统一为文件 `0644`、目录 `0755`，确保非 root 应用可以读取字体和图片。

浏览器显示比例只作用于纸面外的容器，打印态取消缩放；分页按纸面未缩放尺寸计算。附图数量没有单独的业务上限，但须满足浏览器内存、站点存储配额与以下整份输出预算。

| 资源 | 默认上限或配置 |
| --- | --- |
| 内嵌图片 | 正文、附图和长图展开后的实际 `img` 合计 32 张；单图解码后 5 MiB，总计 16 MiB |
| 字体 | 128 个分片；单片 256 KiB，总计 2 MiB，计入 CSS / HTML 预算 |
| 文档 | HTML 24 MiB，CSS 合计 4 MiB，DOM 节点 20,000 个 |
| 输入与输出 | 请求体和生成 PDF 分别 32 MiB |
| 服务容量 | 代码与 Compose 默认并发 4，等待名额 2，容器内存 2 GiB |

超过接纳上限时提示稍后重试。只有目标宿主容量压测证明仍有稳定余量，才成对调整并发和内存，不能只扩大请求预算。

运行时版本、镜像体积与 CI 由[打印引擎验证](../scripts/qa/README.md#打印引擎验证--pdf-runtime)维护。新增模板后，生产快照采集默认从模板登记表发现入口；最终镜像验证必须覆盖同一登记集合，不能只检查一个通用 HTML 能否生成 PDF。


## 服务端模板模块归属

`/templates/render-pdf` 按已登记的 `template_key` 检查模块状态。对应模块必须为 `enabled`；`read_only / disabled / 缺失` 均拒绝生成，未知模板 key 返回参数错误。

| 模板 | 必须启用的模块 |
| --- | --- |
| `material-purchase-contract` | `purchase_orders` |
| `processing-contract` | `outsourcing_orders` |
| `engineering-material-detail`、`engineering-color-card`、`engineering-work-instruction` | `material_bom` |

`engineering-work-instruction` 可由物料清单（BOM）页面或委外订单生成业务草稿，但 PDF 模板仍按工程资料门禁登记，委外入口只提供外发上下文，不改变模板归属或写入委外事实。生产镜像的 Chromium 包、Debian snapshot 和基础镜像 digest 统一固定在 `server/Dockerfile`，构建时核对实际包版本。

字体来源与预算见上节；服务端仅接受合法的内嵌 WOFF2，不联网加载字体。

正式制品构建必须通过最终镜像的真实业务 PDF、系统包漏洞和体积门禁，详见 [`scripts/qa/README.md`](../scripts/qa/README.md#打印引擎验证--pdf-runtime)；正式发布 smoke 必须用受控 admin token 调一次真实最小 PDF，校验 HTTP 200、`%PDF` 文件头和非空结果，不把关闭 warmup 当成 PDF 可用证据。

该切片不代表打印留档回写或 Excel 母版回写已经实现。

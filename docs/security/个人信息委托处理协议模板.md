# 个人信息委托处理协议模板 / Data Processing Agreement Template

> 使用说明：本模板用于私有化 ERP 实施、托管、运维、短信或备份等场景。方括号内容必须由双方按真实服务填写并完成法务审查；未填写、未签署的仓库模板不构成生效合同，也不得写入客户原始资料或凭据。

| 乙方（受托人）         | `[乙方全称]` | `[代码]`         | `[安全与事件联系人]`   |

甲方决定本协议所涉个人信息的处理目的和方式；乙方仅按照甲方书面指令和本协议处理。双方实际角色与本描述不一致时，应在处理开始前修订，不能用合同称谓掩盖共同处理、独立处理或向第三方提供的事实。

## 三、甲方权利和义务

1. 确保委托目的、处理依据、告知和必要授权合法、正当、必要，并向乙方提供清晰、可执行的书面指令。
2. 决定信息范围、保存期限、访问权限、跨境和转委托政策，监督乙方处理活动。
3. 及时通知乙方数据主体请求、规则变化、账号撤销、数据错误和安全风险。
4. 不要求乙方实施违法、超目的或明显超过最小必要的处理；乙方认为指令违法时有权暂停相关处理并说明理由。

## 四、乙方权利和义务

1. 只按甲方书面指令和本协议处理，不自行决定新目的，不用于广告、画像、销售、模型训练或向无关方提供。
2. 按最小权限控制人员和系统访问，对获准人员承担保密义务并保留必要审计。
3. 未经甲方事先书面同意，不得转委托；获准的转委托方应承担不低于本协议的义务，乙方对其履约负责。
4. 协助甲方响应查阅、复制、更正、删除、限制处理、账号注销、投诉和监管检查，但不擅自向申请人披露无权数据。
5. 服务终止或指令撤销后，在 `[期限]` 内按甲方选择返还或删除个人信息及副本；法律要求保留的，仅作受限存储并说明依据和期限。
6. 不在日志、工单、聊天、截图、测试报告或代码仓库记录密码、完整 token、密钥及不必要的原始个人信息。

## 五、安全措施

乙方至少采取与风险相匹配的措施，并在附件二写明责任人和证据：

- 身份认证、最小权限、职责分离和账号及时回收；
- 传输保护、存储保护、密钥和 Secret 受控管理；
- 访问、变更、导出、备份、恢复和异常事件审计；
- 漏洞修复、恶意代码防护、备份恢复和业务连续性；
- 开发、测试、生产和客户环境隔离，测试数据脱敏或模拟；
- 网络运行与安全日志按适用要求至少保存六个月；
- 定期风险评估、人员培训和供应链安全核对。

## 六、安全事件

1. 乙方发现或合理怀疑个人信息泄露、篡改、丢失、越权访问或不可用时，应立即止损，并在不晚于 `[例如：发现后 4 小时]` 向甲方初报。
2. 初报至少包含事件时间、范围、信息类别和数量、可能影响、已采取措施、联系人和后续计划；未知项标记待确认，不伪造结论。
3. 乙方持续保全日志和证据，协助甲方评估并履行向个人或主管部门通知的义务。未经甲方授权，乙方不对外发布，但法律另有要求的除外。
4. 事件关闭后 `[期限]` 内提交根因、影响、修复、复发防范和删除/恢复核对记录。

## 七、审计和证明

甲方可按合理频率要求乙方提供与本委托范围有关的安全制度、第三方报告、访问记录、删除证明和整改结果。审计应保护乙方其他客户、商业秘密和系统安全，不得借审计扩大数据访问。发现重大不符合时，乙方应在双方确认的期限内整改；无法整改的，甲方可暂停相关处理或终止委托。

## 八、责任、期限和终止

1. 本协议自 `[日期]` 生效，至委托数据全部返还、删除且必要证明交付后终止；保密、安全事件、审计和依法保留义务按其性质继续有效。
2. 一方违反本协议造成损失、监管处置或第三方主张的，按主合同、适用法律和过错承担责任。
3. 主合同终止、无效、被撤销或委托目的消失时，乙方不得继续保留或使用个人信息，但法律另有规定的除外。

## 应用安全合同 / Application Security Contracts

权限与数据范围以服务端现有 RBAC、持久化业务事实和受控 usecase 为真源。页面隐藏、默认筛选和 Workflow 展示快照不能代替直接接口授权。客户配置选择单客户私有化部署，不承担 runtime tenant 隔离语义。

| 边界 | 当前要求 | 需要覆盖的路径 |
| --- | --- | --- |
| 密码登录 | 不存在账号与错误密码返回相同外部错误码、消息和空数据；内部保留诊断原因及既有 dummy bcrypt。此合同不宣称恒定响应时间。 | 直接登录 API、正常登录、错误密码、不存在账号，以及既有账号状态与会话控制 |
| 财务附件 | 加载附件所属持久化财务事实的 `FactType`，分别使用该类型当前读取 / 确认权限；报表权限不能替代原始附件权限。 | 列表、上传、下载、撤销、已撤销幂等读回；同类型正常访问与跨类型拒绝 |
| 采购收货 | 统一使用当前角色 `ALL / ASSIGNED / NONE` 仓库范围；`ASSIGNED` 必须覆盖整单所有明细。列表在计数与分页前隔离，完整读取不能截断为误导性的明细子集。 | 创建、新增明细、列表、详情及嵌套明细、过账、正式取消、流程别入口，以及创建 / 追加 / 流程幂等读回 |
| 收货事务与重试 | 写入在事实锁及同一事务内核对完整单据和持久化库存事务；幂等重放按当前授权检查，不把范围写入事实快照或请求指纹。 | 单据后来新增范围外行后的重放、混合仓库、范围收缩、并发写入、状态 / 质检 / 数量与冲正控制 |
| 开发工作台 | DEV 页面、读取、会话、执行与取消先检查访问模式。默认 `operator` 使用独立身份，未配置身份失败关闭；个人受控内网可显式启用 `private-network`，符合网络限制的设备无需额外工作台登录。 | 默认认证、匿名 / 错误身份 / 正确身份、显式内网模式、无效配置、公网 / Host / 跨站拒绝与精确可用性读取例外 |
| 开发运维操作 | 所选访问模式与网络、同源、CSRF、固定动作、确认和资源预检共同生效；默认身份模式拒绝远程明文，个人内网模式允许直接 HTTP。可配置单个内网 HTTPS origin，仅信任本机 loopback 代理覆盖的指定 Host、HTTPS 协议与单个私网客户端地址。DEV 路由、Bridge 和本地证据不进入生产构建。 | 会话签发、执行、取消、缺 Origin / CSRF、未配置 / 伪造代理、公网 / 转发链 / 跨源拒绝、预检失败与生产制品边界 |
| 敏感信息 | 凭据由受控服务环境加载，浏览器和业务响应只获得必要内容；内部诊断与用户提示分离。客户原件、私密证据和真实数据遵循受控存储边界。 | 日志、错误、导出、附件、构建制品及子进程环境；详细个人信息合同见相关专题 |

这些控制需同时保留业务状态、质检、数量、幂等、事务、审计及异常恢复规则。安全修复不能通过放宽正常业务合同换取测试通过。

## 如何解读验证 / Interpreting Verification Evidence

| 证据 | 能证明的范围 | 仍需核对的部分 |
| --- | --- | --- |
| 权限与范围回归 | 指定源码快照下，直接接口、嵌套对象、正常访问、拒绝访问与重放行为符合测试合同 | 未覆盖入口、真实配置、运行服务是否已更新；mock 不能代替实际数据库事务 |
| 隔离数据库测试 | 模拟数据下实际查询、锁、事务、重放与并发的行为 | 未运行的数据库用例、真实存量升级、目标数据和部署配置 |
| 秘密扫描 | 指定工具 / 版本 / 规则及扫描范围内是否检出秘密 | staged 候选、制品和全仓 / 历史是不同范围；一次局部通过不能证明全仓不存在泄露 |
| Go 依赖可达性检查 | 固定 Go 依赖和代码路径的已知公告适用性 | 工具未执行时保留缺口；通过不覆盖未知漏洞或完整业务越权 |
| JavaScript 依赖公告 | 锁定依赖版本命中了哪些公开公告 | 必须核对公告前提、运行模式、输入可控性和项目调用链，不能直接升级为应用漏洞结论 |
| 源码复核与浏览器复现 | 已检查路径的控制，或指定隔离浏览器场景的可观察行为 | 局部机制复现不等于完整跨账号利用；未闭环的入口、持久化和敏感影响继续标为候选 |
| 本地门禁与 exact-SHA CI | 回执绑定的源码、环境、门禁范围及结果 | dirty Local、其他提交和未运行目标不能继承绿色结果；跳过、缺失和零执行不能算通过 |
| 发布与目标 smoke | 固定 commit / image、配置、migration、目标状态、业务检查和回滚点是否一致 | 本地修复、历史发布或健康检查不能单独证明当前生产安全 |

执行命令和门禁登记以 QA 脚本与测试策略为准。记录结果时保留时间、来源、源码 / 制品身份、工具版本、实际范围、跳过与失败；工具缺失如实标记，避免将“没有结果”写成“没有问题”。

## 工作台入口 / Workbench Entry

在开发工作台进入“质量验证 → 质量门禁”，用“门禁治理”核对登记风险、触发条件、真源和退出条件，用“覆盖缺口”核对当前 / staged 改动应运行的检查与仍缺证据。两个视图提供本文的文档链接。

“交付运行 → 安全与恢复”集中展示应用、运维访问、异常监测和完整备份的核验要求，复用既有交付与数据库恢复回执；未接入专门回执的安全项保持未核验。防入侵与防勒索要求见[运维安全与勒索恢复](运维安全与勒索恢复.md)。

本文通过既有开发文档查看器读取仓库 Markdown；其中审计摘要带固定日期，不会随页面刷新变成当前安全结论。当前门禁结果继续读取正式回执。自动门禁的覆盖范围与人工安全审计的覆盖范围分别核对。

# 运维安全与勒索恢复 / Operational Security and Ransomware Recovery

本文供项目维护者核对入侵防护、异常发现和业务恢复。开发工作台的“交付运行 → 安全与恢复”汇集核验要求与已有交付、数据库恢复证据；入口和文档本身不执行防火墙配置、监控、备份或事件处置，也不证明目标已具备这些防护。

## 入口与证据 / Entry And Evidence

工作台继续使用 `/__dev/drill-recovery`，复用版本中心的同一份客户与目标隔离摘要。正式 ERP 的账号、角色、权限和审计仍由系统管理的服务端授权控制；主机、部署与备份属于独立运维身份。DEV 页面不进入生产构建，不能承担生产监控入口。

| 检查项 | 当前页面依据 | 可作出的判断 |
| --- | --- | --- |
| 应用与依赖安全 | [应用安全与验证边界](应用安全与验证边界.md)、质量门禁及带日期的审计摘要 | 尚未接入与当前目标运行版本绑定的专门审计回执，保持“未核验” |
| 入口与运维身份 | 本文的网络、身份与最小权限要求 | 尚未接入目标暴露面、访问限制和多因素认证回执，保持“未核验” |
| 账号与异常监测 | 本文的日志与告警要求 | 尚未接入目标安全告警证据，保持“未核验” |
| 备份隔离与完整恢复 | 既有数据库隔离恢复回执与本文的完整备份要求 | 只有目标、客户、版本、时效、校验和清理均有效的数据库回执才显示“仅数据库恢复已核验”；附件与备份隔离仍待核验 |

页面显示核验目标、运行版本，以及取得的数据库回执时间与标识。交付预检、健康检查、成功发布、静态文档或历史审计不能替代当前安全回执。跨目标、错误版本、过期、失败和缺失恢复回执不补齐安全证据；读取失败保留上次结果并提示，刷新只读交付摘要。

## 核验顺序 / Verification Order

| 优先级 | 事项 | 完成标准 |
| --- | --- | --- |
| P0 | 管理入口、特权身份与业务存储访问 | 从目标实际配置和允许来源读回，证明访问限制与最小权限生效 |
| P0 | 攻击后仍可保留的完整备份 | 数据库与附件具有共同恢复点；独立保护副本能抵御业务主机或应用身份删除；隔离恢复与关键业务核验通过 |
| P1 | 异常记录与告警 | 告警能通知到维护者，日志在受影响主机之外保留，失败与恢复分别可读回 |
| P1 | 应用、依赖及主机补丁 | 检查绑定版本和范围，确认漏洞、待验证候选、工具缺口分别记录 |

<a id="access-boundary"></a>

## 网络与身份边界 / Access Boundary

1. 核对真实公网与内网入口。数据库、附件存储管理端、SSH 和工作台按岗位限制来源；远程管理使用受控 VPN 或网关及多因素认证，保留必要的恢复路径。
2. 分离应用运行、数据库迁移、部署、备份和存储管理身份。应用账号只获得业务所需权限，不持有备份删除、主机管理或部署凭据。
3. 核对管理员启停、授权、会话撤销与凭据轮换的实际效果。共享密码或页面隐藏不能替代身份认证和服务端权限。
4. 留存脱敏的配置来源、目标身份、核验时间和允许／拒绝结果；不在页面、文档或日志中展示密码、完整令牌、DSN 和客户明细。

DEV 工作台当前访问模式与独立运维身份合同见[开发服务 Bridge 边界](../../web/dev-server/README.md#边界)。其访问控制不能推导服务器 SSH、VPN 或其他管理工具已启用多因素认证。

<a id="ransomware-backup"></a>

## 抗勒索备份与完整恢复 / Ransomware Backup

数据库和附件须在同一停写窗口形成配套备份，绑定 release、migration、备份标识、文件 manifest、大小和 SHA-256。恢复到干净隔离目标后，核对数据库、逐对象附件及关键业务入口；单独恢复数据库不能证明完整 ERP 可恢复。

至少保留一份离线或不可变副本，并由独立身份与删除权限保护。不可变存储须验证实际保留期及删除限制；普通应用或业务主机身份不能修改、覆盖或删除这份副本。恢复凭据与备份分开保管，保留受控取用路径。异地、加密、RAID 和普通版本副本各自解决部分问题，不能单独证明备份在主机失陷后仍可用。

当前[日常数据库备份脚本](../../scripts/deploy/scheduled-postgres-backup.sh)提供数据库 dump、校验、加密异地副本和受管旧文件清理，只覆盖 PostgreSQL。该脚本拥有异地目录写入和旧副本清理能力，不能据此宣称已经具备不可变保留。完整附件备份与恢复合同见[附件存储与备份](../../server/deploy/compose/prod/README.md#附件存储与raid5)。当前客户操作入口与周期见[备份恢复 Runbook](../../deployments/yoyoosun/runbooks/04-backup-restore.md)。

恢复点目标（RPO）以数据库和附件共同且验证可用的备份为准；恢复时长目标（RTO）以实际恢复、升级审计与业务核验耗时为准。定时器、异地复制或报告文件存在都不能代替安装读回和恢复演练；不能在未演练时承诺固定恢复时间。

<a id="security-monitoring"></a>

## 异常记录与告警 / Security Monitoring

需要核对集中登录失败、特权变更、异常批量下载、存储或主机异常，以及备份失败与过期。应用审计、网关和主机记录保留时间、目标、事件与结果，必要时关联请求标识；重要日志保留到主机之外，避免事件后只剩受损主机的记录。采集范围、保存期限与访问权限按敏感信息合同控制。

告警须验证触发、送达、确认和恢复，明确维护者及受控通知渠道。页面只引用这些实际证据；没有采集或通知回执时保持未核验，不显示“监测正常”。依赖公告先核对使用方式和可达性，待验证候选与已确认漏洞分别处理，不以跨主版本升级代替适用性分析。

<a id="incident-response"></a>

## 疑似入侵或勒索的处置 / Incident Response

1. 记录发现时间、症状与脱敏证据，保护现有日志和备份。在受控流程下隔离受影响主机与身份、暂停相关业务写入，明确影响范围和恢复负责人。
2. 使用可信终端撤销受影响会话，按已核实影响范围轮换凭据；核对应用、数据库、部署、备份及远程管理身份。
3. 选择攻击前可信的数据库与附件恢复点，在干净隔离目标恢复，核对完整性、存量升级审计和业务入口，记录丢失数据与实测恢复耗时。
4. 修复入侵入口并核对可信制品和配置，批准具体恢复方案后再切回业务；恢复后继续观察异常并复核权限和告警。

本页仅提供处置指引。隔离主机、撤销真实会话、轮换凭据、恢复数据库或切换服务须按目标运维流程和实际授权执行；页面不提供自动封禁、清库、任意命令或绕过门禁的操作。

# 完整项目手册 / Project Handbooks

三册覆盖当前产品的业务使用、管理员实施和技术运维路径。手册以当前正式代码、配置与操作入口为依据；它们不证明某个目标已部署、已导入或已验收。

| 读者 | 手册 | 阅读内容 |
| --- | --- | --- |
| 员工、老板、培训人员 | [业务使用手册](业务使用手册.md) | 上手、工作台、任务、岗位交接、填写与状态、打印附件、问题恢复，以及全部现有业务页和工程用料专题 |
| 项目负责人、管理员、实施人员 | [管理员与实施手册](管理员与实施手册.md) | 实施准备、员工账号、岗位权限、审批责任、配置启用、资料准备、日常支持、升级交接与验收 |
| 开发、运维、接手人员 | [技术维护与运维手册](技术维护与运维手册.md) | 架构、环境、启动、接口、字段、迁移、验证、发布、备份、恢复、回滚、排障与手册维护 |

## 在线与离线 / Reading And Export

从 `/erp/help-center` 直接选择“操作图解”、业务手册、管理实施或技术运维，再按目录或搜索进入所需章节。四类内容共用一层导航，书目、正文和下载按同一范围开放；图解首页的“推荐岗位”只改变业务操作推荐，不改变账号权限。业务页问号仍可直达本页说明、图解和完整词条。

| 手册 | 阅读范围 | 下载 |
| --- | --- | --- |
| 业务使用手册 | 当前账号岗位说明与实际已开放业务页面的并集；未知岗位保留通用说明与已开放页面帮助 | 当前账号可读范围的完整业务册 |
| 管理员与实施手册 | 超级管理员、老板 / 管理层，或具备账号读取、岗位读取、客户配置读取任一权限的账号 | 当前获准的完整管理实施册 |
| 技术维护与运维手册 | 超级管理员，或同时具备岗位权限管理、客户配置读取、系统审计读取能力的账号 | 当前获准的完整技术运维册 |

打开“下载手册”菜单后，直接选择 HTML 或 Markdown 下载当前整册可读内容。HTML 可直接离线阅读、查找和通过浏览器打印为 PDF；在线三册均为真实正文，不依赖仓库文件服务或本地 `output` 目录。管理和运维正文由登录接口按当前账号筛选，不进入普通 Web 静态资源；缺少读取结果时展示失败与重试，不能把失败当作无权限。

手机岗位入口从“我的 → 帮助与手册”进入，同样提供当前账号获准的书目、全文搜索、章节阅读和下载。翻章从新章顶部开始，浏览器返回恢复原阅读位置；跨册链接保留手机入口，只链接到当前账号可读章节。三册 HTML 都带可点击目录，与在线下载及仓库导出复用同一渲染入口。

完整仓库三册导出从仓库根执行：

```bash
node scripts/docs/project-manuals.mjs
node scripts/docs/project-manuals.mjs --check
node scripts/docs/project-manuals.mjs --export
```

离线交付包在 ignored 的 `output/pdf/project-manuals/`，包含三册 Markdown / HTML / PDF、阅读首页和来源 hash 清单。发布交付应从固定产品版本重新生成，工作区导出不代替正式发布身份。

## 阅读器与内容组织 / Reader Contract

帮助首页负责按岗位找操作，完整手册负责连续阅读。三册沿用开发工作台文档的目录、章节和正文分层方式，在线阅读使用同一阅读框架，业务帮助保留操作图解、字段词条和办理入口。

| 区域 | 组织规则 | 核对结果 |
| --- | --- | --- |
| 书目与目录 | 操作图解与当前账号可读三册共用一层导航，目录按业务模块分组，选中项与正文一致 | 切换书目保留本册上次章节；刷新可恢复选择，同页前后退恢复阅读位置 |
| 章节阅读 | 章节标题、章内导航、正文与翻页位于同一阅读区；业务、管理和运维章节共用章内导航组件 | 标题和正文左边对齐，正文不重复套框，纠错入口和翻页共用紧凑页脚 |
| 章内导航 | 业务章节取共享结构化内容，管理和运维取同源 Markdown 的小节标题；正文和目录使用同一锚点规则 | 链接跳转到实际小节，代码块内的标题不会成为目录 |
| 连续阅读 | 上一章和下一章仅取当前册的可读章节顺序，首尾章省略不存在的方向 | 不跨册、不跳入词条，也不扩大阅读权限 |
| 控件 | 搜索保留单一即时输入框，下载保留一个 HTML / Markdown 菜单，复用共享控件尺寸与圆角 | 页签条持续挂载，方向键切换后焦点留在页签；四个短标签与下载菜单在窄屏不截断 |
| 正文排版 | 标题、段落、步骤、字段说明、表格和命令块使用限定在帮助中心内的样式 | 桌面采用单行工具栏和可收起的窄目录，目录和正文各自滚动；手机目录与正文在同一滚动区切换，关闭目录恢复原阅读位置，锚点避开顶部导航 |
| 阅读与下载 | 搜索、在线正文和下载共用当前内容及账号范围，错误保留当前书目与章节并允许重试 | 下载的是当前整册可读内容；失败与无权限分别显示 |

管理与运维册按 Markdown 二级标题划分章节，三级和四级标题组成章内导航。业务册按通用阅读与现有业务页组织；每个业务页保留准备、填写与核对、实际动作、完成标准、交接、问题恢复、相关资料和业务边界。简短词条可从完整章节单独打开，避免把连续手册拆成只有解释的零散卡片。

内容变更先修当前真源，再生成消费者。阅读器样式、目录或导航变更时，同步[正式交互设计](../product/ui-design/README.md)，按影响核对默认阅读、章节切换、锚点、搜索恢复、岗位权限、下载和窄屏；导出样式变化时再补离线排版验证。

## 内容真源与维护 / Sources And Maintenance

### 在线纠错与企业补充 / Help Contributions

每个可读章节和操作图解提供“反馈本章问题”。员工可以填写原文和建议，系统记录章节、正式内容身份、当时所读的企业补充发布记录、提交人及时间；普通员工只查看自己的纠错，维护人员可以查看对应手册可读章节的纠错并保存处理回复。正式正文的修正继续回到下述内容真源，不会因反馈提交自动改变系统规则。

企业补充用于本公司的岗位约定、示例和注意事项，附在对应完整章节后；字段词条与操作图解只提供纠错。它们保存在数据库，不写入仓库，也不覆盖正式手册。阅读范围继承所在章节，推荐岗位、编辑或发布权限均不能额外授予章节阅读权。

| 手册 | 编辑草稿与历史恢复 | 发布 |
| --- | --- | --- |
| 业务使用 | `help.business.edit` | `help.business.publish` |
| 管理实施 | `help.administration.edit` | `help.administration.publish` |
| 技术运维 | `help.operations.edit` | `help.operations.publish` |

这些权限在“权限管理 → 岗位设置”独立授予，普通岗位默认不获得；超级管理员拥有全部能力。编辑人员可以保存草稿、预览和把历史内容恢复为新草稿，发布人员可以发布已保存草稿；同一岗位可同时拥有两种权限。每次操作检查当前版本，发生并发修改时拒绝覆盖并保留页面输入。清空正文后保存、发布，可撤下当前企业补充，历史仍保留。

在线阅读、全文搜索与在线 HTML / Markdown 下载只合并同一份已发布内容，草稿不进入读者视图或下载。企业补充读取失败时明确提示并阻断下载，避免生成缺失补充的文件；刷新页面可获取其他维护人员的新发布。仓库三册导出只包含正式产品手册，不带部署中的企业补充或员工纠错。

纠错、补充当前状态及不可变修订分别由 `help_feedbacks`、`help_supplements`、`help_supplement_revisions` 保存，纳入数据库备份恢复；历史恢复是新增记录，不改写旧记录。企业补充支持文字、列表、表格和代码块；预览和离线 HTML 转义原始 HTML，不加载正文图片。修改记录可查看内容、与上一条对照以及恢复；未保存关闭、换页和离开页面会提示，保存期间阻止重复操作。

业务使用手册是生成文件，复用业务页、工程用料、岗位说明与通用阅读章节；不直接编辑生成正文。简要步骤和词条在 `businessUsabilityCatalog.mjs`，逐页准备、填写、动作和问题处理在 `businessHandbookOperations.mjs`，由 `businessHandbook.mjs` 统一组装。具体办理说明保留实际代码来源供维护核对，字段或动作变化时先回查当前表单及 usecase。增加业务页面或字段规则后更新原目录，重新生成并检查，防止在线与离线口径漂移。管理和运维 Markdown 同步生成 `server/internal/projectmanuals/content.generated.json`，随后端发布，通过 `admin.project_manuals` 按当前有效账号角色和权限提供。生成器与检查见[手册脚本](../../scripts/docs/README.md)。

管理员与技术手册保留连续操作路径，专题文档继续维护细则。改动行为、接口、配置或路径时，同轮更新受影响手册、目录、[文档清单](../文档清单.md)和验证；历史发布与验收证据继续保留原事实。

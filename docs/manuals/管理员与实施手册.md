# 管理员与实施手册 / Administration And Implementation Handbook

本手册供项目负责人、系统管理员和实施人员使用，覆盖当前单客户私有化产品的准备、权限、配置、资料、培训、验收和日常管理。普通员工的办理步骤见[业务使用手册](业务使用手册.md)，运行命令、迁移与恢复见[技术维护与运维手册](技术维护与运维手册.md)。

这里描述当前代码与正式配置合同支持的能力，不表示某个客户环境已经部署、已导入数据或已经验收。操作前核对实际发布版本、客户配置和账号；目标环境状态使用本次读回结果。

可从“帮助中心 → 管理实施”在线阅读。书目与正文按账号权限开放，切换推荐岗位不扩大权限；打开“下载手册”后选择 HTML 或 Markdown，HTML 可离线查找并通过浏览器打印为 PDF。

## 阅读顺序 / Reading Path

| 当前任务 | 阅读位置 | 完成标准 |
| --- | --- | --- |
| 首次实施 | 实施准备 → 账号与岗位 → 基础资料 → 培训与验收 | 真实岗位能完成已约定业务，不能越权 |
| 调整人员或职责 | 员工账号 → 岗位设置 → 审批责任 → 重新登录核对 | 保存结果、有效成员和实际会话一致 |
| 调整公司差异 | 客户配置与启用范围 | 固定配置 revision，发布、激活和读回闭环 |
| 日常问题 | 日常管理与问题分流 | 区分业务差异、权限和运行问题，保留必要依据 |
| 升级或恢复 | 变更与恢复交接 | 运维按固定版本、备份和回滚点执行，业务复核结果 |

## 实施准备 / Preparation

1. 明确稳定客户 key、负责人、启用模块、岗位、业务范围、目标环境、培训和验收人员。客户 key 选择独立部署与配置，不代表 SaaS 租户。
2. 核对固定产品版本、数据库迁移版本、客户配置 revision、附件存储和备份恢复安排。只有文档、配置草稿或历史截图时，不记为已启用。
3. 把差异分为通用产品、已支持客户配置、打印模板、受控资料适配和新增能力。未有后端约束与实际消费者的配置候选不作为承诺。
4. 核对真实资料授权、保存位置和访问人员。客户原始文件、私密清单、真实账号及密钥保留在客户专属受控存储。
5. 准备模拟业务与岗位账号，约定如何判断每一笔订单、库存、出货和款项的真实结果。

完整实施合同见[新增甲方客户实施流程](../product/新增甲方客户实施流程.md)。Product Core 构建与普通测试不依赖客户原件或私有仓库。

## 首个管理员与日常管理账号 / Administrator Bootstrap

首个管理员由运维在已经完成正式 migration 的 fresh 目标，通过受控初始化入口创建。它是一次性初始化，不是普通登录失败后的修复方法；初始化前后须核对目标身份、初始化标记、审计和 RBAC。具体入口见[部署脚本](../../scripts/deploy/README.md)。

1. 运维完成初始化并读回结果后，由授权负责人登录核对管理入口。
2. 按实际职责开通日常管理账号，不让所有员工使用超级管理员。
3. 确认员工创建、分配岗位、启停、注销和调整权限分别具备相应能力；页面中部分动作受限时，按缺失权限处理。
4. 超级管理员账号只能按服务端约束由超级管理员维护。不要通过直接改库、前端隐藏或伪造角色绕过限制。

## 员工账号 / Employee Accounts

正式入口是“权限管理 → 员工账号”。只有拥有对应查看或管理权限的账号才能执行相应动作。

### 新增和分配岗位

1. 先按姓名或已有身份查找员工。一个人兼任多个岗位时维护原账号；同名人员先核对是否为同一人。
2. 在当前页面允许的创建动作中填写必要资料，按提示处理登录方式和身份信息，不在共享文档中记录密码。
3. 分配实际承担的岗位；需要兼任时核对多岗位合并后的页面、动作与数据范围，不只看岗位名称。
4. 保存后重新查看关联账号和岗位，再用该员工的实际会话验证入口及动作。
5. 员工账号创建成功不表示其所有业务权限、审批责任和待办都已配置好，继续核对后续章节。

### 调岗、临时停用与离职注销

| 场景 | 处理方式 | 核对结果 |
| --- | --- | --- |
| 调岗或兼岗 | 修改原账号的岗位分配，保存后核对有效权限和相关责任 | 新岗位可用、旧岗位已撤回的能力不可再用 |
| 临时停止访问 | 使用当前允许的启用 / 停用动作 | 停用状态及重新登录、访问结果符合限制 |
| 离职 | 使用正式离职注销动作，并交接未完成业务与审批责任 | 账号不能继续使用，原业务和审计记录仍可追踪 |
| 注销后返聘 | 按新账号办理；已注销账号不可恢复 | 不把原账号当成可恢复的临时停用 |

当前登录账号不能临时停用自己；超级管理员和敏感账号维护继续遵循服务端保护。关联账号列表没有查看权限时，不能根据空白断言岗位无人使用。

## 岗位设置、数据范围与导航 / Role Settings

“岗位设置”“员工账号”“审批责任”和“岗位导航”各自有读取与管理边界；入口或部分页签可能因权限、客户启用范围而不可用。

1. 在岗位设置中选择实际岗位，核对页面与操作能力。系统内置只读岗位以页面提示为准。
2. 查看关联员工，评估这次调整会影响哪些账号；关联账号用于核对，不替代员工管理。
3. 按当前提供的数据范围和敏感字段设置核对访问边界。仓库范围为空或条件不合法时先修正，不能只保存表面菜单。
4. 在岗位导航查看实际菜单和页面访问。菜单按当前业务模块与岗位权限生成；需要调整可用页面时返回岗位设置修改功能权限，隐藏菜单不等于撤销后端权限。
5. 完成后保存岗位设置。离开、刷新或切换时如有未保存提示，先决定保存或放弃，不把未保存草稿当成已生效。
6. 用受影响员工账号验证：应有入口能进入、允许动作可办、被撤回动作被拒绝、数据范围与敏感字段保持正确。

多角色按各角色有效能力合并；客户配置、来源读取、责任归属、数据范围、状态与版本条件仍共同约束动作。详见[配置与权限策略](../product/配置与权限策略.md)和[角色入口](../roles/README.md)。

## 审批条件与责任 / Approval Settings

1. 打开权限管理中的审批责任，核对当前配置版本、每项审批的有效成员及阻塞原因。
2. 按已开放事项调整主办、备用或升级成员；责任草稿须先预览有效成员，不让停用或无权账号成为有效接手人。
3. 销售与采购订单可按当前支持设置“全部审批”或“按金额审批”。金额门槛使用一个币种、非负十进制金额；达到或超过门槛需人工审批。
4. 金额不完整或币种不匹配仍需人工审批；当前支持的 CNY / USD / HKD 不自动折算。销售使用订单总额，采购使用明细金额合计。
5. 门槛为 0 或切回全部审批时，核对金额与币种条件已按规则清理。出货财务放行保持全部审批，不开放金额免审。
6. “保存并生效”需要发布和启用客户设置的权限，保存后读回条件与责任。新流程使用新 revision；已有流程继续使用启动时冻结的配置。

停用审批事项可能阻止对应新流程启动，不表示免审。收付款、库存调整和生产异常沿用固定流程合同；不能把界面未提供的任意流程编排当成现有能力。详见[审批责任与流程选择](../product/多甲方角色能力与流程编排.md#审批责任与流程选择)。

## 收付款审批与职责核对 / Payment Responsibilities

当前收付款覆盖应收应付结算、订单预收 / 预付和实际退款。创建收付款记录会启动审批，批准后仍由财务确认实际收付；退款须独立审批并保留真实凭据。

1. 在审批责任中核对实际收付款流程的责任人员，用模拟业务检查申请、批准和财务确认分别由谁办理。岗位名称相同不证明是同一责任人。
2. 首款、分期款和发货前尾款关联原订单：销售来源须已生效，采购来源须已批准，委外合同须已确认。只有实际收付确认后才形成可用款项余额。
3. 结算款按同一往来方和币种核销；订单预收 / 预付款后续抵扣同一订单账款，可分批使用，不能跨订单挪用余额。
4. 退款从原款核对可退余额、申请、审批、确认实际退款；冲销错误记录与真实退款分别核对，不用冲销结论替代真实资金结果。
5. 调岗或离职时检查未完成审批与待确认收付，先交接来源单号、当前状态和实际责任，不能只撤掉菜单。

具体字段和恢复方式见[业务使用手册的收付款与核销](业务使用手册.md#finance-payments)。

## 客户配置与启用范围 / Customer Configuration

| 配置面 | 当前支持范围 | 核对边界 |
| --- | --- | --- |
| 模块 | enabled / read_only / disabled | 关闭不删除表和历史；只读及关闭仍由后端约束写动作 |
| 岗位页面和动作 | 已登记页面投影、entitlement 与角色 revoke | 不能超过 Product Core 的后端 RBAC 上限 |
| 审批 | 已登记审批条件、责任与启停 | 固定流程和旧实例冻结条件不随意改写 |
| 列表与 CSV 字段 | 客户、供应商、销售订单已支持 surface 的 visible | 不代表支持任意 label / editable / required，也不改表单校验 |
| 品牌与菜单 | 已审查公开资源、分组与岗位推荐 | 不发布客户私密资料、真实业务行或员工隐私 |

配置走 validate → publish → activate，普通会话读取 active revision。真实客户固定部署缺少 active revision 时业务动作失败关闭，超级管理员也不能据此绕过；保留受控配置修复入口。

同 revision 同内容可幂等重放，同 revision 不同内容必须拒绝。候选包中的编号、导入映射、打印或流程资料，只有具备正式 catalog、校验、消费者与测试的部分才是已支持能力。详见[配置与权限策略](../product/配置与权限策略.md)。

## 基础资料与试用数据 / Master Data And Trial

按下表准备资料，先搜索已有编号和名称，核对交易主体、单位与规格。新订单带值后仍须核对本单内容；修改档案不重写旧单的冻结资料。

试用使用 seed、fixture 或手工模拟资料，不代表真实客户确认、库存、出货或财务。当前没有可直接执行的 yoyoosun 真实数据导入；真实导入另行评审授权、映射、dry-run、幂等、对账与备份恢复，原件不进入通用测试、CI、前端包或镜像。

产品另有销售汇总表和 BOM 材料分析表的窄范围 `.xlsx` 辅助录入：先人工复核，使用已有资料，只新建草稿，不覆盖或自动启用已有记录，也不写下游事实。它不等于通用客户批量导入；客户原件能否用于该入口仍须核对授权。具体步骤见业务手册的销售订单与物料清单章节。

具体业务操作见[业务使用手册](业务使用手册.md)，资料存储与客户实施边界见[实施流程](../product/新增甲方客户实施流程.md)。

### 资料准备顺序与检查结果

| 顺序 | 准备内容 | 保存后核对 |
| --- | --- | --- |
| 1 | 单位、仓库及仓库类型 / 负责范围 | 本岗位可见，材料入库仓与库存类别匹配 |
| 2 | 客户、供应商 / 加工厂与联系人 | 主体不重复，交易条件、地址和联系人可供新单选择 |
| 3 | 材料、产品基础款、产品规格 | 材料厂商料号、单位、产品归属、SKU、单重和启用状态明确 |
| 4 | 加工环节、BOM 与产品图 | 路线位置和工序能力明确，BOM 草稿与启用分开，图片可重新打开 |
| 5 | 岗位账号、审批责任和实际导航 | 经办与审批可分别完成，无权账号被拒绝 |
| 6 | 一笔模拟业务 | 从来源到本次正式结果可追踪，失败后可查询和恢复 |

产品基础图与产品规格附件分别准备。产品可设置 0–2 张图用于相关打印；SKU 归属保存后不能更换，默认单位变更后要重新确认单重。详见[产品档案](业务使用手册.md#products)。

## 打印、附件与日常管理 / Printing And Files

打印先核对当前单据、模板、公司抬头、明细、分页及签字区，再输出；已有模板和当前工作区提供的编辑、批量能力分别核对。客户原始样本继续留受控存储，不把打印示例当作当前正式数据。

附件元数据与文件内容分开保存。日常先检查记录是否已经保存、附件是否关联及能否预览下载；文件服务故障交运维排查，不通过重新上传或清理存储掩盖缺失。

管理员核对权限与业务审计入口；运维负责实际存储、备份和恢复。只有 PostgreSQL 备份不能证明外置附件也能恢复，见[附件存储与恢复](../../server/deploy/compose/prod/README.md#附件存储与raid5)。

## 问题分流与记录 / Support

| 现象 | 先核对 | 交给谁 |
| --- | --- | --- |
| 业务数量、金额或状态不符 | 同一来源单据、本次对象、已保存和已过账结果 | 对应来源岗位；需要更正时使用受控业务动作 |
| 菜单、按钮或数据看不到 | 公司启用范围、实际账号、有效岗位、数据范围与状态 | 系统管理员 |
| 审批不能发起或无人接手 | 当前 revision、有效责任成员、前置条件及旧实例冻结范围 | 责任配置管理员与业务负责人 |
| 上传、下载、PDF 或页面不可用 | 页面提示、来源记录、发生时间、是否存在已完成结果 | 运维；必要时联系开发 |
| 点击后结果不确定 | 先查询同一记录与任务，不连续提交 | 业务经办与管理员共同核实 |

问题记录只保留必要单号、页面、动作、提示与时间。业务审计、任务记录和技术日志各管不同证据；不得用操作日志替代财务、库存或实际出货结果。不要共享密码、完整 token 或无关客户隐私。

## 帮助纠错与企业补充 / Help Contributions

1. 员工从当前章节或操作图解点击“反馈本章问题”，填写原文和建议，提交后在本章查看自己的记录和回复。系统自动记录章节与所读版本，不需要员工填写技术编号。
2. 需要维护本公司操作说明时，在“权限管理 → 岗位设置”为指定岗位授予对应手册的“编辑企业补充”和 / 或“发布企业补充”。业务使用、管理实施、技术运维分别授权；普通岗位默认只有原有阅读范围，没有编辑和发布权。
3. 维护人员在完整章节中打开“维护补充与纠错”，填写企业补充和修改说明，预览后保存草稿。只有编辑权限时先保存，再交具备发布权限的人核对发布；同时具备两种权限的人可以直接完成保存与发布。
4. 已发布的补充同时进入在线阅读、搜索和本册 HTML / Markdown 下载。未发布草稿仅维护人员可见；正式手册仍从产品来源维护，企业补充不能改变实际字段、审批、权限或业务结果。
5. 在“修改记录与恢复”查看修改人、时间、说明、正文及前后对照，选择“恢复为草稿”后核对，再发布。清空正文并发布可以撤下当前补充，原历史保留。
6. 在本章纠错记录中保存处理回复，员工回到同章即可查看。正式正文需要修正时，把核对结果交给项目维护人员，同步正式来源后随产品发布；企业操作约定则通过企业补充发布。

同时编辑发生冲突时，页面保留当前输入。先留存所写内容，再“重新读取”最新保存版本并核对后重新保存；不要反复点击尝试覆盖。手机提供相同的纠错、草稿、发布、记录和恢复动作。

## 升级、备份和恢复交接 / Change And Recovery

1. 负责人确认业务范围、窗口、目标和验收账号，运维固定产品、镜像、migration、配置 revision 和回滚点。
2. 备份须覆盖数据库、配套附件与配置身份，并在隔离环境恢复验证；业务负责人选定需核对的单据、数量、金额和附件。
3. 发布后分别检查 health、ready、登录、权限、配置、业务读取与选定办理链路。服务健康不等于业务验收通过。
4. 代码回滚不自动回滚数据库或客户配置；需要数据恢复时由运维执行单独的受控恢复计划。
5. 发生失败或结果不确定时先保留现场并读回，不清库、不删附件、不重复触发部署。

具体运行步骤见[技术维护与运维手册](技术维护与运维手册.md)。本手册不保存任何目标凭据、私密清单或一次性确认串。

## 日常巡查与人员交接 / Daily Checks

| 频率 / 触发 | 管理员动作 | 异常时下一步 |
| --- | --- | --- |
| 首次开通或调岗后 | 用受影响账号核对岗位、菜单、数据范围和允许动作，重新登录检查有效会话 | 权限问题回岗位设置；责任问题回审批责任；不把菜单显示当作服务端授权证据 |
| 业务反馈有待办未处理 | 按来源单号核对任务状态、当前办理人、阻塞原因和到期时间 | 交实际责任岗位处理，不由管理员代填业务事实 |
| 档案或模板调整后 | 核对新单带值、旧单快照、当前打印预览和附件关联 | 先区分新旧单及保存结果，再交来源岗位或模板维护人 |
| 文件或运行告警时 | 保存发生时间、页面、相关单号和必要提示，联系运维核对恢复与备份 | 不能把最近一次 PostgreSQL 备份当作附件完整恢复证明 |
| 员工离职前 | 盘点待审批、未完成订单、收付款和文件责任，完成来源级交接后执行离职注销 | 无明确接手人时由负责人决定责任，不批量完成原任务 |

交接至少记录业务来源、未完成动作、当前责任、受阻原因及接手人确认；不在交接表中抄录密码、令牌或客户原始私密资料。

## 培训与验收 / Training And Acceptance

按“客户需求 → 销售生效 → 工程和采购 → 生产与委外 → 质量和收仓 → 包装放行与实际出货 → 财务”的实际启用范围安排演练。并列或非启用环节不伪装成已执行主链。

| 检查对象 | 验收方法 | 应看到的结果 |
| --- | --- | --- |
| 每个真实岗位 | 用该岗位账号登录，找任务并办理 | 信息、可用动作和责任一致 |
| 权限限制 | 使用未授予能力的账号尝试对应动作 | 服务端拒绝，不能仅依赖按钮隐藏 |
| 业务闭环 | 核对同一来源的订单、实收、库存、出货与款项 | 各自正式记录正确，任务结束不代替业务结果 |
| 异常恢复 | 退回、缺值、失败后重新查询及继续 | 原因、责任与结果可查，无重复办理 |
| 电脑与手机 | 同账号、同对象、同条件比较 | 核心信息、动作和追踪一致，布局按设备适配 |
| 打印和附件 | 核对来源、预览、下载与恢复样本 | 内容、分页、关联与文件可用 |

验收记录绑定实际版本、环境、账号岗位、场景结果、未完成项及负责人反馈。自动化、本地浏览器和历史发布记录都不能代替本次客户使用结果。

## 当前边界 / Current Limits

产品保持单客户私有化；没有 SaaS 租户、license 或计费后台。客户配置只支持正式登记能力，不能任意上传脚本、SQL 或改变核心状态机。真实导入、生产部署、数据重建和目标恢复均须按各自合同单独核验；本手册的存在不表示这些操作已执行。

# 前端实现与交互约定 / Frontend Implementation And Interaction Contracts

本文维护 ERP 桌面、岗位任务端和开发工作台共用的前端实现约定。业务对象状态与允许动作由[生命周期与页面动作规则](../product/业务数据生命周期与页面动作规则.md)维护；视觉与交互设计见[交互设计说明](../product/ui-design/交互设计说明.md)，认证与敏感信息见[应用安全合同](../security/应用安全与验证边界.md)。实现仍以当前代码和测试为准。

下文代码路径以 `web/` 为工作目录；页面布局、权限和业务事实分别由所属组件、后端 RBAC 与领域 usecase 负责。

## 组件复用与使用入口 / Shared Component Entrypoints

新增或修改界面前，先按当前任务核对下表、实现源码与已有调用。相同职责和交互优先复用：适合当前任务的领域组件 → 项目通用封装 → 已确定的第三方组件。第三方组件已满足设计时直接使用；现有二次封装承担了尺寸、焦点、状态或其他合同的，调用方使用该封装入口。

### 反馈、切换与选择

| 场景 | 正式入口 | 使用边界 |
| --- | --- | --- |
| 单步提示与应用面板告警 | `AlertDialog`，内部使用 `AppModal variant="panel"` | 面板模式保留专用外观、背景隔离、可访问名称和焦点恢复，不作为一般业务表单壳 |
| 命令式确认、消息与通知 | `common/utils/antdApp` 的 `useModal()`、`message`、`notification` | React 页面及 hook 使用 `useModal()`，确认框跟随所属栏；工作区外及非 React 全局动作保留 `modal`。沿用 App context、居中、默认焦点和消息语义，调用方不另建 `Modal.useModal()` 或直接导入静态 API。离开来源或撤销权限时销毁所属确认框，迟到读取不能重新打开 |
| 内容页签、工作方式和结果筛选 | `SlidingTabs`、`SlidingSegmented`、`SlidingTabList`、`FilterChip` | 按导航、模式和筛选职责选择；沿用共享选中外观、键盘和动效  `FilterChip` 的可选 `help` 由调用方提供岗位帮助节点，与选择文字共用外框、独立响应 |
| 普通枚举、主数据及单据引用选择 | Ant Design `Select` 或已有领域选择器 | 有领域读取、搜索、清空和快照合同的先用领域组件；不写原生 `<select>`，不为统一名称再包一层空组件 |
| 下拉输入与切换 | `common/components/select/AppSelect` | 输入、预览和记录选择统一支持清空；保留用途提示及重新选择入口，主动清空后不得自动回选。仅没有合法空态的操作参数显式关闭清空，具体边界见[下拉选择与清空](../product/ui-design/交互设计说明.md#select-controls) |
| 空提示与读取反馈 | `common/components/empty/AppEmpty.jsx` | 列表、表单明细、候选及工作台共用三种规格；调用方依据实际读取、筛选及权限状态提供文案与恢复动作，见[空提示规格](../product/ui-design/交互设计说明.md#empty-states)。`AppTable` 等待时不显示空记录，`AppSelect` 沿用紧凑候选规格 |
| 搜索和业务筛选 | `common/components/SearchInput`、`common/components/select/FilterSelect`、业务列表的 `SelectFilter` | 空条件通过清空表达，不在下拉菜单提供“全部……”占位选项；查询空值、范围和恢复仍由调用方管理 |

### 明细、媒体与内容复用

| 场景 | 正式入口 | 使用边界 |
| --- | --- | --- |
| 当前记录的选择与操作 | `BusinessPageLayout`、`BusinessOperationPanel`、`SelectionActionBar`、`BusinessDataTable` | 同一页面壳内由主表提供可选 / 加载状态，未选时保留已授权的禁用入口；任务协作直接可见，其余按实测宽度收纳。页面声明业务角色与动作顺序，共享栏负责分类、禁用提示和浮层期间的位置稳定；打印角色用 `output`，任务协作入口用 `collaboration`。分类与主次独立：保留次要优先级的业务动作使用 `secondary` 配合 `data-business-action-group="business"`；组件可声明 `selectionActionGroup` 字符串或按 props 返回类别的函数，实例显式分组优先。共享订单状态按钮按动作区分提交 / 确认与关闭 / 取消，只读入口按实际权限归类，不以组件名、按钮颜色或低频推断业务类别 |

组件按使用范围放置：产品无关的通用组件在 `common/components/`，ERP 领域共享组件在 `erp/components/` 的对应子目录，手机专属组件在 `erp/mobile/components/`，研发工具专属组件在 `dev-workbench/components/`；只在当前页面内部使用的组件就近维护，不集中到一个大目录。纯数据转换放 `utils/`，可复用的状态与副作用放 `hooks/` 或所属模块。

主数据列表与工作台队列的请求分页与已显示结果分开维护：读取成功后，记录、总数、页码和每页条数一起更新；读取期间保留上一批结果并显示加载状态，失败时保留对应页码与条数，可重试或重新选择目标页、条数重读。不能把新页码或新条数直接套用到尚未替换的旧数据上；过期请求沿用现有取消与结果检查。

页面加载反馈留在正在更新的内容区域。桌面路由在 `ERPLayout` 的内容出口设置按路径重置的 `Suspense`，复用 `common/components/loading`；等待新页面时保留侧栏、目标页面名称和切页能力，同路径查询变化不重建加载边界。手机待办、已办、风险与超时共用 `MobileTaskListContent`：首次进入显示轻量卡片骨架，之后无旧内容的查询显示局部加载提示；刷新保留已显示内容，结果未确认前不显示零条汇总或空结果。筛选、搜索和底栏保持挂载，失败沿用现有重试与过期响应保护。

手机骨架只模拟内容，不创建业务记录或可交互控件；宽度、间距、标题、关联内容和底栏几何复用任务卡片样式及密度变量。固定四张占位卡片，透明度动画按卡片执行，减少动态效果时完全停止；成功、失败或离开列表后移除占位动画。加载组件只消费已有读取状态，不增加取数、缓存或计时后台任务。

业务表单与筛选中的大规模引用使用 `RemoteReferenceSelect`，沿用生产单选择器的请求代次、合并和分页规则，打开时读取 50 条，搜索防抖并取消旧请求，滚动续取。列表、编辑与打印按实际引用 ID 分批读取，每批最多 200 个；已选资料读取不套用候选的启用过滤，保留原字段、停用提示、禁用选择、清空和快照回补规则。页面内引用缓存随账号与有效权限变化失效，不跨会话共享。材料批量添加通过 `RemoteReferencePicker` 复用 `SourceImportPickerModal` 的服务端分页与跨页选择。

客户、供应商、产品、SKU 和物料的新建、修改或启停确认成功后，正式 API 入口通过 `referenceRecordChanges` 在当前窗口通知资料类型与 ID；`ReferenceRecordsProvider` 按所属读取权限重读该 ID 并合并引用，不在编辑器间传递资料快照。展开中的 `RemoteReferenceSelect` 保留搜索词与筛选条件重读候选；打开的 `RemoteReferencePicker` 保留分页、筛选及已选项重读，沿用原有失败重试。关闭的选择框或批量选择弹窗不扫描候选列表，同一 Provider 内多个引用共用一次定点读取，同一 ID 的后续更新取消旧读取。账号、权限变化及卸载丢弃迟到结果。仅原先发起“新建并使用”的业务回调可回填目标字段，独立建档不改变其他表单的选择、数量、备注、附件或冻结快照。

关联资料读取失败时保留当前输入，在当前编辑区显示“重试读取”；`BusinessFormPage` 通过轻量的 `ReferenceRecordsFeedback` 承接提示，隐藏的编辑器不占用反馈位置。重试只重读失败资料，不重放新建或修改，不重新初始化表单。这是当前窗口内已挂载引用的更新，跨标签页和跨设备不自动同步；分栏行为见[桌面分栏工作区](#desktop-split-workspace)。

单位、仓库配置及确需完整数据的导出/导入匹配保留现有完整分页读取。销售 Excel 客户匹配、BOM Excel 产品与材料匹配只在选择文件后读取完整匹配集合，不能用首屏候选代替完整匹配结果。BOM 和采购合同打印只读取单据涉及的资料，仍以冻结快照优先、原有缺值回补规则补充历史资料；委外收货质检按来源 ID 集合读取，出货前检验按批次 ID 集合读取。

工作台“交互设计 → 控件设计 → 组件选用”直接读取本节，按用途查找正式组件与边界；操作样例与真实页面导航由控件分类同源生成。页面名称和路径通过现有 `businessUsabilityCatalog.getBusinessPagePresentation` 展示适配器投影，只提供 `title / path`，正式业务模块与工作中心目录仍是唯一来源，样例不直接读取内部目录配置。“业务表单与明细”直接组合 `BusinessFormPage`、`BusinessFormSection`、`BusinessLineItemsSection`、`BusinessLineItemRow` 和 `BusinessTextArea`，核对字段校验、增删、空态、长文本、离开保护、失败与重试；“来源选择”使用 `SourceImportPickerModal` 核对搜索、跨页选择、停用、关闭重开及读取恢复。“列表与分页”继续使用 `AppTable` / `AppPagination`。共享表单与来源选择仅限对应呈现样例复用，依赖检查与浏览器共同守住无业务 I/O；新增业务组合仅在进入对应分类时加载，不把业务数据读取、业务校验或权限判断复制到演示。

长值与多列样例只组合真实的明细布局、选项格式化 helper 和 `WorkflowTaskImagePlaceholder` 占位，不从产品身份或真实图片读取模块间接引入附件 API。表单读取 `erpThemeContext.jsx` 中的纯上下文，主题偏好加载与保存仍由外层 `erpTheme.jsx` 的 Provider 管理；分区上下文、选择器完整值展示及相关纯依赖进入现有依赖守卫，按具体消费者登记，同时验证业务 I/O、持久化和未登记导入仍会被拒绝。

示例只修改本地虚构数据，不请求业务接口或写入偏好；真实页面在新标签页打开并沿用业务账号权限。开发入口使用当前站点，独立工作台构建时从已有部署目标解析业务站点，不维护第二份客户地址配置。组件目录与选用规则在本节维护；远程引用、附件、流程和打印的读取、写入及事实边界仍在正式业务入口核对。

现有组件不符合当前正式、已确认的 UI 设计时，先修改共享默认行为；仅部分场景存在明确差异时，用少量、语义明确的参数或变体承接。职责、交互结构或运行环境确实不同，且共享实现不能合理承接时才独立实现，说明现有能力缺口并复用适合的底层能力。迁移保留已有业务信息、权限、状态和有效操作，完成后清理范围内的重复实现与失效覆盖。

独立可下载 HTML 无法直接导入 React 组件时，复用该原型已有的选择、导航与浮层实现，并验证相同的视觉和操作合同。当前 `docs/product/ui-design/index.html` 的选择入口统一使用 `ui-select`，独立搜索通过 `bindSubmittedSearch` 统一草稿、搜索按钮、Enter 提交、清除与输入法保护，下拉选择器内部继续即时筛选；原型、打印工具、工作台和岗位页面均纳入各自适用的检查范围。

入口约束复用现有 ESLint：根包及 `es / lib` 聚合入口的命名、别名、命名空间与默认导入，内部模块深路径、原生 JSX 及 `createElement` 写法均不能绕过已指定的实现。底层导入仅对对应实现的精确路径放行，不能因某组件需要一个底层能力而放开整个目录。测试夹具可以构造底层控件以验证正反例，运行代码继续受限。Stylelint 继续守住共享外观与页面几何的职责；新差异不通过关闭规则或页面高优先级覆盖实现。

验证同时覆盖组件本身和代表性调用页面：错误调用应被拒绝，正确调用及必要例外应通过；页面按实际支持的主题和设备检查焦点、选值、关闭、禁用、恢复、相邻布局与滚动。使用现有 lint、`affected`、浏览器场景和 CI 入口选择受影响范围；生成器修改后重新生成，并验证输出 lint、生成一致性及相关消费者，避免手改产物。

## 主题模式 / Theme mode

电脑版、登录页、手机岗位端与工作台共用“跟系统 / 浅色 / 暗色”。跟系统保存的是模式，每台设备按自己的系统偏好显示，不改变权限、入口或路由。

### 偏好保存到哪里

| 使用场景 | 保存位置 | 恢复与缺值 |
| --- | --- | --- |
| ERP 已登录账号 | `admin_users.erp_preferences.appearance` | 跨设备恢复主题色、明暗模式、表格密度与线条；首次缺值用蓝色、跟系统、紧凑、网格，不导入未登录偏好 |
| ERP 未登录 | 浏览器 `plush_erp_theme_mode`、`plush_erp_appearance` | 退出时保留刚才显示的明暗模式和主题色；登录其他账号仍读取各自偏好，不导入登录页设置 |
| 本地及独立工作台 | 站点浏览器 `plush_workbench_appearance` | 所有 `/__dev/**` 共用，同源标签页同步；首次或存储损坏用同一默认值，ERP 登录、退出、切换账号不影响它 |

工作台保存失败时保留当前显示并提供重试，不回退为账号保存。业务会话存储另见[应用安全合同](../security/应用安全与验证边界.md#业务会话与请求保护--business-session-and-request-protection)。

### 色板与实现真源

色板在 `src/common/theme/erpAppearance.mjs`，允许标识和默认值复用服务端 `admin_erp_appearance.json`。提供蓝色、橄榄绿、青绿、橙金、粉色、藕紫、橙色和灰紫；橄榄绿 / 橙金 / 灰紫沿用 `green / yellow / purple`，粉色为 `pink`，青绿 / 藕紫为 `teal / mauve`。

浅色使用深操作色配白字，暗色使用亮操作色配深字。标准与自定义按钮共用默认、hover、active 配色，主按钮和链接分别核对对比度；主题色用于交互，业务状态保留独立语义色。两端色块四列换行，手机保留完整名称和触区。

工作台的当前、默认、只读等强调标签使用 `erp-dev-accent-tag`，普通 Mermaid 图同步响应主题色和明暗模式；图例分类与成功、警告、失败保留各自语义色。显式指定 `themeMode` 的纸面与固定预览沿用固定配色。独立工作台登录页只读同站点的工作台外观偏好，CSP 仅允许内容哈希匹配的外观初始化脚本。

| 层 | 实现入口与要求 |
| --- | --- |
| 状态 | `erpTheme.jsx` 管理偏好加载与保存，`erpThemeContext.jsx` 提供纯上下文读取，`erpThemeMode.mjs` 维护模式规则 |
| Ant Design | 主应用、独立工作台与控件样例的 `ConfigProvider` 共用 `src/common/theme/erpAntdTheme.mjs`，统一明暗算法、色板、按钮与表格密度；手机尺寸和工作台字号由入口参数选择，偏好仍由各自 provider 保存 |
| 自定义界面 | `data-erp-theme`、`src/erp/styles/app.css` 及分区 ERP 变量 |
| Mermaid 全屏 | 浏览器顶层画布、工具栏和按钮沿用主题；退出恢复缩放模式、比例和焦点 |
| 新增状态组件 | loading、empty、alert、message、notification、tooltip、popover、tag、badge、progress、pagination、drawer、table placeholder 同步检查暗色，优先全局 token 与 Style L1 |
| 打印与 PDF | 纸面预览固定浅色，不跟随屏幕主题 |

输入框、数字输入、日期与选择器的基础背景和占位文字由共享 Ant Design 主题维护，页面只维护场景布局。控件样例的局部主题通过 `erpThemePalette.mjs` 将同一色板映射为作用域内的 CSS 变量，下拉浮层挂载到样例根节点；切换样例不写工作台外观偏好。回归覆盖内外明暗组合、往返恢复、输入值及浮层，开发入口和独立工作台构建制品均验证。

原生数据表声明 `data-table-lines="appearance"`，共用 `native-table-lines.css` 的简洁 / 网格偏好；网格不改列宽、行高和合并单元格，转卡片时由所属容器关闭列线。打印、法律正文、教学图解和固定线框 BOM 用 `data-table-lines="fixed"`；普通列表继续用 `AppTable`。声明由 ESLint 检查。

## 账号偏好 / Account preferences

`admin_users.erp_preferences` 是个人偏好真源：`appearance` 保存外观，`column_orders` 保存模块列排列，`hidden_columns` 保存列显隐。普通登录账号只能改自己，接口不接收其他账号 ID。

设备设置留在设备；编号、审批、权限和公司打印模板仍属业务配置。新增账号偏好组时补齐允许值、默认值、缺值读取、局部更新、API 投影及测试。

| 情况 | 保存与恢复规则 |
| --- | --- |
| 局部更新 | 服务端在同一账号行锁下读最新 JSON，只改指定组或字段，保留其他组 |
| 连续操作 | 选项即时生效，按顺序保存；不自动重试失败写入 |
| 响应迟到或切换账号 | 浏览器按账号缓存；旧资料 / 保存响应不能覆盖新偏好或另一个账号 |
| 保存失败 | 提示“外观设置未保存到账号，请重试”，提供手动重试 |
| 手机保存 | 只更新主题色与明暗模式，保留桌面表格密度 |

`appearance.formDisplay` 保存长编辑页的显示方式：`all`（目录，首次默认）或 `section`（页签）。统一通过账号菜单“外观与密度”的“编辑页显示”调整，立即生效并自动保存；编辑页标题栏不重复提供切换入口，短表单忽略该选项。选中分区、阅读位置和全屏属于当前编辑现场，不写入账号偏好。

服务器结果为准；浏览器缓存不承担授权或业务配置。

## 共享控件样式边界 / Shared control style boundary

桌面业务页以紧凑布局为基础，尺度由 `src/erp/styles/app/design-tokens.css` 维护：页面外围 8px、区块间隔 6px、面板上下 6px与左右 12px、表单正文上下 10px、字段间距 10px × 12px。模块页头与内容之间只由壳层提供一次 gap；共享页头、工具栏、表单和可视化工作区消费同一变量，不依赖表格密度开关才变紧凑。

页内纵向间距由 `BusinessPageLayout` 与 `BusinessToolbarWorkspace` 的 Flex gap 统一提供，切换容器继承所属 gap；表格、内容视图和页头不再按 DOM 直系关系补外部 margin。直接表格、嵌套业务页与可视化内容均保持一份 `--erp-page-gap`，浏览器回归核对委外及仓库各分类切换、往返和不同视口下工具栏到内容的实际距离，防止漏距或双倍留白。

共享业务主表和工作中心任务表四边贴合卡片内侧，单元格、分页与可选表格标题区分别保留自身内边距。表格“标准 / 紧凑”继续只控制数据行；手机触控、打印和阅读正文分别遵守已有合同。

共享表格在适用吸顶的桌面视口首次挂载时即保留吸顶表头结构，后续测量只校准偏移；横向滚动入口和吸顶偏移按帧合并测量，读取列表时立即保留原有高度。尺寸读取集中在样式写入之前，相同结果不重复写入；可见性与尺寸校准不重复渲染未变化的记录，数据、列、选择和办理状态变化仍更新表格。页签指示只响应选中项和实际尺寸变化；选择框在候选层打开时才测量宽度。操作栏复用未变化的尺寸测量副本，副本保持隐藏、不可交互并退出滚动区域探测；实际动作及其权限、确认和弹窗状态继续由原组件维护。

生产记录、采购列表／跟进及库存分类通过 `BusinessViewPanels` 复用已访问的页内视图，范围限调用方声明的有限分类，离开页面后释放。未访问内容不提前挂载；隐藏内容及其浮层不可交互，尺寸与横向控件暂停更新，返回时应用最新数据和权限。库存响应按分类分别保存当前页，不能把上一分类的记录用于新分类；刷新、取消过期请求与业务写入仍走原有主路径。该复用只保留界面状态，不替代后端事实与权限校验。

普通模块页签、采购列表／跟进及库存分类使用共享 `useResponsiveSwitch`：未保存／保存保护先于选中反馈，确认通过后立即显示目标页签，再让浏览器绘制该帧后以 transition 提交内容更新。新选择取消尚未提交的旧目标；外部路由变化或卸载取消排队工作，较晚完成的确认不能覆盖新选择。等待区域由 `BusinessSwitchContent` 保持原节点并隔离旧操作与浮层，页签条仍可继续选择。加载与失败恢复使用原有路由或页面读取反馈，不增加业务数据缓存；分栏继续使用各栏原有导航与保护。

业务搜索的短占位提示只列主要搜索对象，完整范围由 `businessSearchScopes.mjs` 的 `searchHint` 提供并在输入聚焦时展示。按实际可用输入宽度验证提示可读，不通过页面加宽或缩小字号容纳全部字段；搜索范围及提交、清空行为保持原合同。

页签沿用 `SlidingTabs`、`SlidingSegmented` 或 `SlidingTabList`，切换期间保留同一个页签条，只替换内容。`SlidingTabList` 的 `appearance="chips"` 用于与工作台分类一致的圆角导航，复用筛选按钮的外观基线与共享滑动指示，保留页签语义、方向键和 Home / End；窄区域单行横向滚动，选择或收缩时将当前项完整滚入导航可视区，不改变页面纵向滚动。已将选择写入 URL 的页面从当前路由解析已提交选中项；响应式切换只临时投影已通过离开保护的点击目标，提交或外部位置变化后重新使用路由。本地偏好仅在缺少有效路由选择时提供默认选择，避免选中项与旧 URL 相互覆盖。库存台账的 `view` 与项目文档的 `path` 均按此恢复刷新、深链和浏览器前进后退。逐帧回归同时检查选中状态不回跳、指示条不反向、页签条持续挂载及位置和尺寸稳定。共享页签与分段按钮的选中、未选文字均为 500 字重，通过主题色、下划线或滑块区分当前项，避免中英文文字宽度随选中状态改变。筛选数量与清除操作保持稳定占位，读取提示置于结果区域，不能挤动导航和搜索控件。

文字按钮的水平内边距由 `src/common/theme/erpAntdTheme.mjs` 的 Ant Design `Button` token 统一提供：普通和小号按钮均为 12px，大号按钮为 16px。主应用、独立工作台的工具栏、当前操作区、弹窗和浮层沿用这套基线；同一规格的主按钮、次按钮、禁用和 loading 状态不另设 padding。普通业务动作与状态动作统一按内容定宽，长文案自然伸展。

可点击动作使用手型光标；禁用按钮、页签、筛选与选择项使用 `not-allowed`，文字、图标和边缘保持一致，恢复可用后恢复手型。禁用原因在需要时就地说明；加载中的控件沿用忙碌状态，普通文字与只读内容保留阅读光标。语义基线由 `control-affordance.css` 维护，AntD 控件沿用库的禁用状态；页面不得用不区分状态的按钮或输入内部 `cursor: pointer` 覆盖。浏览器回归同时核对实际命中元素、禁止触发和恢复操作。

嵌入列表的当前操作区在桌面统一使用 32px 按钮高度；空间不足时收纳辅助动作，窄屏保留内边距和至少 44px 触控高度。纯图标、行内文字链接和手机整行按钮按各自用途保留紧凑外形或触控布局，不用固定宽度修补普通按钮的留白。

选择器、搜索、表单字段与整行动作的宽度分工见[控件宽度与拉伸](../product/ui-design/交互设计说明.md#control-width)。宽度由所属布局负责：短选择器使用有上限的列，普通按钮在 Grid／Flex 中按内容排列；先修正父级拉伸与空白列，再核对控件自身，不在全局控件层统一限宽。业务链路的状态对象、事实定义与流程定义共用 `.erp-dev-flow-definition-selector`；其 controls 容器承接可用宽度，选择器使用有上下限的列，避免空值时按内容收缩。三个定义菜单通过 `popupMatchSelectWidth={false}` 与所属 popup 样式独立约束宽度，选项显示可读名称，技术标识保留用于检索；调整时同时核对三个入口及复用该布局的财务口径。

分组下拉的分类标题、选项缩进与行节奏统一维护在 `control-foundation.css`；页面只声明分组数据、内容排版和浮层宽度。分类语义、视觉合同、演示和当前使用入口集中在[分组选项](../product/ui-design/交互设计说明.md#grouped-select-options)，不在页面追加 `.ant-select-item-group` 的外观覆盖。`AppSelect` 为分组单选与多选提供选中勾选，保留显式传入的 `menuItemSelectedIcon`。

材料档案选择器通过 `presentation="reference"` 以 560px 为资料候选基准宽度，并随触发控件和视口调整；候选尚未加载或搜索为空时沿用同一宽度计算。`RemoteReferenceSelect` 的候选区域按 `listHeight`（默认 256px）保留高度，加载、少量候选及空结果不改变弹层方向；自定义底部动作通过原有 `popupRender` 组合保留。靠近视口底部的回归须同时测量慢响应前后、再次打开及搜索清空时的控件、弹层和滚动位置。

业务筛选浮层由 `.erp-business-operation-panel__filters` 分配字段宽度，日期范围、直接点选组和多选明确保留整行；办理人选择在 `workflowTaskDiscovery.css` 内约束自身，旁边的上下文与说明仍可使用整行。压力报告的两处选择器共用 `.erp-dev-pressure-report-select`；质量证据的“流程与原理”按钮由 `.erp-dev-quality-server-evidence` 自身约束 Grid 对齐，不能只在某个引用页面补样式。相关 `style:l1` 场景验证 1024、1920、3840px 视口的真实几何尺寸及打开、选择、清空或恢复行为；表单字段列、BOM 添加行、窄屏触区与目录导航分别按原有语义验收。

样式按职责隔离；拆成多个 CSS 文件不会自动形成隔离。`src/erp/styles/app.css` 统一加载基础样式与共享控件层，模块 CSS 必须以自身根节点或浮层类名限定作用域。全局基线文件由 `scripts/stylelint/styleBoundaries.mjs` 的允许清单维护，不能把业务文件加入允许清单来绕过检查。

Modal、Drawer、Message、Notification、Tooltip 和 Popover 的通用配色由 `common/theme/erpAntdTheme.mjs` 的组件 tokens 维护，业务弹窗 CSS 负责自身布局。局部主题使用 `ERPThemeScope` 同步 Ant Design 配置与 CSS 变量，并为无触发节点的浮层维护独立的 `body` 子容器；容器随主题更新、随作用域卸载清理，位于应用根之外以保留弹窗背景隔离与焦点恢复。触发型下拉、提示和筛选气泡仍在所属内容作用域内定位，箭头与内容共用主题底色；切换样例不写入全局外观偏好。

| 层级 | 负责什么 | 隔离与变更边界 |
| --- | --- | --- |

| 弹窗与浮层 | 所属页面的弹窗内容与弹出选项排版 | Portal 可能挂到 `body`；用显式 root/popup 类名隔离，不用裸 `.ant-modal`、`.ant-select-dropdown` 修改全站 |

| 打印 | 命名纸张、打印根节点和模板内容 | 使用命名 `@page` 与所属打印根；屏幕预览工具仍遵守运行态控件规则 |

维护规则：

- 改 caret、placeholder 垂直居中、input 高度时，优先改 `business-control-rhythm.css`，并确认真实 `input.ant-input`、Select placeholder/search input 和 wrapper 作为一个控件合同一起生效；带字数/清空的 textarea 外壳、日期与数字内层也属于该合同。
- 业务引用选中后以名称为主，完整识别信息保留在选项标签。`AppSelect` 根据选项的结构化 `identity` 自动处理单选与多选；表单长名称完整换行，`FilterSelect` 保持紧凑单行。选项生成器直接读取真实名称、编码与其他字段，不拆分拼接标签；单据号、批次号、版本号及来源行号保留其业务身份语义。普通枚举与自定义动作标签沿用原合同。选择、清空、禁用与 Form 值仍归原组件；不新增编码辅助行、额外请求或业务事实。尺寸归 `business-control-rhythm.css`，名称排版归 `app-select.css`；更换或清空后同步更新关联字段，不在页面叠加样式覆盖。
- AntD 输入控件的圆角只由 `control-foundation.css` 绘制；组合控件内侧接缝通过局部 `--erp-control-radius: 0` 表达，外层保持统一圆角。页面负责布局与尺寸规格，不重新声明同一控件的圆角。
- focus ring 只由 `control-focus.css` 绘制，颜色由 `--erp-control-focus-border / --erp-control-focus-ring` 提供；主题切换调整变量。使用 inset ring，避免被圆角容器或滚动区域裁掉。Select outlined 变体按 AntD 的 disabled / customize / pagination 条件覆盖，不通过重复类名提权。
- 不在业务页面 CSS 里重复写单字段 caret、line-height 或 focus ring 补丁；确有新控件类型时先补 `style:l1` 浏览器断言，再扩展共享层。
- 新增规则不能使用 `!important`，除非正在对抗不可控的第三方内联样式，并且必须在交付说明中写明原因。

Tailwind Forms 只生成显式 `form-*` 类，供原生表单控件按需使用，不对 AntD 内层 input 做全局重置。表头共享规则归 `src/common/components/table/app-table.css` 的 `.app-table` 作用域；业务页面 CSS 不定义全站 AntD 表头。模块打印使用命名 `@page`，对 body 的隔离仅在该模块打印根节点存在时生效。

`pnpm css` 通过 `scripts/stylelint/styleBoundaries.mjs` 检查模块作用域、重复类名、控件尺寸/圆角/焦点/单选文本归属、单选换行冲突与打印页作用域；属性归属检查同样作用于全局允许文件。`!important` 例外只在必要声明附近附理由，现有 SVG 内联尺寸覆盖和 reduced-motion 无障碍覆盖保持局部范围。规则测试使用 CSS 输入验证允许与拒绝行为，涵盖 `:is` / `:where` / `:not` 和混合选择器，不以放宽允许清单或绑定源码文本代替约束。

同一命令通过 `scripts/stylelint/styleDeclarationOwnership.mjs` 扫描全部源码 CSS：同一条件、选择器和属性不能跨文件重复声明，即使值相同也应合并到唯一维护位置。检查器按锁定版本的 `mdn-data` 展开简写属性，拦截 `margin / margin-top`、`font / font-weight` 等重叠写入，包括简写对省略值的重置。不同主题、断点及状态的明确变体保留；同文件的浏览器值回退仍由 Stylelint 检查。清理历史覆盖前核对实际加载路径与生效值，删除失效声明，保留当前合同；不能为通过检查移动加载顺序或扩大例外。此检查不推断逻辑方向与物理方向属性的等价关系，也不能代替 computed style、不同选择器竞争或运行时浮层验证。

浏览器回归复用 `scripts/style-l1/inputControlAssertions.mjs` 的内外层合同、`singleSelectAssertions.mjs` 的选中值边界及 `styleIsolationAssertions.mjs` 的外观采集；访问其他模块后比较同一控件的默认、hover、focus 与选中内容样式，保留已加载 CSS，不用刷新页面消除污染。覆盖长值、窄列、导入/禁用、清空重选及必要的主题、手机和 portal。模块业务验证不依赖 DEV 页面；共享样式隔离专项可访问控件样板以验证按需加载样式不会污染业务页。业务场景复用共享断言，不重复实现颜色、圆角和几何判断。

## 表格对齐 / Table alignment

业务列表、弹窗明细和研发工作台的 Ant Design 表格统一使用 `src/common/components/table/AppTable.jsx`。表头和单元格默认上下居中；表头文字水平居中，排序、筛选和列设置控件保留操作空间。

单选和多选的行选择列由 `AppTable` 统一为 52 CSS px，表头与正文同宽。普通业务主表复用 `AppTable` 的 `widthMode="columns"` 与固定布局，按列定义的宽度预算显示；宽屏保留自然表宽，窄区域只在数据区横向滚动。列宽预算在加载、有数据、空结果和恢复后保持一致，文字在列内自然换行；主表的滚动宽度由当前可见列计算。页面沿用共享选择列宽度。

出货默认保留产品、单号、状态、财务审批、客户、日期、来源、净重、收货信息和备注；物流、包装和实际运费可从列设置、详情及完整导出读取。库存余额默认保留八项数量、产品规格、仓库、批次及单位，登记提示和存货类型按需显示；库存变动将来源类型与业务单号合并展示，原始来源明细、冲正关联和记录提示仍保留在详情、列设置及导出。已保存的个人列选择继续优先。

独立表头与表体共用列宽和横向滚动范围。`TableScrollControls` 在现有尺寸观测中读取表体实际滚动条占位，减去 Ant 已预留的滚动条列，仅将差额应用于表头视口；WebKit 的原生滚动条不会因此拉伸表头或使最右端偏移。弹窗样式不另行设置表体的 `scrollbar-gutter`。

序号、编号、单位、日期、状态、短分类和操作列默认水平居中；品名、厂商、地址、备注和复合说明列通过 `align: 'left'` 保持扫读；数量、重量、单价和金额列通过 `align: 'right'` 方便核算。列定义明确语义，不按运行时文字长度或字段名称猜测对齐方式。

联系人、收货信息、物流信息、库存预留的产品与规格及仓库与批次使用 `business-list/BusinessCellStack` 紧凑上下排列：上行放姓名、收货人及电话、承运商及运输方式、产品身份或仓库，下行放电话、地址、运单号、规格或批次。收货信息共用 `DeliveryInfoCell`。两行左对齐，次行沿用主题次要文字色和正文大小；缺项不占空行，长内容自然换行。复制、排序和导出继续读取结构化字段组成的文本，不从界面拆行反推数据；金额、数量和独立短状态仍按各自列语义展示。

销售订单的订单编号、客户与跟单、订单与用料也使用 `BusinessCellStack`，允许传入原字段的展示节点与共享复制按钮；两个状态分别保留“订单”“用料”标签。原字段列定义是详情、导出、复制与排序的依据，先过滤字段显示策略，再生成列表复合列；订单总额保留币种、右对齐与数值排序，列表不再单列币种。合并列按主字段排序，同值时比较补充字段；保存列设置时以信息组为单位，读取已有设置时按原成员首次出现的位置合并，只在已保存成员全部隐藏时隐藏整组。个人隐藏不减少详情或导出字段。

表格导出的缺值保留为空单元格。`exportValue` 根据字段真源判断缺失；共享展示函数通过 `{ emptyText: '' }` 返回空文本，页面继续使用默认占位。日期按现有字段合同把未填写的时间戳导出为空；数量、金额不得通过页面格式化把缺值补为 `0`，原始数值导出保留有效值。组合字段省略缺失部分，保留已有内容。CSV 统一由 `csvExport.mjs` 序列化，保持列位置和公式防护。

任务来源资料复用 `BusinessRecordDetails` 的 `mobile-task` 展示，两端使用同一字段布局。列通过 `taskDetailRole` 指定单据身份（`identity`）、页头状态（`status`）或底部图片（`media`），其余字段按 `taskDetailOrder` 排列，未配置的字段保持原相对顺序并完整展示。出货资料依次并排显示来源与客户、净重与财务审批、明细行与备注，其他有值资料继续展示；复制和图片预览复用原组件。资料容器宽度达到 520px 时标签和值同行，窄区域使用两列上下标签；长文字和缺值原因可跨列并自然换行，短复制值与短缺值提示不独占整行。普通空值省略；来源列的 `taskDetailEmptyValue(record)` 在真实字段缺失时返回 `{ text, reason, tone }`，其他情况返回 `null`，不依赖格式化后的占位文字判断缺值。缺值使用普通 `span` 原位提示，字号继承字段值，统一中等字重；`tone: 'warning'` 消费 ERP 警示文字 token，其他情况使用次要文字色，不使用 Tag、底色、边框或圆角。原因放在 `mobile-task-facts__note`。回调须区分字段明确为空与响应中未返回，后者不能显示为待补填；字段权限过滤继续先于展示，数值 0、否和原有业务状态保持有效。出货净重按来源状态区分“待确认 / 未记录”，有值时保留实际 / 最终口径。该配置只服务任务资料，不改变桌面完整单据、导出、表单校验、业务状态样式或办理入口。

任务资料的字段集合可由 `BusinessDataTable.taskDetailColumns` 传入，与列表显隐分开。出货页复用列设置 hook 已经过字段策略筛选的 `visibleColumns`，个人隐藏及默认隐藏的列表列不减少任务资料。

| 字段情况 | 导出规则 |
| --- | --- |
| `null`、`undefined`、空字符串或仅空白字符 | 空单元格，不写入页面占位 `-`、`—` 或“未填写” |
| `0`、零天账期、负数及布尔值 | 保留有效值或对应业务文字 |
| “不需要发票”“未分规格”“无批次”等明确业务含义 | 保留业务文字；有部分数据但需核对的异常提示也保留 |
| 编号、名称、备注中的横杠或真实文本 | 按原值导出，不按字符全局替换；公式敏感文本仍经过安全转义 |

序号有逐行核对用途时独立成列，不拼入品名。可复制字段的按钮不挤偏居中文字；原生单据编辑表与 BOM 明细沿用相同表头、垂直对齐和数值输入规则。文档表格的正文保留长文本阅读方式，打印纸面按各模板正式版式单独维护。

## 工作入口与视口命名 / Work Entry And Viewport

界面与当前设计说明使用“电脑版／手机版”表示工作入口，使用“宽屏／窄屏布局”表示可用尺寸。入口决定功能、权限投影与导航，视口只影响布局。

### 入口与授权

桌面后台只有一个业务入口，不设置岗位首页或角色切换菜单；统一登录页和 `/entry` 负责选择电脑版或手机版。两端共用管理员登录态、后端菜单和 permission code；角色名称、页面可见和当前选中岗位都不能代替后端授权。

权限分类直接读取后端 `module_name`，未知或缺失分类合并为一个“未分类功能”。分类导航只定位，不改变权限勾选。正式业务菜单及生产模块内部入口统一按菜单专题维护，本节不另列菜单树。

| 场景 | 页面行为 |
| --- | --- |
| 登录与退出 | 固定提供密码登录；仅后端启用短信能力时显示短信登录。登录失效、手机号未绑定或当前岗位未授权时进入 `/admin-login`，成功后返回允许的任务页 |
| 手机导航 | 使用 `/m/<role>/tasks` 及 `/m/<role>/handle/...`，不按岗位拆端口或仓库。任务、进度、办理、帮助及返回保留当前手机岗位与界面；完整单据与来源跳转在电脑端查看 |
| 手机办理与返回 | 已支持的任务办理入口使用 `useBusinessNavigate` / `BusinessLink`，字符串及对象路径保留 query、hash 与返回上下文。具体可用入口见岗位任务页专题；权限不足或适配缺失在手机内说明，不自动切电脑版 |
| 公开规则 | `/legal/privacy`、`/legal/system-rules` 在登录页可读；电脑账号菜单、手机“我的 / 入口与安全”保留同一入口。短信模式说明手机号的验证用途 |
| 规则知悉 | `LegalNoticeGate` 按账号、客户 `legalNotice` 版本和规范化内容指纹读取追加式知悉审计；内容变化重新提示。它不是概括授权同意；核对失败可重试，不阻断整个 ERP |

知悉回执不保存手机号、密码、token 或业务原文。业务会话与认证保护见[应用安全合同](../security/应用安全与验证边界.md)。

### 列表、搜索与来源跳转

正式业务列表单击行选中，双击进入整页编辑或当前主操作；只读详情由显式入口打开。销售订单、采购订单和加工合同的明细按录入、保存顺序展示，不提供手动排序；`display_order` 表示位置，`line_no` 保持稳定身份，不改既有事实。

“相关单据”每一跳都用目标页的数值 ID 或来源类型加来源 ID 建立精确筛选。业务单号只作回显；唯一目标可自动选中，多条取消历史不能臆选。用户修改或清空筛选后退出关联上下文。

所有独立搜索框（业务列表、开发工具、目录、控件和本地内容）通过共享 `SearchInput` 的 `value` / `onSearch(value)` 合同提交，`useSubmittedSearch` 只管理草稿、中文输入、规范化去重与外部恢复。页面的 `onSearch` 更新查询状态和页码，由原查询生命周期发起一次读取，不叠加 Enter 直接读取；`resetKey` 标识页签或业务范围。`MobileSearchInput` 在 `.erp-mobile-search-row` 内展开，提交即收起并 blur，结果到达不驱动动画。取消不查询，清除只提交空关键词；选择器内部的本地候选过滤仍即时进行。基础选项加载与列表查询各自依赖所属范围，复用现有请求取消和错误反馈。

提示文案按[输入提示与帮助](../product/ui-design/交互设计说明.md#input-hints)分工。`SearchInput` 接收短 `placeholder` 与真实完整范围 `searchHint`，提供独立范围时默认在聚焦后展示；与 placeholder 完全相同的说明不重复展示，显式 `showSearchScope={false}` 可关闭浮层。仅透传调用方明确提供的 `title`，不把范围重复放入原生悬停提示。来源选择弹窗继续透传同一份范围，不另建说明。普通字段使用已有标签、必要的常显说明及 `BusinessHelpLabel`，不由组件自动截字或猜测业务规则。补充说明的图标、气泡、焦点及关闭行为统一由 `SupplementalHelp` 维护；同一时刻只展开一处，窄屏和分栏按可见范围限制浮层并允许内部滚动。页面帮助、警告、记录详情、图表数值和图节点检视保留各自用途，不把所有浮层都改成说明入口。

`MobileSearchInput` 在所属搜索行和承载搜索框的直接子项上维护展开状态，CSS 只按该状态隐藏同排其他操作。搜索框可直接放在搜索行内，也可由搜索表单承载；提交、取消、范围切换及卸载时同步恢复同排操作，避免输入长单据时触发全页后代的关系选择器重算。

独立搜索框统一显示左侧搜索图标、右侧“搜索”按钮；输入、删除字符和中文候选确认只更新组件草稿，点击按钮或 Enter 才应用关键词。下拉选择器内部的候选搜索保留即时筛选。确认候选的 Enter / Escape 不提交、清空搜索或冒泡触发外层快捷键，完成组词后恢复正常键盘行为；URL、前进后退和范围重置仍由调用方提供的值恢复。页面不再重复维护草稿、composition 状态或外围提交按钮；`onSubmitted(value)` 处理收起搜索、空值校验或尚未执行的预填业务定位，不与 `onSearch` 重复发起查询。共享组件回归须覆盖真实浏览器组词、连续选字、按钮与 Enter 等价提交、清除及恢复，直接填入中文字符串不能替代输入法验证。

业务搜索筛选完整单据或任务，不裁掉未命中的明细，也不改变审批范围、数量或金额。多款产品优先展示命中款的名称、编号和同款图片，标明“命中 N 款，共 M 款”；款数按产品去重，物料种数独立计算。只命中单号、客户或说明时保留默认代表项；清空关键词恢复默认顺序。

| 搜索对象 | 展示真源 |
| --- | --- |
| 任务、已办、日历与流程跟踪 | `WorkflowTaskIdentity` 按已提交关键词从服务端展示投影选择命中项；名称和编号来自单据快照，图片归同一正式产品 |
| 订单交付与生产进度 | 后端同一读快照返回完整单据、当前页命中款、总款数和代表产品；无产品命中时不返回命中计数 |
| 业务单据列表 | 从真实来源或明细检索，不以任意首款冒充命中项；单明细汇总与库存记录保留自身身份 |
| 主数据、选款与来源导入 | 单实体显示自身名称、编号和图片；本地筛选使用可见列或声明字段，来源选择保留正式单据或明细粒度 |

### 复制与身份展示

| 位置 | 复制规则 |
| --- | --- |
| 正式业务主表 | 仅白名单内的业务编号、名称、联系人、批次和可转交短引用提供复制；电脑悬停或聚焦显示，触屏常显 |
| 任务与进度条目 | 单据编号、产品编号、款号使用常显行内图标；详情可复制产品 / 物料信息及任务信息 |
| 空值与非复制字段 | 日期、金额、数量、状态、备注、内部 ID 不加快捷按钮；弹窗及明细子表沿用文字选择 |

复制只取当前值，不触发行选择、双击打开或改变筛选。鼠标移出后隐藏悬停按钮，键盘操作保留焦点；手机触区至少 44px。共享剪贴板 helper 提供成功提示与失败后的手动复制。投影已明确缺失或不可用时，不复制旧快照或内部引用。

任务名称保持主标题。`WorkflowTaskIdentity` 列表显示首项和总项数，详情可展开其余产品 / 物料；任务复制信息包括产品、单据、状态原因、已知责任及完整日期时间。

身份优先读取服务端 `display_context`：名称与编号取正式来源快照，材料款号取 `supplier_item_no`。系统物料编号和内部 `style_no` 只在详情与完整复制中按各自名称保留，缺值不互相代填。无正式来源的任务可用自身已有展示快照；明确空投影或来源失效不得回填旧 payload。

### 任务读取、处理与恢复

任务数量来自后端分页前统计，不取本地数组长度、不扇出全部岗位请求，也不循环拉取任务拼总数。手机首次无游标读取的公式与槽位规则见[岗位任务数量读投影](../product/业务主链路数据流向与字段来源规则.md#47-岗位任务数量读投影--role-task-count-projection)；可信总数未读到时显示“—”，不显示 `0`。

桌面任务抽屉与手机详情将流程进度和“处理记录”分开读取。记录默认通过 `list_task_events(scope=flow)` 汇总当前任务正式关联范围内的可见任务事件，可切换“含关联任务 / 只看本任务”；后一范围沿用 `scope=task`。每条记录标明本任务或来源任务、姓名与岗位、时间、状态变化及意见，最近在前，并支持加载更早记录。关联范围复用任务办理链，不因同属一张订单而扩大；没有跨岗关联时只显示本任务。两档记录独立加载与重试，任务、版本或有效权限变化时清理旧结果；流程进度读取失败不隐藏记录。它们均不等同于完整审批链或业务事实。

进度区保留真实流程名称，通用标题使用“相关任务进度”，整单入口使用“查看整单进度”。进度和记录标题旁的 ⓘ 复用 `BusinessHelpLabel`，由 `WorkflowTaskScopeHelp` 提供范围图解：前者看有哪些任务、办到哪里，后者查谁在什么时候做过什么。电脑可悬停、点击或键盘聚焦查看，手机可点按；关闭说明回到 ⓘ，Escape 不关闭任务详情。图解随当前范围高亮，范围切换不改变查询合同、权限或业务状态。

一次办理按以下顺序执行：

1. 新 intent 先读取 `explainWorkflowActionAccess` / `explainWorkflowTaskAssignment`，核对服务端原因。
2. 在任何 `await` 前取得同一 task 的同步 in-flight lease，阻止完成、阻塞、退回、恢复和催办跨动作双发。
3. 冻结业务参数、`expected_version` 与安全 UUID `idempotency_key`。HTTPS 优先 `crypto.randomUUID()`；内网 HTTP 用 `crypto.getRandomValues()` 生成 RFC 4122 v4，禁用 `Math.random()`。
4. HTTP 408、网络中断、5xx 或成功响应结构不合法时，保留 attempt、抽屉、原因、证据和原 key，按原意图读取 / 重放 receipt；不刷新列表，也不把未知结果报成失败。
5. 收到可信结果后刷新服务端投影、恢复列表上下文；`finally` 只释放本次持有的 lease。

同意图重试不重复 explain，但后端每次仍校验登录、RBAC、客户范围、任务可见性和 receipt。Go / JS 共用 `scripts/qa/workflow-task-mutation-intent-v1.vectors.json` 核对混合证据、顺序、空白 key、精确重放与意图变化；历史通过数量不作为当前验证结论。

转交仅在桌面任务详情办理：候选来自 `get_task_assignment_options`，`reassign_task` 提交接收人或岗位池、version、幂等键及必填原因。前端不从管理员列表拼候选。默认老板和 super admin 可转交，PMC 只读监督；能转交不等于具备接收岗位身份。成功只改个人归属并关闭、刷新抽屉，不改任务状态或 Fact。手机当前不提供桌面转交动作。

### 工作台与任务看板

工作台任务队列使用全宽表格，单击行或在任务标题按 Enter / Space 打开共享抽屉；拖选文字不打开。保留待我处理、审批、阻塞逾期筛选，直接显示问题原因；不重复放“查看任务”列或常驻选中任务侧栏。

| 看板规则 | 合同 |
| --- | --- |
| 范围与分类 | `/erp/task-board` 读取 `get_task_board`；常规待办、阻塞、到期提醒、已结束四类互斥，其和等于当前筛选总数 |
| 概览布局 | 内容宽度至少 1200px 时四列，至少 600px 时两列，其余单列；每栏预览最多两项，进入分类后用完整列表 |
| 加载与关闭 | 首次整卡加载，分类或翻页只更新任务区并保留同范围数量；关闭抽屉恢复筛选、滚动及原任务焦点 |
| URL 恢复 | 保存关键词、状态、角色、到期、来源、泳道、页码和每页条数；刷新、返回与复制链接恢复 |
| 筛选收起 | 搜索、负责岗位常显，其余按需展开；已应用条件仍以可移除标签可见。切换分类清理不适用状态 / 日期，URL 与请求共用规范化规则 |
| 清空筛选 | 保留分类、审批范围、排序和每页条数，仅页码回到第一页 |
| 待办角标 | 与“待我处理”共用 `get_task_board(todo_only=true)`，只统计当前责任池 / 本人指派的 `ready / blocked` 并去重；不追加主管监督或本人创建范围，与 `approval_only` 互斥 |

角标不受清单搜索和分页影响，办理回执确认后重读；浏览不清零，失败不冒充零。“全部任务”保留历史可见范围；待办视图隐藏已结束分类。

工作台队列、任务管理分类列表、进度看板和流转记录共用分页配置：默认每页 20 条，可选 20 / 50 / 100 条，显示当前范围与服务端总数；任务概览仍只预览每类 2 条，日历保留每批 30 条。分页外观与窄屏精简页码复用 `AppPagination`，保留每页条数选择。修改条数回第一页，翻页成功定位首项，读取中禁用分页，失败可重读。手机岗位端沿用分批续取。

### 进度看板

`/erp/business-dashboard` 用逐单进度显示订单交付与生产执行；资料、领料、工序、质检、数量和处理人同屏。两种列表均单击整行打开完整进度详情，产品名称保留 Enter / Space 键盘入口；复用 `openWorkflowTaskRow`，拖选文字、图片预览和行内按钮不误触行打开。取消独立“查看”列，关联任务入口放在“当前关注 / 处理人”内，仍按现有可见性与权限直达任务或查看关联任务列表；多单位数量继续按明细核对。详情按来源权限打开原单，关闭保留筛选、分页、列表位置并恢复入口焦点。未关联订单的协同任务从“全部任务”进入任务看板。

两端复用 `business.list_progress/get_progress`。全范围数量在后端分页前汇总，风险可以重叠；只按实际出货和扣除返工后的有效完工计算，不把关闭当完工，不把领料进度当齐套。不同单位分开、缺少关联显示待核对，原单查看另验权限。

完整进度由 `BusinessProgressDrawer`、`BusinessProgressHeader` 与 `BusinessProgressSummary` 共用身份、当前关注和阶段口径。桌面固定六类导航（总览、产品、生产单、工序批次、领料、任务），手机固定四类（总览、产品、生产、任务）；手机生产类只展开一个明细组，空记录与无权限分开表达。标题、当前关注、分类与底栏不随内容滚动；内容独立滚动，右侧另留空间防止覆盖式滚动条挡住文字和按钮。每个分类保存阅读位置，手机关联任务返回恢复分类与阅读位置；手机生产进度和任务沿用岗位导航。

进度图提示复用 `ProgressMetricHint` 与正式展示 helper，hover / focus / 点按可查看数值、单位、比例与口径，明细入口独立。通用标准见[图形关键信息](可视化表达规范.md#chart-inspection)。

手机入口、权限组合、查询恢复、任务直达和卡片布局统一见[手机进度](../product/移动端岗位任务页改版.md#手机进度--mobile-progress)。账号、权限或客户配置变化后不复用旧数据，读取失败清除旧结果并提供重试。

### 产品图与业务媒体

委外订单的“选择合同附图”只收 PNG / JPEG / WEBP / GIF，标记 `print_appendix`。打开加工合同打印时冻结未撤销附图；普通附件不自动上纸，窗口内调序、移除或新增不回写业务附件，详见[打印图片来源](../打印模板实现原理.md)。

产品图片与普通证据附件分别维护，格式、预算、持久化和撤销规则见[产品图片媒体例外](../architecture/业务附件证据边界评审.md#产品图片媒体例外)及[编辑与弹窗](#桌面业务编辑与弹窗约定)。

| 展示位置 | 实现与读取 |
| --- | --- |
| 任务身份 | 两端列表用 64px 图片位，延迟读取 160px 缩略图并按账号权限去重；详情保留各自尺寸 |
| 产品及业务明细 | `ProductIdentity` 桌面普通列表共用 64px 主图，紧凑选款与表单保留 48px；名称和编号分层展示，选中后提供放大；可见区域每批最多读取 80 款主图引用 |
| 无图或不可读 | 无正式关联、无 `product.read`、物料项或主图缺失保留同尺寸占位；不借用另一产品的图片，不把失败当无图 |
| 原图预览 | 打开时才读取，复用 Ant Design Image 的缩放、拖动、适应屏幕与 Esc；关闭释放原图，恢复列表位置和触发焦点 |

图片点击与任务打开、行选择、编辑相互独立；占位不打开预览。加载失败可重试；关闭、来源切换、主图清空或权限变化后丢弃迟到响应，不回填旧引用。正常黑色照片不按颜色过滤，单像素图片不可用。图片不增加导出列，也不替代款号或质检证据。

打印带值由业务页选中记录后打开；BOM 生成物料明细 / 作业指导书时冻结 0–2 张产品图，委外订单只有全部有效产品行属于同一产品才自动带图。打印中心保留样例与两栏预览，字段及草稿图片在独立打印窗口编辑；后续主档变化不改已打开草稿。

### 页头、反馈与事实边界

业务页标题区只留标题、按需帮助及必要状态 / 数量，规则放在所属操作、表单或帮助中。`PageHeaderCard` 不接收常驻介绍文案；数据范围、权限限制与失败反馈仍就近展示。

页面刷新只用于重新读取已登记的数据查询，每个查询范围保留一个入口；没有 `registerPageRefresh` 回调的帮助、模板目录和功能预览不提供整页重载。`BusinessFormPage` 隐藏常驻刷新，保留窄屏导航和全屏操作；保存后按原业务链路读回，加载失败原位重试。待办日历使用自己的刷新入口与请求反馈，桌面页头不再重复提供。

`PageHeaderCard.stats` 只接受非负安全整数；`0` 表示可信的零值。字符串、视图名、负数和不可用占位不能当指标；未读取和失败由所属页面使用“— / 暂不可用”说明。

桌面任务、手机办理与附件上传都不直接写库存、出货、应收、开票、付款等事实。采购 / 出货 / 生产的来源、审批、草稿退出与过账边界统一查阅[页面血缘](../product/页面来源生成入口规则.md)和[Workflow / Fact 合同](../architecture/状态工作流事实边界.md)。真实客户批量导入、打印留档回写、硬件链路、PDA、条码枪和图片识别尚未接入；本地源码与测试不证明目标已部署或客户已验收。

## 桌面分栏工作区 / Desktop Split Workspace

桌面页面操作区在“刷新”旁提供“分栏”；进入后保留原页面，在右栏选择当前账号可访问的页面。分栏不另设工作区标题和左右栏说明行，页面标题直接作为按菜单目录分组、可搜索的选页入口；刷新、分栏菜单与收起按钮放在现有页头。分栏时模块页签保留挂载，由标题下拉提供同一组页面导航；编辑时只显示编辑标题，返回列表后恢复列表标题，业务内部的视图切换继续保留。最多同时打开两栏，页面、编辑器、专项弹窗及保存入口复用原实现；手机岗位任务入口保持原有办理方式。

1. 点击一栏设为当前栏，再从菜单打开页面；也可将菜单拖入目标栏，或点击任一栏的页标题选页。分栏时，菜单项在悬停或键盘聚焦时显示右侧六点手柄，预留位置不挤动文字；拖入目标栏时以虚线轮廓提示，放下或取消后清除。选择器按现有菜单目录分组，只列当前账号可访问的页面，分类标题不参与选择，搜索保留匹配分组。
2. 左右页的搜索、筛选、分页和导航各自维护，可以打开同类页面。两页打开后可“左右互换”，页面与各自的操作一起移动，保留屏幕左侧宽度比例；页面实例、搜索、草稿及各自保存入口不变。主栏标题右侧的“分栏”菜单提供互换与屏幕“左栏宽度”，支持键盘输入；尚未输完的数字不立即钳制，离开输入框时按32%至68%的范围校正。输入框旁的“恢复默认”只还原屏幕左栏 50%、右栏 50% 的宽度比例，左右互换后也按屏幕位置还原；提示显示默认比例，已在默认宽度时置灰，执行后保留菜单并聚焦数字输入框。分隔线在两种排列下均使用原生预览线跟随拖动，预览位置按32%至68%的物理边界限制，放手后一次更新页面宽度，避免拖动期间反复重排长表；页内文字、表格和浮层仍沿用原方向。窄屏通过左右切换查看，标签随位置更新，保留另一栏，当前可见栏的标题旁始终可打开分栏菜单；隐藏栏的延迟聚焦不能切走当前栏。
3. 两栏分别保存。换页检查目标栏草稿，退出工作区或登出检查两栏；收起分栏只隐藏附加页，恢复后继续原页面。附加页标题下拉框内的清空按钮只清空本栏页面，先检查草稿与浮层离开守卫；取消时保留原页面和输入，确认后保持空栏并聚焦选页入口，也可在标题搜索为空时按 Delete 清空。栏右侧的叉号按钮直接收起分栏，空栏和窄窗口的当前可见栏同样可用；再次展开恢复原页面及草稿，左右互换后动作仍跟随附加页。主栏标题不提供清空动作。分栏中的通用主数据表单返回列表时保留一份未保存输入，可“继续编辑”或“放弃修改”；保留的表单仍参与换页、刷新和退出检查，不能因暂时隐藏而丢失保护。栏内弹窗与抽屉打开时，外侧叉号继续可点；收起只隐藏附加页及其浮层，再次展开恢复原实例和输入。浮层正文避开栏头的收起区域，其他背景操作继续隔离；退出工作区等全局确认仍覆盖收起按钮。
4. 一栏确认写入成功后，另一栏自动重读已登记的列表或查询；正在编辑的主表保留输入，关联候选按权限单独更新，结束编辑后补读列表。等待补读时，在所属页面的刷新按钮旁显示一行轻提示“相关资料有变动，返回列表后更新。”；编辑页仅在此状态显示刷新入口，手动刷新仍检查未保存内容。读取失败使用醒目提示和重试入口，只重试读取，不重放写入。
5. 属于页面的弹窗、抽屉、附件预览、下拉及确认框在本栏内打开，遮罩和背景滚动隔离只作用于本栏，另一栏仍可操作。内容过长时在浮层内滚动，标题与底部动作保持可达；关闭不抢走另一栏的输入焦点。左右互换、收起和恢复保留已打开浮层及内容，窄屏随所属栏切换。切页、刷新及登出同样检查浮层草稿和保存状态；全局离开确认覆盖整个工作区。
6. 分栏中从 BOM 物料名称旁“新建物料”发起补建，在另一栏复用材料档案的完整编辑页，提供“保存并使用”；保存成功后只选回发起的物料组，保留部位、用量、备注和单据输入。从材料档案独立新建只更新候选，不替换 BOM 当前选择。回填按原物料行身份和当前关联核对：来源被移除、改绑或离开后失效，写入完成后的回填失败只提示重新选择，不重复建档。未进入分栏或不具备材料主列表访问能力时，快捷建档沿用当前弹窗及原动作权限。

`BusinessSplitWorkspace` 保持原页面的 `Outlet` 挂载，附加页使用同一个 `desktopPageRoutes` 与原页面。导航适配器隔离 location、query、history 和页面上下文；菜单、有效会话、客户运行边界和后端权限继续决定可用范围。每页的读取与离开守卫分别登记，统一路由守卫协调两页，附加页渲染失败在本栏恢复。React Router 升级时须核对该适配器及双栏导航测试。

`common/components/overlay/OverlayScopeProvider` 为每栏维护稳定的 portal 容器，按栏位置与尺寸更新；`AppModal`、`AppDrawer` 及 `useModal()` 共用其隔离、焦点和离开守卫。页面关闭或账号范围变化时清理所属确认框。全局退出确认显式使用 `getContainer: () => document.body`，消息和通知保持应用级反馈；业务页面不自行创建第二套弹窗或抽屉表单。

分栏样式保留 Drawer 根节点原生的 `pointer-events: none`，蒙层和内容沿用组件的交互规则，关闭后的预挂载外壳不拦截页面点击。每个可见栏复用尺寸观察器和视口监听，调宽与互换只更新几何；栏内滚动不重新测量自身固定边界。 抽屉保持打开时仍可双向调宽，拖动预览线和拖动保护层位于栏内普通浮层之上；保护层接收拖动中的鼠标事件，避免选中抽屉文字，松手后移除保护层并恢复组件原层级，全局确认继续覆盖分隔条。

栏头使用独立上下文订阅导航与布局信息；可搜索的标题下拉沿用共享的键盘、可访问名称和焦点外框。仅调宽不触发附加页路由和业务内容的无关重新渲染；页面导航、权限及上下文变化仍正常更新。可见范围只按实际生成布局盒的祖先裁切，`display: contents` 不参与裁切；分栏切换后重新核对现有祖先的裁切规则，页面保留的滚动监听继续覆盖新形成的滚动容器。

分栏同时覆盖输入建议、日期与省市区选择、菜单、气泡说明和轻量确认。浮层按本栏可见范围对齐，较宽的日历和级联列在面板内部滚动，不能裁掉选项；`AppSelect` 与地址级联共用 `useOverlayPopupAlign`。标题、显示切换、地址字段和保存区按编辑区宽度换行，最窄栏也保留完整保存入口。

权限设置与帮助图表的全屏区域只展开到所属栏，滚动锁、背景隔离和 Escape 只作用于本栏；互换、隐藏及恢复继续使用原实例，另一栏草稿保持。普通整页表单的浏览器全屏入口在分栏时隐藏。订单原表图片与产品图片共用现有预览器，沿用订单附件读取及归属校验；打印工作区仍按正式入口打开独立窗口。

ERP 根表单统一使用 `business-list/BusinessForm.jsx`；`Form.Item`、字段路径和所属 form 实例沿用 Ant Design。附加页从首次挂载起使用独立 DOM 名称，收起或互换后保持；原页面的编号稳定，避免布局变化改变正在编辑字段的身份。标签、清空、校验定位和同类页面并排不能作用到另一栏。

`rpcChanges` 只在已登记写入的成功响应后通知方法与工作区标识，不传递表单内容或业务快照。短时间的多次写入合并重读；读取期间的新写入补读一次，切页、权限范围变化或卸载丢弃旧结果。两栏各自执行原有查询，没有跨设备推送、后台轮询或客户端业务事实派生。自动重读只适用于已有 `registerPageRefresh` 的范围；没有登记读取的帮助、模板目录和功能预览沿用原有恢复入口。

## 桌面业务编辑与弹窗约定

- 项目弹窗默认上下左右居中：`AppModal` 标准模式与 `BusinessModal` 由根 `ConfigProvider` 统一启用 `centered`，命令式 `modal.confirm/info/success/warning/error` 由 `AntdAppBridge` 的消费层统一补齐居中配置；`AppModal` 面板模式在同一 Ant Design 基础上补充专用面板外观、背景隔离与可访问名称。
菜单主列表的新建、编辑和已支持的只读查看复用 `BusinessFormPage`，在当前模块路由内切换正文并保留列表筛选、选择和滚动。正文独立滚动，底部固定“返回列表 / 保存”。

表单、待上传附件或产品图有改动时，返回、换菜单、浏览器后退和刷新都提示；保存中阻止离开。快捷新建、来源选择、预览、审批、核销、冲销和岗位分配继续用专项弹窗，详情抽屉只作显式只读核对。

适用对象包括主数据、BOM、销售 / 采购 / 生产订单、加工合同、出货单、质检补建、收付款 / 红冲、生产事实草稿及员工资料。来源生成的排产、审批和异常任务不提供通用任务创建；页面动作及其事实边界见[来源入口规则](../product/页面来源生成入口规则.md)。
- 整页业务表单的标题区和固定操作栏使用独立底色及清晰分隔线，正文保持独立内容底色，分组线弱于区域边界；底部操作栏带轻微上阴影。浅色采用灰绿底与白色正文，暗色复用主题表面色与边框色，统一由 `business-form-page.css` 管理。
- 任务内嵌入原编辑器时，分区目录继续复用 `BusinessFormBody`。桌面目录列的底色和分隔线覆盖完整正文高度，目录内容在列内吸顶；窄屏改为横向分区选择条并随任务吸顶。独立编辑页与任务页使用同一套目录主题和间距，滚动容器适配不改变业务字段、校验和保存入口。
- 整页内容基本可读、只剩阅读边距级溢出时，不把几像素滚动强行映射到全部分区；目录点击仍可定位。正常长表单继续随滚动依次定位，末屏短分区仍可到达。
- 分区的目录定位、字段焦点和阅读位置由 `BusinessFormBody` 统一提供，`BusinessFormSection` 消费同一当前分区；新建、编辑、只读和任务内嵌共用，字段及其浮层切换不卸载表单。分区、普通标题、明细标题和 BOM 标题的外观统一维护于 `business-list/businessFormSections.css`：单行最小高 32px，使用 3×14px 短竖线、主题文字、小圆角及淡主题色标题带，与中性表头和只读框区分；当前分区加深标题底色，并保留极浅正文底色和 1px 细边框。配色直接消费主题变量；目录继续沿用现有选中背景，输入焦点和明细行组仍使用各自共享规则。当前分区的整块底色与边框在同一表单内互斥，切换时原分区恢复普通标题浅底；只读明细也必须复用共享标题。整页表单由 `BusinessFormBody` 管理当前位置；局部弹窗通过 `BusinessFormSectionScope` 提供独立聚焦范围，避免与来源表单串联。已有分组必须使用 `BusinessFormSection` 包住真实字段；普通子标题仍归所属分区，不另增目录。查看窗的单据信息和完整明细、BOM 复制草稿及加载、空态、错误分支也保留共享标题。分区焦点不代表有改动，未保存及离开保护继续按整单真实差异判断。末屏短分区随滚动依次定位，向上滚动按相反顺序恢复；标题变色不向明细控件传播继承变量。
- 桌面整页表单统一提供可选“全屏编辑 / 退出全屏”，默认普通布局，切换保留原表单、输入、附件及阅读位置；短弹窗、手机业务入口与窄于 768px 的视口不提供。全屏的恢复和浮层键盘顺序见[整页表单与分区定位](../product/ui-design/交互设计说明.md#4-整页表单与分区定位)。
- 三个及以上分区的整页表单沿用账号外观设置中的“目录 / 页签”显示偏好。目录模式连续展示整单，桌面用左侧目录，窄屏用跳转选择条；页签模式使用持续挂载的 `SlidingTabList` 横向导航，只显示选中区域，窄屏横滑查看全部页签。导航固定在独立正文滚动区上方，任务共用滚动区时在任务及工作区导航下吸顶，明细工具栏与表头接在其下。两种模式保留原表单、各区阅读位置与整单校验保存，目录及页签展示各区错误数量；保存失败先显示第一个错误区域，再滚动聚焦。页签支持方向键及 Home / End，全屏切换保留显示方式与当前分区，短表单和局部弹窗保持原布局。
- 分区外部间距统一消费 `--erp-form-section-gap: 12px`，由表单栅格、整页正文和查看弹窗各自的布局维护文件负责，字段行距继续独立使用 `--erp-form-field-gap`。选中与未选中均预留相同的 1px 边框，仅切换边框与背景颜色；不随聚焦增减 margin、padding 或边框宽度，隐藏分区不占布局间距。
- 分区圆角由 `businessFormSections.css` 的 `--erp-form-section-radius` 统一维护；普通标题带与明细编辑器的贴边标题均使用外圆角减去 1px 边框的内圆角，避免子层不透明背景覆盖边角。正文保留可见溢出，让输入焦点与吸顶工具栏正常显示。圆角回归同时检查四角实际叠层、祖先裁切和标题内沿，覆盖新建空明细及已有明细。
普通表头字段可通过 `BusinessFormSection fieldLayout="adaptive"` 自然换行，`Form.Item` 的 `erp-business-action-form__field--short` / `__field--wide` 类 表达内容宽度；常规、短字段与长字段的布局预算及手机适配集中在 `business-list/businessFormSections.css`。整行说明继续使用现有 `__field--full`，不改变控件内部高度、字号与浮层。备注与附件使用 `fieldLayout="support"` 并将附件置于 `erp-business-form-section__attachments`；有来源版式约束的明细和已有适合的专用栅格不切换到该布局。字段仍使用原 Form 实例、校验及保存主路径。

### 明细录入

BOM 之外的可维护明细采用轻量表格，常用字段直接在主行录入，使用中性标题、固定水平分隔和清晰的控件焦点，不叠加行内卡片、交替色块和右侧操作列。原生字段编辑表使用 `data-table-lines="fixed"` 表达固定行线；主业务列表继续沿用账号网格偏好，BOM 编辑器保持原有结构与外观。

复制、移除及已有的行顺序动作集中在本编辑区顶部。点击明细或通过键盘聚焦其中字段即选中所在行，以浅底色标记，操作区显示行号和业务名称；不增加行选择圆圈或选择列，未选择时原按钮禁用。按钮沿用原权限、忙碌、最少行数、已保存行取消及确认流程，移除后清空选择；切换选中对象关闭旧行操作的浮层。新增和复制后聚焦业务字段并选中所在行，清空选择后焦点回到原行且不重新选中。选择状态不参与业务表单取值，独立弹层的 form 实例具有独立选择与操作区，浮层操作不改变外层对象。

数量与单位使用同一列中的两个原字段；加工品类与对象、加工项目与工序相邻排布，出货产品与 SKU 在主行直接核对。采购主行保留下单名称与档案名称的差异及已填写颜色，材料不可读时仍显示本单名称。生产路线、客户验货、仓库、批次及差异处置等当前办理所需信息保持直接可见。固定来源的库存、核销和补价明细不增加原本没有的选行、复制或移除能力。

主行行号旁的小箭头展开本行补充资料，采购下单资料、产品来源、规格和备注直接编辑，不增加第二层调整入口。资料默认收起，仅改变可见性，保留字段节点、值及校验；保存失败在滚动聚焦前同步展开错误行所在组和资料，并保留待修改数量。手机与窄区域使用完整标签表单及就近行操作，资料不作第二次折叠。

桌面默认连续展示全部主行，通过“分组显示”按需组织相邻同类记录，首次启用时各组展开；整条分组标题、全部展开／收起和错误定位继续可用。到货清点等依赖材料与采购单位说明来源口径的区域保留必要分组，手机任务沿用原有分组边界。BOM 保留物料与部位的原有分组和字段布局，操作遵循下述两层选择。

- 业务明细按[业务归组边界](../product/ui-design/交互设计说明.md#editor-line-grouping)连续录入，不增加分页。共享分组支持全部展开、全部收起和校验定位，保存覆盖所有已注册字段；校验定位和新增聚焦先展开目标组。开启分组显示时，出货编辑页在同一表格内按相邻同产品显示只读身份标题，产品名、编码和图片共用一次；组内保留每条明细的原序号、SKU、仓库、批次、数量、单位及来源、箱号、包装和备注。不重排非相邻行、不合并不同计量单位，也不从组标题提供批量修改。产品更换和清空仍绑定原行，来源锁定仍生效；组标题变化不重建行节点或覆盖草稿。其他编辑页按需开启各自业务归组；到货清点等必要分组继续保持。
- 每条明细的主字段、补充资料和备注组成完整行组，交替使用内容底色与弱分组底色，组间分隔强于组内边界。序号跨越所属行组，编辑任一字段时以整组细边框及序号强调显示归属；离开后恢复。电脑宽表保留共享表头、列对齐和单一横向滚动，序号与补充资料保持可见；窄屏、手机仍以同一业务条目分组。
- 分组呈现由 `business-list/businessLineItemGroups.css` 统一维护，`BusinessLineItemRow`、`BusinessCompactFieldRow`、联系人及 BOM 物料组共同复用。BOM 保留按物料与单位合并部位的语义；展开状态仅在本次表单中维护；折叠不卸载字段，不改变明细身份、字段、校验、增删和保存路径。
- 明细顶部复用 `BusinessLineItemsHeader`，标题与组数在左侧，展开收起、错误定位、横向查看及来源导入在同一工具栏内分组排列；宽度不足时自然换行，手机保持触控范围。有标题工具栏的明细通过 `TableScrollRegion.useToolbar` 接入自身 `data-table-scroll-scope` 下的滚动插槽，不再为组数和横向按钮分别保留整排空间。无横向溢出时滚动插槽不占位；嵌套明细不能占用外层或其他表格的工具栏。字段、浮层、输入节点、整单校验与保存继续由原表单维护。
- 长明细通过 `TableScrollRegion stickyHeader` 接入共享区域吸顶，工具栏由 `BusinessLineItemsHeader` 测量后选择是否吸顶；多排按钮、手机及低窗口保留阅读空间。列名镜像使用原表实测列宽和横向位置，保持原表头语义，不复制字段或焦点入口；吸顶范围止于所属明细，跨业务分组不解除，进入下一表单章节时释放。输入与新增定位使用吸顶高度预留，分区导航共用 `BusinessFormBody` 的阅读起点。
- 桌面端业务录入表单默认按紧凑自适应栅格排布：文本字段在可用宽度内多列展示，数量类短字段进一步收口，备注、边界说明和明细区保留整行。
- BOM 使用连续表格：同一物料和单位的名称、厂商料号、规格及单位只展示一次，下面直接维护多个部位；支持同料增行、复制、移除与从 Excel 粘贴部位数据。损耗输入为百分比，总用量沿用精确十进制计算，片数不重复乘入单位用量。
- BOM 删除右侧操作列，不增加选择列或行选择圆圈；点击物料的四个合并字段选中整组，点击部位字段选中该部位，键盘聚焦字段同样确定对象。原业务字段的列序、宽度、合并单元格与组尾用量汇总保持。顶部显示所选物料 / 部位名称，所选区域以浅底色标记；部位提供复制与移除，物料提供添加部位与移除整组。移除后清空，重置表单或收起所选组后不保留失效对象；移除物料确认显示部位数，仅作用于当前 BOM。仅剩一个部位时沿用不可单独移除的限制，选择物料后可移除整组。添加物料仍在底部；部位粘贴、来源快照清理、精确用量和整单保存沿用原实现。
- 其他明细条目按共享列宽预算展示，长文本字段保留较宽输入，数量 / 单价 / 金额等短数字字段收窄；数量后缀读取当前行已填单位，金额类字段默认显示 `CNY` 后缀，但不把空单位强行保存成 `pcs`。
- 可连续录入的明细通过 `BusinessLineItemsFooter` 在末行下方提供唯一主新增入口：左侧按钮按图标、文字和正常留白自适应宽度，右侧展示计数及已有汇总，窄屏自然换行。底栏自身左右各保留 12px、上下各保留 10px 内边距，为按钮聚焦环和分区边框留出空间。标题区域保留来源选择与导入等操作。BOM 的添加物料复用同一底栏，选中物料后从顶部添加部位。销售订单、采购、加工合同、出货、联系人、生产订单、质检及采购退货 / 调整沿用已有权限和只读边界，共用新增后的定位与聚焦。复制行在原行后插入；光标进入新行首个可编辑控件，BOM 已指定的物料 / 部位焦点继续保留。底栏位于明细横向滚动区之外，随正文滚动。
### 附件与产品图

- 单据级附件属于主对象证据字段，放在备注、交付、合同资料或凭证语义附近，并位于订单行、BOM 明细、出货明细等 item 区之前；未保存状态可先选择附件并在保存成功后自动上传绑定，单个普通附件上限 200MB，PNG / JPG / WEBP / GIF / PDF 可轻量预览，HEIC / HEIF、Office、ZIP、邮件证据和 WPS 文件下载后查看，无附件状态使用紧凑空态，不在明细末尾放置独立大区块，避免明细增多后必须滚到最后才看见上传入口。
- 附件待上传列表按文件名、文件内容和附件用途去重：同批选择、再次选择和拖入相同文件只保留一项并提示跳过；同名但内容不同的版本仍可加入，移除后允许重选。失败或结果待确认的附件保留原状态，重选不绕过重试限制；读取、上传和重试期间阻止重复提交。
- 独立附件弹窗底部操作统一靠右，关闭按钮始终标为“关闭”；文件选择后通过“上传”执行，成功或失败由上传结果反馈。待上传时关闭继续提示，上传期间禁止关闭与重复提交；表单内嵌附件区沿用表单保存与离开提醒，不额外显示关闭按钮。
- 产品图不是普通证据附件：产品表单内固定显示两个紧凑图片位，选择、替换或清空先留在当前表单会话，产品保存成功后才调用产品媒体接口；取消或产品保存失败不写图片，已打开打印草稿也不随主档后续替换而变化。
- 产品图片位没有图片时显示“暂无图片”，仅保留选择入口；已保存图片加载失败与尺寸不可用分别显示失败或不可用提示，保留文件信息和替换 / 清空操作，不用黑色图片充当空态。图片列表读取失败时先重试，不能显示为无图或覆盖未知图片。产品主图、任务缩略图、业务附件预览和打印图片工具沿用同一可用性判断；产品上传拒绝单像素图片，正常黑色产品照片不按颜色过滤。
产品识别图片统一复用 [ProductIdentity 与媒体读取规则](#产品图与业务媒体)，不在表单另建图片状态或读取策略。
### 浮层、输入与焦点

- 弹窗壳层按主题区分：浅色主题保持 Ant Design 轻量基线；暗色主题必须提供可辨认的遮罩、独立边框、浮层阴影以及 header / body / footer 分隔，避免业务页背景和弹窗融成一片。
- 弹窗 body 内部接管纵向滚动，避免长表单溢出视口；明细横向滚动只允许收口在明细容器内，不外溢到整组 Modal。
- 输入控件的共享外层圆角由 `control-foundation.css` 的 `--erp-control-radius` 管理；高度与文字节奏由根 `ConfigProvider`、`business-control-rhythm.css` 和所属页面规格共同决定。

  视觉尺度见[高保真视觉合同](../product/ui-design/交互设计说明.md#高保真视觉合同--visual-contract)。组合输入框（密码、搜索、前后缀与清空按钮）只由外层绘制圆角、背景、边框和焦点环，内部原生 input 保持零圆角、零边框、零内边距、透明背景和无焦点阴影，并继承外层字体。

  页面及主题的外观选择器排除内层 input，避免依赖样式加载顺序或高优先级覆盖；登录样式集中在 `login.css`，不由打印样式文件提供。
- 下拉选项、标准操作菜单和“更多操作”共用基础控件样式：12px 浮层圆角、8px 项目圆角、轻分隔线、完整文字和长名称自动换行。悬停与键盘焦点清晰可见，选择型菜单保留当前选中态，命令型菜单保留危险操作颜色及禁用原因；手机项目至少 44px 高，任务端沿用更大的触控尺寸。“更多操作”内的单据菜单按 Escape 时同时关闭内外层浮层，焦点回到“更多操作”入口；再次打开仍可正常执行。表头图标入口、带搜索的选择器和既有业务分组按任务保留，不强制改成相同控件。
- 输入控件焦点边框和焦点环跟随当前主题色，暗色普通 hover 使用中性色，focus 使用所选主题的亮色。浏览器回归须在弹窗仍打开时检查默认、空值聚焦、明文切换、填写、校验错误、禁用和重新打开状态；公共焦点扫描同时检查内外层，不能仅凭外层圆角与焦点环通过判断输入完整。

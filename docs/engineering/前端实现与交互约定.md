# 前端实现与交互约定 / Frontend Implementation And Interaction Contracts

本文维护 ERP 桌面、岗位任务端和开发工作台共用的前端实现约定。业务对象状态与允许动作由[生命周期与页面动作规则](../product/业务数据生命周期与页面动作规则.md)维护；视觉与交互设计见[交互设计说明](../product/ui-design/交互设计说明.md)，认证与敏感信息见[应用安全合同](../security/应用安全与验证边界.md)。实现仍以当前代码和测试为准。

下文代码路径以 `web/` 为工作目录；页面布局、权限和业务事实分别由所属组件、后端 RBAC 与领域 usecase 负责。

## 主题模式 / Theme mode

桌面后台、统一登录页、岗位任务端和开发工作台支持「跟系统 / 浅色 / 暗色」三种主题模式，默认跟随系统偏好。开发工作台在共享侧栏操作区提供主题入口，所有 `/__dev/**` 页面复用同一运行时状态。登录后主题色、明暗模式、表格密度和表格线条保存到当前账号的 `admin_users.erp_preferences.appearance`，换设备登录后恢复；未登录时仅使用浏览器 `plush_erp_theme_mode` 与 `plush_erp_appearance`，退出登录后恢复这份浏览器外观。账号首次没有外观偏好时使用蓝色、跟系统、标准密度和简洁线条，不把未登录的浏览器设置自动写入账号。`跟系统` 保存的是模式，每台设备根据自己的系统偏好决定实际明暗；不影响入口选择、权限判断或最终路由。

主题色提供蓝色、橄榄绿、青绿、橙金、粉色、藕紫、橙色和灰紫，默认蓝色。色板真源是 `src/common/theme/erpAppearance.mjs`，允许保存的颜色标识与默认值复用服务端 `admin_erp_appearance.json`。橄榄绿、橙金和灰紫分别沿用 `green`、`yellow`、`purple` 偏好标识，粉色继续使用 `pink`，青绿与藕紫分别使用独立的 `teal`、`mauve`；已保存的账号选择直接读取当前色板。浅色使用较深的操作色及白色按钮文字，暗色使用较亮的操作色及深色按钮文字；标准组件与自定义按钮共享默认、hover、active 配色，主按钮与链接分别核对对比度。桌面后台与独立工作台复用 `getERPAccentTokens`。主题色集中用于交互强调，业务状态颜色独立保留。桌面与手机色块均按四列换行，手机保留完整名称和触控尺寸。


业务会话与认证存储的风险和保护边界见[应用安全合同](../security/应用安全与验证边界.md#业务会话与请求保护--business-session-and-request-protection)。

主题主路径：

- 运行时状态由 `src/common/theme/erpTheme.jsx` 和 `src/common/theme/erpThemeMode.mjs` 维护。
- Ant Design 组件通过根 `ConfigProvider` 在 `defaultAlgorithm / darkAlgorithm` 间切换。
- 项目自定义壳层、岗位任务卡片和局部硬编码样式通过 `data-erp-theme` 与 `src/erp/styles/app.css` 入口及 `src/erp/styles/app/` 分区文件中的 ERP theme 变量覆盖。
- 共享 Mermaid 查看器的全屏画布、工具栏和按钮沿用当前主题变量，通过浏览器顶层避开父级裁剪与导航遮挡；进入全屏不切换明暗主题，退出后恢复页面原有的缩放模式、比例与焦点。
- 新增状态类组件时必须同步覆盖暗色主题，包括 loading / empty / alert / message / notification / tooltip / popover / tag / badge / progress / pagination / drawer / table placeholder；优先复用全局 token 和页面级浏览器回归断言（Style L1），避免组件只在浅色模式可读。
- 打印、PDF、采购合同 / 加工合同纸面预览默认固定浅色，不跟随暗色主题，避免污染导出物。

原生数据表通过 `data-table-lines="appearance"` 接入同一“简洁 / 网格”偏好，复用 `common/components/table/native-table-lines.css`，覆盖进度、录入明细、字段对比、岗位权限与研发数据表。网格只在屏幕真实单元格边界绘制，不改变列宽、行高或合并单元格；窄屏转为卡片时由所属容器规则关闭列线。打印纸面、法律正文、教学图解和 BOM 等有固定线框的专用表显式使用 `data-table-lines="fixed"`，保留各自结构；普通列表继续使用 `AppTable`。ESLint 检查原生表格的声明，避免新增页面漏接。

## 账号偏好 / Account preferences

`admin_users.erp_preferences` 是个人页面偏好的统一持久化入口。当前包含 `appearance`、`column_orders` 与 `hidden_columns`，分别保存外观、模块列排列与列显隐；普通已登录账号可以修改自己的偏好，接口不接收其他账号 ID。以后需要随账号恢复的个人显示或操作习惯按用途增加明确的偏好组；设备设置留在当前设备，编号规则、审批、权限和公司打印模板继续使用各自的正式业务配置。

新增偏好组须补齐允许值、默认值、缺值读取、局部更新、API 投影和相关测试。服务端在同一账号行锁下读取最新 JSON，只修改指定组或字段，其他组保持；浏览器按账号缓存已保存外观，较早的资料或保存响应不能覆盖新的偏好或另一个账号。连续操作顺序保存，不自动重试失败写入；选项即时生效，失败时显示“外观设置未保存到账号，请重试”并提供手动重试。手机只更新主题色和明暗模式，保留桌面表格密度。服务器保存结果是账号偏好真源，浏览器缓存不承担授权或业务配置。


## 共享控件样式边界 / Shared control style boundary

桌面业务页以紧凑布局为基础，尺度由 `src/erp/styles/app/design-tokens.css` 维护：页面外围 8px、区块间隔 6px、面板上下 6px与左右 12px、表单正文上下 10px、字段间距 10px × 12px。模块页头与内容之间只由壳层提供一次 gap；共享页头、工具栏、表单和可视化工作区消费同一变量，不依赖表格密度开关才变紧凑。表格“标准 / 紧凑”继续只控制数据行；手机触控、打印和阅读正文分别遵守已有合同。

页签沿用 `SlidingTabs`、`SlidingSegmented` 或 `SlidingTabList`，切换期间保留同一个页签条，只替换内容。已将选择写入 URL 的页面直接从当前路由解析选中项；点击只更新路由，本地偏好仅在缺少有效路由选择时提供默认选择，避免本地选中项与旧 URL 相互覆盖。库存台账的 `view` 与开发文档的 `path` 均按此恢复刷新、深链和浏览器前进后退。逐帧回归同时检查选中状态不回跳、指示条不反向、页签条持续挂载及位置和尺寸稳定。

文字按钮的水平内边距由 `src/App.jsx` 的 Ant Design `Button` token 统一提供：普通和小号按钮均为 12px，大号按钮为 16px。工具栏、当前操作区、弹窗和浮层沿用这套基线；同一规格的主按钮、次按钮、禁用和 loading 状态不另设 padding。普通业务动作与状态动作统一按内容定宽，长文案自然伸展。嵌入列表的当前操作区在桌面统一使用 30px 按钮高度；窄屏允许长文案换行，保留内边距和至少 44px 触控高度。纯图标、行内文字链接和手机整行按钮按各自用途保留紧凑外形或触控布局，不用固定宽度修补普通按钮的留白。

`src/erp/styles/app.css` 的最后三层是输入框、选择器、日期框、数字框和 Ant Design portal 浮层控件的共享治理层。它们只处理控件基线，不承接单页布局、字段语义、业务状态或客户差异。

| 文件 | 职责 | 不应放入 |
| --- | --- | --- |
| `src/erp/styles/app/control-foundation.css` | ERP runtime 可见控件 token、圆角、wrapper 裁剪、portal 控件基线和嵌套原生输入透明化。 | 单页间距、业务字段宽度、表格布局、具体弹窗内容排列。 |
| `src/erp/styles/app/business-control-rhythm.css` | 业务表单、业务 action modal、业务筛选和业务记录弹窗的控件高度、真实 input / placeholder / search input 的 line-height、textarea 最小高度。 | focus 颜色、hover 状态、页面级 grid / flex 布局、业务保存逻辑。 |
| `src/erp/styles/app/control-focus.css` | 应用根与 portal 控件的 focus / focus-within ring、组合控件内层焦点清理、checkbox focus ring。 | 控件高度、圆角、字段语义、可见文案、权限或菜单规则。 |

维护规则：

- 改 caret、placeholder 垂直居中、input 高度时，优先改 `business-control-rhythm.css`，并确认真实 `input.ant-input`、Select placeholder/search input 和 wrapper 作为一个控件合同一起生效。
- AntD 输入控件的圆角只由 `control-foundation.css` 绘制；组合控件内侧接缝通过局部 `--erp-control-radius: 0` 表达，外层保持统一圆角。页面负责布局与尺寸规格，不重新声明同一控件的圆角。
- focus ring 只由 `control-focus.css` 绘制，颜色由 `--erp-control-focus-border / --erp-control-focus-ring` 提供；主题切换调整变量。使用 inset ring，避免被圆角容器或滚动区域裁掉。Select outlined 变体按 AntD 的 disabled / customize / pagination 条件覆盖，不通过重复类名提权。
- 不在业务页面 CSS 里重复写单字段 caret、line-height 或 focus ring 补丁；确有新控件类型时先补 `style:l1` 浏览器断言，再扩展共享层。
- 新增规则不能使用 `!important`，除非正在对抗不可控的第三方内联样式，并且必须在交付说明中写明原因。

Tailwind Forms 只生成显式 `form-*` 类，供原生表单控件按需使用，不对 AntD 内层 input 做全局重置。表头共享规则归 `src/common/components/table/app-table.css` 的 `.app-table` 作用域；业务页面 CSS 不定义全站 AntD 表头。模块打印使用命名 `@page`，对 body 的隔离仅在该模块打印根节点存在时生效。

`pnpm css` 通过 `scripts/stylelint/styleBoundaries.mjs` 检查模块作用域、重复类名、控件圆角与焦点归属、打印页作用域；全局基线文件的允许清单也由该规则维护。`!important` 例外只在必要声明附近附理由，现有 SVG 内联尺寸覆盖和 reduced-motion 无障碍覆盖保持局部范围。规则测试使用 CSS 输入验证允许与拒绝行为，避免绑定整份源码文本或行号。

浏览器回归复用 `scripts/style-l1/inputControlAssertions.mjs` 的内外层合同与 `scripts/style-l1/styleIsolationAssertions.mjs` 的外观采集；访问其他模块后比较同一控件的默认、hover、focus 样式，保留已加载 CSS，不用刷新页面消除污染。业务场景只编排真实交互与状态，不重复实现颜色、圆角和几何判断；DEV 打印隔离留在 DEV 场景中，普通业务回归不依赖 DEV 路由。

## 表格对齐 / Table alignment

业务列表、弹窗明细和研发工作台的 Ant Design 表格统一使用 `src/common/components/table/AppTable.jsx`。表头和单元格默认上下居中；表头文字水平居中，排序、筛选和列设置控件保留操作空间。序号、编号、单位、日期、状态、短分类和操作列默认水平居中；品名、厂商、地址、备注和复合说明列通过 `align: 'left'` 保持扫读；数量、重量、单价和金额列通过 `align: 'right'` 方便核算。列定义明确语义，不按运行时文字长度或字段名称猜测对齐方式。

序号有逐行核对用途时独立成列，不拼入品名。可复制字段的按钮不挤偏居中文字；原生单据编辑表与 BOM 明细沿用相同表头、垂直对齐和数值输入规则。文档表格的正文保留长文本阅读方式，打印纸面按各模板正式版式单独维护。

## 前端实现与读取边界

- 桌面后台继续只保留一个入口
- 桌面后台不再保留角色切换、角色首页或角色入口菜单；统一登录页和 `/entry` 只做后台 / 岗位任务端入口选择
- 桌面后台管理员已接入 RBAC 权限中心；普通管理员通过 `roles` 获得 `permissions`，后端返回 `menus`，桌面菜单、岗位任务端入口和后端接口统一消费 permission code。权限清单按后端 `module_name` 展示“物料清单（BOM）/ 库存管理 / 生产执行 / 敏感字段”等业务分类，不在前端重复维护模块翻译；仅对未知或缺失分类合并显示一个“未分类功能”，避免多个技术模块同时冒充“其他功能”。分类导航只负责页内定位，不改变勾选结果或权限真源
- 桌面后台主业务菜单按当前产品设计保留看板中心、主数据、销售管理、产品工程、采购管理、质检管理、库存管理、委外管理、生产管理、出货管理、财务业务、运营工具和系统管理；系统管理当前包含权限管理和审计日志。客户档案 / 供应商与加工厂走正式 MasterData API，销售订单走正式 SalesOrder API，采购订单走正式 PurchaseOrder API。正式业务列表统一为单击行选中、双击行进入整页编辑或当前主操作；详情抽屉只由显式详情入口打开。
- 正式业务主表只在显式白名单内的业务编号、名称、联系人、批次和可直接转交的短引用值上提供快捷复制。电脑端悬停单元格或用键盘聚焦时显示复制按钮，触屏端直接显示；鼠标复制后移出单元格即隐藏，键盘操作保留焦点。复制按钮只复制当前字段，不触发行选择或双击打开；空值、日期、金额、数量、状态、备注和内部 ID 不显示按钮，弹窗及明细子表继续使用系统文字选择能力。
- 采购订单页面支持列表、关键词 / 状态 / 采购日期或预计到货日期范围筛选、详情、订单头与明细保存、提交、审批、关闭和取消，但只表达采购承诺，不写库存、批次或财务事实。入库、来料质检、库存台账、委外订单、出货单、生产记录、排产确认、异常处理、出货放行、库存预留和财务业务已分别接入正式业务入口、Workflow 或收窄 Operational Fact 页面。
- 销售订单、采购订单和加工合同不提供明细手动排序入口或弹窗。明细按录入、保存顺序展示。`display_order` 只负责展示位置，`line_no` 保持稳定行身份；已有单据的排列和已经形成的库存、出货或财务事实保持不变。
- 出货单页面支持状态 / 计划出货或实际出货日期范围筛选、事务内聚合新建草稿、只读查看明细、启动财务审批、确认出货和已出货取消冲正。品质岗位可在启动前从 `DRAFT` 出货单按产品规格、仓库和批次发起出货前成品检验；一旦存在检验，未完成合格 / 让步判定时后端会阻止启动，启动成功后也不再允许补建检验。前端必须校验返回的 ProcessInstance、财务 approval 节点和来源锚点，结构不可信时不冒充成功。没有发起检验仍按当前可选策略启动；创建检验不会启动 Workflow。财务审批通过后只写 Shipment 版本化放行门禁，业务仍须显式确认出货；`SHIPPED + inventory OUT` 才是真实出货事实。草稿逐行追加已退出，避免重复提交和多行半保存。
- 审计日志页面只读展示启动初始化和账号 / 角色 / 权限等系统控制面事件，不替代业务事实流水。排产确认与历史出货放行由 Workflow 协同页只读或按现有任务合同办理；排产确认待办由生产订单下达产生，新的 Shipment 财务 approval 由 `finished_goods_delivery` 产生，历史 `shipment_release` 不再有公开 producer。异常处理的待审批任务由正式处置申请启动的 `production_exception_approval` 生成；返工事实过账产生的 `production_exception` 来源提醒不进入该页待审批任务表。这些页面都不提供通用新建入口，保留任务组和确定性编号不能由普通任务创建或客户配置占用。任务终态只更新协同投影；来源随后关闭、取消或真实出货时可以继续投影 `closed / cancelled / shipped`，但不改写任务处理结论。相关页面只读取对应的 Source Document、Workflow 或 Fact 投影，也不提供删除、回收站、业务数据导出或跨领域事实旁路。
- 生产管理侧栏只展示“生产订单”和“生产记录”。“排产确认”从已发布生产订单的明确动作或任务链接进入；“异常处理 / 待审批”从生产记录内切换或任务链接进入。两个内页仍保留正式路由、RBAC 和来源精确筛选，只是不再占用独立侧栏叶子。
- `异常处理` 是上述 Workflow 页面中的正式复合变体：`异常处理` 页签读取 ProductionExceptionDecision 并承接审批后的执行 / 冲正，`待审批` 页签只读取 `production_exception_decision_approval` 任务。两个页签分别维护统计、刷新和操作区，每次只挂载当前页签；任务完成仍不代替报废 / 在制让步执行或超领额度消费。

- 手机列表不再展示独立岗位状态统计卡；保留可点击筛选数量与当前列表范围。顶部搜索通过 `list_role_tasks(keyword)` 在服务端分页前匹配订单 / 产品 / 款号 / 物料，关键词进入查询范围和返回状态，搜索变化时重置游标；保留现有主题、按权限投影的三项或四项导航、全屏详情及底部操作。列表使用独立任务卡、产品名称与款号及整卡查看入口；未设置截止不显示占位符。详情首先展示任务、产品、责任和阻塞原因，再展示附件与补充信息；仅有催办权限时主按钮明确标为“催办任务”。结果回执采用紧凑状态提示，保留本次方式、状态、来源与反馈。
- `/erp/task-board` 任务看板的关键词、状态、角色、到期、来源、泳道和页码使用 URL query 保存，支持复制链接、刷新恢复和一键清空。页面读取服务端 `get_task_board` 全量投影，“常规待办 / 阻塞 / 到期提醒 / 已结束”四个互斥分类的数量直接展示在栏标题中，不再重复渲染顶部大指标。四项之和等于当前筛选的真实总数。首次进入看板才使用整卡加载；分类或翻页切换会保留同一筛选范围的分类数量，只让下方任务显示局部加载并在请求完成后替换结果。总览按内容区宽度显示四列（至少 1200px）、两列（至少 600px）或单列，每栏最多预览 2 项；任务卡单击或按 Enter / Space 直接打开共享详情抽屉，不保留“当前选中任务”侧栏。关闭抽屉保留筛选、滚动位置并将焦点返回原任务卡；通过“查看全部 N 项”进入该分类的完整任务列表；列表顶部使用带数量的紧凑分类标签，标题旁的返回箭头回到概览，不再提供重复的分类下拉框或通用说明句。完整列表采用三列宽表格，默认按 8 项分页，可切换为每页 20 / 50 项，单击任务行或在任务标题按 Enter / Space 进入共享抽屉，返回看板继续保留筛选；不再把 `list_tasks(limit: 200)` 的当前页长度冒充全量统计，也不在前端循环拉取全部任务。这些筛选和投影只影响看板展示，不写用户偏好、Workflow 任务状态或 Fact 表。
- 电脑版任务菜单角标与“待我处理”共用 `get_task_board(todo_only=true)`：在现有配置版本、岗位责任池及本人指派范围内只统计 `ready / blocked`，同任务去重，不追加主管监管或本人创建可见性；与 `approval_only` 互斥。返回完整总数和有界任务页，待办视图隐藏已结束分类。“全部任务”保留原可见范围和历史。角标不受清单搜索、分类或分页影响；确认办理回执后重新读取，浏览不清零，失败不冒充零。

任务看板的“全部任务 / 待我审批”范围切换与标题同行。搜索和负责岗位常显，任务状态、截止时间和业务来源通过“筛选”展开；已选的收起条件仍显示为可逐项清除的标签。状态与日期选项按当前分类收窄，切换分类时清除不适用的组合，URL 读取和请求构造使用同一规范化规则。仅有筛选时显示“清空筛选”，清空保留当前分类、审批范围、排序和每页条数，页码回到第一页。

业务搜索按完整单据或任务筛选；关联多款产品时，搜索结果优先显示命中款的名称、编号与同一款图片，并标明“命中 N 款，共 M 款”。款数按产品去重，不把同款的重复明细或关联订单重复计数。物料命中使用物料种数，不与产品款数混算。只命中单号、客户、任务或说明时保留默认代表项，不标成产品命中；切换和清空关键词恢复对应结果与默认顺序。该展示不改变完整单据明细、审批范围、数量、金额或事实口径。

| 搜索结果类型 | 展示真源与两端口径 |
| --- | --- |
| 任务列表、已办、日历及流程跟踪 | 共享 `WorkflowTaskIdentity` 按已提交关键词从服务端展示投影选择命中项；产品名称和编号沿用单据快照，图片归同一正式产品。受控来源办理任务复用正式来源绑定读取关联内容。 |

工作台、任务看板和岗位任务端的业务单据编号、产品编号、款号使用常显的行内复制图标；复制只取编号原值，不触发进入任务或改变筛选。详情提供“复制产品信息 / 物料信息”和“复制任务信息”，后者包含当前产品、单据、状态原因、已知责任及完整日期时间。共享展示投影已明确缺失或不可用时，不复制旧快照；空值和内部引用不提供复制入口。任务卡的打开按钮与复制按钮独立，手机复制点击范围至少 44px，支持键盘操作、成功提示及失败后的手动复制。剪贴板操作复用共享 helper，不写业务数据。

工作台和任务看板分类列表共用底部吸附分页栏：上一页 / 下一页配文字和方向图标，桌面点击区域至少 36px，窄屏至少 44px；显示当前范围与当前分类总数，可切换每页 8 / 20 / 50 项，默认 8 项。桌面超过 7 页时提供跳页输入，窄屏以可输入的当前页代替密集页码。改变每页条数回到第一页，任务看板将条数写入 URL，刷新及筛选后保留；翻页成功后定位列表首项，读取中禁用分页，失败可重新加载。移动岗位端继续使用原有分批展开。

- 桌面业务页标题区保留标题、已有按需帮助和必要的状态 / 数量，不常驻介绍页面用途或操作顺序。进度看板、系统操作记录和打印中心沿用同一原则；业务规则留在对应操作、表单或现有帮助中，数据范围、权限受限和失败反馈继续明确展示。共享 `PageHeaderCard` 不接收介绍文案，也不保留空段落及其间距。
- 正式业务列表页的 `PageHeaderCard.stats` 只接受非负安全整数计数，`0` 表示已成功读取且确实为零；数字字符串、视图名、模式名、文字状态、负数和不可用占位不会渲染为页头指标。当前视图和状态文字放在页签、标签或说明中；请求失败 / 尚未读取等 unavailable 语义继续由看板自己的 `— / 暂不可用` 状态承接，不伪装成 `0`。
- 当前业务页、岗位任务端页面、桌面工作台、任务看板、异常闭环、进度看板和模板预览已经齐入口；业务数据分别落在领域专表、Source Document、Workflow 与 Fact 真源。采购合同 / 加工合同已支持业务页带值打开，桌面任务看板只处理 Workflow 协同任务，不直接写库存、出货、应收、开票、付款或其他事实表；真实客户数据批量导入、打印留档回写和尚未接入的细分领域专表继续 deferred

## 桌面业务编辑与弹窗约定

- 项目弹窗默认上下左右居中：JSX 版 `antd Modal` 由根 `ConfigProvider` 统一启用 `centered`，命令式 `modal.confirm/info/success/warning/error` 由 `AntdAppBridge` 的消费层统一补齐居中配置；`AppModal` 复用 Ant Design 的遮罩、键盘、焦点圈定和触发点恢复，并只补充业务面板外观与可访问名称。
- 菜单主列表的新增 / 编辑统一使用 `BusinessFormPage`，在当前模块路由内切换主内容区，保留列表筛选、选择与滚动位置。正文独立滚动，底部固定“返回列表 / 保存”；已支持的只读查看复用此骨架。内容、待上传附件或产品图片有修改时，返回、切换菜单、浏览器后退和刷新前提示；保存中阻止离开。适用客户、供应商、材料、产品、产品规格、加工环节、BOM、销售 / 采购 / 生产订单、加工合同、出货单、质检补建、收付款 / 红冲登记、生产事实草稿及员工账号创建 / 资料修改。编辑过程中的快捷新建、来源选择、预览，以及审批、核销、冲销、岗位分配等专项动作继续使用弹窗。详情抽屉只用于显式只读核对。排产确认和出货放行页只读取并处理来源生成的 Workflow 协同任务；生产记录内的异常处理以独立页签分开处置申请和待审批任务。三者都不提供通用任务创建弹窗，也不能把协同结果写成生产订单、生产异常执行、出货单、库存、财务或发票事实；来源、打印、删除等未接入真实 usecase 的动作不能写成真实业务动作。
- 整页业务表单的标题区和固定操作栏使用独立底色及清晰分隔线，正文保持独立内容底色，分组线弱于区域边界；底部操作栏带轻微上阴影。浅色采用灰绿底与白色正文，暗色复用主题表面色与边框色，统一由 `business-form-page.css` 管理。
- 桌面整页表单统一提供可选“全屏编辑 / 退出全屏”，默认普通布局，切换保留原表单、输入、附件及阅读位置；短弹窗、手机业务入口与窄于 768px 的视口不提供。全屏的恢复和浮层键盘顺序见[整页表单与分区定位](../product/ui-design/交互设计说明.md#4-整页表单与分区定位)。
- 桌面端业务录入表单默认按紧凑自适应栅格排布：文本字段在可用宽度内多列展示，数量类短字段进一步收口，备注、边界说明和明细区保留整行。
- BOM 使用连续表格：同一物料和单位的名称、厂商料号、规格及单位只展示一次，下面直接维护多个部位；支持同料增行、复制、移除与从 Excel 粘贴部位数据。损耗输入为百分比，总用量沿用精确十进制计算，片数不重复乘入单位用量。
- 其他明细条目按共享列宽预算展示，长文本字段保留较宽输入，数量 / 单价 / 金额等短数字字段收窄；数量后缀读取当前行已填单位，金额类字段默认显示 `CNY` 后缀，但不把空单位强行保存成 `pcs`。
- 可连续录入的明细在末行下方提供新增入口，销售订单、采购、加工合同、出货、联系人、生产订单及采购退货 / 调整共用新增后的定位与聚焦。复制行在原行后插入；光标进入新行首个可编辑控件，BOM 已指定的物料 / 部位焦点继续保留。新增按钮位于明细横向滚动区之外，随正文滚动。
- 单据级附件属于主对象证据字段，放在备注、交付、合同资料或凭证语义附近，并位于订单行、BOM 明细、出货明细等 item 区之前；未保存状态可先选择附件并在保存成功后自动上传绑定，单个普通附件上限 100MB，PNG / JPG / WEBP / GIF / PDF 可轻量预览，HEIC / HEIF、Office、ZIP、邮件证据和 WPS 文件下载后查看，无附件状态使用紧凑空态，不在明细末尾放置独立大区块，避免明细增多后必须滚到最后才看见上传入口。
- 附件待上传列表按文件名、文件内容和附件用途去重：同批选择、再次选择和拖入相同文件只保留一项并提示跳过；同名但内容不同的版本仍可加入，移除后允许重选。失败或结果待确认的附件保留原状态，重选不绕过重试限制；读取、上传和重试期间阻止重复提交。
- 独立附件弹窗底部操作统一靠右，关闭按钮始终标为“关闭”；文件选择后通过“上传”执行，成功或失败由上传结果反馈。待上传时关闭继续提示，上传期间禁止关闭与重复提交；表单内嵌附件区沿用表单保存与离开提醒，不额外显示关闭按钮。
- 产品图不是普通证据附件：产品表单内固定显示两个紧凑图片位，选择、替换或清空先留在当前表单会话，产品保存成功后才调用产品媒体接口；取消或产品保存失败不写图片，已打开打印草稿也不随主档后续替换而变化。
- 产品图片位没有图片时显示“暂无图片”，仅保留选择入口；已保存图片加载失败与尺寸不可用分别显示失败或不可用提示，保留文件信息和替换 / 清空操作，不用黑色图片充当空态。图片列表读取失败时先重试，不能显示为无图或覆盖未知图片。产品主图、任务缩略图、业务附件预览和打印图片工具沿用同一可用性判断；产品上传拒绝单像素图片，正常黑色产品照片不按颜色过滤。
- 产品档案与产品规格、选款、工程 / BOM、生产和委外产品明细、成品库存、出货明细及产品 / 在制品质检复用 `ProductIdentity`：名称旁显示 48px 主图，选款候选使用 40px 静态缩略图，选中后再提供放大入口。只在可见区域按当前产品读权限批量读取主图引用（每批最多 80 款），随后懒加载缩略图；点击图片才读大图，关闭返回原位置和焦点，不触发行选择或编辑。无主图保留占位，读取失败支持重试 / 页面刷新；切换或清空产品、保存产品图片和手动刷新时更新展示。图片不增加导出列、不替代款号或质检证据，也不为材料、财务或汇总行推测产品。
- 弹窗壳层按主题区分：浅色主题保持 Ant Design 轻量基线；暗色主题必须提供可辨认的遮罩、独立边框、浮层阴影以及 header / body / footer 分隔，避免业务页背景和弹窗融成一片。
- 弹窗 body 内部接管纵向滚动，避免长表单溢出视口；明细横向滚动只允许收口在明细容器内，不外溢到整组 Modal。
- 输入控件的共享外层圆角由 `control-foundation.css` 的 `--erp-control-radius` 管理；高度与文字节奏由根 `ConfigProvider`、`business-control-rhythm.css` 和所属页面规格共同决定。视觉尺度见[高保真视觉合同](../product/ui-design/交互设计说明.md#高保真视觉合同--visual-contract)。组合输入框（密码、搜索、前后缀与清空按钮）只由外层绘制圆角、背景、边框和焦点环，内部原生 input 保持零圆角、零边框、零内边距、透明背景和无焦点阴影，并继承外层字体。页面及主题的外观选择器排除内层 input，避免依赖样式加载顺序或高优先级覆盖；登录样式集中在 `login.css`，不由打印样式文件提供。
- 下拉选项、标准操作菜单和“更多操作”共用基础控件样式：12px 浮层圆角、8px 项目圆角、轻分隔线、完整文字和长名称自动换行。悬停与键盘焦点清晰可见，选择型菜单保留当前选中态，命令型菜单保留危险操作颜色及禁用原因；手机项目至少 44px 高，任务端沿用更大的触控尺寸。“更多操作”内的单据菜单按 Escape 时同时关闭内外层浮层，焦点回到“更多操作”入口；再次打开仍可正常执行。表头图标入口、带搜索的选择器和既有业务分组按任务保留，不强制改成相同控件。
- 输入控件焦点边框和焦点环跟随当前主题色，暗色普通 hover 使用中性色，focus 使用所选主题的亮色。浏览器回归须在弹窗仍打开时检查默认、空值聚焦、明文切换、填写、校验错误、禁用和重新打开状态；公共焦点扫描同时检查内外层，不能仅凭外层圆角与焦点环通过判断输入完整。

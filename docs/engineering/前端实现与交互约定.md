# 前端实现与交互约定 / Frontend Implementation And Interaction Contracts

本文维护 ERP 桌面、岗位任务端和开发工作台共用的前端实现约定。业务对象状态与允许动作由[生命周期与页面动作规则](../product/业务数据生命周期与页面动作规则.md)维护；视觉与交互设计见[交互设计说明](../product/ui-design/交互设计说明.md)，认证与敏感信息见[应用安全合同](../security/应用安全与验证边界.md)。实现仍以当前代码和测试为准。

## 组件复用与使用入口 / Shared Component Entrypoints

新增或修改界面前，先按当前任务核对下表、实现源码与已有调用。相同职责和交互优先复用：适合当前任务的领域组件 → 项目通用封装 → 已确定的第三方组件。第三方组件已满足设计时直接使用；现有二次封装承担了尺寸、焦点、状态或其他合同的，调用方使用该封装入口。

### 列表、页面与弹窗

| 场景 | 正式入口 | 使用边界 |
| --- | --- | --- |

| 业务附件展示与办理 | `business-list/BusinessAttachmentPanel`、`BusinessAttachmentModalButton` | 沿用所属对象、权限、读取恢复与附件状态；工作台展示选用入口，实际上传和撤回在正式业务入口验证 |

| 明细录入、纸面、教学图解及只读证据表 | 已有 `BusinessLineItemsTable`、`BusinessCompactFieldTable`、`DevToolTable`、领域图解或打印组件 | 原生语义表格可承载其专有结构；相近标签不表示同一交互，不将纸面、编辑栅格和紧凑进度强行改为通用列表 |
| 打印纸面文本编辑及采购合同元信息 | `erp/components/print/PrintEditableText`、`MaterialContractMetaPair` | 共用编辑 DOM、草稿同步和元信息双列结构；字段规范化、富文本与工程焦点仍由模板负责，不引入第二份 PDF 正文 |

组件按使用范围放置：产品无关的通用组件在 `common/components/`，ERP 领域共享组件在 `erp/components/` 的对应子目录，手机专属组件在 `erp/mobile/components/`，研发工具专属组件在 `dev-workbench/components/`；只在当前页面内部使用的组件就近维护，不集中到一个大目录。纯数据转换放 `utils/`，可复用的状态与副作用放 `hooks/` 或所属模块。

主数据列表与工作台队列的请求分页与已显示结果分开维护：读取成功后，记录、总数、页码和每页条数一起更新；读取期间保留上一批结果并显示加载状态，失败时保留对应页码与条数，可重试或重新选择目标页、条数重读。不能把新页码或新条数直接套用到尚未替换的旧数据上；过期请求沿用现有取消与结果检查。

业务表单与筛选中的大规模引用使用 `RemoteReferenceSelect`，沿用生产单选择器的请求代次、合并和分页规则，打开时读取 50 条，搜索防抖并取消旧请求，滚动续取。列表、编辑与打印按实际引用 ID 分批读取，每批最多 200 个；已选资料读取不套用候选的启用过滤，保留原字段、停用提示、禁用选择、清空和快照回补规则。页面内引用缓存随账号与有效权限变化失效，不跨会话共享。材料批量添加通过 `RemoteReferencePicker` 复用 `SourceImportPickerModal` 的服务端分页与跨页选择。

单位、仓库配置及确需完整数据的导出/导入匹配保留现有完整分页读取。销售 Excel 客户匹配、BOM Excel 产品与材料匹配只在选择文件后读取完整匹配集合，不能用首屏候选代替完整匹配结果。BOM 和采购合同打印只读取单据涉及的资料，仍以冻结快照优先、原有缺值回补规则补充历史资料；委外收货质检按来源 ID 集合读取，出货前检验按批次 ID 集合读取。

工作台“交互设计 → 控件设计 → 组件选用”直接读取本节，按用途查找正式组件与边界；交互分类使用实际组件和本地示例。“列表与分页”示例直接使用 `AppTable` / `AppPagination`，覆盖翻页、调整条数、筛选回首项、单页、空列表、加载禁用与失败恢复；组件选用提供直达入口。示例仅使用本地虚构记录，不请求业务接口或写入偏好。组件目录与选用规则在本节维护，工作台不另存组件清单；打印专用组件继续关联打印专题及正式工作台核对。

现有组件不符合当前正式、已确认的 UI 设计时，先修改共享默认行为；仅部分场景存在明确差异时，用少量、语义明确的参数或变体承接。职责、交互结构或运行环境确实不同，且共享实现不能合理承接时才独立实现，说明现有能力缺口并复用适合的底层能力。迁移保留已有业务信息、权限、状态和有效操作，完成后清理范围内的重复实现与失效覆盖。

独立可下载 HTML 无法直接导入 React 组件时，复用该原型已有的选择、导航与浮层实现，并验证相同的视觉和操作合同。当前 `docs/product/ui-design/index.html` 的选择入口统一使用 `ui-select`；原型、打印工具、工作台和岗位页面均纳入各自适用的检查范围。

入口约束复用现有 ESLint：根包及 `es / lib` 聚合入口的命名、别名、命名空间与默认导入，内部模块深路径、原生 JSX 及 `createElement` 写法均不能绕过已指定的实现。底层导入仅对对应实现的精确路径放行，不能因某组件需要一个底层能力而放开整个目录。测试夹具可以构造底层控件以验证正反例，运行代码继续受限。Stylelint 继续守住共享外观与页面几何的职责；新差异不通过关闭规则或页面高优先级覆盖实现。

验证同时覆盖组件本身和代表性调用页面：错误调用应被拒绝，正确调用及必要例外应通过；页面按实际支持的主题和设备检查焦点、选值、关闭、禁用、恢复、相邻布局与滚动。使用现有 lint、`affected`、浏览器场景和 CI 入口选择受影响范围；生成器修改后重新生成，并验证输出 lint、生成一致性及相关消费者，避免手改产物。

## 主题模式 / Theme mode

电脑版、登录页、手机岗位端与工作台共用“跟系统 / 浅色 / 暗色”。跟系统保存的是模式，每台设备按自己的系统偏好显示，不改变权限、入口或路由。

### 偏好保存到哪里

| 使用场景 | 保存位置 | 恢复与缺值 |
| --- | --- | --- |
| ERP 已登录账号 | `admin_users.erp_preferences.appearance` | 跨设备恢复主题色、明暗模式、表格密度与线条；首次缺值用蓝色、跟系统、紧凑、网格，不导入未登录偏好 |
| ERP 未登录 | 浏览器 `plush_erp_theme_mode`、`plush_erp_appearance` | 退出后恢复浏览器外观 |
| 本地及独立工作台 | 站点浏览器 `plush_workbench_appearance` | 所有 `/__dev/**` 共用，同源标签页同步；首次或存储损坏用同一默认值，ERP 登录、退出、切换账号不影响它 |

工作台保存失败时保留当前显示并提供重试，不回退为账号保存。业务会话存储另见[应用安全合同](../security/应用安全与验证边界.md#业务会话与请求保护--business-session-and-request-protection)。

### 色板与实现真源

色板在 `src/common/theme/erpAppearance.mjs`，允许标识和默认值复用服务端 `admin_erp_appearance.json`。提供蓝色、橄榄绿、青绿、橙金、粉色、藕紫、橙色和灰紫；橄榄绿 / 橙金 / 灰紫沿用 `green / yellow / purple`，粉色为 `pink`，青绿 / 藕紫为 `teal / mauve`。

浅色使用深操作色配白字，暗色使用亮操作色配深字。标准与自定义按钮共用默认、hover、active 配色，主按钮和链接分别核对对比度；主题色用于交互，业务状态保留独立语义色。两端色块四列换行，手机保留完整名称和触区。

工作台的当前、默认、只读等强调标签使用 `erp-dev-accent-tag`，普通 Mermaid 图同步响应主题色和明暗模式；图例分类与成功、警告、失败保留各自语义色。显式指定 `themeMode` 的纸面与固定预览沿用固定配色。独立工作台登录页只读同站点的工作台外观偏好，CSP 仅允许内容哈希匹配的外观初始化脚本。

| 层 | 实现入口与要求 |
| --- | --- |
| 状态 | `erpTheme.jsx`、`erpThemeMode.mjs` |
| Ant Design | 根 `ConfigProvider` 切换 `defaultAlgorithm / darkAlgorithm`；桌面和工作台复用 `getERPAccentTokens` |
| 自定义界面 | `data-erp-theme`、`src/erp/styles/app.css` 及分区 ERP 变量 |
| Mermaid 全屏 | 浏览器顶层画布、工具栏和按钮沿用主题；退出恢复缩放模式、比例和焦点 |
| 新增状态组件 | loading、empty、alert、message、notification、tooltip、popover、tag、badge、progress、pagination、drawer、table placeholder 同步检查暗色，优先全局 token 与 Style L1 |
| 打印与 PDF | 纸面预览固定浅色，不跟随屏幕主题 |

原生数据表声明 `data-table-lines="appearance"`，共用 `native-table-lines.css` 的简洁 / 网格偏好；网格不改列宽、行高和合并单元格，转卡片时由所属容器关闭列线。打印、法律正文、教学图解和固定线框 BOM 用 `data-table-lines="fixed"`；普通列表继续用 `AppTable`。声明由 ESLint 检查。

## 账号偏好 / Account preferences

`admin_users.erp_preferences` 是个人偏好真源：`appearance` 保存外观，`column_orders` 保存模块列排列，`hidden_columns` 保存列显隐。普通登录账号只能改自己，接口不接收其他账号 ID。

设备设置留在设备；编号、审批、权限和公司打印模板仍属业务配置。新增账号偏好组时补齐允许值、默认值、缺值读取、局部更新、API 投影及测试。

| 情况 | 保存与恢复规则 |
| --- | --- |
| 局部更新 | 服务端在同一账号行锁下读最新 JSON，只改指定组或字段，保留其他组 |
| 连续操作 | 选项即时生效，按顺序保存；不自动重试失败写入 |
| 响应迟到或切换账号 | 浏览器按账号缓存；旧资料 / 保存响应不能覆盖新偏好或另一个账号 |
| 保存失败 | 提示“外观设置未保存到账号，请重试”，提供手动重试 |
| 手机保存 | 只更新主题色与明暗模式，保留桌面表格密度 |

服务器结果为准；浏览器缓存不承担授权或业务配置。

## 共享控件样式边界 / Shared control style boundary

桌面业务页以紧凑布局为基础，尺度由 `src/erp/styles/app/design-tokens.css` 维护：页面外围 8px、区块间隔 6px、面板上下 6px与左右 12px、表单正文上下 10px、字段间距 10px × 12px。模块页头与内容之间只由壳层提供一次 gap；共享页头、工具栏、表单和可视化工作区消费同一变量，不依赖表格密度开关才变紧凑。

共享业务主表和工作中心任务表四边贴合卡片内侧，单元格、分页与可选表格标题区分别保留自身内边距。表格“标准 / 紧凑”继续只控制数据行；手机触控、打印和阅读正文分别遵守已有合同。

页签沿用 `SlidingTabs`、`SlidingSegmented` 或 `SlidingTabList`，切换期间保留同一个页签条，只替换内容。已将选择写入 URL 的页面直接从当前路由解析选中项；点击只更新路由，本地偏好仅在缺少有效路由选择时提供默认选择，避免本地选中项与旧 URL 相互覆盖。库存台账的 `view` 与项目文档的 `path` 均按此恢复刷新、深链和浏览器前进后退。逐帧回归同时检查选中状态不回跳、指示条不反向、页签条持续挂载及位置和尺寸稳定。

文字按钮的水平内边距由 `src/App.jsx` 的 Ant Design `Button` token 统一提供：普通和小号按钮均为 12px，大号按钮为 16px。工具栏、当前操作区、弹窗和浮层沿用这套基线；同一规格的主按钮、次按钮、禁用和 loading 状态不另设 padding。普通业务动作与状态动作统一按内容定宽，长文案自然伸展。

嵌入列表的当前操作区在桌面统一使用 32px 按钮高度；空间不足时收纳辅助动作，窄屏保留内边距和至少 44px 触控高度。纯图标、行内文字链接和手机整行按钮按各自用途保留紧凑外形或触控布局，不用固定宽度修补普通按钮的留白。

`src/erp/styles/app.css` 的最后三层是输入框、选择器、日期框、数字框和 Ant Design portal 浮层控件的共享治理层。它们只处理控件基线，不承接单页布局、字段语义、业务状态或客户差异。

| 文件 | 职责 | 不应放入 |
| --- | --- | --- |
| `src/erp/styles/app/control-foundation.css` | ERP runtime 可见控件 token、圆角、wrapper 裁剪、portal 控件基线和嵌套原生输入透明化。 | 单页间距、业务字段宽度、表格布局、具体弹窗内容排列。 |
| `src/erp/styles/app/business-control-rhythm.css` | 业务表单、业务 action modal、业务筛选和业务记录弹窗的控件高度、真实 input / placeholder / search input 的 line-height、textarea 最小高度。 | focus 颜色、hover 状态、页面级 grid / flex 布局、业务保存逻辑。 |
| `src/erp/styles/app/control-focus.css` | 应用根与 portal 控件的 focus / focus-within ring、组合控件内层焦点清理、checkbox focus ring。 | 控件高度、圆角、字段语义、可见文案、权限或菜单规则。 |

维护规则：

- 改 caret、placeholder 垂直居中、input 高度时，优先改 `business-control-rhythm.css`，并确认真实 `input.ant-input`、Select placeholder/search input 和 wrapper 作为一个控件合同一起生效。
- AntD 输入控件的圆角只由 `control-foundation.css` 绘制；组合控件内侧接缝通过局部 `--erp-control-radius: 0` 表达，外层保持统一圆角。页面负责布局与尺寸规格，不重新声明同一控件的圆角。
- focus ring 只由 `control-focus.css` 绘制，颜色由 `--erp-control-focus-border / --erp-control-focus-ring` 提供；主题切换调整变量。使用 inset ring，避免被圆角容器或滚动区域裁掉。Select outlined 变体按 AntD 的 disabled / customize / pagination 条件覆盖，不通过重复类名提权。
- 不在业务页面 CSS 里重复写单字段 caret、line-height 或 focus ring 补丁；确有新控件类型时先补 `style:l1` 浏览器断言，再扩展共享层。
- 新增规则不能使用 `!important`，除非正在对抗不可控的第三方内联样式，并且必须在交付说明中写明原因。

Tailwind Forms 只生成显式 `form-*` 类，供原生表单控件按需使用，不对 AntD 内层 input 做全局重置。表头共享规则归 `src/common/components/table/app-table.css` 的 `.app-table` 作用域；业务页面 CSS 不定义全站 AntD 表头。模块打印使用命名 `@page`，对 body 的隔离仅在该模块打印根节点存在时生效。

`pnpm css` 通过 `scripts/stylelint/styleBoundaries.mjs` 检查模块作用域、重复类名、控件圆角与焦点归属、打印页作用域；全局基线文件的允许清单也由该规则维护。`!important` 例外只在必要声明附近附理由，现有 SVG 内联尺寸覆盖和 reduced-motion 无障碍覆盖保持局部范围。规则测试使用 CSS 输入验证允许与拒绝行为，避免绑定整份源码文本或行号。

浏览器回归复用 `scripts/style-l1/inputControlAssertions.mjs` 的内外层合同与 `scripts/style-l1/styleIsolationAssertions.mjs` 的外观采集；访问其他模块后比较同一控件的默认、hover、focus 样式，保留已加载 CSS，不用刷新页面消除污染。业务场景只编排真实交互与状态，不重复实现颜色、圆角和几何判断；DEV 打印隔离留在 DEV 场景中，普通业务回归不依赖 DEV 路由。

## 表格对齐 / Table alignment

业务列表、弹窗明细和研发工作台的 Ant Design 表格统一使用 `src/common/components/table/AppTable.jsx`。表头和单元格默认上下居中；表头文字水平居中，排序、筛选和列设置控件保留操作空间。

单选和多选的行选择列由 `AppTable` 统一为 52 CSS px，表头与正文同宽；宽屏的剩余空间分配给业务列，选择列不随页面、数据量、密度或横向滚动拉伸。页面沿用共享宽度，不单独设置选择列宽度。

序号、编号、单位、日期、状态、短分类和操作列默认水平居中；品名、厂商、地址、备注和复合说明列通过 `align: 'left'` 保持扫读；数量、重量、单价和金额列通过 `align: 'right'` 方便核算。列定义明确语义，不按运行时文字长度或字段名称猜测对齐方式。

联系人、收货信息、物流信息、库存预留的产品与规格及仓库与批次使用 `business-list/BusinessCellStack` 紧凑上下排列：上行放姓名、收货人及电话、承运商及运输方式、产品身份或仓库，下行放电话、地址、运单号、规格或批次。收货信息共用 `DeliveryInfoCell`。两行左对齐，次行沿用主题次要文字色和正文大小；缺项不占空行，长内容自然换行。复制、排序和导出继续读取结构化字段组成的文本，不从界面拆行反推数据；金额、数量和独立短状态仍按各自列语义展示。

销售订单的订单编号、客户与跟单、订单与用料也使用 `BusinessCellStack`，允许传入原字段的展示节点与共享复制按钮；两个状态分别保留“订单”“用料”标签。原字段列定义是详情、导出、复制与排序的依据，先过滤字段显示策略，再生成列表复合列；订单总额保留币种、右对齐与数值排序，列表不再单列币种。合并列按主字段排序，同值时比较补充字段；保存列设置时以信息组为单位，读取已有设置时按原成员首次出现的位置合并，只在已保存成员全部隐藏时隐藏整组。个人隐藏不减少详情或导出字段。

序号有逐行核对用途时独立成列，不拼入品名。可复制字段的按钮不挤偏居中文字；原生单据编辑表与 BOM 明细沿用相同表头、垂直对齐和数值输入规则。文档表格的正文保留长文本阅读方式，打印纸面按各模板正式版式单独维护。

## 工作入口与视口命名 / Work Entry And Viewport

界面与当前设计说明使用“电脑版／手机版”表示工作入口，使用“宽屏／窄屏布局”表示可用尺寸。入口决定功能、权限投影与导航，视口只影响布局。

| 名称 | 判定依据 | 布局边界 |
| --- | --- | --- |
| 手机版 | `/m/...` 手机岗位入口及其任务、进度、跟踪、异常和帮助界面 | 在电脑宽窗口中打开仍是手机版；日常导航保持手机岗位流程 |

| 研发效能工作台 | `/__dev/...` 开发与验证入口 | 其中的“手机版／电脑版”设计样例表示被说明的业务界面，工作台本身保持自己的入口 |

### 入口与授权

桌面后台只有一个业务入口，不设置岗位首页或角色切换菜单；统一登录页和 `/entry` 负责选择电脑版或手机版。两端共用管理员登录态、后端菜单和 permission code；角色名称、页面可见和当前选中岗位都不能代替后端授权。

权限分类直接读取后端 `module_name`，未知或缺失分类合并为一个“未分类功能”。分类导航只定位，不改变权限勾选。正式业务菜单及生产模块内部入口统一按菜单专题维护，本节不另列菜单树。

| 场景 | 页面行为 |
| --- | --- |
| 登录与退出 | 固定提供密码登录；仅后端启用短信能力时显示短信登录。登录失效、手机号未绑定或当前岗位未授权时进入 `/admin-login`，成功后返回允许的任务页 |
| 手机导航 | 使用 `/m/<role>/tasks` 及 `/m/<role>/handle/...`，不按岗位拆端口或仓库。任务、进度、办理、帮助及返回保留当前手机岗位与界面；完整单据与来源跳转在电脑端查看 |
| 手机办理与返回 | 已支持的任务办理入口使用 `useBusinessNavigate` / `BusinessLink`，字符串及对象路径保留 query、hash 与返回上下文。具体可用入口见岗位任务页专题；权限不足或适配缺失在手机内说明，不自动切电脑版 |
| 公开规则 | `/legal/privacy`、`/legal/system-rules` 在登录页可读；电脑账号菜单、手机“我的 / 入口与安全”保留同一入口。短信模式说明手机号的验证用途 |
| 规则知悉 | `LegalNoticeGate` 按账号、客户 `legalNotice` 版本和规范化内容指纹读取追加式知悉审计；内容变化重新提示。它不是概括授权同意；核对失败可重试，不阻断整个 ERP |

知悉回执不保存手机号、密码、token 或业务原文。业务会话与认证保护见[应用安全合同](../security/应用安全与验证边界.md)。

### 列表、搜索与来源跳转

正式业务列表单击行选中，双击进入整页编辑或当前主操作；只读详情由显式入口打开。销售订单、采购订单和加工合同的明细按录入、保存顺序展示，不提供手动排序；`display_order` 表示位置，`line_no` 保持稳定身份，不改既有事实。

“相关单据”每一跳都用目标页的数值 ID 或来源类型加来源 ID 建立精确筛选。业务单号只作回显；唯一目标可自动选中，多条取消历史不能臆选。用户修改或清空筛选后退出关联上下文。

业务搜索筛选完整单据或任务，不裁掉未命中的明细，也不改变审批范围、数量或金额。多款产品优先展示命中款的名称、编号和同款图片，标明“命中 N 款，共 M 款”；款数按产品去重，物料种数独立计算。只命中单号、客户或说明时保留默认代表项；清空关键词恢复默认顺序。

| 搜索对象 | 展示真源 |
| --- | --- |
| 任务、已办、日历与流程跟踪 | `WorkflowTaskIdentity` 按已提交关键词从服务端展示投影选择命中项；名称和编号来自单据快照，图片归同一正式产品 |
| 订单交付与生产进度 | 后端同一读快照返回完整单据、当前页命中款、总款数和代表产品；无产品命中时不返回命中计数 |
| 业务单据列表 | 从真实来源或明细检索，不以任意首款冒充命中项；单明细汇总与库存记录保留自身身份 |
| 主数据、选款与来源导入 | 单实体显示自身名称、编号和图片；本地筛选使用可见列或声明字段，来源选择保留正式单据或明细粒度 |

### 复制与身份展示

| 位置 | 复制规则 |
| --- | --- |
| 正式业务主表 | 仅白名单内的业务编号、名称、联系人、批次和可转交短引用提供复制；电脑悬停或聚焦显示，触屏常显 |
| 任务与进度条目 | 单据编号、产品编号、款号使用常显行内图标；详情可复制产品 / 物料信息及任务信息 |
| 空值与非复制字段 | 日期、金额、数量、状态、备注、内部 ID 不加快捷按钮；弹窗及明细子表沿用文字选择 |

复制只取当前值，不触发行选择、双击打开或改变筛选。鼠标移出后隐藏悬停按钮，键盘操作保留焦点；手机触区至少 44px。共享剪贴板 helper 提供成功提示与失败后的手动复制。投影已明确缺失或不可用时，不复制旧快照或内部引用。

任务名称保持主标题。`WorkflowTaskIdentity` 列表显示首项和总项数，详情可展开其余产品 / 物料；任务复制信息包括产品、单据、状态原因、已知责任及完整日期时间。

身份优先读取服务端 `display_context`：名称与编号取正式来源快照，材料款号取 `supplier_item_no`。系统物料编号和内部 `style_no` 只在详情与完整复制中按各自名称保留，缺值不互相代填。无正式来源的任务可用自身已有展示快照；明确空投影或来源失效不得回填旧 payload。

### 任务读取、处理与恢复

任务数量来自后端分页前统计，不取本地数组长度、不扇出全部岗位请求，也不循环拉取任务拼总数。手机首次无游标读取的公式与槽位规则见[岗位任务数量读投影](../product/业务主链路数据流向与字段来源规则.md#47-岗位任务数量读投影--role-task-count-projection)；可信总数未读到时显示“—”，不显示 `0`。

桌面任务抽屉与手机详情分开读取两条证据：`get_task_process_context` 展示“业务轨迹”，`list_task_events` 展示“本任务处理记录”。任务记录按最新在前显示进度、异常、恢复、责任与意见；一条读取失败不隐藏另一条，也不把单任务事件当完整审批链或业务事实。

一次办理按以下顺序执行：

1. 新 intent 先读取 `explainWorkflowActionAccess` / `explainWorkflowTaskAssignment`，核对服务端原因。
2. 在任何 `await` 前取得同一 task 的同步 in-flight lease，阻止完成、阻塞、退回、恢复和催办跨动作双发。
3. 冻结业务参数、`expected_version` 与安全 UUID `idempotency_key`。HTTPS 优先 `crypto.randomUUID()`；内网 HTTP 用 `crypto.getRandomValues()` 生成 RFC 4122 v4，禁用 `Math.random()`。
4. HTTP 408、网络中断、5xx 或成功响应结构不合法时，保留 attempt、抽屉、原因、证据和原 key，按原意图读取 / 重放 receipt；不刷新列表，也不把未知结果报成失败。
5. 收到可信结果后刷新服务端投影、恢复列表上下文；`finally` 只释放本次持有的 lease。

同意图重试不重复 explain，但后端每次仍校验登录、RBAC、客户范围、任务可见性和 receipt。Go / JS 共用 `scripts/qa/workflow-task-mutation-intent-v1.vectors.json` 核对混合证据、顺序、空白 key、精确重放与意图变化；历史通过数量不作为当前验证结论。

转交仅在桌面任务详情办理：候选来自 `get_task_assignment_options`，`reassign_task` 提交接收人或岗位池、version、幂等键及必填原因。前端不从管理员列表拼候选。默认老板和 super admin 可转交，PMC 只读监督；能转交不等于具备接收岗位身份。成功只改个人归属并关闭、刷新抽屉，不改任务状态或 Fact。手机当前不提供桌面转交动作。

### 工作台与任务看板

工作台任务队列使用全宽表格，单击行或在任务标题按 Enter / Space 打开共享抽屉；拖选文字不打开。保留待我处理、审批、阻塞逾期筛选，直接显示问题原因；不重复放“查看任务”列或常驻选中任务侧栏。

| 看板规则 | 合同 |
| --- | --- |
| 范围与分类 | `/erp/task-board` 读取 `get_task_board`；常规待办、阻塞、到期提醒、已结束四类互斥，其和等于当前筛选总数 |
| 概览布局 | 内容宽度至少 1200px 时四列，至少 600px 时两列，其余单列；每栏预览最多两项，进入分类后用完整列表 |
| 加载与关闭 | 首次整卡加载，分类或翻页只更新任务区并保留同范围数量；关闭抽屉恢复筛选、滚动及原任务焦点 |
| URL 恢复 | 保存关键词、状态、角色、到期、来源、泳道、页码和每页条数；刷新、返回与复制链接恢复 |
| 筛选收起 | 搜索、负责岗位常显，其余按需展开；已应用条件仍以可移除标签可见。切换分类清理不适用状态 / 日期，URL 与请求共用规范化规则 |
| 清空筛选 | 保留分类、审批范围、排序和每页条数，仅页码回到第一页 |
| 待办角标 | 与“待我处理”共用 `get_task_board(todo_only=true)`，只统计当前责任池 / 本人指派的 `ready / blocked` 并去重；不追加主管监督或本人创建范围，与 `approval_only` 互斥 |

角标不受清单搜索和分页影响，办理回执确认后重读；浏览不清零，失败不冒充零。“全部任务”保留历史可见范围；待办视图隐藏已结束分类。

工作台队列、任务管理分类列表、进度看板和流转记录共用分页配置：默认每页 20 条，可选 20 / 50 / 100 条，显示当前范围与服务端总数；任务概览仍只预览每类 2 条，日历保留每批 30 条。分页外观与窄屏精简页码复用 `AppPagination`，保留每页条数选择。修改条数回第一页，翻页成功定位首项，读取中禁用分页，失败可重读。手机岗位端沿用分批续取。

### 进度看板

`/erp/business-dashboard` 用逐单进度显示订单交付与生产执行；资料、领料、工序、质检、数量和处理人同屏。单号或环节打开上下文侧栏，再按来源权限打开原单；关闭保留筛选与列表位置。未关联订单的协同任务从“全部任务”进入任务看板。

两端复用 `business.list_progress/get_progress`。全范围数量在后端分页前汇总，风险可以重叠；只按实际出货和扣除返工后的有效完工计算，不把关闭当完工，不把领料进度当齐套。不同单位分开、缺少关联显示待核对，原单查看另验权限。

手机入口、权限组合、查询恢复、任务直达和卡片布局统一见[手机进度](../product/移动端岗位任务页改版.md#手机进度--mobile-progress)。账号、权限或客户配置变化后不复用旧数据，读取失败清除旧结果并提供重试。

### 产品图与业务媒体

委外订单的“选择合同附图”只收 PNG / JPEG / WEBP / GIF，标记 `print_appendix`。打开加工合同打印时冻结未撤销附图；普通附件不自动上纸，窗口内调序、移除或新增不回写业务附件，详见[打印图片来源](../打印模板实现原理.md)。

产品图片与普通证据附件分别维护，格式、预算、持久化和撤销规则见[产品图片媒体例外](../architecture/业务附件证据边界评审.md#产品图片媒体例外)及[编辑与弹窗](#桌面业务编辑与弹窗约定)。

| 展示位置 | 实现与读取 |
| --- | --- |
| 任务身份 | 两端列表用 64px 图片位，延迟读取 160px 缩略图并按账号权限去重；详情保留各自尺寸 |
| 产品及业务明细 | `ProductIdentity` 名称旁 48px 主图，选款候选 40px 静态图，选中后提供放大；可见区域每批最多读取 80 款主图引用 |
| 无图或不可读 | 无正式关联、无 `product.read`、物料项或主图缺失保留同尺寸占位；不借用另一产品的图片，不把失败当无图 |
| 原图预览 | 打开时才读取，复用 Ant Design Image 的缩放、拖动、适应屏幕与 Esc；关闭释放原图，恢复列表位置和触发焦点 |

图片点击与任务打开、行选择、编辑相互独立；占位不打开预览。加载失败可重试；关闭、来源切换、主图清空或权限变化后丢弃迟到响应，不回填旧引用。正常黑色照片不按颜色过滤，单像素图片不可用。图片不增加导出列，也不替代款号或质检证据。

打印带值由业务页选中记录后打开；BOM 生成物料明细 / 作业指导书时冻结 0–2 张产品图，委外订单只有全部有效产品行属于同一产品才自动带图。打印中心保留样例与两栏预览，字段及草稿图片在独立打印窗口编辑；后续主档变化不改已打开草稿。

### 页头、反馈与事实边界

业务页标题区只留标题、按需帮助及必要状态 / 数量，规则放在所属操作、表单或帮助中。`PageHeaderCard` 不接收常驻介绍文案；数据范围、权限限制与失败反馈仍就近展示。

`PageHeaderCard.stats` 只接受非负安全整数；`0` 表示可信的零值。字符串、视图名、负数和不可用占位不能当指标；未读取和失败由所属页面使用“— / 暂不可用”说明。

桌面任务、手机办理与附件上传都不直接写库存、出货、应收、开票、付款等事实。采购 / 出货 / 生产的来源、审批、草稿退出与过账边界统一查阅[页面血缘](../product/页面来源生成入口规则.md)和[Workflow / Fact 合同](../architecture/状态工作流事实边界.md)。真实客户批量导入、打印留档回写、硬件链路、PDA、条码枪和图片识别尚未接入；本地源码与测试不证明目标已部署或客户已验收。

## 桌面业务编辑与弹窗约定

- 项目弹窗默认上下左右居中：`AppModal` 标准模式与 `BusinessModal` 由根 `ConfigProvider` 统一启用 `centered`，命令式 `modal.confirm/info/success/warning/error` 由 `AntdAppBridge` 的消费层统一补齐居中配置；`AppModal` 面板模式在同一 Ant Design 基础上补充专用面板外观、背景隔离与可访问名称。
菜单主列表的新建、编辑和已支持的只读查看复用 `BusinessFormPage`，在当前模块路由内切换正文并保留列表筛选、选择和滚动。正文独立滚动，底部固定“返回列表 / 保存”。

表单、待上传附件或产品图有改动时，返回、换菜单、浏览器后退和刷新都提示；保存中阻止离开。快捷新建、来源选择、预览、审批、核销、冲销和岗位分配继续用专项弹窗，详情抽屉只作显式只读核对。

适用对象包括主数据、BOM、销售 / 采购 / 生产订单、加工合同、出货单、质检补建、收付款 / 红冲、生产事实草稿及员工资料。来源生成的排产、审批和异常任务不提供通用任务创建；页面动作及其事实边界见[来源入口规则](../product/页面来源生成入口规则.md)。
- 整页业务表单的标题区和固定操作栏使用独立底色及清晰分隔线，正文保持独立内容底色，分组线弱于区域边界；底部操作栏带轻微上阴影。浅色采用灰绿底与白色正文，暗色复用主题表面色与边框色，统一由 `business-form-page.css` 管理。
- 桌面整页表单统一提供可选“全屏编辑 / 退出全屏”，默认普通布局，切换保留原表单、输入、附件及阅读位置；短弹窗、手机业务入口与窄于 768px 的视口不提供。全屏的恢复和浮层键盘顺序见[整页表单与分区定位](../product/ui-design/交互设计说明.md#4-整页表单与分区定位)。
### 明细录入

- 桌面端业务录入表单默认按紧凑自适应栅格排布：文本字段在可用宽度内多列展示，数量类短字段进一步收口，备注、边界说明和明细区保留整行。
- BOM 使用连续表格：同一物料和单位的名称、厂商料号、规格及单位只展示一次，下面直接维护多个部位；支持同料增行、复制、移除与从 Excel 粘贴部位数据。损耗输入为百分比，总用量沿用精确十进制计算，片数不重复乘入单位用量。
- 其他明细条目按共享列宽预算展示，长文本字段保留较宽输入，数量 / 单价 / 金额等短数字字段收窄；数量后缀读取当前行已填单位，金额类字段默认显示 `CNY` 后缀，但不把空单位强行保存成 `pcs`。
- 可连续录入的明细在末行下方提供新增入口，销售订单、采购、加工合同、出货、联系人、生产订单及采购退货 / 调整共用新增后的定位与聚焦。复制行在原行后插入；光标进入新行首个可编辑控件，BOM 已指定的物料 / 部位焦点继续保留。新增按钮位于明细横向滚动区之外，随正文滚动。
### 附件与产品图

- 单据级附件属于主对象证据字段，放在备注、交付、合同资料或凭证语义附近，并位于订单行、BOM 明细、出货明细等 item 区之前；未保存状态可先选择附件并在保存成功后自动上传绑定，单个普通附件上限 100MB，PNG / JPG / WEBP / GIF / PDF 可轻量预览，HEIC / HEIF、Office、ZIP、邮件证据和 WPS 文件下载后查看，无附件状态使用紧凑空态，不在明细末尾放置独立大区块，避免明细增多后必须滚到最后才看见上传入口。
- 附件待上传列表按文件名、文件内容和附件用途去重：同批选择、再次选择和拖入相同文件只保留一项并提示跳过；同名但内容不同的版本仍可加入，移除后允许重选。失败或结果待确认的附件保留原状态，重选不绕过重试限制；读取、上传和重试期间阻止重复提交。
- 独立附件弹窗底部操作统一靠右，关闭按钮始终标为“关闭”；文件选择后通过“上传”执行，成功或失败由上传结果反馈。待上传时关闭继续提示，上传期间禁止关闭与重复提交；表单内嵌附件区沿用表单保存与离开提醒，不额外显示关闭按钮。
- 产品图不是普通证据附件：产品表单内固定显示两个紧凑图片位，选择、替换或清空先留在当前表单会话，产品保存成功后才调用产品媒体接口；取消或产品保存失败不写图片，已打开打印草稿也不随主档后续替换而变化。
- 产品图片位没有图片时显示“暂无图片”，仅保留选择入口；已保存图片加载失败与尺寸不可用分别显示失败或不可用提示，保留文件信息和替换 / 清空操作，不用黑色图片充当空态。图片列表读取失败时先重试，不能显示为无图或覆盖未知图片。产品主图、任务缩略图、业务附件预览和打印图片工具沿用同一可用性判断；产品上传拒绝单像素图片，正常黑色产品照片不按颜色过滤。
产品识别图片统一复用 [ProductIdentity 与媒体读取规则](#产品图与业务媒体)，不在表单另建图片状态或读取策略。
### 浮层、输入与焦点

- 弹窗壳层按主题区分：浅色主题保持 Ant Design 轻量基线；暗色主题必须提供可辨认的遮罩、独立边框、浮层阴影以及 header / body / footer 分隔，避免业务页背景和弹窗融成一片。
- 弹窗 body 内部接管纵向滚动，避免长表单溢出视口；明细横向滚动只允许收口在明细容器内，不外溢到整组 Modal。
- 输入控件的共享外层圆角由 `control-foundation.css` 的 `--erp-control-radius` 管理；高度与文字节奏由根 `ConfigProvider`、`business-control-rhythm.css` 和所属页面规格共同决定。

  视觉尺度见[高保真视觉合同](../product/ui-design/交互设计说明.md#高保真视觉合同--visual-contract)。组合输入框（密码、搜索、前后缀与清空按钮）只由外层绘制圆角、背景、边框和焦点环，内部原生 input 保持零圆角、零边框、零内边距、透明背景和无焦点阴影，并继承外层字体。

  页面及主题的外观选择器排除内层 input，避免依赖样式加载顺序或高优先级覆盖；登录样式集中在 `login.css`，不由打印样式文件提供。
- 下拉选项、标准操作菜单和“更多操作”共用基础控件样式：12px 浮层圆角、8px 项目圆角、轻分隔线、完整文字和长名称自动换行。悬停与键盘焦点清晰可见，选择型菜单保留当前选中态，命令型菜单保留危险操作颜色及禁用原因；手机项目至少 44px 高，任务端沿用更大的触控尺寸。“更多操作”内的单据菜单按 Escape 时同时关闭内外层浮层，焦点回到“更多操作”入口；再次打开仍可正常执行。表头图标入口、带搜索的选择器和既有业务分组按任务保留，不强制改成相同控件。
- 输入控件焦点边框和焦点环跟随当前主题色，暗色普通 hover 使用中性色，focus 使用所选主题的亮色。浏览器回归须在弹窗仍打开时检查默认、空值聚焦、明文切换、填写、校验错误、禁用和重新打开状态；公共焦点扫描同时检查内外层，不能仅凭外层圆角与焦点环通过判断输入完整。

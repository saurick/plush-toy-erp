# 可视化表达规范 / Visualization

文档、效能工作台和业务页面的图示应先帮助读者回答一个具体问题，再提供条件与证据。默认先看主线，按需查看一个专题或对象；事实、状态和数值仍来自现有代码、数据及运行回执。本文面向页面和文档维护者，后续 Codex 会话沿用同一规则。

## 选择表达 / Choosing A View

| 要回答的问题 | 优先表达 | 配套信息 |
| --- | --- | --- |
| 谁依赖谁、数据从哪里来、职责怎样分开 | Mermaid 流程或关系图 | 箭头含义、来源链接、关键边界 |
| 一笔任务或订单走到哪里、轮到谁办理 | 轻量步骤节点与当前阶段明细 | 当前岗位、状态、受阻原因、办理入口；沿用页面原有样式 |
| 一个对象允许怎样改变状态 | 按对象筛选的状态图 | 转换条件、权限与异常清单 |
| 请求或交接按什么次序发生 | 少量参与者的时序图 | 失败、重试与事务边界 |
| 几个值差多少、随时间怎样变化 | 现有业务图表组件 | 单位、时间范围、口径与同源明细 |
| 精确比较权限、字段、证据或差异 | 表格 | 筛选、来源和缺失说明 |
| 简单顺序、命令或单一结论 | 编号步骤、代码块或短段落 | 必要的成功与失败信号 |

不按文档篇幅决定是否画图；新增图必须让依赖、分支或比较更容易理解。经营统计继续使用已有查询、聚合与图表模型，不能把示意图或示例数字当成运行结果。

## 页内理解与上下文 / In-context Reading

本规范适用于研发效能工作台、ERP 桌面和手机页面。流程、分支、依赖、状态变化优先用图与短说明；精确对账用表格，填写用表单，简短事实直接表达。先合并重复，再组织层级，不为减少文字删除当前判断所需的条件、错误、权限或业务结果。

查看说明、流程、关系和当前对象详情，优先在原处展开或使用同一详情区。控件名称应对应实际动作；普通“查看”不隐式切换其他 Tab、页面或新开浏览器标签。跨环节的分支复用同一来源，并标出关联环节，不能给每个步骤复制通用异常。

完整单据编辑、独立业务办理和明确的导航仍使用已有正式页面，以“打开采购单”等名称说明目的地，返回保留筛选、选中对象和必要定位。不要为留在原页叠加多层弹窗或把复杂表单挤进抽屉；新开标签仅在用户明确选择时使用。

## 图形关键信息 / Chart Inspection

所有交互式可视化中的业务图形（进度条、柱／折线数据点、分段、流程与关系节点等）均须支持鼠标悬停查看关键信息；同一信息也能通过键盘聚焦和手机点按获得。静态图片、打印与导出应直接保留必要标签或配套表格，不能依赖 hover 才能理解。

| 场景 | 提示内容与交互要求 |
| --- | --- |
| 数量、金额与比例 | 对象或系列名称、实际值及单位／币种；比例同时给分子、分母、占比与统计口径，按当前筛选解释范围 |
| 时间、状态与流程 | 对象、当前状态或环节、真实时间／统计区间；只有来源提供时才展示责任人和关系依据，不补造事件或百分比 |
| 缺值、多单位与权限 | 明确待核对、多单位分开查看或无查看权限；不将未知显示成 0，不在提示中泄漏被隐藏的数据 |
| 桌面和键盘 | hover 与 focus 信息一致；Escape 关闭提示并保留触发焦点；提示可移入阅读，不遮住必要操作 |
| 手机与下钻 | 点按可查看和关闭同样的信息；若图形已有下钻，提示与进入明细使用明确的独立入口，避免点按立即跳走 |
| 可读性 | 保留图上必要标签，颜色不能独立承载状态；长文本、窄屏与明暗主题均可读，悬浮层不能被滚动容器裁切 |

复用已有图表和提示组件，从当前展示数据读取提示；按需下钻沿用既有权限与请求链路。验收覆盖 hover、focus、Escape、触屏、长内容及缺值／权限，不以截图中出现提示替代交互检查。新图与本轮触达图同步落实；存量缺口按实际范围登记，不宣称未核验的页面已经完成。

## 信息层级 / Reading Order

总览只展示主线和关键分支，通常以 5–9 个节点为宜。正式文档和工作台静态说明中的单张流程图最多 12 个业务节点、18 条关系；超出时按读者问题拆图，不把多个动作硬塞进一个长标签。不要为了满足数量删掉取消、拒绝、恢复或事实边界；它们应在对应专题图或相邻清单中可找到。

专题只解释一种机制，例如把“旧数据能否复用”和“哪些模块一起刷新”分开。图下的表格解释条件、权限和证据路径，不逐字重抄节点。三层足够：总览 → 当前专题或对象 → 条件与证据，不增加层层弹窗。

流程、异常和关系的表达优先使用可交互图，配合短节点名、条件与当前节点说明；不得用长段落或无连线的步骤列表替换已有分支图。总览只显示有正式来源和处理路径的专项分支，普通受阻说明不自动生成“异常”入口；专题选定直接显示图，导航名称和位置保持稳定。完整规则按需展开，拒绝、恢复、终止和事实边界仍须可追溯。

业务页面的复杂流程优先用少量阶段节点组织，不把所有任务卡片或完整关系图直接铺在首屏。默认定位当前任务或异常，一次展开一个阶段；该阶段只优先展开当前任务和最需处理的记录，剩余记录有可见数量及直接展开入口，受阻数量不能藏入历史。岗位、状态和下一步操作放在同一处，不另堆重复标签、说明与筛选。无法确认前后依赖的并列任务只分组，不画成实际执行顺序；未知阶段和缺失记录明确保留，任务结束不能染成业务阶段完成。轻量步骤节点使用原有组件与点击展开，不附加关系画布的缩放、平移或全屏工具栏。

动态全量关系通过现有目录或运行数据生成，允许在明确标为“完整图”的按需视图中超过静态图上限。默认先按领域、阶段、状态或选中对象聚焦；显示当前范围及总数，保留完整关系和明细入口。筛选必须同时作用于图和清单，不能静默截取前若干项或补画不存在的连接。

## 图形与交互 / Presentation

一图只用一种主要阅读方向。节点用短名称，动作或条件写在必要的连线上；复杂条件放到相邻说明。实线、虚线和颜色的含义须在附近说明；通过文字、线型或图例共同表达，不能仅靠红绿区分状态。总览合并阶段时明确说明聚合口径，不把阶段数量或静态连线染成“已通过”。

订单总览的阶段节点在电脑与手机上统一自上而下，连接线带向下箭头；阶段序号只表示阅读顺序，阶段内并列任务不连线。任务详情的前序步骤使用数字节点、细连接线和“从早到晚 ↓”顺序标注，完成或异常由状态文字说明；当前节点与前序节点的圆点共用纵向基线。具体流程的执行轨迹保留状态标记与细线，不在相邻节点间逐段添加箭头。

异常独立使用分支图标、虚线边框与“分支”文字，待处理时使用风险色，任务结束后恢复中性色；无正式来源或恢复关系时不补画主线往返箭头。待核对环节单独保留，不接在主线末尾。处理记录固定最近在前，将条数与方向提示合并到标题旁，多条记录标出最新项，不使用推进箭头或排序控件。

复用共享 `MermaidDiagram`、业务视图容器及现有筛选控件。图内支持缩放、拖拽平移和全屏，溢出留在图内。默认按原生宽度与可用宽度中的较小值，根据实际可用宽高适应全图；长图首次打开即可完整显示，不设预览缩放下限，也不需要切换布局触发适配。预览高度不超过 520px 或视口高度的 60%。

所有 Mermaid 图统一使用完整工具栏，直接提供布局切换、适应全图、适配宽度、缩小、当前比例、放大、重置 100% 与全屏；布局切换仅用于支持的图类型。订单环节、业务专题和异常处理沿用共享组件的默认适应全图规则。进入全屏后保持同一套工具，退出恢复行内模式、比例与入口焦点。

缩放工具按当前模式互斥显示选中状态，并以底色、图标颜色和内描边标明；手动操作后再次点击“适应全图”恢复全图模式。模式由用户选择决定，不能只根据缩放百分比判断：自动适配恰好算到 100% 时，仍选中对应的适配按钮。

| 查看状态 | 选中按钮 | 隐藏区域展开、窗口或容器尺寸变化后 |
| --- | --- | --- |
| 适应全图，首次打开默认采用 | 适应全图 | 按可用宽高继续适配并居中 |
| 按可用宽度查看 | 适配宽度 | 继续按当前宽度适配，长图在图内纵向滚动 |
| 手动比例为 100% | 重置 100% | 保持 100% |
| 其他手动比例 | 三个模式按钮均不选中，显示当前百分比 | 保持用户比例 |

查看细节可放大或重置为 100%。HTML 换行标签也必须正确读取原生尺寸，不把短图拉满宽屏。进入全屏或切换布局后选中“适应全图”并自动适配，退出全屏恢复页面原来的模式和缩放。

“切换布局”只调整 flowchart / graph 的根流向，保持文字正向、节点与关系完整，不改文档源码或子图方向；其他图类型不提供该动作。打印按纸面宽度展示完整内容，不继承屏幕缩放和预览高度。折叠的完整图在展开时才挂载，收起后释放；规则说明、空结果和错误提示仍可读取。

布局切换沿用当前画布高度，重渲染期间保留工具栏与原图并显示加载状态；完成后适配新布局，并在可用画布内水平、垂直居中，保持页面及外层滚动容器的位置。放大后超出画布的图仍须能滚动查看全部内容。全屏查看保留原位，退出后恢复焦点且不带动页面滚动。重新选择图表内容时重置预览尺寸，不显示前一张图作为新结果。

保持规则图、模拟样例和实际执行三个口径清楚。CI 图只从当前提交的真实依赖生成；运行缺失或不可读时保留未证明状态。业务图不把 Workflow 完成画成 Fact 过账，权限图不把页面可见画成后端授权。

## 验证与维护 / Validation

组件交互说明按读者问题选择图形：结构和尺寸用解剖标注，同一任务的取舍用并排对比，可执行动作与关闭规则用状态流，实际效果用共享组件演示。默认只展开当前主题与短说明，细则链接规范原文。演示参数标为讲解，不写入用户偏好；尺寸优先读取组件配置，样式数值核对当前 CSS。图解是说明，不能替代真实操作证据。

1. 核对图想回答的问题、箭头含义及领域真源；来源或边界改变时同轮更新图、正文与消费者。
2. 在仓库根目录运行 `node --test scripts/qa/visualization.test.mjs`。该检查解析当前正式文档和已登记的工作台静态说明图，约束流程图规模；历史归档不自动改写。
3. 文档入口或章节变化运行 `node --test scripts/qa/docs-inventory.test.mjs`。动态聚合、筛选和缺失数据使用对应模型测试，不能只比较生成字符串。
4. 页面变化在真实浏览器检查默认、筛选、展开／收起、空结果及相邻区域；确认标签完整、没有页面级横向溢出。设计稿同步受影响交互，避免复制所有业务状态。

语法、规模检查和本地渲染只证明图可读、结构受控；业务含义、权限、运行结果与发布状态仍需各自证据。

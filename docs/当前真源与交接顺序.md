## 当前产品结构

- 产品是一套 Product Core，面向多个毛绒 / 轻工制造客户做独立私有化部署；当前不实现 SaaS 多租户、`tenant_id`、license server、套餐计费或客户工单系统。
- 客户差异通过配置、角色、菜单、字段投影、编号、打印和批准的流程 manifest 表达。配置只能收窄能力，不能改 schema、提升后端 RBAC、绕过领域状态机或改变事实底线。
- 当前稳定客户 key 是 `yoyoosun`。永绅是种子客户和验证来源，不是 Product Core 规则；`reference-customer` 只是中性 draft / preview 工程参考，不是生产实例或交付证据。

新增客户与差异边界见[客户实例策略](product/客户实例策略.md)和[客户差异策略](product/客户差异策略.md)。

## 当前业务边界

| 领域 | 当前主路径 | 不能误判成 |
| --- | --- | --- |
| 主数据 | 客户、供应商、联系人、产品、SKU、材料、单位、仓库、工序和 BOM 使用正式模型 | 客户 Excel、页面或配置是真源 |
| 源单据 | 销售订单、采购订单和加工合同表达业务承诺；草稿修改、提交、取消和版本并发由各自 usecase 管理 | 提交或审批等于库存、出货、质检或财务过账 |
| 采购、库存与质检 | 收货、退货、调整、检验、库存流水和余额分别由领域事实负责，并保留明确来源、批次和数量关系 | Workflow task done 自动写事实，或按名称猜来源和规格 |
| 生产与委外 | 生产订单按锁定 BOM 和显式工艺路线形成 WIP、委外和分段质量事实；机器语义使用正式字段与快照 | 把 WIP 当库存，或把流程文本扩成隐式 MES / MRP |
| 出货与财务 | 财务放行、真实出货、库存扣减、应收 / 应付、发票和收付款分别走独立领域动作 | 审批完成等于已出货、已扣库存或已收付款 |
| Workflow / ProcessRuntime | 负责任务协同、责任池、流程实例和受控领域命令；事实仍由领域 usecase 写入 | 通用 BPMN、第二套业务状态机或事实写入旁路 |
| RBAC 与客户配置 | 有效页面和动作取后端权限、模块状态、active revision 与角色投影的交集 | 前端隐藏或配置授予了后端权限 |
| 页面、帮助与打印 | 展示并办理上述正式对象，给岗位提供业务语言入口和来源追溯 | 页面、PDF、原型或帮助文档本身成为业务真源 |

字段来源与跨模块关系看[业务主链路数据流向与字段来源规则](product/业务主链路数据流向与字段来源规则.md)；Workflow / Fact 细节看[状态工作流事实边界](architecture/状态工作流事实边界.md)；生产路线与 WIP 看[生产工艺路线与在制品边界评审](architecture/生产工艺路线与在制品边界评审.md)；财务语义看[财务第一版](finance/财务第一版.md)。

旧 `business_records / business_record_items / business_record_events` 已退出。不要恢复旧 JSON-RPC、旧页面、旧 seed、旧 source snapshot、别名、fallback 或兼容双写。

本节只给稳定主路径，不声明每项能力已经可用、发布或被客户接受。当前状态回到能力台账；客户是否可用还要绑定固定版本、目标环境验证、岗位 smoke 和实际使用反馈。

### 业务对象退出与纠错

当前业务模块不提供通用回收站。主数据默认走启用/停用，源单据走取消、关闭或归档，事实/台账走取消、冲正、调整或只读。只有允许删除的草稿 / 误建记录才能进入对象专项评审；后端必须检查状态和引用关系，被引用或已生效时拒绝删除并返回可读原因。

“不再活跃”用筛选、状态过滤或归档视图表达；已归档记录仍然是有效历史，归档记录不进入回收站，不使用“回收站 / 还原删除”语义表达取消归档。必须清理脏数据时走管理员级数据修复 / 合并 / 迁移专项，保留审计和可重放脚本。

## Workflow 与 Fact

- Workflow 只负责任务、责任池、流程实例 / 节点、提醒、阻塞、退回和必要的协同派生；ProcessRuntime 只承载已登记节点和白名单领域命令，不是通用 BPMN。
- Source Document、Workflow / ProcessRuntime、Fact / Ledger 是不同真源。任务 `done`、`blocked` 或 `rejected` 只表示协同结果，不能创建、重过账、冲正或取消领域事实。
- 出货财务放行不等于已出货；质检任务完成不等于质检事实完成；仓库协同完成也不自动等于采购或库存入账。
- 幂等、CAS、receipt、恢复、补偿、并发和迁移合同以当前代码、schema、migration 与测试为准，不在本导航页复制。

跨模块的持久化边界、失败关闭和链查询入口统一看[状态工作流事实边界](architecture/状态工作流事实边界.md)与[业务链与运行轨迹边界](architecture/业务链与运行轨迹边界.md)。

## 角色、页面与客户配置

后台权限真源是用户、角色、权限码和 `is_super_admin`。用户可以持有多个角色；岗位差异优先用多角色和责任池表达，不让流程节点写死员工或公司岗位名。

普通账号的有效页面与动作由后端 RBAC、模块状态、active revision、角色投影和撤权共同收窄。客户配置不能增加账号本来没有的后端权限；super admin 也不能绕过领域 usecase。完整口径见[多甲方角色能力与流程编排](product/多甲方角色能力与流程编排.md)与[配置与权限策略](product/配置与权限策略.md)。

## 客户资料、公开资源与导入

- 客户原始 Excel、PDF、图片、工程资料和员工信息保留在每客户专属 Private 仓库或经确认的等价受控存储，不进入 Product Core 或公开前端产物。
- Product Core 只保存审查后的配置、公开资源、通用工具、合成 fixture 和脱敏类别映射；普通构建、测试、CI 和源码包不依赖私有仓库或凭据。
- 当前仓库没有真实客户数据导入执行器。现有提取、冻结和 dry-run 工具不连接正式业务写入；模拟 seed / fixture 不能写成真实导入结果。
- 客户交付结论必须绑定固定产品版本、目标环境、active 配置、岗位验证和客户实际反馈；本地绿色或较早版本证据不能替代当前交付。

客户实施与产品边界见[新增甲方客户实施流程](product/新增甲方客户实施流程.md)、[客户实例策略](product/客户实例策略.md)和受控客户交付资料。

## 打印边界

采购合同、加工合同和工程资料打印复用正式模板工作台。业务行来自 Source Document 或正式映射，客户配置只提供抬头、模板选择和获准公开的资源；预览或生成 PDF 不等于签章、批准、入库、结算或事实过账。详见[打印模板实现原理](打印模板实现原理.md)和[打印模板字段与编辑行为清单](打印模板字段与编辑行为清单.md)。

## 前端入口

- 正式 ERP 菜单只显示可用或明确受控的业务页；开发、治理、文档和原型入口只在 `/__dev/**`。
- 岗位任务端使用 `/m/<role>/tasks`；岗位帮助使用 `/erp/help-center`，多岗位账号必须显式选择当前办理岗位。
- 用户可见文案使用业务语言，不展示无必要的 Workflow / Fact、raw id、内部 key 或底层英文异常。

页面来源与菜单口径见[页面来源生成入口规则](product/页面来源生成入口规则.md)和[菜单映射评审表](product/菜单映射评审表.md)；具体布局、权限解释和交互行为回到当前前端代码与测试。

## 测试与发布

- 测试按影响面从[自动化测试策略](product/自动化测试策略.md)和 [QA 说明](../scripts/qa/README.md)选择；页面 / 样式变更再做真实浏览器验证。

# 产品完成路线图 / Product Completion Roadmap

- 文档类型：长期产品方向
- 状态：当前规划真源
- 作用域：说明产品往哪里发展、什么条件下进入下一类工作
- 不替代：当前代码、schema / migration、能力状态、目标环境证据或客户验收

## 怎么使用

本文不是实施阶段表、当前完成清单或甲方逐级确认表。普通需求不需要从头走完本文，也不按里程碑编号施工：

- 判断当前是否可用，看[当前真源与交接顺序](../当前真源与交接顺序.md)、[产品能力进度台账](产品能力进度台账.md)、代码、migration 和测试。
- 把甲方需求或反馈交给 Codex 闭环，看[模块实施治理](模块实施治理.md)。
- 判断 Workflow、Source Document 与 Fact 的责任，看[模块边界](模块边界.md)和[状态、工作流与事实边界](../architecture/状态工作流事实边界.md)。
- 判断部署、升级和回滚，看[部署约定](../部署约定.md)及 `server/deploy/README.md`。

路线图只在长期方向、进入条件或明确不做的范围变化时更新；不得复制能力台账、单轮测试结果、历史发布回执、客户待确认项或补丁过程。

## 产品定位

`plush-toy-erp` 是面向毛绒玩具及相近轻工制造企业的 ERP 产品内核。当前形态是：

- 一套 Product Core。
- 一套可复用的行业默认配置。
- 每个客户独立的配置、资料和私有化部署证据。
- 只有真实需求无法由 Core、行业默认或配置承接时，才评审 Customer Extension。
- 多个私有化客户稳定运行后，才单独评审 SaaS、多租户、license 和计费。

客户输入推动产品改进，但单个客户的公司名、原始资料、特殊字段或流程不能直接成为 Product Core 规则。

## 长期方向

| 方向 | 目标 | 进入或继续条件 | 不在这里记录 |
| --- | --- | --- | --- |
| 核心业务正确性 | MasterData、Source Document、Workflow、Fact、RBAC、API / UI 各守真源，主链可恢复、可审计 | 当前客户需求或已实现能力暴露真实缺口 | 单项实现进度、测试输出和字段清单 |
| 客户实际可用 | 岗位人员能在固定版本完成真实工作，反馈能快速进入修正循环 | 有明确业务目标、岗位和可观察结果 | 要求甲方阅读代码或确认内部层级 |
| 私有化交付与恢复 | 固定制品、migration、配置、健康检查、备份恢复和回滚可复核 | 每次明确的目标环境发布授权 | 历史发布回执和本地绿色摘要 |
| 行业模板与复制 | 从真实客户共性沉淀角色、菜单、字段、编号、打印和导入默认 | 至少出现可复核的跨客户共性 | 把第一客户特殊项直接泛化 |
| 外部集成与 SaaS | 扫码、设备、银行、税控、总账或多租户按真实价值单独评审 | 出现明确客户、数据、运维和合规需求 | 为未来可能性预建平台或配置引擎 |

这些方向不是客户验收层级，也不要求全部同时推进。下一项工作由真实需求、风险和当前阻塞决定。

## 个人开发与客户反馈循环

当前默认由项目负责人使用 Codex 完成讨论、开发和测试，并在取得明确授权后部署。甲方可以在其他聊天软件提出需求、校对方案或反复反馈；项目负责人把明确范围带回 Codex 后，按下面方式推进：

1. 用业务语言说明目标、痛点、岗位和预期结果。
2. Codex 回到真实代码和正式文档，提出最简单的可闭环方案。
3. 在同一个业务切片内实现必要的正确性、权限、异常恢复和基础易用性。
4. 按风险验证；本地实现、目标环境发布和甲方业务验收分别陈述。
5. 获得发布授权后部署固定版本，甲方按实际使用继续反馈。
6. 反馈按缺陷、原需求细化或新需求进入下一轮，不反向否定旧版本的真实完成状态。

甲方只需理解业务结果、版本、使用方式和已知边界，不需要确认代码结构、架构责任层、验证内部键或测试形态。

## 选择下一项工作的原则

优先顺序不是固定阶段，而是以下判断：

1. 先处理会造成错账、越权、数据损坏、无法恢复或主路径阻断的问题。
2. 再处理甲方正在使用或即将使用的明确需求和痛点。
3. 在扩展新能力前，先补齐与当前需求直接相关的闭环缺口。
4. 复用现有真源、usecase、组件和运维入口；没有真实需求不增加抽象、配置、状态、后台任务或兼容分支。
5. 客户需求确实需要复杂方案时，写清现有能力不足、简单替代为何不够、增加的维护和验证成本。
6. 目标环境、真实数据、客户签收或外部系统尚未具备时，只报告精确边界，不用更多本地实现掩盖外部阻塞。

## 长期边界

以下边界不会因路线图简化而放宽：

- Workflow 管协同，Source Document 管业务承诺，Fact / Ledger 管真实发生；任务完成不等于库存、出货或财务已经过账。
- 复用现有主数据、采购、库存、质检、生产、出货、财务和 RBAC 真源，不重复造表、别名或双写。
- 已生效事实按领域使用取消、冲正、调整或只读审计，不设计通用物理删除。
- 客户真实资料、导入和私有部署证据继续走受控边界，不进入 Product Core 源码包。
- 本地测试、页面存在、历史发布或模拟数据都不能冒充当前目标环境和甲方验收。
- 当前不做 `tenant_id`、SaaS 多租户、license server、套餐计费、低代码平台或通用 BPMN 引擎，除非出现真实需求并完成专项评审。

## 维护规则

- 长期方向和进入条件改变时才更新本文。
- 产品能力状态改变时只更新[产品能力进度台账](产品能力进度台账.md)。
- 当前代码、菜单、schema、migration 或部署入口改变时更新对应真源，不在本文复制。
- 单客户决定、发布、UAT、签收和真实资料只进入对应受控交付资料。
- 不再增加编号阶段、完成百分比、全量实施清单或另一张能力汇总表。

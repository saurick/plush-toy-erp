# 产品能力进度台账 / Product Capability Ledger

本文是 `plush-toy-erp` 唯一的全局产品能力状态表，只回答三件事：当前能不能用、主要可用范围是什么、还差什么。目标环境发布、真实账号、培训、客户试用、UAT 和签收由对应客户的受控交付资料与环境 evidence 管理，不在 Product Core 源码包中复制。

## 怎么查

1. 先在“能力状态”中定位业务能力。
2. 需要确认字段、状态、Workflow / Fact 或实现细节时，继续看对应专题文档、代码、migration 和测试；本表不复制领域合同或测试清单。
3. 产品状态不能推出目标环境已发布，也不能推出客户已验收。

代码、schema、migration、测试和运行态证据与本文冲突时，以前者为准并修正本文。完整阅读顺序见[当前真源与交接顺序](../当前真源与交接顺序.md)。

## 状态口径

| 产品状态 | 含义                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 待办     | 只有需求线索或评审结论，当前还不能使用                                                                         |
| 实现中   | 已有部分能力，但尚未形成岗位人员可用的完整主路径                                                               |
| 可试用   | 当前承诺范围内的主路径、真源、权限、异常、测试、正式页面和帮助已经收口，可在固定版本中试用；已知边界写在对应行 |
| 暂不做   | 不在当前版本范围，出现真实需求后再评审                                                                         |

这些状态不是开发阶段，也不要求客户逐级确认。`可试用` 是本台账对当前承诺范围的完成状态，但不等于已部署到目标环境或已完成客户 UAT。面向甲方只说明具体需求在哪个固定版本可用、是否已发布、已知边界和反馈处理结果；不要求甲方阅读整张台账、代码、架构层、验证内部键或测试形态。

## 能力状态

| 业务能力                                     | 状态   | 当前可用范围                                                                                                                                 | 主要边界 / 下一步                                                                    |
| -------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Workflow、ProcessRuntime 与业务事实边界      | 可试用 | Workflow、ProcessRuntime、Source Document 与业务事实已分层；销售、采购和出货审批已有明确拒绝终点，独立领域动作才写库存、生产、出货或财务事实 | 复杂异常下的自动恢复与跨模块一致性继续按实际问题补强；目标环境另行验证               |
| 主数据、SKU、BOM 与固定生产路线              | 可试用 | 客户、供应商、联系人、产品、显式 SKU、材料、单位、仓库、工序和版本化 BOM 已接入正式页面与权限；固定路线在生产订单发布时冻结                  | 不从客户文件或名称文本猜 SKU、单位、路线和历史分类；真实数据导入另行办理             |
| 销售订单                                     | 可试用 | 草稿、并发版本、提交审批和批准后激活已接                                                                                                     | 订单批准不代替出货、库存或财务事实                                                   |
| 采购订单、收货、质检、退货与调整             | 可试用 | 采购草稿、审批、收货、来料质检、入库、来源退货、调整、取消冲正和应付入口已有事务与幂等边界                                                   | 收货、质检和入库独立办理；当前采购退货不重开可收量                                   |
| 库存、批次与预留                             | 可试用 | 库存流水不可直接改写；余额、批次、盘点、调拨、人工调整，以及销售订单行预留、释放和出货消费已接                                               | 完整 WMS、真实库位、历史库存重分类和客户真实导入不在当前承诺内                       |
| 出货                                         | 可试用 | 来源、出货前质检、财务放行、正式出货、库存出库和取消冲正已形成追溯链                                                                         | 财务放行不等于已出货                                                                 |
| 应收、应付、发票、收付款、核销与红冲         | 可试用 | 来源应收应付、发票、真实收付款、多单与部分核销、冲正和红冲已接                                                                               | 银行直连、总账和税控不在当前版本范围                                                 |
| 生产订单、WIP、生产事实与委外                | 可试用 | 订单与 BOM 快照、固定路线、WIP 数量守恒、分段质检、领料、完工、返工、异常决定，以及委外合同、发料、回货和应付已接                            | 批准只形成决定或额度，事实仍须显式执行；目标发布和岗位使用另行验证                   |
| 业务附件与审计                               | 实现中 | 受控上传、一次性撤销、授权下载、完整性校验和基础操作记录已接                                                                                 | 模块级审计覆盖、特权调阅、保管策略、对象存储运维和恶意文件扫描仍需评审               |
| 岗位任务端与岗位帮助                         | 可试用 | 多岗位入口、任务、数量守恒、动作锁、附件、异常留痕、受控返工安排和岗位帮助已接                                                               | 通用任务完成不写业务事实；真实账号、扫码与现场使用另行取证                           |
| 客户配置与受控发布                           | 可试用 | 配置校验、发布、激活、回滚、有效 revision、页面与动作投影和审批责任配置已接                                                                  | 配置不能改写业务事实或提升权限；具体目标环境发布仍逐次授权和取证                     |
| 客户数据导入与私有部署包                     | 实现中 | 只读提取、manifest、来源冻结和 dry-run 可运行；Product Core 与客户原件、私密 manifest 已分离                                                 | 当前没有获准真实数据和正式写入执行器；产品版本、目标发布、真实导入和客户签收分别取证 |
| 行业模板与多客户复制包                       | 实现中 | 已有内部候选和新增客户包模板                                                                                                                 | 不代表已有第二真实客户，也不代表 SaaS 或多租户                                       |
| Customer Extension、通用报表、扫码与外部集成 | 待办   | 只有 Core、行业模板和配置无法承接的真实需求才评审 extension；其余能力尚未形成统一产品范围                                                    | 等事实层稳定且出现真实需求后再评审，不预建运行时扩展层                               |
| SaaS、多租户、license 与计费                 | 暂不做 | 当前按单客户私有化部署和客户配置包管理                                                                                                       | 不新增 `tenant_id`、license server 或套餐计费                                        |

## 维护规则

- 只有产品状态、可用范围、主要边界或关键阻塞发生实质变化时才更新对应一行。
- 普通缺陷修复、重构、样式、文案和测试补强不更新本表。
- 不复制领域合同、测试输出、补丁历史、客户待确认项或目标环境流水。
- 客户启用、发布、UAT、签收和客户差异只更新对应客户的受控交付资料。
- 实现与本文冲突时先核对正式真源，再修正文档；不得反向修改实现来迎合台账。

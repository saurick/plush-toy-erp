# 配置与权限策略 / Config And Permission Policy

## 分层

| 层 | 作用 |
| --- | --- |
| Feature Flag | 控制客户启用哪些模块或产品内置流程模式 |
| RBAC | 控制角色、权限、动作、职责和岗位任务端入口 |
| Data Scope | 控制用户能看或能操作哪些数据范围 |
| State Machine | 控制当前状态是否允许执行动作 |
| Idempotency | 防止重复提交、重复回调、重复扣库存或重复开票 |
| Audit Log | 记录关键配置、权限、状态和业务事实变化 |
| Approval Responsibility | 固定审批事项的启停、主办 / 备用 / 升级责任池及角色 / 具名成员 |

业务动作判断顺序：

1. Feature Flag：客户是否启用该模块。
2. RBAC：用户是否拥有动作 / 职责权限。
3. Data Scope：用户是否拥有数据范围权限。
4. State Machine：当前状态是否允许该动作。
5. Idempotency：同一动作是否已经处理过。
6. Audit：记录谁在何时做了什么。

审批办理还必须取四层交集：

```text
可办理审批 = Product Core RBAC
          ∩ active/stored revision entitlement
          ∩ task owner pool 的角色或具名成员
          ∩ assignee、状态、version 与幂等合同
```

管理员页面只维护固定审批模板，不提供表达式或任意流程设计器。草稿预览返回最终有效角色、责任层级和阻塞原因；常规“保存并生效”同时要求发布与激活权限，并在一个后端事务内按 active revision/hash CAS 写入 immutable revision、完整投影和 active 切换，失败整体回滚。通用客户配置控制面仍保留独立 publish / activate 合同，用于受控发布流水线。事务提交后启动的新 ProcessRuntime 立即读取新 active revision，已启动实例继续读取自身冻结 revision。

## 客户可以配置

- 公司名、logo、主题色。
- 菜单开关、模块开关。
- 字段显示、字段必填。
- 编号规则。
- 打印抬头、页脚、logo、公司信息等低风险展示参数，或客户打印样本引用；不包含通用打印模板引擎。
- 角色模板、权限模板。
- 初始化数据。
- 默认仓库、默认单位。
- 销售订单、采购订单和 Shipment 财务放行三项可配置审批的启停、主办 / 备用 / 升级成员。

## 客户不能配置

- 库存扣减规则。
- 入库增库存规则。
- 库存流水删除。
- 财务核销逻辑。
- 审计关闭。
- 核心状态机自由拖拽。
- 数据库结构。
- 自定义业务对象。
- 已登记客户退货、收付款、库存人工调整和生产异常流程的固定责任池；这些责任由 Product Core 流程合同管理，不能在三项审批责任模板中任意改写。
- 尚未登记的 PMC / 工程自由审批流程或任意条件表达式。

## 流程节点绑定职责

流程节点绑定固定审批事项、责任池和稳定职责 / 权限，不把岗位称谓直接写死到节点：

| 节点 | 建议职责 / 权限 |
| --- | --- |
| shipment.release | `workflow.task.approve` + Shipment 财务放行责任池；批准后仍由正式 Shipment usecase 写门禁 |
| sales_return.approve | `sales_return.approve` + 老板固定责任池；批准只改退货 Source，仓库显式收货才写库存与 RMA 待检 |
| finance_payment.approve | `finance.payment.approve` + 老板固定责任池；批准只改收付款 Source，财务显式过账才写分配与结清读模型 |
| inventory_adjustment.approve | `warehouse.adjustment.approve` + 老板固定责任池；批准不改库存，仓库显式过账才写流水和余额 |
| production_exception.approve | `production.exception.approve` + 老板固定责任池；批准只记录决定或超领额度，生产显式执行才写 SCRAP / WIP，超领仍由正常领料消费 |
| material_readiness.confirm | `material_readiness.confirm` / `pmc.plan.update` |
| quality.inspection.pass | `quality.inspection.update` 或后续独立 pass 动作 |

客户角色再绑定这些职责。不同客户有不同岗位名称时，不需要改 Product Core。

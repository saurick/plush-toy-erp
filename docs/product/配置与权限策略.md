# 配置与权限策略 / Config And Permission Policy

本文说明客户配置怎样在 Product Core 上收窄功能。它不是权限码清单、流程设计器说明或客户实例交付记录；角色和责任池看[多甲方角色能力与流程编排](多甲方角色能力与流程编排.md)，当前实现仍以代码、active revision 和测试为准。

## 业务动作怎样判定

```text
基础授权 = 后端 RBAC
        ∩ enabled 模块
        ∩ active revision entitlement
        - 当前角色 revoke

当前可执行 = 基础授权
          ∩ 来源读取权限
          ∩ owner / assignee / 责任池
          ∩ 数据范围
          ∩ 对象状态、版本、幂等和领域门禁
```

多角色账号先分别计算每个角色的 entitlement 与 revoke，再取并集。页面或按钮可见、前端隐藏和 super admin 身份都不替代服务端校验。

## 当前已经生效的客户配置

| 配置面 | 当前能力 | 边界 |
| --- | --- | --- |
| 模块状态 | `enabled / read_only / disabled` | 关闭模块不删表、migration 或历史事实；写动作仍由后端拒绝 |
| 页面投影 | `rolePageProjections` | 只收窄岗位页面，不授予后端权限 |
| 动作投影 | `access_entitlements` + 角色 revoke | 不能超过 Product Core 内置角色 RBAC 上限 |
| 审批责任 | 销售订单、采购订单、出货财务放行三项的启停、主办 / 备用 / 升级成员 | 收付款、库存调整和生产异常使用固定流程合同；返工回厂不使用审批模板 |
| 字段投影 | `customers.default`、`suppliers.default`、`sales_orders.default` 的列表 / CSV 列 | 当前只支持 `visible`，不支持 `label / editable / required`，也不改表单和领域校验 |
| 品牌与菜单 | 审查后的公开品牌资源、菜单分组和岗位推荐 | 私密资料、工程图、员工 PII 不进入公开产物 |

客户包还可以保存编号、打印、导入映射和流程候选等评审资料；只有已登记 catalog、后端 validator、运行时消费者和测试全部存在的部分才是当前能力。`preview_only / review_required / deferred` 不能写成已经生效。

## 未来扩展必须先登记

以下内容不是任意 JSON 配置项。确有客户需求时，先补 Product Core catalog、后端约束、运行时消费者和测试，再开放声明式配置：

- 新的字段 surface，以及显示、必填、可编辑或标签策略。
- `warehouse_set / owner_only` 等固定数据范围。
- 新编号格式、导入适配、打印模板或外部系统 adapter。
- 新流程变体、责任池或业务动作 capability。

客户配置不能上传 SQL、脚本、Go / JavaScript 插件、任意过滤表达式或隐藏执行器。

## 客户不能配置

- 数据库结构、客户专属 migration、自定义业务对象或核心 usecase 分叉。
- 库存增减、质检准入、真实出货、财务核销等领域事实底线。
- 提升后端 RBAC、关闭审计、绕过幂等或改变 Source / Fact 生命周期。
- 自由拖拽核心状态机、增加未登记节点，或改写固定审批 / 执行责任。
- 把客户原始文件、Secret、员工个人信息或真实业务行发布到 Product Core。

## Revision 与审批责任

配置 revision 经过 validate → publish → activate。普通业务会话只读取 active revision；真实客户部署缺少 active revision 时失败关闭，不回退为 RBAC-only。

审批责任草稿先预览有效成员和阻塞原因。“保存并生效”要求发布与激活权限，并按 active revision / hash CAS 在单个事务中写 immutable revision、完整投影和 active 切换。新 ProcessRuntime 使用新 revision，既有实例继续使用启动时冻结的 revision。

流程节点绑定稳定 capability 和责任池，不绑定客户岗位称谓。六条已登记 ProcessRuntime、三项可配审批和三项固定责任的当前边界见[多甲方角色能力与流程编排](多甲方角色能力与流程编排.md#审批责任与流程选择)。

# 发布门禁 / Release Gates

## 完成定义 / Definition of Done

| 层                | DoD                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| Product Core      | schema / usecase / tests / docs 同步，核心事实规则不按客户分叉                                        |
| Industry Template | 默认角色、菜单、字段、流程和 seed template 明确，不污染核心事实                                       |
| Customer Config   | 客户差异有配置位置、审批记录和回滚方式                                                                |
| Workflow          | done / blocked / rejected、reason、幂等、终态保护和非目标任务测试覆盖                                 |
| MasterData        | 字段真源、唯一约束、导入和历史缺值回补路径明确                                                        |
| Fact              | happy path、非法状态、重复提交、取消 / 冲正、幂等、事务失败和不可物理删除覆盖                         |
| RBAC              | 未登录、disabled、非管理员、无权限、角色不匹配、super_admin 和业务边界覆盖                            |
| API / UI          | UI 只展示和提交动作，不承接后端事实逻辑；后端仍校验权限和状态                                         |
| Help / QA         | 当前不维护产品内 docs registry；未来若恢复帮助或验收入口，必须同步导航 seed、菜单权限、路由和验收文档 |
| Delivery / Ops    | migration、备份恢复、发布、健康检查、smoke、回滚和清理记录明确                                        |

## Release candidate promotion

| 层           | 必须绑定                                                                               | 通过口径                                                                                                      | 不能证明                  |
| ------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 本地质量     | clean HEAD、非零执行数、零失败、零意外 skip                                            | `full`、`strict`、`prepare-push` 绑定最终树                                                                   | 远端 CI 或部署            |
| 本地业务验收 | 同一 clean SHA、按批人工验收库与 `browser_actions` 库、隔离后端和真实浏览器              | 九岗位数据、52 项只读页面、四条真实写异常流、停服删库与残留读回全部通过                                      | 133 或客户 UAT / 签收     |
| 远端 CI      | push 后的同一 40 位 SHA                                                                | required job 绿色终态；queued / cancelled / skipped / 其他 SHA 均不算                                         | 镜像已生成或 133 已发布   |
| 不可变制品   | 同一 SHA、`linux/amd64` content ID、tar checksum、SBOM、migration 序列、客户配置源指纹 | manifest 与加载后 image inspect 全部一致，source / image metadata secret scan 通过                            | 目标 active config 或运行 |
| 本地发布演练 | 同一制品、一次性 `plush_erp_release_<run-id>`、唯一生产 Compose                        | migration readback、health / ready / identity、登录、local-test config、PDF、备份恢复、steady restart、零残留 | 133 或客户验收            |
| 133 技术发布 | exact SHA / content ID、目标数据库 / migration / active config、rollback point         | 正式 preflight、备份、迁移锁、load / pull、runtime readback、smoke 与恢复证据                                 | 客户 UAT / 签收           |

失败停在当前层。禁止从 dirty tree 打包、在 133 构建、使用 `dev/latest` tag、用旧 CI / 旧镜像 / 旧目标 evidence 拼接，或把本地演练、技术发布写成客户验收。

## 必测门禁

- blocked reason 必填，trim 后不能为空。
- 同一 workflow event 幂等。
- 同名但非目标 task 不触发。
- settled 终态保护。
- `shipment_release` 不写 `inventory_txns / shipments / reservations / AR / invoice`。
- `shipping_released` UI 不能显示成已出库。
- 中文文案修改不影响业务逻辑。
- UI 隐藏按钮后，后端仍校验权限、状态和数据范围。

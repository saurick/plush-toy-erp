# 菜单与正式入口合同 / Menu And Formal Entry Contract

本文说明正式 ERP 入口由谁定义、客户配置怎样收窄、菜单变更要同步什么。它不复制当前全部菜单，也不把候选原型写成已实现能力；具体菜单、路由、权限和页面状态始终以当前代码、active customer revision 和测试为准。

## 当前结论

- Product Core 只维护一套正式入口，不为客户复制菜单代码或业务页面。
- 客户配置可以隐藏、排序、分组、改低风险显示文案和推荐岗位入口，但不能新增后端权限、路由、业务对象或事实能力。
- 页面可见、菜单可点和动作可执行是三件事。任何业务动作仍由服务端 RBAC、模块状态、active revision、来源读取权、责任池、对象状态和领域 usecase 共同校验。
- Workflow / ProcessRuntime 页面只办理协同或已登记的领域命令；任务完成不等于库存、质检、出货或财务事实生效。
- `/__dev/**`、原型、治理、测试和项目文档只属于开发工作台，不进入正式 ERP 菜单。

## 运行时真源

| 层面 | 当前真源 | 职责 |
| --- | --- | --- |
| 默认导航与分组 | `web/src/erp/config/seedData.mjs`、`businessModules.mjs`、`web/src/erp/utils/businessModuleGroups.mjs` | 定义正式页面、业务归属、模块成员顺序、侧栏投影和默认入口 |
| 前端权限投影 | `web/src/erp/config/menuPermissions.mjs` | 从正式导航生成菜单权限分组和角色预设 |
| 后端菜单 | `server/internal/biz/rbac.go` 的 `BuiltinAdminMenus()` | 登录菜单、权限管理选项和后端 required permissions |
| 客户菜单 | `config/customers/<customer-key>/menuConfig.mjs` 与部署注入的 `customer-config.js` | 在 Product Core 上收窄显隐、排序、分组和文案 |
| 最终有效入口 | `customer_config.get_effective_session` 与当前账号 RBAC | 返回当前客户、账号和角色真正可进入的页面与动作 |
| 页面行为 | 当前路由、页面、API client、后端 handler / usecase 和测试 | 决定页面能做什么，菜单不能替代这一层 |

只改其中一层会造成漂移。菜单或路由变化时，必须同时核对前端默认导航、客户配置、后端内置菜单、权限投影、帮助文档和测试。

## 可见与可执行边界

```text
页面可见 = 后端菜单允许
        ∩ Product Core 页面存在
        ∩ active revision 页面投影
        ∩ 当前角色页面投影
        ∩ 模块可读

动作可执行 = 后端 RBAC
          ∩ active revision entitlement
          ∩ 模块可写
          ∩ 来源读取权与数据范围
          ∩ owner / assignee / 责任池
          ∩ 对象状态、版本、幂等和领域规则
```

前端隐藏不是安全边界；super admin 也不能绕过领域状态、事实真源和 active customer revision 的失败关闭规则。

## 入口颗粒度

桌面侧栏直接显示获准模块，模块内页面通过页签进入；侧栏底部只保留账号入口。模块切换与页签跳转沿用当前页面的离开检查，取消离开保留编辑内容；再次点击当前页面不触发刷新。

| 表达位置 | 应表达 | 不应表达 |
| --- | --- | --- |
| 菜单分组 | 稳定业务域，如销售、采购、仓储、生产、财务 | 把多个流程步骤拼成一个长期分组 |
| 菜单入口 | 稳定业务对象或工作台，如销售订单、库存台账、任务看板 | 用入口存在暗示未实现能力已经可用 |
| 模块页签 / 页面筛选 | 模块页签切换同一业务域的获准页面；页面筛选改变当前对象的状态、队列或查询条件 | 以视觉合并扩大权限，或新建第二套状态机和事实判断 |
| 页面动作 | 新建、提交、审批、过账、取消、冲正、打印等真实动作 | 用按钮文案掩盖无来源或无后端闭环 |
| 岗位任务端 | 当前岗位的任务、交接和可恢复办理路径 | 复制整棵桌面菜单树 |

当前 yoyoosun 配置使用 `sectioned`，完整业务侧栏使用四个导航区；无可见入口的区不显示，不额外生成“常用工作”分组：

| 导航区 | 职责 |
| --- | --- |
| 工作中心 | 工作台、任务和进度概览 |
| 业务模块 | 按 `businessModules.mjs` 的正式业务域生成，每个模块一个入口 |
| 工具与查询 | 打印工具与历史记录查询 |
| 系统与帮助 | 权限、系统操作记录与帮助中心 |

模块成员和标准默认顺序由正式业务目录统一定义，单页模块直达，多页模块显示页签。所有投影都先过滤页面权限；模块默认入口只从获准页面选择，客户页面数组排序不作为隐式默认入口。当前四区菜单不使用岗位推荐或自定义排列。最近访问恢复前必须重新验证权限。

客户配置可以收窄和调整展示顺序，正式业务归属仍使用页面所属业务域。模块页签保留模块内各个获准页面，权限配置中的菜单预览从同一来源按业务归属投影，不另建页面成员或权限清单。采购入库明确限定采购收货来源，生产成品入库继续由生产记录办理；跨模块协作使用关联跳转，不改变模块归属。

权限管理的“岗位导航”只读核对“实际菜单 / 页面访问”：实际菜单按当前业务模块生成侧栏入口；页面访问逐页展示岗位授权、最终结果及受限原因。内部页面即使可进入，也不会因此新增侧栏入口。菜单排列、常用工作、自定义顺序和默认页面设置已经退出权限配置页；查看或切换视图不产生修改。未保存的功能草稿会更新预览，保存岗位设置后才生效。

权限与仓库范围仍通过现有 `set_role_settings` 接口按一个角色 version CAS 原子保存；该请求将已有导航字段归为标准推荐模式和空路径集合，不让旧排列阻断权限保存。读取岗位不会自动修改已有记录，不改变页面和动作权限。

来源生成、事实动作和只读台账的入口规则见[页面来源生成入口规则](页面来源生成入口规则.md)。

### 工作台汇总 / Workbench summaries

`/erp/dashboard` 默认打开待办；有可查看汇总的账号显示“待办 / 汇总”页签。汇总页内切换销售订单汇总、材料汇总，后续维度放在相应视图的筛选中。汇总不单设侧栏菜单，也不在默认待办页预取数据；切换页签保留各自筛选。岗位任务端继续围绕具体任务办理材料审批。

可见性复用当前有效权限，不按角色名称硬编码。工作台页面可见且有 `erp.workbench.read` 是共同条件：销售订单汇总另需 `sales_order.read` 和 `sales_order_item.read`，材料汇总另需 `engineering.material.read` 和 `sales_order.read`。

没有任何可查看汇总时隐藏整个汇总页签；只开放一种时直接显示该视图。后端清单查询同步校验这些读取权限及客户模块状态，单价等商业字段仍独立受字段读取权限约束。

销售订单汇总是跨订单、每款产品一行的只读投影，分页查询原订单与明细，可按当前筛选导出 CSV 并返回原订单。生产数量沿用订单数量加船头版数量，未出货数沿用真实出货记录计算；行交期优先于订单默认交期，显示为“计划交付日期”。设计师来自关联 BOM，缺少事实依据时保持空值，不从原表备注补造。材料汇总列出已提交的用料审批记录，详情绑定具体提交记录；订单及任务中的材料入口继续复用同一详情组件。

## 候选菜单与原型

[交互设计](ui-design/README.md)提供最新 HTML、设计说明与依据；正式菜单、RBAC、route、schema、migration 和客户配置仍以各自合同为准。

候选入口进入运行时前，至少回答：

1. 它服务哪个岗位和高频任务，是否已有更直接入口。
2. 页面、路由、API、RBAC、模块状态和恢复态是否真实存在。
3. 它是 MasterData、Source Document、Workflow、Fact、Ledger 还是只读报表。
4. 客户配置是收窄已有能力，还是试图创造新的 Product Core 能力。
5. 旧入口是否应直接退出；本项目不为未发布草稿保留兼容别名或重定向。

## 变更与验证

菜单或正式入口变化时按以下顺序收口：

1. 先确认页面职责、字段真源和业务动作已经闭环。
2. 修改前端导航、业务模块和路由。
3. 同步后端内置菜单、required permissions 和客户配置投影。
4. 核对帮助、培训、原型状态和本文件是否仍准确。
5. 覆盖未登录、disabled、无权限、模块关闭、active revision 缺失、多角色账号和直接 URL 访问。
6. 用真实浏览器检查默认态、切换态、无结果、无权限和恢复态；菜单可见性测试不能替代业务动作测试。

最低静态入口：

```bash
node --test web/src/erp/config/seedData.test.mjs web/src/erp/config/menuPermissions.test.mjs
cd server && go test ./internal/biz ./internal/service
```

实际执行范围以[自动化测试策略](自动化测试策略.md)和 `bash scripts/qa/affected.sh --plan` 为准。

## 登录入口与客户菜单投影

本节 `src/` 路径相对 `web/`。读取顺序是：**登录 → 核对部署客户与 effective session → 过滤菜单 → 判断当前路由 → 由后端鉴权业务请求**。

### 登录与入口选择

| 情况 | 行为 |
| --- | --- |
| 统一登录 | `/admin-login` 承接电脑版与手机版；不在登录前选择岗位 |
| 默认入口 | 手机选岗位任务端，电脑选后台，平板无历史选择时保留入口选择；手动选择优先并随刷新恢复 |
| 入口配置 | `entryConfig.mjs` 与 `window.__PLUSH_ERP_ENTRY_CONFIG__` 控制显隐，不授予权限 |
| 登录后岗位 | 先使用已授权的明确深链，否则进入首个可用 `mobile.<role>.access` 岗位；最终按刷新后的账号状态、权限、菜单和 effective session 判断 |
| 账号体系 | 统一使用 `admin_users`、角色与权限码；普通 `users` / `user` RPC、旧 `/login`、`/admin-accounts`、`/admin-users` 不再提供入口或重定向 |

短信能力由后端 `auth.capabilities` 决定。登录方式随刷新恢复，验证码倒计时在当前标签页刷新后继续；浏览器存储失败时保留本次选择，不读回失效旧值。

| 短信结果 | 可显示的信息 |
| --- | --- |
| 后端明确 `mock_delivery=true` | 可显示临时验证码；冷却期重试复用有效码及原失效时间、重发时间和剩余次数 |
| 真实 provider | 只显示“请求已受理”，不承诺送达 |
| 账号未知、停用、无岗位、频控或 provider 异常 | 公开响应不泄露账号有效性；真实资格与频控由后端执行，日志与 Trace 脱敏 |
| 验证码错误或过期 | 按后端错误码显示中文提示 |

### 静态外观与运行态配置

| 来源 | 负责的内容 | 不负责的内容 |
| --- | --- | --- |
| `seedData.mjs`、`customerMenuConfig.mjs` | 产品导航及客户候选菜单 | 最终授权 |
| `brand.js` | 中性产品名 | 客户身份选择 |
| 部署的 `customer-config.js` / `window.__PLUSH_ERP_CUSTOMER_CONFIG__` | 品牌、favicon、菜单分组、排序、显隐和文案；同时声明部署 customer key | 后端权限、业务事实 |
| `customer_config.get_effective_session` | active revision 的页面、动作、字段策略和责任池投影 | 代替领域 usecase 鉴权 |

默认产品构建不打包客户配置，也不通过 `VITE_ERP_CUSTOMER_KEY` 或 `window.__PLUSH_ERP_CUSTOMER_KEY__` 查找内置客户。部署时注入 `customer-config.js` 和客户资产；可用 `config/customers/yoyoosun/customer-config.example.js` 生成。后端查询未传 customer key 时落到中性 `demo`，不自动选择 yoyoosun。

### 先判断能否挂载客户业务

已声明部署 customer key 时，`ERPLayout` 等待首次 profile / effective session 同步，并要求 key 一致。正式构建、静态预览、同步失败、缺失或 key 不匹配且无同客户缓存时，显示“暂时无法进入工作台”，不挂载业务 `Outlet`，也不降级为全量后台。

| 运行场景 | 菜单与数据挂载边界 |
| --- | --- |
| 普通账号，正常 active revision | 菜单取 RBAC 路径与 active pages 交集；业务数据仍由后端权限与领域规则保护 |
| super admin，带有效 customer key 的 active revision | 可审阅完整产品菜单、动作及字段；`dataRuntimeScope=customer_runtime`、`canMountCustomerBusinessPages=true`，读取该客户运行环境。后端写入门禁不放宽 |
| 无客户 key 的 Product Core super admin | 仅控制面导航；`/erp/dashboard` 为产品核心总览，直达客户数据页只显示能力审阅，不查询客户事实 |
| 中性构建同步失败的 super admin | `dataRuntimeScope=sync_failed_diagnostic`、`canMountCustomerBusinessPages=false`；仅控制面与能力审阅。已配置客户 key 的部署不走此分支 |
| `start:yoyoosun` DEV 成功读回同 key 的 `builtin_rbac_fallback` | 仅带警示的本地桌面预览壳；不是 customer runtime。工作台 / 任务看板零 Workflow RPC，客户业务页与手机仍被拦截 |

`super_admin_product_core` 只是 `visibilityMode`，不能用于判断客户数据是否可挂载。业务页 guard 通过 `shouldGuardCustomerBusinessPageRuntime` 消费 `dataRuntimeScope / canMountCustomerBusinessPages`；带同 key 的 `builtin_rbac_fallback` 也不能升级为客户运行态。

### 再过滤菜单与直达 URL

普通账号必须先命中 `allowedMenuPaths`，再命中 `effective_session.pages`。空数组表示无可见页面；pages 缺失或类型错误也不回退 RBAC-only，`attachEffectiveSessionToAdminProfile` 将其归一为空数组。

local dev 仅指前端 DEV 构建。它可对“已登记且 RBAC 已允许”的直达 URL 放开第二层 pages 以排障，但不把隐藏页加入侧栏，不绕过上一节的客户运行态挂载检查，也不改变后端授权。

| 职责 | 实现入口 |
| --- | --- |
| 投影与跳转判定 | `adminProfileSync`；只返回 helper 判断，不执行读取、导航或页面注册 |
| 会话读取、缓存和实际跳转 | `ERPLayout`；管理 `get_effective_session` 与 `navigate(..., { replace: true })` |
| 当前路径的 RBAC 识别 | `resolveMenuPermissionKey(location.pathname)` |
| 当前路径的 page key | `resolveCurrentNavigationEntry` 解析完整产品导航的 exact / prefix 路径；侧栏过滤仍使用当前运行态菜单 |
| 未登记路径 | 仅提供工作台标题 / 面包屑显示 fallback，`pageKey / menuPath` 为空；不授予页面访问，也不选中工作台菜单 |

`shouldRedirectFromCurrentNavigation` 判定需要跳转后，只有 `visibleSections[0].items[0].path` 存在才 replace 到首个可见入口。没有可见入口时显示“当前账号暂无可见后台入口”并阻止业务 `Outlet`。未解析出菜单权限路径时，不单独因 RBAC helper 触发跳转；实际路由与后端仍独立守门。

### 同步失败怎样恢复

1. 只复用 `adminProfileRef.current.effective_session`，普通 `me` profile 缓存不算客户配置缓存。
2. 已有正常同客户投影时按它继续收窄；缓存已是 sync-failed 空投影时继续保持空投影。
3. 没有投影缓存时挂载 `effective_session_sync_failed` 空投影，并按客户运行态规则决定不可用页或控制面审阅。
4. active revision 正常返回空 pages 是有效的空权限结果，不是同步失败。

`getAdminProfileSyncErrorAction.hasCachedProfile` 只分类错误动作，不替代上述缓存判断。代表性 reason 为 `effective_session_page`、`effective_session_page_blocked`、`local_dev_customer_config_diagnostic`、`customer_runtime_missing` 和 `super_admin_product_core`。

### 手机与正式文案

手机先按静态客户 key 读取 effective session。普通账号须同时具备岗位入口权限、真实岗位和 active revision 同岗入口动作；缺客户 key、active revision、首次同步成功结果或有效入口时，不挂载任务，可恢复故障保留重新连接。

super admin 默认 `/m/all/tasks`，明确岗位深链仍进入该岗位；“查看岗位”只改变读取范围，不产生角色或办理身份。可选岗位取静态入口配置与 active session 有效岗位 / 入口动作的交集。普通 `admin` 不享有全部岗位查看，办理仍验 owner、assignee、状态及领域命令。

正式页面使用岗位语言。customer key、Product Core、配置投影等术语限开发调试、DEV 警示、无客户控制面、日志及技术文档；业务中的“客户”“甲方 / 委托方 / 订货方”照常保留。

## 帮助与岗位设置

### 岗位设置：编辑、预览与保存

权限管理以“岗位设置 / 员工账号 / 审批责任 / 岗位导航”组织；桌面侧栏在权限过滤后附加历史记录和帮助中心，不另造权限别名。

| 区域 | 当前规则 |
| --- | --- |
| 可用功能 | 读取 `menu_options` 与 `effective_role_access`；每行区分菜单入口和页内操作，同行说明入口位置或所需页面 |
| 分类导航 | 电脑吸顶直达并显示已选 / 总数；手机“跳到功能分类”；保留“只看已选”，不另建全文搜索 |
| 未保存预览 | `permission_keys` 只预览有效范围；唯一主办理入口可补齐，关闭入口只移除该页独有操作，不删除跨页能力 |
| 岗位导航 | 默认实际菜单，可切页面访问的全部 / 可进入 / 不可进入；只读说明最终原因，配置版本按需看，不编辑菜单顺序 |
| 关联账号 | 按 `admin.list` 和现有岗位关系显示账号、状态、兼岗；管理动作仍到“员工账号”，仅预填岗位搜索 |

岗位列表、摘要、保存状态和设置留在同一工作区，说明放岗位头部问号。切换预览不清草稿、不重新请求权限解释、不增加保存入口。

“保存岗位设置”一次 `set_role_settings` 提交权限与仓库范围，采用标准导航。后端以一个角色 version CAS、一个事务、一条审计原子保存；冲突保留草稿。已有导航字段归为标准推荐模式和空路径集合，读取本身不修改记录。

员工显示“姓名（账号）”：`display_name` 供识人，`username` 用于登录和唯一审计身份。新建与维护必填姓名；历史缺值只显示账号，不补造姓名。

### 审批责任：保存并生效

只配置已有正式 ProcessRuntime / 领域命令闭环的三类审批。具名员工须启用并持有所选岗位，多岗位按真实关系入选；主办、备用、升级按最低可用优先级串行生效。

1. 同时核对发布与激活权限。
2. 按 active revision/hash CAS，在一个事务生成新 revision 并切换 active。
3. 新流程使用新设置，在途流程继续使用冻结 revision。
4. 响应不确定时保留同一 intent 权威读回，不另造 revision；具名员工停用 / 注销后，未结束待办回到冻结责任池。

### 帮助：操作图解与完整手册

`/erp/help-center` 统一承接操作图解及业务、管理实施、技术运维三册。内容来源、阅读权限、纠错补充和在线 / 离线下载以[手册合同](../manuals/README.md)为准；本节不再复制书目、章节数和下载实现状态。

| 内容 | 来源与边界 |
| --- | --- |
| 岗位与场景 | `roleHelpContent.mjs`、`helpScenarios.mjs`；默认有效岗位与可进入场景，未知岗位使用安全通用说明 |
| 业务步骤与完成标准 | `businessUsabilityCatalog.mjs`；保留完成结果、交接、异常与恢复，教学顺序不表示真实单据进度 |
| 参考词条与工程用料 | `helpManualCatalog.mjs`、`engineeringMaterialHelp.mjs`；同名词保留页面上下文，库存参考不自动抵扣采购数量 |
| 帮助深链 | 业务页“这页怎么用”和字段问号定位本页说明；可阅读不等于可办理，按钮仍受当前菜单与业务权限约束 |

查询参数恢复当前有效阅读位置，无效或跨岗位参数退回允许内容。仓库的采购入库、成品入库、库存查询和实际出货分别解释；协同页只展示服务端确认的阶段，阻塞或升级按实际责任字段提示联系岗位。

仓库项目文档继续由 `/__dev/docs` 阅读，不镜像为 ERP 文档中心。`web/src/erp/docs/*.md`、`docs.mjs`、`docRegistry` 以及旧 `/erp/docs/*`、`/erp/qa/*`、`/erp/source-readiness`、`/erp/mobile-workbenches` 均不恢复路由、重定向或权限别名。

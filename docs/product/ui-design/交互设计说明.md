# ERP 交互设计说明 / ERP Interaction Specification

本说明定义统一 UI 的操作合同。读者是实现、测试及产品维护者；页面使用者只看到业务对象、状态和可执行动作。唯一交互参照为 [最新 HTML](index.html)，选择依据见 [设计依据](设计依据.md)。

## 高保真视觉合同 / Visual Contract

HTML 是正式页面的高保真外观与交互参照。实现使用真实业务数据与权限，补齐稿中未列出的异常、恢复和键盘路径；不得自行换回旧绿色卡片风格或加大控件和留白。

| 项目 | 标准 |
| --- | --- |
| 桌面骨架 | 侧栏展开为 206px、收起为 64px 图标栏，顶栏 48px、内容边距 12px；顶栏承载移动导航、刷新、外观和账号等全局操作。已有内容区标题的业务页与效能工作台不在顶栏重复当前页面名称；没有独立内容标题的页面仍由顶栏标明当前位置 |
| 页面标题文案 | 每个业务页、整页表单和效能工作台视图只保留一个可见主标题，与必要状态、视图切换或当前主动作同区；不在顶栏和内容区重复同名标题，也不重复解释页面用途、所属模块或“不办理哪些业务”。模块页签旁不放可由页签、字段和动作直接判断的长期说明。风险、异常、提交后果及证据范围放在对应字段、操作确认或正文区域。交互稿版本与样例范围只在外层查看器或证据上下文标注，不重复放进模拟系统的品牌栏和顶栏 |
| 菜单图标 | 同级业务模块使用各自的线性图标：基础资料为资料库、销售为购物袋、产品工程为结构图、采购为购物车、委外为双向协作、生产为工具、库存为收纳箱、质检为盾牌勾选、出货为货车、财务为账本。图标绑定模块身份，不随岗位授权或默认页面变化；工作台、任务、进度、工具和系统入口也各有独立图标。展开、收起和移动抽屉复用相同图标，菜单名称保留为可访问名称 |
| 桌面侧栏收起 | 品牌栏右侧图标按钮切换展开与收起；收起后隐藏品牌文字和业务分组标题，保留菜单图标、当前选中态及“全部模块”入口，图标可查看完整名称。“更多功能”在收起态触发时先恢复完整侧栏再展开分组；移动端继续使用完整文字抽屉，不受桌面状态影响 |
| 桌面按需导航 | “按需入口”下以省略号图标显示“更多功能”，不显示页面数量；收起箭头向右、展开向下。沿用岗位权限和业务分组，当前页面在内部时自动展开并选中 |
| 全部模块 | 固定在侧栏底部，打开后聚焦搜索，按功能名称或业务分组筛选当前账号可用页面；合并模块内页面可搜索直达。点击后关闭目录并沿用未保存保护，关闭恢复焦点，重开清空搜索；状态模拟控件仅用于设计评审 |
| 颜色 | 默认蓝色 `#0a66c2`；浅色页面使用 `#f2f5f3`、白色内容面和 `#dce4df` 分隔线。暗色以中性黑而非灰绿为底：页面 `#050607`、侧栏与顶栏 `#080a0c`、内容面 `#0d1013`、浮层 `#121619`、弱分组 `#151a1f`、边界 `#2a3138`；状态色只表达业务状态 |
| 全局背景层次 | 电脑端、移动端及效能工作台共用页面底色、壳层、内容面、弱分组底色和浮层底色；普通页面与卡片间隙沿用页面底色，背景不通过半透明白色叠加产生。暗色不把所有区域压成同一块纯黑，侧栏、内容、卡片和浮层按固定黑阶抬高，依靠边界与明度区分层次 |
| 电脑操作区与数据区 | 同一操作区的切换、搜索、筛选和摘要由最外层统一承载背景：浅色使用白色内容面，暗色使用主题内容面；独立操作区内边距为上下 10px、左右 12px，边框 1px、圆角 10px。内部布局继承内容面，不重复套卡片；业务页面与效能工作台遵循相同规则。数据卡片裁切内部表头与内容，圆角外保持页面底色；表格横向滚动留在数据区 |
| 表格内的顶部内容 | 产品、收付款、库存等嵌入数据卡片的页签，以及汇总标题、筛选说明，保留上方 10px、左右 12px 的阅读间距。共享表格顶部插槽统一承载内边距，页签或说明不重复叠加；工作台汇总的选择器和搜索区沿同一左侧边缘排列。业务主表距数据卡片上沿 10px、左右边缘 12px，表头与单元格仍使用各自内边距；列表、弹窗和明细宽表统一使用一组顶部左右按钮和底部细拖动条：只有存在数据及横向溢出时显示，到边界后禁用对应方向。主表复用现有工具栏；没有工具栏的明细在表格上方放紧凑按钮组。每张表只保留两个方向按钮，底部不重复加箭头、百分比或说明。细条在纵向滚动期间隐藏并暂停定位，停止约 180ms 后按表格当前可视底边定位再显示；横向滚动与拖动时保持可见。翻页加载期间复用滚动控件并保留表格占位高度，临时隐藏细条、禁用方向按钮；数据到达后恢复实际高度，在绘制前完成定位，避免清空数据时把页面拉回顶部。空结果取消占位和横向控件，末页按实际行数收缩。悬停、键盘聚焦和拖动时，轨道与滑块由 6px 加粗至 10px，24px 外层高度保持不变。表尾留出独立空间并避开分页，支持拖动、键盘和原有滚轮手势。启用细拖动条时隐藏同一滚动区的原生横向条，滚到表底或最右端仍只保留一条；纵向滚动条继续可用，固定表头与内容保持一致的滚动边界。保留已有列设置，不增加常用列切换，滚动仍限制在数据区 |
| 固定区与浮层 | 吸顶工具栏和固定操作区用不透明背景，保证滚动内容不透出；弹窗、抽屉、筛选及列设置沿用同一主题。普通弹窗点击遮罩、按 Escape 或使用关闭/取消均可退出；二次确认的遮罩等同“继续编辑/取消”，保留原输入。保存、上传或执行中，以及法务确认、断连恢复等必须明确处理的门禁不允许遮罩关闭。关闭后恢复原页面状态与焦点 |
| 纸面内容 | 打印纸张、模板缩略图中的纸面保留白底，外围导航、工具栏和预览容器仍随界面主题变化 |
| 移动操作区 | 搜索、页签和筛选的布局容器沿用页面底色，圆角控件外不出现白色矩形垫底；吸顶筛选栏使用不透明页面底色，滚动时不透出下方内容 |
| 移动数据区 | 任务、已办、风险、进度、我的及详情/办理/回执共用页面底色；独立卡片、输入框、浮层和固定导航使用内容面，暗色也从主题变量取色；卡片间隙、空结果和读取状态延续页面底色 |
| 字体与密度 | 系统中文字体，表格正文 13px；“表格密度”统一控制桌面业务列表、任务表格、权限矩阵、操作记录与效能工作台数据表。标准行高基准 52px、紧凑 42px，单元格上下留白分别为 9px、4px；长内容允许增加行高。单据、BOM 与联系人编辑表只收紧留白，保留输入框和校验提示空间；表头、按钮、筛选控件、卡片、手机页面与打印纸面保持原尺寸 |
| 业务分区标题 | 表单及详情明细的同级分区统一使用“主题色细竖条 + 文字标题 + 浅色横线”；竖条宽 3px、高 15px、圆角 2px，窄屏不压缩，颜色随主题切换。标题保留完整文字并允许换行；普通分区标记不表示可点击，展开 / 收起箭头只用于真实支持折叠的区域。标题含动作时按钮放在横线右侧 |
| 控件与容器 | 桌面常用输入及按钮高 34px、圆角 8px；业务卡片圆角 10px；表头 40px |
| 日期与日期时间 | 表单、弹窗与筛选统一使用共享日期控件；点击文字、留白或日历图标都打开选择面板，键盘仍可聚焦操作，日期时间保留直接录入能力，禁用态不响应。共享控件只提供可配置的快捷入口，具体选项由业务字段决定，不能把截止时间与发生时间混成同一组。日期范围由一个共享组件管理日期类型、开始和结束值，但三者各自保留清晰边界、焦点和错误反馈，以“至”说明范围，不用一条大外框掩盖当前操作位置 |
| 顶部页签与视图切换 | 财务、生产、工作台、进度和权限等同类顶部切换统一使用圆角底轨与滑块外观；底层页签与分段控件只保留路由、键盘和状态语义的差别。桌面整组高 38px、外圆角 9px、内边距 3px、中性边框 1px；选项高 30px、内圆角 6px、字号 14px，左右内边距 12px，与操作区内部阅读边缘对齐，操作区与数据区间隔 9px。背景分四层：页面底色、操作区内容面、中性浅底轨、主题浅色选中块；选中块保留中性细描边，未选项透明。独立导航必须具备操作区内容面，透明仅用于已处于内容面内部的布局；不保留独立白色页签、白色滑块或通栏底线。暗色使用相同主题变量形成深色层次，不能残留白底；吸顶容器保留对应区域的不透明底色 |
| 列表层次 | 页名、视图切换和只读摘要；状态、搜索、筛选及整表动作；当前记录操作；间隔 9px 后为表格，分页在表格底部 |
| 列与选择 | 默认文字从阅读边缘对齐，数量与金额右对齐；表头沿对应列对齐，浅色标题带与完整竖向分隔区分每列；排序标记紧邻列名，当前排序使用主题强调色，键盘焦点清晰；列设置集中在工具栏，排序、记录选择与展开明细的点击区独立 |
| 手机列表 | 搜索、待办/已办、状态筛选、任务卡、底部导航；左右边距 12px、卡片圆角 16px，不重复增加大标题和说明区 |
| 手机任务内容 | 卡片显示任务、状态、来源、产品和时间，进入详情查看完整字段并复制；实际产品图片保留预览入口；底部任务与风险使用同一红色通知角标 |
| 手机我的 | 顶部仅显示头像、姓名和账号；显示设置、入口与安全、系统信息和退出登录直接可达；普通多岗位沿用已有岗位导航 |
| 管理员手机查看 | 超级管理员默认“全部岗位”，顶部单行“查看岗位”下拉可选有效单岗位，并保持“管理员视角”标识；切换只改变读取范围，不冒充员工、不改变办理责任，所有环境相同 |
| 空状态 | 电脑业务列表、手机待办/已办/风险/超时与效能工作台统一使用简洁收纳图标、14px 中性文字、22px 行高和居中布局；图标高 40px，与文案间隔 10px，区域上下留白 24px、左右 16px。下拉候选仅缩小为 28px 图标与 12px 留白；普通空结果不使用警示色或虚线框。保留场景文案和当前筛选，清除条件或新建入口仅在实际可用时出现 |
| 效能工作台 | 复用相同侧栏、顶栏、字体、底色和主题；总览、产品工程、质量验证、交付运行保留各自操作职责。版本发布的手动指引按需展示 Git `index.lock` Mermaid 判定图，活动 owner、证据隔离、候选复核和继续收口保持一条可读路径，不在首屏常驻技术流程 |

“外观与密度”提供蓝、绿、黄、粉、橙、紫六种主题色，明暗/跟随系统与两档表格密度。手机“我的 → 显示设置”只展示明暗模式和主题色，卡片保持统一布局；桌面、规则页和效能工作台点击外观按钮直接打开设置弹窗，三类选项集中在同一处；登录页的“外观设置”只提供主题色与明暗模式。偏好在当前浏览器保存，刷新与跨页保持；手机修改主题不改写表格密度，颜色切换不改变业务状态含义。暗色主题统一使用浅色强调色与近黑按钮文字，选中、悬停、焦点和主动作随所选主题色变化，不恢复固定绿色或蓝色底块；黄色主按钮同样使用深色文字。

低频筛选进入“筛选”浮层，当前查询保持可见。手机浮层选择立即生效并保持打开，排序与状态、记录范围与其他关注共用分段控件；重置只恢复当前浮层的条件，保留主搜索。点击或轻触浮层外侧只关闭筛选，保留已选条件并恢复触发按钮焦点，同一次点击不触发底下的卡片、搜索或导航。手机不设置常驻刷新按钮，下拉重取当前查询，失败保留同一查询已加载内容并提供重试。键盘进入浮层后可依次操作，Escape 先关闭内层选择器，再关闭筛选并恢复触发按钮焦点。主表单与详情继续保留各自未保存、返回和权限边界。

### 权限管理

权限管理以已确认高保真的页面骨架、控件层次和操作路径为 UI 基准。设计稿漏掉的现有能力补入同一布局；不以旧实现的内页签和长列表反向改造高保真。真实岗位、权限、账号、审批责任、数据范围和保存结果仍以正式 API 为准，样例数量与未实现的动作不进入正式页面。

顶部独立工具栏横排岗位设置、员工账号、审批责任、岗位导航四个视图，搜索和当前视图的主操作放在同一行。下方主卡片采用约 260px 岗位侧栏与工作区；岗位信息和保存位于工作区顶端，授权摘要、改动摘要与次要的展开/收起操作位于下一行。功能区使用“业务对象 × 操作”二维表：业务域为可折叠分组，业务对象为行，查看、新建、编辑为固定列，其他业务操作保留完整名称并逐项勾选。表头与对象列在功能区滚动时保持可辨认；没有独立权限的格子显示“—”，被当前筛选隐藏的操作显示“…”并提供说明，不补成可操作格。工程用料审核、批准采购、激活、确认、取消及红冲等动作不合并为泛化权限。对象与动作来自现有权限元数据，筛选不重命名对象。

功能区底部只保留一条紧凑设置栏：“可访问 N 页”、岗位导航和仓库范围，不再使用独立卡片与常驻说明。页面入口说明通过帮助按钮查看；只有指定仓库时显示多选控件，选择结果保持单行，完整仓库清单在下拉内查看。保存状态放在卡片底部。桌面窗口高度不足时保留可操作的权限表高度，辅助设置可在岗位内容区滚动到达，保存按钮继续可见。岗位导航使用同一岗位草稿和“保存岗位设置”，两个视图间切换不丢失修改；切换岗位、员工账号或离开页面时继续执行未保存保护。敏感字段在表内独立成组，头部补充入口查看当前字段范围与关联账号。窄屏使用同一份勾选状态，转为按业务对象分组的紧凑列表，常规操作保留列名提示、专有操作换行；岗位横向选择，底部设置按可用宽度自然换行。边框、底色、焦点及选中态使用系统主题变量。

岗位导航分为“菜单排列”和“页面访问”，页签不混用模块数、入口数和页面数。菜单排列按业务模块显示：每个模块只占一个入口，常用工作保留 1–5 个入口，其余按业务模块、工具与查询、系统与帮助分组；同一导航区内可上移、下移或移到常用 / 更多。多页模块提供“默认页面”选择，只列出当前岗位已获准页面；再次进入沿用最近访问恢复。工作中心、历史记录和帮助沿用固定位置。选择系统推荐后恢复推荐布局，修改仍在同一岗位草稿中统一保存。

页面访问逐页保留最终结果，按正式业务域分组，支持模块和可进入 / 不可进入筛选。“岗位授权”和“页面访问”分列，只有后端有效访问结果决定可进入；受限原因沿用服务端原因码解释核对方向，不猜测公司配置中的具体限制项。顶部使用紧凑来源说明，配置版本按需查看，功能与操作对应表默认收起。手机排列列表改为单列，按钮可触达，页面表格在内部横向滚动；筛选和排序均保持键盘可用。设计稿使用虚构样例模拟这些交互，不读写正式岗位配置。


功能搜索按名称、业务分类或页面匹配，可只看已选、展开或收起。筛选不改变勾选结果；分组复选框显示全选或部分选中，“全选结果 / 清空结果”以当前结果为操作范围，页面入口与页内操作的既有依赖继续生效。勾选与已保存设置比较后标出新增或撤销，点击改动摘要核对完整清单；保存读回成功后清除标记。系统内置岗位只读，当前系统不提供新建、复制岗位或自建审批规则的操作。

员工账号的搜索、状态和创建入口位于顶部工具栏。创建和修改资料使用主内容区整页表单，分配岗位、密码重置及账号状态使用专项弹窗；返回保留列表条件，未保存离开时可继续编辑或放弃。数据范围仅维护已有的全部仓库、指定仓库和不允许查看；审批责任维护三项既有审批的条件与责任，调整后统一保存并生效，在途流程继续按启动时的条件与责任办理。销售和采购订单默认“全部审批”，可切换“按金额审批”，再选择币种和审批起始金额；金额等于门槛也需审批，0 恢复全部审批，切回全部审批时清除原金额和币种。销售按订单总额（含税费及约定运费）、采购按明细金额合计判断；其他币种或金额不完整仍需人工审批。列表显示当前条件摘要，弹窗保留调整后仍需页面“保存并生效”；取消弹窗、放弃页面草稿和保存结果待确认沿用现有恢复交互。出货财务确认保持全部审批。免审订单的提交回执与轨迹明确显示“按规则免审”，生效成功必须由后端结果确认。

## 登录 / Login

登录页采用居中的单张卡片，桌面宽度上限 456px、圆角 10px；输入框和登录按钮高 44px、圆角 8px。品牌标题与外观按钮同行，长公司名称自然换行。窄屏收紧边距，短屏或软键盘占用空间时允许整页纵向滚动。背景、文字、边框和主按钮都读取共享主题变量。

“电脑版／手机版”选择工作方式，“密码登录／短信登录”切换验证方法，二者使用不同的控件层级。切换条保持挂载，支持方向键、选中状态和共享滑动动效。短信能力来自服务端；未开通时只显示密码表单。客户品牌与入口开关来自现有配置，实际岗位、可用入口和原页面返回仍由登录结果与现有路由合同决定。

保留账号与手机号的自动填充语义；密码显示按钮可用键盘操作，大写锁定只作即时提示。切换登录方式清空密码与验证码，修改手机号清空旧验证码和发送提示。发码前校验手机号，提交中锁定表单、入口和登录方式，阻止重复请求；失败保留可修正的输入，离开页面后迟到的响应不再导航或写入会话。浏览器偏好只沿用工作方式、登录方法和既有短信倒计时合同，不新增记住密码或岗位自选。

工作台同一份 HTML 提供“业务界面／登录页”预览入口，`/__dev/ui-design?page=login` 可直达登录设计。预览中的演示账号与模拟验证码只在隔离页面内工作，不发送真实短信；演示登录可进入对应业务或手机界面，退出返回登录页。实际系统沿用既有认证接口和两份规则页面。

## 页面结构 / Page Structure

销售、采购、加工、采购入库、出货、生产订单和 BOM 的列表通过当前记录操作进入完整查看。销售、采购、加工与采购入库使用单据详情弹窗；出货、生产订单与 BOM 复用完整只读页面。明细总数与分页留在完整查看中，列表不再放置独立的条数展开列。查看与编辑保持各自入口，返回保留原查询、选择及列表位置。

业务列表表头只保留字段名与适用的排序入口，不在每列重复放置省略号。权限允许且适合逐行核对的业务列全部进入“列设置”，默认勾选常用字段，支持全部显示、调整排列及恢复默认，至少保留一列。销售订单联系人、客户与供应商简称默认展示；英文品名、海关编码、税务拆分、收货地址、唛头、BOM 补充信息和质检辅助字段按需勾选。销售、工程材料和委外加工汇总复用同一设置入口；短表与录入明细继续直接展示完成任务所需字段。

只有点击“完成”才将显隐与顺序一起保存到当前账号的对应列表；关闭弹窗放弃本次调整，保存失败保留草稿供重试。“恢复默认”恢复各页面推荐列及顺序，仍需点击完成；“全部显示”也可保存并跨刷新保持。权限和字段策略先于个人偏好，个人隐藏不改变详情、导出及打印字段。设置沿用 `admin_users.erp_preferences`：完整 `column_orders` 记录用户已选择的列范围和排列，`hidden_columns` 记录其中隐藏的列；恢复系统默认同时清空两项。新增可选字段沿用自己的默认显隐，既有列的个人选择优先，失效列标识忽略，不读取未隔离账号的浏览器列顺序缓存。

| 页面族 | 首要任务 | 结构与主路径 |
| --- | --- | --- |
| 登录 | 验证账号并进入可用工作方式 | 客户品牌、电脑/手机版、密码或已开通的短信登录、校验反馈、登录和规则链接 |
| 工作台 | 找到当前岗位需要先处理的事项 | 待办、逾期和阻塞作为可进入的队列；读取较慢的任务不阻塞页面框架；统计有明确范围 |
| 任务与进度 | 核对责任、来源和下一步 | 列表/看板与筛选共享条件，打开真实任务；核对上下文、选择动作、填写必要原因、提交、读回结果 |
| 业务列表 | 查找、比较并选择业务对象 | 紧凑筛选、可排序列、稳定选择、分页、明确的当前记录操作；详情和编辑具有不同入口职责 |
| 新建与编辑 | 连续完成一张单据 | 在主内容区整页编辑，分组字段、明细内横向滚动、底部固定保存/返回；局部来源选择和确认使用弹窗 |
| 详情与来源 | 核对信息并追溯业务依据 | 源单摘要、真实明细、附件、关联入口及可见状态；打开对应记录，返回时保留原有查询与位置 |
| 库存与财务事实 | 查看已发生的数量或金额 | 展示事实来源、单位、币种和余额；写入只通过已支持的确认、取消、冲正、调整或核销动作 |
| 主数据与权限 | 维护业务资料和操作责任 | 使用已有字段与权限码；启停、引用和禁用原因明确；权限不足不会出现可执行的假入口 |
| 打印、附件、导入、审计与帮助 | 完成业务的辅助操作 | 复用当前模板、附件与导入合同；结果、失败、重试和来源可追溯 |
| 移动岗位任务 | 在有限屏幕完成当前岗位交接 | 高频筛选直达，搜索不重复；同级页签各自记忆条件；连续列表按批追加，失败保留已加载结果 |

工作台与任务看板分类列表以产品或物料名称为主要识别信息，任务名称用较弱文字并排显示，不再独占标题行或附加箭头。产品图片、编号、关联数量和来源单据继续保留；缺少关联内容时，任务名称仍作为详情入口，关联失效提示保持可见。整行点击与标题按钮打开同一详情；图片预览和复制各自操作，Enter / Space 打开、Escape 关闭后回到原任务。

任务看板概览与手机待办、已办、风险、超时卡片沿用相同标题层级，长标题自然换行。整张卡片只有一个任务详情入口，不再附加“进入处理”“查看任务”“查看结果”或装饰箭头；状态、负责岗位、风险原因、入岗和截止时间继续显示。手机已办卡片仍通过整卡查看处理结果，产品图片独立预览，完整字段和复制留在详情；返回后保留当前分类、筛选和列表位置。

任务看板交互稿同时提供概览卡片与分类表格：点击分类或概览中的“查看列表”进入该类完整列表，切回概览恢复卡片视图；搜索和岗位条件在两种视图间保留。两种视图均进入同一任务抽屉，办理权限、原因校验及结果回执沿用原路径。

进度看板使用左侧订单进度列表与右侧当前订单阶段摘要。列表显示 56px 代表产品主图，摘要与完整详情显示 64px 主图；多产品订单只显示代表图并用 `+N` 与“等 N 项”同时说明，不把首图误写成唯一产品。整条订单卡片继续作为选择入口，卡内缩略图、摘要、详情和产品明细中的真实图片都可独立预览；点击图片只放大，不切换订单或打开详情，点击产品文案、客户、留白或使用 Enter / Space 才更新并定位摘要。预览沿用任务工作台的遮罩、原图读取、放大 / 缩小 / 适应屏幕、滚轮或双指缩放及拖动查看，Escape 或关闭后回到原图，不再增加“查看阶段”按钮。分页复用工作台与任务看板的共享组件，提供当前记录范围、每页条数及上一页 / 下一页；选择记录和分页条件保存在查询地址，返回可恢复。切换查询、范围、每页条数或页码后选择当前结果的首条，空结果与读取失败清空旧摘要。

桌面“查看完整进度”使用居中详情弹窗，手机使用带返回头栏与固定操作区的整页详情；右侧摘要、桌面详情和手机详情复用同一份订单身份、阶段进度及当前关注展示。桌面详情保留产品明细、生产单、批次、领料与关联任务分类及来源下钻；手机按真实记录收成“产品信息 / 生产执行 / 关联任务”三个整行分组，生产执行连续展示生产单、工序批次和领料，空分组不占入口。手机不跳电脑版原单，生产单和任务分别进入现有手机生产进度与任务详情；需要电脑业务页时由用户从“我的”主动切换工作入口。窄屏看板将摘要排在列表前方，点击卡片后定位摘要；岗位手机列表继续按需追加。

手机进度卡片底部展示任务摘要：单项待办显示名称与责任岗位 / 经办人，直接进入该任务详情；多项待办显示数量与首要任务，进入当前单据的关联任务分组选择。首要任务沿用后端的阻塞优先、截止时间优先顺序，不由前端猜测。无待办使用灰色非交互提示，无权限不展示任务信息；详情继续按现有权限提供办理、催办或只读。返回进度时恢复原查询和列表位置。

阶段进度条只使用有分子与分母的事实：资料已确认项 / 总项、已领齐项 / 领料总项、生产单有效完工 / 计划数量、实际出货 / 订购数量。采购到货和质检完成比例尚无当前进度接口口径，不能把领料改称采购，也不能用待检批次或已关闭单据补造完成率。无可靠比例时显示实际状态，不画虚假进度；多单位、关联待核对和无权限保留明确说明。风险数量沿用现有接口并允许重叠，任务名称使用共享岗位文案。


桌面任务抽屉沿用 640px 上限、52px 标题栏、38px 三步导航和底部固定操作区。正文使用 12px 边距、10px 卡片圆角，来源与责任、入岗与截止按两列核对，处理方式使用两列选择卡片，窄屏恢复单列。步骤圆点、选中项、焦点和当前任务标记使用统一主题变量；阻塞、退回、完成等业务状态保留各自语义色。只有本任务记录时使用紧凑横排并说明处理链范围，不能补造上游或后续岗位。详情、选择、确认和结果保持原有权限、原因校验与提交边界。

## 单据新建跟进任务 / Business Follow-up

销售订单、采购订单、加工合同、生产订单和出货单的当前记录操作区统一使用“新建跟进任务”，旁边提供“相关任务”。一次只针对一张已保存单据；未选中或多选时不能创建。主数据、库存台账、质检和财务事实页不铺设同名入口。

| 项目 | 交互与边界 |
| --- | --- |
| 来源 | 自动绑定单据类型与 ID，显示服务端读取的单据号；不能改成无来源的自由任务 |
| 可创建状态 | 销售草稿 / 已提交 / 已生效；采购草稿 / 已提交 / 已审批；加工合同草稿 / 已提交 / 已确认；生产草稿 / 已发布；出货草稿。结束状态保留相关任务查询 |
| 填写内容 | 任务事项、责任岗位、办理人或岗位共同待办、未来截止时间、普通 / 紧急、任务要求；截止时间提供“今天 23:59、明天此时、7 天后、15 天后、30 天后”，不显示会立即失效的“此刻”；不提供审批、过账等流程类型选择 |
| 岗位与人员 | 只提供当前具备单据读取、任务读取、更新及完成能力的有效岗位人员；切换岗位清空之前的办理人。无候选人显示原因并禁用提交 |
| 创建与恢复 | 有未保存内容时关闭须确认放弃；创建中防重复点击；结果不完整或网络中断时保留原内容和请求标识，使用“重试并确认结果”核对同一次创建；成功回执进入相关任务 |
| 查询与办理 | 相关任务按来源类型和 ID 精确分页；创建人可以回看与催办，不能因创建身份代替接收岗位完成。普通跟进任务可在详情办理，关闭详情返回相关任务；审批等流程任务进入任务看板办理，保留其专用表单。接收人也可沿用任务看板和手机待办办理 |
| 处理结果 | 完成时必填处理结果；桌面、手机详情和复制内容保留任务要求与完成反馈。任务完成不改变来源生命周期，不写库存、质检、出货或财务事实 |
| 附件 | 新建表单只收集任务字段；任务创建后使用已有任务附件入口，遵循查看与办理权限 |

交互稿使用本地样例演示创建、相关任务、接收方处理和回执。正式入口使用 `BusinessTaskActions` 与 `workflow.get_task_create_options / create_followup_task`；原型不证明目标环境已经部署。按钮、表单、允许状态及结果展示与上述范围同步维护。

## 岗位帮助 / Role Help

岗位帮助按当前有效岗位和独立办事场景组织。桌面使用场景导航与说明正文，手机用场景下拉保留正文空间；角色与场景选择保存在地址中，刷新、前进和后退恢复，跨岗位或失效参数回到当前可用内容。选择岗位只改变说明，不改变账号岗位或权限。

岗位与场景选择器使用同一套紧凑弹层，沿用主题背景、圆角、选中底色与勾选标记。列表按实际内容直接排列，限定高度并滚动，展开位置避开视口边缘。支持方向键、Home／End、Enter 选择，Esc 关闭并保留原值；点击外部或 Tab 离开关闭。切换岗位后同步重建场景选项与当前场景，避免残留上一岗位内容。

所有岗位场景都显示“办理概览”，表现形式由场景决定。需要交接或处理异常分支的用业务链；连续操作用编号步骤；简单查询用紧凑路径。节点使用 1、2、3 等编号，不强制补满五步；责任岗位按实际场景展示。初始选择本岗位参与的首步，点击节点联动当前步骤说明、“完成后”或“遇到异常”。一般场景只展开当前步骤，完整办理说明按需查看；已有局部图解继续用 A、B、C 标注操作位置，点击字母高亮对应位置与说明。流程高亮只表示正在查看的步骤，不使用已完成、进行中或百分比暗示实际单据进度。

成品入库明确分开生产提交报告、仓库核对实收、确认入库和核对库存结果；差异用虚线分支交生产核对，并标明返回核对步骤。收付款核销区分分配、按配置审批、确认过账与余额核对；审批通过不代表核销完成，受控更正保留在完整办理说明中。BOM 区分用料核对、启用版本和生产读取；版本变更不改写旧订单冻结资料。销售、采购、生产、品质等流程也呈现各自交接与异常去向。查库存等简单场景显示短路径，库存查询同时保留位置与数量口径图解。

桌面直接展示关系图，较长流程在图内横向滚动，页面本身不横向溢出；正文可用宽度不足时使用同一定义的纵向编号步骤及异常返回提示。步骤节点使用原生按钮，支持键盘选择并保留焦点。“怎么做／完成后／遇到异常”的切换控件保持挂载，只替换说明正文。操作示意使用只读样例，点击办理入口查看实际办理位置，不在帮助里模拟业务提交。

设计审查由 `/__dev/ui-design?page=help` 进入同一份 HTML，复用现有主题和控件风格，支持全屏、重置及下载；切换设计说明后返回预览保留当前场景。重置演示或重新打开恢复默认样例。稿内关系图、编号步骤、当前说明与异常去向由同一份场景定义生成，不另存预绘制的流程图。快照检查对照 `helpScenarios.mjs` 与 `roleHelpContent.mjs`；岗位优先事项之外的收付款示例对照 `businessUsabilityCatalog.mjs` 中的正式页内说明。正式帮助变更时提示同步交互稿并复核概览；它不自动证明后端逻辑与帮助一致。

电脑版正式入口为 `/erp/help-center`，已接入上述布局与联动。`HelpCenterPage` 负责有效岗位、菜单权限与地址恢复，`HelpScenarioContent` 根据 `helpScenarioPresentation.mjs` 的布局和 `helpScenarios.mjs` 的当前内容生成概览与说明。成品入库、收付款核销、BOM、库存提供 A／B／C 教学示例，所有样例均标明示意；结果和异常正文继续读取正式帮助来源，完整办理说明保留原步骤及受控更正。收付款作为独立帮助场景，不改变财务首页的优先入口。岗位下拉复用 Ant Design Select，说明视图复用共享 SlidingSegmented。

帮助说明可阅读，业务入口必须取当前菜单权限交集。通用业务步骤复用现有页内说明目录，场景只增加节点标题和岗位关系。帮助不执行审批、入库、出货等业务动作，实际办理返回原业务页面。未知岗位只提供通用指南。

## 操作记录与历史查询 / Record Centers

系统操作记录使用统一的筛选工具栏、分页表格、列设置和筛选结果导出，点击“查看变化”或双击记录打开详情抽屉。详情按字段展示完整的修改前后值；列表摘要可缩短，详情和导出不截断变化条数，手机号脱敏且不展示密码、凭据或原始事件结构。日期筛选以业务时区的完整自然日为范围；读取失败显示明确的重试入口，不保留上一查询的记录。

正式审计读取沿用现有系统管理、客户业务设置、系统准备和紧急任务处理来源。HTML 中的登录安全、统一成功/失败结果及网络地址是交互样例，当前 `audit_logs` 未提供相应记录与查询合同，正式界面不能据此补造字段。现有风险分类仅筛选当前服务端分页，界面须明确标注“本页”；启用该条件时不允许把局部结果冒充完整筛选导出。

历史记录中心保留现有 11 类来源，并同时服从菜单可见性和业务读取权限。来源选择保持直接可见，状态使用当前对象的历史状态；选中记录后提供查看详情和前往所属模块。来源、关键字、状态与页码保存在地址中，返回历史中心可继续原查询；切换来源和查询失败清空旧选择与详情。导出逐页读取当前对象的全部筛选结果，沿用现有列表权限和完整分页校验，不在前端合并跨对象总数。列设置只改变列表展示，历史中心继续保持业务只读。

## 任务动作与来源 / Task Actions And Sources

动作入口按服务端允许的动作直接展示，排序不增加或取消权限。普通协同任务优先排列完成、阻塞；审批任务优先排列通过、退回；阻塞任务优先排列解除阻塞，其余允许动作按稳定顺序继续展示，不再进入“更多处理方式”。只有一个动作时直接展示摘要，不要求重复选择。桌面和手机复用相同排序规则，必填原因、提交确认与结果待确认仍按原办理合同执行。

转交只选择同一负责岗位的合格接收人或共同待办；催办只记录催办原因，不改变任务状态，也不承诺站外消息已经送达。正常未完成不等于阻塞，恢复只处理当前阻塞，已完成与已退回任务只查看结果。到货、排产等来源专用任务进入所属业务办理，不能用通用完成替代来源动作。

任务默认显示对象、岗位、时间、当前原因与可追溯来源。存在实际材料汇总或来源摘要时提供按需查看入口，不为每种任务推造汇总表，也不从单号前缀判断业务能力。交互稿使用明确的样例关联；来源详情关闭后回到原任务和步骤。

## 业务汇总口径 / Summary Scope

材料汇总属于业务汇总详情，任务、订单与工作台入口复用同一份正式组件。电脑端使用宽详情弹窗；产品摘要按可用宽度并排，保留图片或缺图提示、产品编号、订单行、BOM 和生产数量。材料表优先用于核对材料、厂商、单位、总用数量、库存与备注；横向滚动留在表格内，溢出时沿用共享顶部按钮组和底部细拖动条，固定材料列继续保留。部位用量可用键盘展开，长备注按需完整查看，不同单位分别合计。

采购口径默认保留一行：财务批准后按总用数量生成采购订单，库存仅供参考且未自动抵扣。计算方法、审批冻结依据及库存读取时间收在“查看用料计算与采购生成依据”内；生成采购单不表示到货或入库。库存无权限显示“未开放查看”，读取失败显示“暂不可用”并可重新读取，单位不一致显示“单位待核对”，均不能补成零值。手机继续提供逐项查看与整表对照，产品摘要恢复单列。

材料汇总关闭或按 Escape 后回到原任务、步骤、滚动位置与触发按钮；从汇总列表打开时保留搜索和分页。效能工作台直接展示同一份 HTML，从任务的“查看材料汇总”或业务汇总行进入，演示多产品、部位用量、长备注、分单位合计、计算依据与返回；演示数据不参与正式业务写入。

| 汇总 | 当前可展示内容 | 解释边界 |
| --- | --- | --- |
| 工程用料申请 | 订单、产品、审批状态、提交时间，进入订单或用料申请核对 | 不推算待采购、可分配库存、到货齐套率 |
| 销售订单产品行 | 订单承诺、船头版数量、生产数量、未出货数、交期与订单状态 | 船头版是数量；生产数量不是完工数量；协作进度不替代单据生命周期 |
| 委外合同明细 | 加工对象、项目、工厂、工序、单位、加工数量、计划回货与合同状态 | 合同确认不表示已发料、回货、质检或产生应付 |

工作台正式入口沿用工程用料和销售订单汇总，委外明细沿用委外模块已有入口；交互稿将三者并列供核对口径。来源入口绑定具体记录，搜索后仍打开该行来源；导出与当前筛选使用相同行集。未知数显示待核对，正常待采购、待交付或待回货不能仅因大于零就标红。完整采购执行与委外发回货跟踪需要另外确认业务目标和事实来源，不包含在本轮界面收口内。

交互稿的订单交付与生产执行切换使用不同记录，数量来自对应样例集合；筛选后只选择当前结果，空结果不残留上一条阶段摘要。手机查看普通业务列表时保留分页入口，审计表在自身区域横向滚动；专用手机任务流继续按批追加，不能把第一页或前几条当作全部记录。

## 模块入口与页签 / Module Navigation

完整侧栏统一使用“工作中心、业务模块、工具与查询、系统与帮助”四个导航区，空区不显示。业务模块按正式业务归属合并，每个模块只占一个同级入口；单页模块直接进入页面，多页模块使用同一条共享页签。基础资料、产品工程和库存也使用该规则，避免部分模块用分组标题、部分模块用直接入口。

模块成员、顺序和默认页面来自 `businessModules.mjs`；侧栏、页签和全部模块目录共同消费权限过滤后的页面。标准入口进入该模块第一个获准页面，客户菜单的页面数组排序不隐式改变默认入口；岗位保存的优先页面优先于标准入口，重新进入模块时恢复最近有权访问的页面。岗位导航继续展示工作中心、常用工作和更多功能；相同模块不重复占用常用与更多入口，模块中的其他获准页面由页签或全部模块目录进入。

基础资料按客户、供应商与加工厂、产品、材料切换；产品工程按物料清单与加工环节切换；库存按采购入库、库存台账切换。采购入库只处理采购收货、待检、退货和调整，生产成品入库仍从生产记录办理。委外直接进入委外订单。生产模块页签为“生产订单、生产记录”；生产记录内部统一为“记录明细、生产工序、异常处理、待审批”一组视图切换，按现有权限显示，并与“生产记录”页名和只读摘要共用同一标题卡，不再单独占用一条通栏卡片；只有一个可用视图时省略切换。该页头由两个路由共用的布局持续承载，切换只替换下方内容，加载、摘要与工具栏变化不改变导航位置；不再叠加单独的记录 / 工序切换和局部刷新按钮，工序刷新使用顶栏刷新。出货页签为“出货单、放行审批、库存预留”；财务页签为“应收、应付、收付款、对账、发票”。排产确认归入生产订单，异常处理归入生产记录，从任务或关联单据进入时直接选中所属页签。

库存预留页负责核对订单占用库存和释放预留，不承担实际出库确认。财务放行只表示允许发货，仓库仍在出货单中确认真实出货；财务模块独立处理应收、应付、收付款核销、对账和发票。

模块页签条在切换时保持挂载，离开当前编辑页沿用未保存保护。当前已验证会话中分别记忆各页面的筛选、分页、视图和地址查询，切换后重新读取业务记录；重新进入模块恢复最近有权访问的页面。重复点击当前模块入口不刷新或重置页签，刷新使用顶栏刷新动作；账号或权限变化时沿用会话状态重建边界。

在业务列表和只读详情中，按实际转交或检索需要，为单号、客户单号、来源单号、产品及批次编号提供同样的复制图标。图标靠近当前值，只复制实际编号；空值、占位文字和无权查看的字段不出现入口。金额、日期、状态及普通说明不批量增加复制动作；复制结果和失败提示沿用共享反馈，键盘可操作。

## 带数量的状态筛选 / Counted Status Filters

销售、采购、委外、生产、质检、出货和财务单据列表在操作区直接显示“全部 + 各状态”的数量筛选，使用共享 `BusinessStatusFilter` / `FilterChip`。它改变当前查询，使用按钮与 `aria-pressed`，不充当切换页面的导航 Tab。任务看板沿用已有队列统计；主数据和没有稳定状态分类的页面不强行增加一排控件。

状态值和名称以对应对象的正式生命周期为准。销售订单使用草稿、已提交、已生效、已关闭、已取消；工程、生产、阻塞和交付进度继续在各自字段或视图中表达。采购到货、委外回货与财务部分收付同样不新增成源单状态。

数量由现有列表 API 在 `include_status_counts: true` 时返回 `status_counts`，按状态分组查询。统计复用列表的权限、对象类别、客户/供应商、搜索、日期、来源及当前/历史范围，忽略本次选中的状态和分页；“全部”是这些分组的记录数之和。财务统计继续服从可读取的应收、应付、发票及对账类别，不将金额相加。导出和来源选择无需附带统计。

切换状态保留其他条件并回到第一页；翻页不改变统计范围，搜索和其他条件变化后重新读取数量。加载中或读取失败显示“—”，已知无结果显示 0，旧响应不能覆盖新查询。由关联入口限定为单条记录时，数量来自已读回的该条记录，暂不能切换状态；清空筛选后恢复普通列表。状态按钮可用键盘操作，窄屏换行而不撑宽页面，明暗主题沿用共享控件样式。

## 数据可视化 / Business Views

列表与可视化由同一业务查询驱动。切换控件保持挂载，视图各自保存浏览位置和局部筛选；查看详情不会清空列表选择。数字若用于筛选，使用有选中状态的筛选按钮；只读统计保持只读外观。

| 视图 | 数据和排序 | 可执行交互 |
| --- | --- | --- |
| 销售交付 | 服务端销售明细的产品主图、订购、已出货、待交数量和计划交期；优先逾期、关闭未交完与近期到期；未知数量不能显示成 0% | 按交付状态筛选、分页、打开所属销售订单；整行打开订单，行内图片独立预览且不触发打开订单 |
| 采购到货计划 | 供应商确认日期优先于预计日期；已关闭、取消等终态不计入逾期；单数按采购单统计 | 前后 14 天、指定日期、今天、七天内、逾期和未填日期；选择日期读取对应订单，打开采购单 |
| 生产总览 | 生产单状态、计划开始/结束日期；结束订单不再标记计划逾期 | 按计划提醒筛选，查看订单及其产品工序 |
| 生产工序 | 服务端固定四工序与每产品的主图、WIP 批次、执行方式、品质结果；各工序状态来自实际聚合 | 选择订单、筛选产品与异常、预览产品图、查看工序上下文并打开生产订单；品质关口与库存入库分开核对 |
| 财务到期 | 对应应收/应付事实的原金额、未结金额、币种、到期日和来源；逾期/近期优先 | 应收、应付独立记忆；筛选、分页、查看账款及其真实来源；不跨币种相加 |
| 库存分布 | 仓库、物料分类和库存记录分布 | 数量及比例必须说明单位和口径，不能把不同物料数量直接相加；打开既有台账 |

所有业务视图使用真实数据的分页/批量读取，不把 HTML 的“500 条样例”开关放进员工页面。桌面结果分页限制渲染量；窄屏横向滚动只发生在数据区域。

库存预留、销售订单关联产品、出货来源选择、出货前质检、委外产品汇总、委外回货与返工进度复用同一产品身份组件。紧凑列表和选择项用 48px 缩略图，普通业务列表与动作摘要使用 56px 图片，关键产品摘要与任务身份使用 64px 图片；名称、编号或规格始终同时保留。只要真实产品图片已经加载，所有尺寸和位置都可点击放大，选择项中点图只打开预览、不选中或关闭候选项。无图、读取失败或无产品查看权限时保留同尺寸占位和完整文字，不能借用附件、样品图、物料图或另一条产品图片。物料行继续显示物料身份，不套产品图。

## 明细编辑 / Line Editing

明细容器使用中性细边框与浅底色区分区域，左右留白对称；联系人沿用轻量表格。容器不增加通长主题色装饰边，主题色继续表达选中、焦点和主要动作。

桌面列宽按字段内容分配：数量、单位、日期、金额、状态及操作保持足够录入的稳定宽度，产品、材料、来源与说明承接剩余空间。窗口变宽时不按比例放大所有列；数字宽度结合单位后缀、清空按钮和小数精度选择，不以当前样例值的位数限制可输入值。明细宽度不足时沿用自身横向滚动或窄屏重排，不增加逐列拖拽与列宽保存设置。联系人电话列保持稳定宽度，BOM 的剩余空间优先给材料名称。

可由用户逐行添加、复制、移除或填写的重复明细统一显示序号。桌面使用 40–44px 的窄序号列，窄屏把序号收成每行左侧标记，不为编号额外套卡片；卷 / 包等分组明细在所属材料内连续编号。序号只帮助识别当前排列，不作为数据库主键、业务编号或保存后的稳定身份。

可新增的明细在标题行提供一个清晰的业务动作，例如“添加订货明细”“添加生产明细”；明细底部保留同名入口，服务连续录入。两个入口执行同一新增逻辑，共用权限、禁用和加载状态；嵌套的 BOM 部位、采购到货卷 / 包等就近在所属分组提供入口。新增后将该行滚动到可见位置、聚焦首个可编辑字段，并用短暂浅色反馈标明落点；减少动态效果时取消可感知动画。系统统一维护这套反馈，不增加逐页列宽调节或添加方式设置。

重复表单按同一字段横向对齐，桌面共用表头，窄屏恢复逐字段标签并分两列排列。生产明细的产品、规格、单位、数量和 BOM 常驻；路线、客户验货和选填备注以一行摘要呈现，展开编辑，必填错误自动展开定位。来料检查项的依据、实际情况、结果和检查范围始终可见。生产展开区在桌面将路线与客户验货并排，明细备注另起一行；窄屏自然换行。路线未填时继续展开，路线冻结与验货含义可通过标签旁的说明入口查看。生产、工程打样、加工合同和出货的产品图片放在产品选择旁，沿用 48px 缩略图与大图预览，不再在补充区重复占行。

库存盘点、调拨和手工调整以来源摘要加数量 / 目标仓库呈现，单条作业不叠加编号卡片；原因保持可见，选填备注按需展开。采购退货与入库调整使用共享列头，调整目标随方式变化；核销将来源、未核销余额和本次金额分列。工程与打样按客户需求横向排列产品、规格、BOM、设计师和进度，返单沿用确认常驻，打样说明折叠后仍显示已有内容摘要。单字段的展开区由折叠标题标识，不再重复占一行标签；字段的可访问名称与校验仍保留，覆盖打样说明、库存明细备注、采购退货及入库调整备注。销售、BOM、采购与委外的空明细只显示一行提示和添加入口。

HTML 原型可从销售、采购、质量检验、采购入库的“更多业务操作”打开工程、到货清点、来料检查项、退货和入库调整示例，支持增加 / 移除、展开备注、字段联动、校验、取消以及保存后重新打开；演示值仅保存在当前页面。生产和库存表单以及收付款核销沿用对应页面入口。

整页表单的标题栏与底部操作栏固定在正文两端，正文独立滚动。两个固定栏使用不透明的同色系主题浅渐变：标题栏从顶部 14% 主题色向正文侧 8% 收淡，操作栏从正文侧 12% 向屏幕底部 20% 加深；不单独增加左侧色条。标题栏下沿、操作栏上沿使用主题色与强边界色混合的 1px 分隔线，操作栏叠加向上的浅阴影。明暗主题从对应主题变量取色，正文保持内容面，分区目录沿用轻底色；标题栏只保留单行表单标题及已有状态徽标，不长期展示介绍、边界或排除清单，具体规则放在相关字段、提示或警告区域。底部背景只表达当前外观主题，保存按钮仍为最突出的主动作。

底部未修改与只读状态使用次要文字；有未保存修改时显示语义色圆点和加重文字，窄屏也保留状态与返回、保存入口。校验失败定位错误字段，返回或切换页面时提供继续编辑和放弃修改，保存期间保留处理反馈并阻止重复提交与离开。视觉强化复用现有表单状态和交互，不增加额外确认步骤。

BOM、采购、销售、加工合同、生产订单与出货单的整页编辑采用可定位分区：关键基本资料之后直接进入明细，再维护交付、结算、制表等补充资料，备注与附件置后。宽屏左侧显示窄目录；可用宽度不足时改为顶部跳转框。点击定位、手动滚动和校验定位共同更新当前分区，跳转到收起的制表资料时先展开；分区切换不卸载字段，不改变同一表单的输入与保存语义。客户、供应商、物料、产品、规格、工序和待入库完工报告也复用相同分区；联系人紧随客户或供应商基本资料，产品图片和规格附件独立定位。存在三个及以上分区时显示目录。质检、收付款、员工资料、领料和返工等短表单保持紧凑排列，不为增加目录强行拆组。

分区内按可用宽度排成四列、两列或一列，长地址与备注跨列，BOM 材料和业务明细的横向滚动只发生在明细区。BOM、采购、销售、加工合同、出货与产品规格编辑页的附件默认显示真实数量和管理入口，展开后复用共享面板；待处理文件和附件读取失败保持展开，新建草稿仍在保存业务记录后上传绑定。

复制使用所点行的当前输入，移除和排序使用稳定行身份；复制不携带持久化主键、过账结果或后端派生值。复制后的两行可独立修改；删除首行或中间行后，其余值、单位、来源和只读快照保持对应。新增行为完整空白初值，不残留已删除行的数据。

销售、采购、加工合同和出货明细共用表头与行内主字段，补充信息默认收起，有值时显示一行真实内容摘要；展开只影响当前行，不卸载表单字段，复制、排序、清空和保存仍沿用原字段与权限。销售客户款号与订货名称同列常显，类别、船头版和规格按需编辑，工艺与备注在宽屏并排、窄屏上下排列；已有导入行的原表核对入口始终可见，原表图片在同一核对浮层内查看。采购主行保留材料、单位、单价、数量、金额与预计到货，产品来源、下单材料资料和备注进入补充区。出货来源、箱号、包装与备注、加工行备注显示内容摘要；仓库、批次、加工对象与工序继续常显。备注沿用自动伸缩文本框与原长度限制，不用固定大高度占位。销售已关联产品与规格等资料同组，工艺与备注并排；加工合同的规格与行备注并排；出货包装说明与备注并排。打样说明、完工与领料备注使用单行起步的自动伸缩文本框，返工原因保留两行起步且始终可见；长内容继续增高，保留长度限制、错误与必填规则。保存校验失败自动展开错误所在行并定位字段。

到货清点按材料共用表头，每卷 / 包占一行，实点、送货标示、仓库、批次和差异常显，补充说明显示摘要；库存多行作业共用来源库存、作业数量和目标仓库表头，单据级原因只填写一次。可用宽度不足时沿用紧凑表格的字段重排，保留来源和差异。联系人、生产、工程打样、来料检查、采购退货 / 调整、核销和 BOM 已有紧凑结构按岗位任务保留，统一补足轻量序号，但不统一增加折叠层。

客户、供应商联系人在宽屏按每人一行排列，共用序号、联系人、职位、手机、电话、邮箱、主联系人和操作表头，不显示重复的“条目”标题或逐人卡片。单人时自动作为主联系人并省略选择列，多人时单选，删除主联系人后由首位剩余联系人接替。备注默认收起，有内容时显示可展开的一行摘要，完整编辑保留换行及既有长度上限；姓名、联系方式与校验错误直接可见。标题行与底部都使用“添加联系人”，底部同时显示人数统计。可用宽度不足时，序号收成行首标记，每位联系人按两列字段重排，邮箱和操作跨列，页面不产生横向溢出；添加、复制、移除和保存读回保留原有身份与字段对应关系。交互设计稿与业务表单使用相同操作语义。

新建、重新编辑、来源切换/清空、草稿保存和重新读回使用同一字段映射。金额按当前币种、数量、单价与真实税费口径计算；缺值保留待补齐，单位不混算。表单校验失败保留输入并定位问题；提交中阻止重复保存及离开；未保存离开须确认。

客户档案、销售订单和出货单复用收货信息控件：收货人、收货电话、可搜索的国家 / 地区在前，中国大陆使用可搜索的省市区和详细地址，其他国家 / 地区使用可粘贴原文的完整地址多行输入。新建时默认选中中国大陆；编辑已有记录及来源带值保留原国家 / 地区，手动清空后不自动补回。窄屏上下排列，国际号码沿用现有电话校验；国家变化清空原地址，省市区变化替换地区前缀，客户或来源单据变化整体覆盖或清空收货信息。地址仍保存为完整文本，原文中的换行随快照保留，不新增多地址簿或全球地区树。HTML 演示只展示少量地区选项；真实控件使用随前端发布的版本固定字典。

### 数量与计量单位 / Quantity And Units

业务单位沿用当前标准目录：个、套、对、片、条、块、码、千克。计数单位只接受整数，码最多 6 位小数，千克最多 3 位小数；实际表单以所选数据库单位的精度为准。精度是输入上限，展示只保留有效小数，不补齐小数位，也不统一截成两位。数量在同单位内汇总，单位切换后重新校验已有值，超出精度时保留输入并提示修正，不静默四舍五入；单位缺失时不能提交已有数量。

BOM 单件耗用系数可保留 6 位小数；实际采购、领料需求按目标单位精度向上取整，两者不混用。交互稿的采购、库存和明细示例同步当前单位名称与数量校验，样例不执行真实写入。标准目录和精度快照由设计合同检查与服务端单位真源核对。

## 附件管理 / Attachments

任务、业务单据和表单复用共享附件面板。表单内的紧凑附件摘要栏整条可点击，名称、数量、空白和右侧提示属于同一个展开入口；右侧显示“展开附件 / 收起附件”与方向箭头，支持键盘操作。展开后的文件选择、预览、下载等动作独立生效；有待处理文件、正在处理附件或列表读取失败时保持展开保护。

独立管理窗口宽度上限为 780px，不重复嵌套标题卡片；“全部 / 图片 / 文件”显示各自数量，切换保留队列，右侧以轻量按钮刷新列表。“选择附件”作为上传区内的主按钮；有合同附图入口时放在同一区域，顶部不重复提供文件选择。手机端采用紧凑上传区与“选择照片或文件”提示，电脑端保留拖拽提示。文件行显示缩略图或类型图标、可展开的完整文件名、大小、状态及真实上传记录，动作按权限和文件状态提供。

点击选择与拖拽使用相同格式和 100 MB 单文件限制。已保存对象先选择并核对文件，再点击“上传”；新建对象的附件在业务记录保存成功后上传绑定。上传中显示已处理文件数，不模拟网络百分比；阻止重复上传、移除和关闭。离开管理窗口前确认放弃未完成附件，业务表单沿用未保存保护。

上传失败保留文件并支持逐项或批量重试，成功项不重复上传；结果待确认的文件只能先刷新核对，不能自动重试。列表读取失败在原位显示重试，不能表现为空附件。未上传文件可移除；已上传文件按既有权限填写原因后撤销，继续保留审计且停止预览和下载。产品主图、副图仍使用专用图片槽位，不从普通业务附件推断主图或替换关系。

同一指引还包含自动续办交接图：等待心跳每 10 分钟只读重查项目会话与后台 writer；条件未满足时继续等待，不写共享文件。全部结束后，先删除并读回本次心跳，删除成功才在同一次续办中进入实现、验证、造数、Git 与部署；删除失败保持执行阶段未开始。执行期间不重建同目的心跳，只有用户后来再次要求等待才创建新心跳。工作台只解释这条生命周期规则，不直接调度 Codex 会话或自动化。

每个主区独立保留搜索与筛选。空结果可清除当前条件；状态预览可切换加载、空结果、失败和正常，重新读取保留查询与未完成操作。页签条保持挂载，方向键、Home / End 切换，滑块遵循共享 220ms 动效与减少动态效果设置。

交付前置证据缺失时，准备按钮禁用并显示缺失原因；切到“准备就绪”样例后才能核对版本、目标基线和恢复点。确认只推进隔离演示状态，执行中阻止重复准备；切换主区或页签仍保留操作和读回入口。演示回执显式标注真实状态未证明，不发起网络请求或执行发布、迁移、回滚。

## 响应式与动效 / Responsive And Motion

窄屏仍保留生产计划日期、提醒和“查看工序”，库存视图切换与日期输入按实际控件高度排列。采购日期的日号、月份和星期各有明确位置，今天有可辨识标记。表格明细展开按钮与记录选择列保持独立点击范围。

页签指示条随真实页面切换连续滑动，中途反向切换从当前位置继续，内容切换不能重新挂载、隐藏或挤动切换条。启用系统“减少动态效果”后取消滑动及延迟。验证需采样实际 DOM 位置、尺寸、透明度和中间帧；仅检查 CSS 中存在 transition 不算通过。

共享页签过渡使用 220ms 与 `cubic-bezier(.2,.7,.2,1)`，不能在每次内容读取后重新播放指示条入场。颜色和焦点过渡不应遮盖最终选中态。

明暗主题下，正文、状态、统计和可操作链接保持可读对比度。浮层与窄屏导航将键盘焦点留在当前层内，Escape 先关闭最内层，再恢复触发控件的焦点。设计查看器全屏保留四边操作边界；其内部菜单的 Escape 不应同时退出外层全屏。

# UI 交互设计 / UI Interaction Design

这里维护 ERP 的界面结构、视觉规范与交互合同。唯一可交互稿为 [index.html](index.html)，当前采用统一 UI V8；设计稿同时表达页面布局、控件外观、状态反馈和完整操作路径。

| 要核对什么 | 入口 |
| --- | --- |
| 页面与交互如何工作 | [最新可交互 HTML](index.html)，或研发效能工作台的“UI 交互设计” |
| 页面职责、状态、数据及验收行为 | [交互设计说明](交互设计说明.md) |
| 为什么这样安排布局和动作 | [设计依据](设计依据.md) |
| 当前共享控件 | 工作台“UI 交互设计 → 交互控件规范” |

开发入口是 `/__dev/ui-design`。它直接读取本目录，支持“业务界面／效能工作台／登录页／岗位帮助”切换、隔离预览、全屏、重置演示和下载同一份 HTML。效能工作台由 `/__dev/ui-design?page=workbench` 直达，演示总览、产品工程、质量验证、交付运行及证据详情、操作确认和结果读回；所有操作仅改变隔离样例。登录设计可由 `/__dev/ui-design?page=login` 直达；岗位帮助由 `/__dev/ui-design?page=help` 直达，也可从交互稿的“系统与帮助 → 帮助中心”进入。这里只保留一份最新 HTML，不维护图片方案、重复查看器或历史版本目录；历史改动由 Git 追溯。

岗位帮助演示按岗位选择办事场景，所有场景都在同一位置显示“办理概览”：交接与异常使用业务链，连续操作使用编号步骤，简单查询使用短路径。点击节点查看当前步骤、完成结果或异常恢复，窄屏自动转为纵向编号；已有局部图解继续用字母标注操作位置。图、编号与步骤说明由同一份场景数据生成，后续细节继续在这份交互稿中审查。

帮助中心演示“岗位操作图解 / 操作参考手册”两个内容入口，共用搜索和可收起目录；搜索按任务、字段、状态、别称或问题定位相同词条。工程用料审批与采购生成提供教学图解，文字参考复用现有 24 个业务页说明及工程用料专题，覆盖办理顺序、名词、公式、来源、条件与异常恢复；这些内容来自代码目录快照，不另外维护第二套业务规则。正式实现入口为 `/erp/help-center`。

效能工作台交互稿与正式页面使用分组侧栏、紧凑页头和工具表。总览默认展示全部工具，可搜索、按领域筛选、添加常用入口；使用指南按需查阅。通过“UI 交互设计”进入查看器后，可选择效能工作台预览，体验验证、交付条件核对、计划确认与回执读回。原型的样例状态和模拟动作仅用于交互审查，正式页面仍以代码、接口和实际证据为准。

业务界面的“进度看板 → 经营统计”演示交付概览、客户 / 产品维度、交期与币种筛选、图表 / 表格切换、来源下钻及返回、应收账龄和口径说明。正式页面使用服务端完整汇总，复用销售与财务字段权限；设计中的虚构数据仅说明布局和交互。

HTML 使用固定日期和虚构样例说明交互。正式页面使用当前 API、权限、业务状态与共享组件。设计说明、代码和测试共同说明实现范围；该设计入口不承担业务写入、发布证明或客户验收。

维护时同时核对设计稿、说明、共享实现及相关浏览器场景。`web/src/dev-workbench/config/devUIDesign.test.mjs` 检查稿内岗位场景快照与正式帮助内容是否一致，以及所有场景是否有有效概览；正式说明变化时须同步快照并复核图中交接、异常与完成条件。该检查不自动推断后端业务变化。更新设计稿不能放宽 API/RBAC、取消/冲正、未保存保护或 Workflow 与业务事实的边界。

# UI 交互设计 / UI Interaction Design

本目录维护 ERP 的界面结构、视觉与操作合同。唯一可交互稿是 [index.html](index.html)，修订由 Git 追踪。

| 要核对什么 | 入口 |
| --- | --- |
| 页面布局、控件、状态和完整操作路径 | [最新可交互 HTML](index.html)，或工作台“UI 交互设计” |
| 页面职责、状态、数据及验收行为 | [交互设计说明](交互设计说明.md) |
| 为什么这样安排布局和动作 | [设计依据](设计依据.md) |
| 当前共享控件 | 工作台“UI 交互设计 → 可交互设计 → 控件设计” |

共用反馈的三个操作入口：[设计说明的弹窗图解](/__dev/ui-design?view=specification&topic=dialogs)、[设计依据的结构与留白](/__dev/ui-design?view=rationale&topic=dialogs)、[真实控件演示](/__dev/ui-design?page=controls)。目录包含组件选择、弹窗结构与尺寸、Toast 与反馈选择、提交与恢复、关闭与焦点；每个主题链接规范和对应阅读入口。

演示使用共享组件与隔离本地状态，可切换成功、失败、结果未知，重试或重置。附件仅选择本地文件，导出只模拟生成，不上传、不下载、不写业务数据；讲解参数不写外观偏好。规则、设计表达、实际运行和业务验收分别核对。

## 怎样阅读 / Reading

1. 打开 `/__dev/ui-design`，选择“设计说明”或“设计依据”。
2. 在可搜索目录中选一个图解主题，点击图中区域、调整滑块或操作虚构样例。
3. 切到“规范原文”，按章节核对完整规则；比较看表格，顺序看编号，关系看图。
4. 用上一 / 下一主题继续阅读；目录可收起，正文独立滚动。
5. 复制链接、刷新或前进后退时，恢复阅读方式、主题、章节及搜索词。

| 图解内容 | 维护方式 |
| --- | --- |
| 页面骨架、间距、平面层次、文字对齐 | 复用当前主题变量；样例不写入账号偏好 |
| 下钻返回、表单容器、失败恢复、数据来源、窄屏排列 | 关系图直接读取正式说明 |
| 完整页面操作 | 继续使用同一份 HTML |

四类页面预览支持隔离浏览、全屏、重置演示及下载同一份 HTML；控件设计直接使用共享组件，在主内容区单独阅读和操作。

| 预览 | 地址 | 重点内容 |
| --- | --- | --- |
| 业务界面 | `/__dev/ui-design` | 单据、列表、表单与来源下钻 |
| 效能工作台 | `/__dev/ui-design?page=workbench` | 总览、产品工程、质量验证、交付运行、证据详情与操作确认 |
| 登录页 | `/__dev/ui-design?page=login` | 身份、工作方式、验证与失败修正 |
| 岗位帮助 | `/__dev/ui-design?page=help` | 办理概览、图解和参考手册；也可从稿内“系统与帮助 → 帮助中心”进入 |

### 控件设计看什么

1. 与业务界面、效能工作台、登录页、岗位帮助同级切换，入口为 `/__dev/ui-design?page=controls`。
2. 左侧搜索并选择弹窗与反馈、页签与视图、筛选与搜索、按钮与动作、空白与错误、数字提醒。
3. 右侧只展开当前示例，结合三步核对和“场景 / 设计选择 / 原因”表阅读；共享实现按需查看。
4. 目录选择与关键词随 URL、刷新及前进后退恢复；浅深主题仅影响样例，重置演示只重置当前展示区域。

### 岗位帮助看什么

| 阅读任务 | 展示方式 |
| --- | --- |
| 交接与异常 | 业务链，在同一位置显示办理概览 |
| 连续办理 | 编号步骤；点击查看当前步骤、完成结果或恢复 |
| 简单查询 | 短路径；窄屏由同一场景数据生成纵向编号 |
| 局部操作位置 | 字母标注，联动对应示意 |
| 查字段、公式、条件与边界 | “操作参考手册”，复用 24 个业务页说明及工程用料专题 |

“岗位操作图解 / 操作参考手册”共用搜索和可收起目录，可按任务、字段、状态、别称或问题查找。工程用料审批与采购生成有教学图解；正式帮助入口为 `/erp/help-center`，内容来自代码快照，不另建业务规则。

### 工作台与统计看什么

| 预览 | 核对重点 | 事实边界 |
| --- | --- | --- |
| 效能工作台 | 分组侧栏、紧凑页头、工具表；默认全部工具，可搜索、筛领域、添加常用 | 指南按需查阅；验证、交付核对、确认及回执仅改变隔离样例 |

## 如何维护 / Maintenance

1. **保留唯一来源**：本目录仅一份最新 HTML；不增加重复查看器、图片方案或历史版本目录。
2. **分清演示与事实**：固定日期和虚构数据仅用于审查；正式页面以 API、权限、状态、共享组件和实际证据为准。
3. **同步相关内容**：同时核对设计稿、说明、共享实现和受影响的浏览器场景。
4. **核对帮助快照**：`web/src/dev-workbench/config/devUIDesign.test.mjs` 检查岗位内容同步及概览有效性；内容变化后复核交接、异常和完成条件。
5. **保留业务边界**：不放宽 API/RBAC、取消/冲正、未保存保护或 Workflow 与事实的区分。快照检查不自动证明后端逻辑一致。

设计入口不写入业务，也不证明发布或客户验收；实现范围由设计说明、代码和测试共同核对。

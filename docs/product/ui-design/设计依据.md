# ERP 设计依据 / ERP Design Rationale

统一界面的目标是让使用者快速识别当前对象、理解状态、完成动作，并能在失败或返回后继续工作。高保真外观、交互稿和正式实现共同服务这条操作路径；颜色或静态截图不能单独说明流程可用。

## 信息与动作 / Information And Actions

| 选择 | 原因 | 如何判断有效 |
| --- | --- | --- |
| 紧凑筛选与可比较的业务列表 | ERP 的主要任务是查找、比较和处理，重复统计卡会挤占数据区域 | 首屏能看见对象、状态和下一步；统计点击后有明确结果 |
| 精简常驻标题说明 | 标题、页签、字段和动作已经能说明页面职责时，再长期展示用途、排除清单或“交互样例”标签只会占空间并制造视觉噪声 | 正式业务页、整页表单和交互稿同类标题区结构一致；标题下不重复解释页面，模块页签旁无泛化说明，风险、异常、提交后果与证据范围仍在发生判断的位置可见 |
| 宽表留出卡片边距，使用顶部按钮组与底部细拖动条 | 顶部按钮容易发现，拖动条方便跨越多列；重复方向按钮和文字会增加操作区复杂度 | 主表复用原工具栏，每表仅两个方向按钮；只在有数据且溢出时显示，边界禁用；底部只放可拖动细条，纵向滚动时隐藏、停稳后定位显示，横向拖动保持可见；翻页复用控件，加载期间保留表格高度，响应后按实际行数恢复，避免反复拆装与页面回跳；悬停加粗但不改变外层高度，避开分页；保留列设置 |
| 全量可选业务列与按任务设置的默认列 | 横向箭头降低查看后续列的成本，税务、地址或参考信息仍只在部分核对任务中需要 | 字段权限允许的可用业务列能在列设置中找到；默认列支持常用判断，全部显示与恢复默认可保存，账号选择不会被新增列覆盖 |
| 出货入口合并，财务保持同级独立模块 | 出货单、放行审批和库存预留服务同一交付过程；财务同时处理销售、采购和委外结算 | 出货操作在同一模块内按权限切换；预留与放行不被误读为实际出库，财务不被误读为出货子功能 |
| 全部业务模块统一为同级直接入口 | 分组标题、业务模块与单页入口混排会让用户误判功能归属；数组顺序也不应隐式改变默认页面 | 四个导航区职责明确；每个业务模块只有一个入口，单页直达、多页内部切换，默认与岗位优先入口都有明确规则 |
| 页面只保留一个可见主标题 | 顶栏与内容区重复同名标题不会增加页面定位信息，还会挤占首屏；页面自带标题时应由内容区承载对象、帮助、视图和摘要 | 业务页与效能工作台示例的顶栏只保留全局操作，内容区主标题唯一且可读；没有独立内容标题的页面仍能在顶栏辨认当前位置 |
| 同类顶部切换共用圆角底轨和主题浅色滑块，操作区使用完整内容面 | 页面与视角的语义差别由标签、路由和键盘行为表达；页面底色、操作区内容面、底轨、选中块形成四层背景，让切换、搜索和筛选属于同一个操作区域 | 财务、生产、工作台、进度、权限及效能工作台的同类控件和承载背景一致，交互设计同步呈现；浅色操作区为白底，暗色随主题变化，已有内容面内部不重复套卡片；结果条件保留筛选按钮 |
| 主表单整页，局部操作弹窗 | 完整单据需要连续输入和可用宽度；来源选择、确认和预览需要保持上下文 | 明细只在自身区域横向滚动，主动作始终可达 |
| 主数据表单只要求岗位可判断的资料 | 加工环节的列表顺序由系统追加，人工质检提示不触发质检；BOM 参考适用期也不控制版本启用 | 操作者不必填写展示顺序，质检提示和参考日期与真实质检结果、BOM 启用状态分开表达 |
| 详情支持精确来源与返回 | 业务核对经常跨单据，丢失筛选和滚动会迫使重复查找 | 下钻对象正确，返回可继续原来的工作 |
| 手机进度明细按判断路径分组 | 产品身份、生产执行和协同任务的用途不同；把生产单、批次、领料与电脑版原单入口平铺，会让辅助核对看起来像六个同级动作 | 手机只显示有记录的产品信息、生产执行、关联任务三组；生产执行内部连续核对生产单、批次和领料，生产与任务使用手机原生下钻，电脑原单只从工作入口主动进入 |
| 进度卡片显示任务摘要并按数量下钻 | 只显示负责人或待办数量无法判断具体要办什么；单项待办可直接进入，多项需要保留选择 | 任务名称、责任与首要事项来自现有进度投影；单项直达任务详情、多项查看关联任务，无待办不提供假入口，查看权限不扩大办理权限 |
| 空状态复用统一组件配置 | 同为无记录时，图标、纯文字与黄色虚线框混用会让用户误判重要程度；无风险不应呈现为警告 | 电脑、手机和工作台的空状态在图标、文案颜色、间距上保持一致，加载失败仍有独立恢复入口 |
| 效能工作台直接进入工具 | 经常使用的开发入口需要可扫描、可搜索、可直接进入；固定六步教程占用首屏并增加定位成本 | 常驻分组侧栏与工具表使用同一登记；全部工具、常用工具、使用指南按需切换；来源与帮助就近展开，状态只来自真实结果，风险确认保留在实际操作处 |
| CI/CD 原理与运行证据分别按需查看 | Job 并行、Runner 槽位、内部并发和资源锁的作用不同；机制示意不能充当当前配置或实际结果 | 质量门禁复用说明抽屉，四组图按需渲染；Job 性能使用真实起止时间显示重叠，缺值与排队单列，领域明细可收起；版本中心复用发布说明，交互稿只演示机制 |
| 产品工程直接呈现工具 | 同一组入口换成问题或图模型分类，没有增加实际判断结果，却增加一层选择和解释 | 五个工具名称与侧栏一致，每项保留一句用途和打开动作，技术来源与边界按需查看；改动规则收在开发文档，具体关系图留在对应工具内，页面说明检查收进质量验证 |
| 按信息关系选择表达方式 | 连续操作需要明确顺序，相同维度需要横向比较，同层独立任务需要保留上下文，复杂关系需要可视化；统一用卡片会掩盖这些关系 | 主路径用编号步骤；工具、检查、环境和演练用二维表；发布、耗时与记录用稳定 Tab；权限和业务链继续用关系图；详情按需打开，真实阻断与未结束操作始终可见 |
| 待办和风险优先，说明按需展开 | 岗位首先要决定处理什么；常驻说明会与真正异常争夺注意力 | 默认仅保留帮助判断或操作的信息 |
| 工作台、任务看板与手机任务统一主次标题 | 任务名与产品名分别强调会挤占单据和异常信息；卡片已可打开详情，重复入口提示增加扫描负担 | 产品或物料名称优先，任务名称次要显示；无关联内容仍有标题，长文本自然换行，状态、风险与时间可读，键盘打开、独立图片预览及返回恢复继续可用 |
| 材料汇总使用紧凑产品摘要与宽明细表 | 工程与审批需要同时核对材料、用量、库存和备注；逐产品通栏大卡会挤占明细首屏 | 多产品按宽度并排，部位及计算依据按需展开，关闭回到原任务；库存参考不暗示自动抵扣 |
| 登录使用紧凑卡片，工作方式与验证方法分层 | 进入系统前只需辨认公司、选择电脑或手机并验证账号；装饰背景与表格密度会分散注意力 | 主题前后一致、长名称不挤压外观按钮、失败可修正、提交不可重复 |
| 手机账号卡只保留姓名和账号 | 全部岗位与可用入口说明重复已有切换功能，长名单会挤占屏幕 | 能核对登录身份，实际岗位和工作入口仍可直接切换 |
| 单岗位权限采用业务对象与操作二维表 | 同一对象的查看、新建、编辑需要并排核对，逐项卡片会重复对象名称并拉长查找路径 | 每项权限只出现一个勾选控件；不同审批及专有动作保留独立名称；筛选与批量修改不误改隐藏权限，保存前可核对新增与撤销 |
| 岗位导航按模块排列，页面访问逐页核对 | 同一模块多个页面不应占满常用入口；岗位具备功能也不一定满足公司当前启用范围 | 默认页面、模块顺序保存后可读回；访问表分类与业务导航一致，授权与访问结果能分别核对，受限原因有明确检查方向 |

统一“新建跟进任务”把临时资料补充、交期沟通和异常核实放在当前单据旁，省去离开业务页面再寻找入口。名称直接说明会创建一个有责任、有截止、有结果的协同任务，并与“提交订单”“提交合同”等单据生命周期动作区分；已有审批、入库和出货动作继续走各自流程。来源绑定、合格接收人和完成反馈构成最小闭环，相关任务同时承担创建后的追踪入口。

## 视觉与可达性 / Visual And Accessible Behavior

任务动作按收益和使用频率排序：完成保证正常闭环，阻塞及解除阻塞保证卡点可解释和可继续；通过及退回服务已有审批。转交和催办沿用现有能力，不为了按钮齐全扩展复杂调度或消息系统。当前允许动作数量少，桌面和手机直接展示全部可用方式，减少额外展开和遗漏；动作仍须可用键盘选择，选中结果明确显示，权限变化后不能沿用失效选择提交。

汇总先回答已有数据能够支持的问题。工程申请不是采购执行台账，委外合同不是发回货事实；缺值、正常待处理与真实异常分别表达。来源下钻和导出必须沿用同一记录身份及筛选口径，窄屏也能读到后续记录。收敛这几项语义比增加一套视觉皮肤更能减少错误判断。

以最新 HTML 的蓝色、紧凑布局和中性分层底色作为共享视觉真源。浅色保持柔和灰绿页面与白色内容面；暗色改用接近纯黑的页面底色，并让壳层、内容面、卡片与浮层依次抬高一档。这样能形成明确的黑色观感，又不会把边界、输入区域和可点击对象压成同一块黑。暗色中性层不带绿或蓝色偏色，强调色主要用于选中、焦点和主要动作；整页编辑的上下固定栏可使用低比例主题浅色表达当前外观，业务状态继续使用独立语义色。206px 完整侧栏保证入口名称可扫描，64px 图标栏让熟悉模块的用户按需释放业务内容宽度；切换入口始终留在品牌栏，选中态和“全部模块”不因收起而丢失。48px 顶栏与 34px 控件继续把屏幕优先留给业务内容；桌面“表格密度”让用户按阅读需要选择标准与紧凑行距，共享规则覆盖业务、权限和效能工作台的数据表；编辑明细只调整留白，控件与卡片保持稳定尺寸，避免密度切换改变操作目标大小。手机卡片采用统一布局，显示设置只保留有直接效果的明暗模式和主题色。外观由共享主题变量和 Ant Design 配置共同驱动，避免页面保留硬编码旧品牌色或局部暗色例外。页面负责布局，控件外观与页签动效由共享样式负责。

明细的展开态也需要控制高度：少量短字段并排，长说明按内容增高；产品预览紧邻选择字段，避免在下方重复展示。生产路线和客户验货保留原填写与校验规则，解释通过可键盘访问的说明入口查看。空备注不预留多行，必填原因仍直接可见。

长表单同时处理内容顺序和定位成本：关键资料后尽早出现明细，补充资料与附件置后；目录只帮助定位，不拆成多次保存或隐藏必填项的步骤。目录在宽屏常驻，在窄屏改为跳转框，优先把横向空间留给录入字段和明细。附件收紧默认占位，但待处理文件及错误必须可见。

固定标题栏帮助识别当前编辑对象，固定操作栏承载保存与离开，因此两者需要与滚动正文拉开明度层次，底部操作栏略强。两个固定栏的整体背景使用当前主题色的低比例纵向渐变，靠近滚动正文的一侧较浅，靠近屏幕上下外缘的一侧较深；分隔线和浅阴影共同表达边界，无须扩大栏高或另加左侧色条。标题栏只承担对象识别，使用单行标题和必要状态徽标；介绍、业务边界与排除清单长期占用固定空间的收益较低，真正影响填写或提交的规则放回对应正文位置。背景色表达外观主题，不承担业务状态；未保存状态使用独立语义色的文字与圆点共同提示，保存按钮仍是最突出的主动作，普通分组与目录保持较轻层次。

常用状态与搜索保留在列表第一层，其余条件按需展开，当前记录动作单独一行，避免把整表动作与单条业务动作混在一起。状态数量帮助判断工作分布和下一步进入的队列；它必须覆盖当前查询的全部记录，并保留权限与其他筛选。不能把当前页数量冒充整体数量，也不能为了贴合示意图把协作进度变成单据生命周期。手机列表减少重复标题和逐字段复制按钮，来源与产品仍可扫描；完整信息和复制放在详情中，产品图片保留直接预览。产品图只用于区分当前正在判断或操作的产品，不作为装饰：紧凑、标准、关键摘要使用 48px、56px、64px 三级尺寸，避免缩成难以辨认的图标，也不让选择项挤占主要文字；真实图片在行级、摘要、详情和选择项中均可放大。整行操作使用位于内容下方的独立命中层，图片按钮位于其上方，避免嵌套按钮并确保点图不触发行级动作。多产品对象显示代表图和明确数量，物料、财务及缺少权威产品身份的对象不猜测产品图。

状态至少同时提供文字和视觉差异，不只依赖颜色。禁用与读取状态清楚，图标按钮有名称，浮层具有进入焦点、Tab 边界、Escape 和关闭后焦点恢复。普通上下文弹窗允许点击遮罩退出，以降低取消或看完后的退出成本；有未保存内容时先确认，点击确认层遮罩只返回继续编辑，不丢输入。保存、上传或执行中以及法务确认、断连恢复等强制门禁保持阻断，避免结果未知或前置条件未满足时误回业务页面。效能工作台使用相同视觉语言，工具职责、验证证据和交付边界保持独立。

Git `index.lock` 恢复包含活动 owner、现场稳定性、候选内容和恢复读回等真实分支，仅用编号步骤容易让人误以为所有锁都应删除。因此版本发布的手动指引使用 Mermaid 判定图同时呈现“继续、隔离、停止”三条路径，并把精确命令和候选内容留在 Skill 与恢复回执。流程图只解释决策，不执行 Git，也不复制第二套锁状态；非空候选先保全再复核，既避免旧锁永久阻塞，也不牺牲可能唯一的暂存证据。

等待型自动续办和主执行共用同一聊天，如果触发条件满足后仍保留周期心跳，下一次触发可能与正在进行的实现或部署重叠并重复消耗。因此手动指引用第二张 Mermaid 明确原子交接：先删除并读回当前等待心跳，再在同一次续办中进入执行；删除失败保持未开始，执行期不重建同目的心跳。图只表达生命周期和停止条件，不让工作台成为新的任务调度真源。

主题切换不改变状态的业务含义；打印保持独立的纸面合同。长名称允许查看完整值；金额使用数字对齐；不同币种逐行标记；窄屏在当前数据区滚动，不能把整页撑宽。

动效用于解释选中项与内容的关系：指示条连续移动，页面框架保持稳定；快速反向操作不闪烁、不重置。减少动态效果时直接呈现最终状态。窄屏优先调整信息排布，保留日期、数量与主动作，避免通过隐藏关键内容或固定大高度解决拥挤。

截图用于识别遮挡、空白和层次问题，DOM 测量用于定位盒模型与点击范围，浏览器操作用于证明返回、重试和焦点恢复。对比度与动画中间帧另行测量；这些证据共同支持评估，单张截图或测试数量不能替代具体路径的核对。

## 可视化选择 / Visualization Choices

交付进度表达已出货与订购的关系；到货计划表达日期上的采购安排；生产矩阵表达每产品在四道真实工序中的位置；财务顺序表达未结账款的时间优先级。每种视图都能回到原始业务对象。

生产总览回答“哪些订单需要关注”，工序视图回答“某个产品停在哪一道工序”，两者职责不同。质检和入库保持独立的业务结果，不能为了画连续进度条而把任务完成当成事实入账。

进度卡片整条可选，减少用户寻找局部按钮的成本；分页复用工作台控件。电脑弹窗与手机整页详情适应各自屏幕，但订单身份、阶段事实和当前关注使用相同结构与数据口径，避免同一订单在不同入口显示成两套进度。

经营统计放在进度看板，复用“发现交付问题 → 核对来源订单”的路径。参考 [Odoo Reporting](https://www.odoo.com/documentation/19.0/applications/essentials/reporting.html) 的维度、筛选与图表 / 透视切换，以及 [Business Central Analysis Mode](https://learn.microsoft.com/en-us/dynamics365/business-central/analysis-mode) 的同条件分组与明细核对，采用同一查询、同一结果区和可返回的来源下钻。视觉仍使用本项目的白色操作区、蓝色重点、共享滑动分段与紧凑表格。交付、货品金额、出货金额和未结应收各有独立业务来源，默认只提供能回到单据核对的图与数字。

未知值、缺失日期和未形成的事实直接说明，不能用零值或模拟百分比填满图表。库存比例先说明统计的是记录数还是同单位数量；财务不跨币种汇总。没有可靠来源或没有后续业务动作的图，不进入默认页面。

岗位帮助先回答“我要办哪一件事”，再在固定位置提供办理概览，避免切换岗位后有的场景有图、有的只有长文字。业务链回答顺序、责任、结果和异常回到哪里；连续操作用编号步骤，简单查询用短路径。数字表达办理顺序，局部图解的字母表达操作位置；步骤数量取决于场景，不为整齐而补满五步。点击后只展开当前步骤，完整说明按需查看，减少图和长列表重复占用首屏。

图解用于完成任务，文字参考用于查清页面、字段、状态、计算与异常规则；两类内容放在同一帮助中心，搜索与目录共用词条和稳定地址。参考手册保留可复制、可搜索的独立正文，图解下方按需关联术语，目录默认收起，留出操作示意和正文宽度。业务页的“这页怎么用”和字段问号直接定位本页内容，减少离开单据后猜关键词的成本。工程用料样板沿用真实计算与审批边界：库存参考不自动抵扣，财务批准形成采购承诺，实际收货、库存和应付另行办理。

桌面直接展示关键关系，窄屏从同一定义生成纵向步骤，保留可读字号。点击节点联动对应操作或结果，使流程图能帮助办理；教学高亮与真实进度保持区别。帮助只解释，不再实现一套可提交的业务表单。关系图、编号和当前说明共用场景数据，图形只负责排布；异常定义只补充起点、责任和恢复去向。快照检查提示正式帮助内容的变化，维护时再同步复核图形语义，不建立另一套业务引擎，也不承诺自动发现所有后端逻辑变化。

数量精度服务于实际计量：件数类单位保持整数，长度和重量保留其允许的有效小数，BOM 单件耗用与实际办理数量分开。展示不补满小数位，也不为了整齐截掉有效值；切换单位后保留原输入并说明精度问题，避免用户未察觉的数量改写。

明细密度的调整以联系人编辑为参照：主字段保持可比较，低频补充信息显示真实摘要，完整输入按需展开。销售与采购优先减少纵向和横向占位；到货卷包与库存多行共享表头，差异、来源与数量关系始终可见。已有紧凑模块保留原结构。视觉沿用系统主题、控件、表单骨架和字号，独立草稿只作为交互输入；原表核对入口和错误自动展开共同保证压缩后仍可完成核对与修正。

明细列宽由字段类型和可用宽度决定。数量、单位和日期的输入长度相对稳定，产品、材料与来源需要更多阅读空间；把大屏余量分给长内容，能减少横向滚动和空白数字栏。默认布局由系统统一维护，避免把逐页调宽、保存偏好和恢复布局的成本转移给使用者。

重复明细需要一个稳定、低成本的行定位线索，因此序号使用窄列或窄屏行首标记，而不增加编号卡片和持久化业务含义。标题行入口解决首次发现，底部同名入口服务连续录入；新增后的滚动、聚焦与短暂反馈让用户立即知道新行出现在哪里，避免依赖页面高度或反复寻找空白行。

逐行弹窗会割裂跨行比较，整块卡片又会放大纵向占用，所以继续保留共享表头下的行内编辑。系统按业务字段决定列宽和窄屏重排，用户无需维护列宽偏好；只有长说明和低频资料按需展开。

## 设计资产维护 / Design Maintenance

只维护一份最新可交互 HTML、设计说明和本页依据。开发工作台直接读取同一来源，提供交互、说明、依据和真实共享控件四个视角，不再用多版本画廊、图片或生命周期标签增加选择成本。

设计稿以虚构数据覆盖常见、异常和边界状态；正式页面以 API、状态、权限和测试为准。后续变化先说明改善了哪项判断或动作，再同步设计、实现与相关测试。设计资产的存在不证明实现、上线或验收。

本目录保存岗位任务端当前仍在使用的 v1 列表壳 as-built HTML，以及三张早期 PNG 原型图。`Current` 只覆盖列表首屏；同一 HTML 中保留的旧详情内处理仅作历史对照，不再定义选中任务后的当前主路径。

## HTML 口径

保留一个“当前列表基线”HTML，不把三张 PNG 分别机械转成三份 HTML。

原因：

- 这批 PNG 已作为岗位任务端改版参考，真实实现入口已经落到 `web/src/erp/mobile/pages/MobileRoleTasksPage.jsx`，且与早期 PNG 略有差异。
- `implemented-reference.html` 用于记录真实页面吸收早期方向后的当前列表首屏。
- 该 HTML 保持可直接在浏览器打开；脚本状态必须先于首屏内容初始化，不能让演示页因初始化顺序错误停在空白或半渲染状态。
- 当前运行态继续保留本参考的 v1 列表标签、筛选、分页 / 分批展开和任务卡片；待办页使用“已加载任务分布”显示待处理、卡住、已退回和完成数量，标题本身限定为已加载口径，不再常驻解释分页实现，也不把这些数量描述成岗位全量；任务列表右表头精简为“状态 / 截止”并保持单行。主分区顶部不再重复“已加载 N 条……”摘要，待办筛选、已办标题和提醒子标签只在对应内容旁保留数字胶囊；“我的”不硬造计数。已办页直接展示已办任务与完成 / 退回状态，不重复整池分布。真实行为继续以运行时代码、自动化测试和浏览器回归结果为准。
- “我的”页保留账号名称、账号岗位、真实可用入口和入口安全，不在用户名下重复“某岗位任务端”身份说明；有电脑端权限时只在“我的”保留一个“切换工作入口”，页头不再放重复的图标快捷方式。电脑端将同名低频动作收进用户名账号菜单，与“退出登录”放在一起，返回统一入口选择页后仍只展示当前账号已授权的入口。
- 底部主导航仍固定为待办 / 已办 / 提醒 / 我的四项，不增加第五个审批入口。无审批权限时待办筛选为“全部 / 风险 / 超时”；当前账号至少有一项同时通过 RBAC 与 effective action 的已登记审批能力时，同一分段行显示“全部 / 审批 / 风险 / 超时”，并通过独立服务端 `approval` 游标视图读取完整可见集合。“我负责”不再保留为主筛选，因为它只按当前已加载待办做客户端近似计算，常与“全部”重复且不能代表完整个人队列。
- 选中任务后进入 v2 的“查看任务 → 处理任务 → 结果回执”全屏流程，结束后恢复原列表的筛选、已加载分页、滚动位置和焦点。HTML 内的旧详情、原因面板和条件动作栏只用于追溯上一版交互，不属于 `Current` 范围。
- 完成、阻塞、退回、解除阻塞或催办只更新 Workflow 协同任务，不等于库存、质检、出货或财务 Fact 已过账。
- [`../mobile-role-tasks-v2/`](../mobile-role-tasks-v2/) 的选中任务流程同为 Current 并已接入本地运行时代码；它只接管选中任务后的查看、处理与可信回执，不替换或移除 v1 列表。三张 PNG 保持 History / Evidence。

## 边界

- 本目录只保存设计参考，不进入 `web/src`、菜单、路由或生产构建。
- 图片不是业务规则、权限规则、Workflow 状态或 Fact 事实真源。
- 若图片里的字段、状态、按钮或分组与代码、测试、`docs/当前真源与交接顺序.md` 或 Workflow / Fact 边界文档冲突，优先按正式文档和当前代码收敛。

# 新建 / 编辑业务表单样板 / Business Form Page Standard

本目录保存整页业务编辑 的 `待实现 / To Implement` 样板。当前以销售订单为代表对象，对齐运行时 `SalesOrderForm`；其他业务对象只复用共享编辑页、字段布局和明细模式，不机械复制销售订单字段。

## 文件与责任

| 文件 | 责任 |
| --- | --- |
| `index.html` | 销售订单新建 / 编辑表单、附件、订单行、校验、来源切换和只读评审状态。 |

只读完整信息由 `business-detail-page-standard-v1/index.html` 表达；来源选择器、列顺序、状态规则和危险确认由 `action-modal-drawer-standard-v1/index.html` 表达。本样板不再复制这些局部弹窗的内部流程。HTML 展示已选规格的紧凑明细表示例；运行态新建订单从空明细开始，默认值和保存校验以 `SalesOrderEditor`、`SalesOrderForm` 和销售订单页面为准。

## 当前结构

- 占满模块主内容区，新建与编辑复用 `BusinessFormPage`；正文独立滚动，底部固定操作。适用各菜单主列表的新增 / 编辑，包括主数据、完整单据、事实草稿和员工资料；编辑中的快捷新建、来源选择、预览和专项确认继续使用弹窗。
- 主字段按运行态分为“订单与客户、联系人与负责人、结算条件、税费与运费条件、交付与收货、附件与其他说明”。客户、联系人和结算条件可从主数据带出，本单可覆盖的快照继续在本单维护。
- “报价含运费”表示运费已经进入产品单价，另计报价运费禁用并清空；“报价不含运费（另计）”允许在草稿中暂缺，但提交前必须填写，金额沿用订单币种并进入整单计税基础和订单总额。出货实际运费保持独立。
- 订货明细先记录客户需求名称、款号、数量、单位和交期；已有产品规格是选填来源，产品与物料清单由工程后续完善。运行态可先保存无明细草稿，手工添加的明细仍须通过名称、单位与数量校验。
- “添加订货明细”是主入口；“从已有规格添加”打开第二层产品规格选择器；“调整明细顺序”在至少两条明细时显示，只调整本单明细排列。复制行创建新草稿行，移除行不等于删除已生效业务对象。
- 更换 SKU 时只更新产品、颜色、默认单位等来源字段；数量、单价、金额和交付日期不被静默覆盖。清空来源时对应来源摘要必须清空。
- 单据明细共用表头，产品、数量、单位、价格和交期保持可见，关联资料与备注放在行内补充信息；纵向随编辑页展开，宽表保留整表横向滚动，联系人按可用宽度换行。保存错误须展开出错明细并定位字段。
- 通用底部动作只有返回列表和保存。不存在跨业务对象通用的“重置整表”正式动作。

## 运行与事实边界

- 原型状态切换只用于评审新增、编辑和只读展示，不是运行态字段。正式模式来自打开入口、记录状态和当前权限。
- 保存前的必填、日期、数量精度、报价运费残值、金额、来源资格和版本校验仍由正式表单与后端 usecase 共同守住；草稿保存不等于已经满足提交条件。
- 附件选择不等于上传成功；只有业务对象保存和附件上传均成功后才建立正式关联。
- 本样板不创建库存、质检、出货、财务或任务结果，也不替代 schema、API、RBAC、migration 或测试。

## 验收关注点

- 六个字段分组、附件和订单行在桌面可扫描；窄屏改为单列且无页面级横向溢出。
- 订货明细添加、已有规格选择、带出摘要、复制行、移除行、调整明细顺序和统计入口位置清楚；明细纵向随正文展开，宽表整体横向滚动不推宽页面；共用表头，补充信息按行展开，收起不丢失已填内容。
- 必填错误能聚焦首个缺值；只读时全部变更入口和保存禁用。
- 运费条件切换会同步清空 / 启用报价运费，底部货款、报价运费、税额和订单总额随输入更新。
- 明细数量或单价未齐时，货款金额显示“待补齐”，不能把缺值显示为零金额。
- 打开后焦点进入真实控件，Tab 按页面顺序移动；返回列表恢复原触发点，未保存内容退出前提示，Escape 不关闭整个编辑页。
- 浅色、暗色、校验态、禁用态和附件空态均可读。

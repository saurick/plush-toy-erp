# 任务看板中心样板 / Task Command Center Pattern

本目录保存后台“任务看板”的 `To Implement` 标准样板。它把任务入口重构为紧凑的职责处理台，不替代正式业务菜单，也不代表运行时已经实现。

## 文件

| 文件 | 用途 |
| --- | --- |
| `index.html` | 单文件可交互 HTML 原型，覆盖四类互斥任务队列、组合筛选、键盘选中、只读当前详情、相关单据入口和共享处理流程交接。 |
| `images/task-board-redesign-reference.png` | 本轮生成的桌面信息层级方向图，只作视觉比较，不替代 HTML 交互原型或运行真源。 |

共用任务处理流程的完整状态样板见 `../workflow-task-action-flow-v1/index.html`。任务中心只吸收该流程的入口和核心交互，不为自己维护第二套业务规则。

## 本轮重设计结论

- 首屏改为“分类指标 + 紧凑筛选 + 任务队列 / 当前详情”主从结构。删除大面积宣言卡、重复业务对象捷径和独立边界说明区，把空间留给任务判断与处理。
- 四个指标本身就是队列分类入口，不再额外复制一组页签；再次点击当前指标或点击“查看全部分类”回到总队列。
- 任务卡单击选中并同步右侧详情；上下方向键、`Home`、`End` 可在当前结果中移动，`Enter` 显示进入专用处理流程的交接提示。
- 当前详情只展示“为什么现在要看、负责岗位、到期时间、业务来源、相关单据、处理提示、可用动作、最近协同记录”。不展示 raw ID、权限 key、schema 字段或开发说明。
- “处理提示”是只读的原型规则示例，不是用户填写的下一步计划。正式运行时应由任务状态、当前账号可用操作和来源入口共同派生；来源入口还必须通过当前账号的页面权限投影，无法可靠派生时不应显示静态兜底建议。
- 三步状态机 `核对任务 -> 选择处理 -> 确认与结果` 由 `workflow-task-action-flow-v1` 单独维护；本页面不再复制步骤、原因表单、提交或结果回执。
- 有正式 ProcessRuntime 锚点时，共享处理流程展示“执行轨迹”；任务看板只展示当前任务所需的只读摘要和进入流程的单一入口。
- “业务轨迹”和“本任务处理记录”的读取边界由共享处理流程定义；本页面不重复拼装来源单据审批链，也不以任务信息代替领域 Fact。
- 完成、阻塞、退回、解除阻塞和催办的可用性、原因要求与提交状态均由共享处理流程承接，任务看板不维护第二套动作规则。
- 完成动作不要求原因；阻塞、退回、解除阻塞和催办要求原因。提交中禁用重复提交，成功后停留在结果页并给出回执；有正式流程锚点时直接说明下一责任岗位、系统自动处理或流程终点，再由用户关闭或返回队列。
- 原型内含常规、风险、阻塞、到期和已完成任务，便于 review 分类、筛选与只读详情差异；静态任务均为中性样例。
- 保留暗色主题、窄屏单列和队列键盘导航；弹窗焦点、关闭与快捷提交语义只在共享处理流程原型中维护。

## 页面单一主任务

任务看板只帮助有权限的桌面用户完成三件事：

1. 从当前可见范围中判断谁该处理、哪里阻塞、哪些到期。
2. 选中一条任务，核对当前上下文和可用操作摘要。
3. 进入专用任务处理流程，或跳转到相关业务对象继续办理。

它不复制销售、采购、生产、库存、出货或财务菜单，不提供通用业务对象快捷入口，也不把任务完成写成业务事实完成。

## 与当前真源的边界

- 本原型继续按 `待实现 / To Implement` 登记；未获用户明确确认前不得晋级 `Current`。
- 运行时 `/erp/task-board` 本轮已吸收四类可点击指标、组合筛选、左侧任务队列 / 右侧当前任务、只读处理提示、单一“处理任务”入口和共享三步任务抽屉；提交成功后共享抽屉停留在“确认与结果”，业务页协同入口也保留同一回执。原型还覆盖更完整的只读、仅催办和失败重试状态，因此继续保持 To Implement，不自动晋级 Current。
- 共享抽屉在存在正式流程锚点时读取 `get_task_process_context`，展示业务流程、来源单据、流程状态和已执行 / 当前 / 受阻轨迹；结果回执只从当前 linked Workflow task 读取责任岗位，不指定具体人员，也不根据任务标题、责任池或 `waiting` 节点补造下一岗位、起点、终点或未来路线。
- 真实实现必须继续连接现有 `get_task_board`、任务可见范围、动作 explain、RBAC、`owner_role_key`、assignee 和任务状态合同；原型固定数字和 mock 脚本不得进入运行时。
- `rejected` 与 `done` 在本样板中只读；仅催办示例表达动作权限受限，不代表新增权限码或状态。
- “查看相关单据”只表达跳转语义，并且仅在服务端确认真实来源关联、当前账号可读取来源、正式路由可解析且菜单入口可见时显示；普通任务的来源标签和前端路由别名不构成真实关联，不因任务中心新增菜单入口。
- Workflow 任务完成、阻塞、解除阻塞、退回或催办只更新当前协同任务 / 事件；库存、质检、出货、应收、应付、开票和付款仍由对应领域 usecase 处理。

## Review 与验收关注点

- 四个分类数字在当前组合筛选下与各自队列数量一致；全部结果等于四类互斥数量之和。
- 搜索、状态、负责岗位、业务来源和分类筛选可组合；结果变化后只在当前结果内恢复选择，不默认选中已被筛掉的任务。
- 单击、上下方向键、`Home`、`End` 和 `Enter` 在当前队列中均有明确语义，筛选变化后不会保留已被排除的选中项。
- 点击“进入处理流程”后，本页只显示上下文已就绪的交接提示，不展开步骤、原因表单或提交结果。
- 处理方式、仅催办限制和原因必填规则统一在 `workflow-task-action-flow-v1` 核对，本页不复制动作选项。
- 只读任务仍可核对任务详情；只有真实关联且当前账号具备来源读取与菜单权限时才可核对相关单据。终态不能重复提交。
- 多次返工、attempt 和分支 waiting 节点属于专用处理流程验收范围；任务看板只核对当前记录与最近协同记录。
- 任务队列、只读详情、组合筛选、窄屏和暗色状态不得出现页面级横向溢出、遮挡或错误焦点。
- 文案始终区分 Workflow 与 Fact，不把静态原型、局部交互或回执写成真实运行态已交付。

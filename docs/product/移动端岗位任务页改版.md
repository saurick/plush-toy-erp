# 移动端岗位任务页改版 / Mobile Role Tasks Redesign

## 结论

超级管理员手机查看是所有环境的正式能力：手机入口默认 `/m/all/tasks`，顶部“查看岗位”可在“全部岗位”和当前客户已开放岗位间切换，并保留“管理员视角”标识；明确岗位深链与刷新保持该查看范围。它复用本页的进度、任务、风险、详情与“我的”，不另建一套后台。全部 / 单岗位仅收窄任务读取，不模拟员工、不写账号岗位，也不改变既有办理授权。普通 `admin` 角色不自动获得该能力。范围变化立即清除旧数量和分页，拒绝迟到响应；无 active customer runtime 时继续显示恢复入口。

岗位端的唯一高保真交互参照为 [统一 UI HTML](ui-design/index.html)。任务列表负责找到当前事项，进入后依次完成“查看任务 → 处理任务 → 可信结果回执”，结束后恢复原列表；底部导航按权限显示三项或四项，具体业务与权限以本文、页面动作规则及运行时代码为准。

移动端的通用任务动作只更新 Workflow 协同任务。完成、阻塞、退回、解除阻塞或催办均不代表库存、质检、生产、出货、应收、应付、开票或收付款 Fact 已过账。由正式 `production_rework.post` 生成、来源锚点完整且当前经办人同时具备 WIP 读取 / 安排权限的生产异常任务，详情可额外进入现有 WIP“安排本厂或外发”动作；该动作只保存当前返工批次的加工安排，不自动改变任务状态，也不登记后续完工、回仓、质检或库存事实。

## 手机进度 / Mobile Progress

具备业务进度读取权限的岗位，在底部首位看到“进度”。页内依次为订单交付 / 生产执行、搜索与筛选、全部 / 已逾期 / 7天内 / 任务受阻，再进入进度卡片；不重复显示页头或更新时间。筛选与待办共用浮层，记录范围与其他关注即时生效，重置保留搜索词，选择和重置均保持浮层打开。搜索在服务端查询单号、客户、产品和负责人。

卡片显示单号、业务状态、产品、客户、交期、当前工序、具有相同单位的数量与进度，以及任务摘要。56px 产品图不撑开信息区；多产品与多单位明确标注，不制造一个虚假的汇总百分比。仅有一项可见待处理任务时，显示任务名称和责任岗位 / 经办人，点击直接读取该任务详情；多项时显示数量及后端选出的首要任务，点击展开该单据的关联任务供选择。无待处理任务时只显示灰色提示，没有箭头或点击入口；没有任务读取权限时不展示任务摘要。入口使用“查看任务”语义，进入详情后按既有权限决定办理、催办或只读。查看详情后恢复查询与滚动位置；关联任务遵循现有权限和办理合同。

进度详情与任务、风险详情共用返回、标题和状态页头，以及 12px 内容边距、分区卡片和底部固定操作区。手机进度详情按交互稿分别展示单据摘要、紧凑阶段进度和最近记录，不直接套用桌面摘要排版；字段按左标签、右内容对齐。阶段口径复用进度看板的资料确认、领料、生产与质检聚合，仅已知的真实比例显示进度条。最近记录读取当前可见关注任务（无匹配时为首条关联任务）的最近三条正式处理事件，并标明所属任务；无记录、无权限和读取失败分别显示，不从当前阶段推造历史。

“查看业务明细”按需展开仅含真实记录的“产品信息 / 生产执行 / 关联任务”三组；生产执行在同一组内依次展示生产单、工序批次和领料，不再把五类记录平铺成换行按钮。手机详情不提供“打开原单”或行内电脑版单据链接；生产单与关联任务分别进入现有手机生产进度和任务详情，确需使用电脑业务页时从“我的 → 切换工作入口”主动进入。底部“查看关联任务”仅在存在可见任务时直接展开相应分组。返回按钮按内容宽度排布，主要操作占剩余宽度，触控高度至少 44px。进度、关联任务、生产进度之间逐级返回，保留原查询、分组与列表位置。

任务与风险详情使用“任务信息 / 任务办理 / 结果回执”三步页头。首卡保留任务名称、来源与产品简述、负责岗位、截止时间和附件入口；进入本岗等其他时间、完成条件与业务字段在业务信息卡核对，完整产品与来源信息可展开查看和复制。实际产品图片仍可预览，附件与复制入口保持次要操作，底部保留当前权限允许的主要动作。

下拉刷新只移动筛选下方的数据区域，保留视图与查询。同一查询刷新失败保留已加载数据并提供重试；新查询失败不能显示旧条件结果；明确撤权或会话失效立即清除旧进度，不适用失败保留。追加失败保留已加载记录；搜索、视图或授权范围变化结束旧手势并拒绝过期响应。正常动效使用共享 220ms 曲线，减少动画偏好下取消位移动画。

## 当前工作流

1. 登录后从服务端刷新管理员、权限和客户 effective session。明确岗位深链优先；否则直接进入当前账号第一个可用移动岗位，不在登录入口重复选择岗位。
2. 列表底部按权限显示“任务 / 风险 / 我的”，具备进度读取权限时首位增加“进度”；“待办 / 已办”放在任务页内切换。继续保留服务端游标分页 / 分批展开和任务卡片。无审批权限时，待办主筛选为 `全部 / 风险 / 超时`；当前账号至少有一项有效审批能力时，同一分段行变为 `全部 / 审批 / 风险 / 超时`，其中“审批”的完整无障碍名称为“待我审批”，不增加独立审批卡或第五个底部导航。`todo / approval / risk / history` 使用各自服务端游标、快照和分页，不在前端合并成第二套任务真源。
3. 点选整张任务卡进入全屏详情。列表以产品或物料名称为主标题、任务名称为次要文字，保留编号或款号与单据图标；未设置截止时不显示无意义占位。详情先展示任务、产品、责任和阻塞原因，再展示真实任务附件、完成条件和补充业务信息；长标题、长来源和历史处理线索允许换行。旧动作留下的文本证据引用只作为“历史处理线索”只读展示。可信生产返工异常任务可在详情中先为其精确关联的在制批次安排本厂或外发，再回到任务处理页记录本次处理结论。
4. 有操作权限时进入独立全屏处理页；仅催办任务的详情主按钮标为“催办任务”，处理页只提供催办；只读任务不展示假动作。完成必须填写可核验反馈，阻塞、退回、解除阻塞和催办必须填写原因。处理页不再重复提供自由文本证据框或附件上传，附件统一回到详情页按权限查看或管理。
5. 提交后进入独立结果回执。回执区分 `confirmed / unknown / failed`，显示服务端确认的任务快照和本次反馈或原因；只有旧任务确有历史证据引用时才显示“历史处理线索”。没有可信来源时不补造处理人或处理时间。

办理页按高保真使用整行单选项，每项包含动作名称和简短说明，选中态跟随当前主题色；“完成本岗 / 标记阻塞”等名称只影响展示，不改变动作权限和提交参数。当前可用动作数量少，全部方式直接展示，不再增加“更多处理方式”折叠入口。动作选择、原因或完成反馈及必要的批准数量放在同一张办理卡中；底部固定“返回任务”和主要确认按钮，提交中两者均禁用，返回保留已有草稿。

回执先展示居中的结果图标、结论和说明，再展示任务名称、来源及左右对齐的办理方式、确认状态和办理说明。产品图片与完整身份信息回到“任务信息”核对，不在回执重复堆放。确认后使用主色“返回任务列表”；结果待确认或失败时保留重新确认 / 重新载入入口，明确显示已知任务状态，不把它当成此次提交成功。成功回执承担反馈，手机任务流程不再叠加成功浮层遮住页头；失败与刷新异常仍保留对应提示。解除阻塞、催办等非审批动作不显示“审批办理已确认”。

所有岗位共用“核对 / 查看 → 处理 → 结果”的边界。核对页统一展示“任务处理链”：有流程实例时读取既有业务轨迹；工程用料任务按本次提交记录读取提交、老板审核和财务审核证据；其他任务明确仅有当前任务记录，不推测前后岗位。处理链和本任务处理记录各自加载，读取失败不互相替代。

工程用料任务在核对页按需查看材料汇总；处理页统一不展示产品卡片、只读材料汇总、部位明细和既往审核记录。老板和财务的处理页都只选择通过或退回并填写意见。财务审核通过后按冻结的 BOM 应需数量、按厂商自动生成采购订单，不录入采购数量、单价或到货日期；采购单单价、金额和预计到货日期留空。退回必须填写原因，不生成采购订单。工程可先在核对页“查看待重提用料”，原退回记录仍由“查看材料汇总”独立读取；重新整理后校验已保存资料再提交，不在办理步骤重复展示汇总。手机端和电脑端共用处理表单，提交前仍读取来源单据并校验状态与版本。

列表顶部保留搜索和紧凑筛选，移除独立的“当前岗位任务状态”统计卡及数量口径说明。数量在可操作的筛选、底部任务 / 风险入口及“已显示 / 共 N 项”列表范围中呈现；服务端仍维护完整计数合同。

底部“任务”和“风险”统一使用红色通知角标，分别表示当前岗位完整待办数和后端授权范围内的风险任务数；超时是风险的子集，不重复相加。“进度”和“我的”无角标，零值隐藏，超过 99 显示 `99+`，辅助阅读仍提供完整数量。角标复用 `list_role_tasks` 首屏的完整计数，只带回一条任务，不带搜索、状态或分页条件；列表内数量继续反映当前筛选。打开页签不清零，列表读取成功、从详情返回、网络恢复或页面重新可见时重新查询。更新失败保留同一账号岗位范围内的已知数量，并在导航上方提供重试；首次失败保持未知，不显示零值。切换账号、岗位或权限范围立即清除旧数量，拒绝过期响应；明确撤权或会话失效时不保留旧计数。

列表顶部直接显示搜索与筛选，下面依次是待办 / 已办切换和状态胶囊，不重复增加大标题与岗位说明。搜索和筛选按钮高 42px，状态胶囊高 34px。手机端不设置常驻刷新按钮，失败时提供明确的重试入口。待办、已办、风险和进度列表到顶后可下拉，达到提示距离后松开刷新；更新时间只在下拉反馈中显示。短距离、横向、双指、取消、从列表中途开始及输入控件内的手势不触发刷新。刷新只重取当前查询，不重载页面；保留搜索、排序、状态和已有任务，失败时继续展示旧内容与重试入口，刷新中不重复请求。刷新结果提示只保留一条，连续操作时更新当前提示，避免叠放遮住列表。

下拉时搜索、分类与筛选控件及底部导航保持原位；刷新提示位于筛选区下方，只带动数据区下移，完成或取消后复位。加载失败与重试提示同样放在数据区，避免挤动上方操作区。正常浏览沿用页面既有滚动容器和工具栏显隐规则。

“我的”依次提供账号信息、显示设置、入口与安全、系统信息和退出登录。显示设置直接提供跟系统 / 浅色 / 暗色和蓝绿黄粉橙紫六种主题色；明暗模式使用共享分段控件。手机卡片采用统一布局，不提供只控制表格行高的表格密度选项。主题切换即时生效并在当前浏览器保存，与桌面和效能工作台共用主题偏好，不改写已有表格密度；往返“我的”保留待办分类与已展开数量。该页不展示任务刷新入口、任务加载错误或离开列表后才返回的请求提示。下拉反馈独立于任务列表渲染，切换查询、岗位或主页面时结束旧手势；列表的既有过期请求保护继续生效。

待办和风险列表提供“最近进入 / 截止最早 / 等待最久”排序及“全部状态 / 待处理 / 阻塞”状态筛选。搜索旁的“筛选”按钮高 42px，并显示非默认排序和状态的已应用数量。点击后在按钮旁展开浮层，靠近屏幕边缘时自动避让；排序和状态分别使用共享分段切换，当前项以底色和文字强调，点选立即生效并保持浮层打开，以便连续选择并看清选中滑块。点击关闭、再次点击入口、点击浮层外或按 Escape 可收起，分段切换支持方向键选择，主动关闭后恢复入口焦点；点击外部输入框关闭时保留外部输入焦点。默认最近进入，入岗排序使用不可变的 `created_at`；截止排序使用 `due_at`，未设置截止的任务排在最后。同一时间用任务 ID 降序固定顺序。排序、状态和搜索在服务端分页前执行，筛选数量使用同一条件与权限范围；浏览器保留服务端顺序，不再用当前页优先级或更新时间重排。已办仍使用独立历史视图，不受待办状态筛选影响。重置只恢复当前页签的默认排序与全部状态，保留搜索词和待办分类；搜索框的清除动作负责清空搜索，其他页签的条件保持不变。

待办和风险的分类页签保持吸顶，搜索与筛选入口位于页签上方，排序、状态和重置收在筛选浮层内。吸顶后持续向下滚动 24px 收起筛选，向上回看 16px 重新显示；未到吸顶位置时保持显示。轻微方向抖动和手机顶部 / 底部的弹性越界不切换状态。下拉菜单打开或筛选按钮处于键盘焦点时保持显示。收起仅改变可见性，不挤动列表、不重建控件或重发查询；切换查询及返回顶部恢复自然显示，减少动态效果设置下直接切换。

`list_role_tasks` 的可选 `sort_key` 为 `newest / due / oldest`，可选 `status_key` 为 `ready / blocked`；不传排序的其他消费者保留原有 ID 降序。游标绑定关键词、排序、状态、岗位、风险可见范围及完整精度的排序时间与 ID，变更条件后不能复用旧游标。切换条件清空旧分页与滚动位置，加载反馈仅在列表内展示，筛选控件仍可使用；详情返回或详情刷新后恢复所选条件。无匹配任务显示空态，并保留重置入口。

搜索覆盖订单号、产品名称 / 编号、内部款号及物料名称 / 款号，在服务端分页前执行。搜索框复用共享控件，手机高度为 42px，只保留一层焦点边框；停输入 300 毫秒后自动查询，中文输入法组词期间不查询，回车可立即查询，清空立即恢复全量范围，无独立搜索按钮。相同关键词不重复查询，查询范围变化时清空旧游标；离开列表或切换岗位 / 账号权限范围时取消未触发的搜索，旧请求的结果和错误不会覆盖当前范围。

浏览器或系统返回键按“回执 → 列表”或“处理 → 详情 → 列表”恢复，并保留搜索词、列表筛选、已加载分页、滚动位置和焦点；处理草稿在处理路径内恢复。移动软键盘出现时使用 `visualViewport` 收敛可视高度；校验失败聚焦第一个缺失字段，`Ctrl/Cmd + Enter` 提交，`Escape` 返回详情。主要触控目标不小于 44px，底部主动作不随正文滚走。

## 任务识别与布局

外观以 [UI 交互设计](ui-design/交互设计说明.md) 的高保真合同为准：统一默认蓝色、灰绿中性底色、12px 页边距与 16px 任务卡圆角。岗位切换、按权限投影的三项或四项导航和查看 / 处理 / 回执流程继续使用真实业务合同。待办、已办、风险和超时使用同一主次标题：产品或物料名称优先，任务名称以较弱文字并排显示，长文本自然换行；没有关联内容时保留任务名称。状态、来源单据、编号或款号、风险原因和时间继续分层展示。整卡打开任务或已办结果，不再重复显示“查看任务 / 查看结果”与箭头。

工作台、任务看板、业务看板的关注任务和手机列表共用任务时间展示。待办最多显示“进入本岗”和“截止”两项时间，今天 / 昨天用相对日期，其余显示月日，跨年补全年份；详情和桌面悬停可查看精确年月日与时分。任务在创建时进入其负责岗位，`created_at` 是不可变的入岗时间；`owner_role_key` 在当前任务生命周期内不变，更换经办人、退回岗位共同待办、催办、附件更新及解除阻塞均不重置入岗时间，不使用 `updated_at`、单据创建或流程开始时间替代。新岗位的新任务使用自己的创建时间。缺少时间时列表不补造占位，详情明确“未记录”或“未设置截止”。

已完成 / 已退回 / 已撤回列表只显示对应的 `completed_at`，详情保留入岗、原截止和结束时间，终态不再展示当前逾期警告。阻塞详情仅在已有任务事件中找到当前这次进入阻塞的真实转换时显示“本次阻塞”，催办、转交或同状态更新不算新的阻塞；事件截断、缺失或不匹配时不猜测开始时间。列表不额外请求事件或单据，订单交期仍在关联单据中核对，不与任务截止混用。

有产品时显示名称和产品编号，有物料时显示名称和款号；缺少款号时明确提示未填写，不拿系统物料编号代替。列表卡不叠加复制按钮；详情保留字段及整项信息复制，另外保留独立的内部款号或系统物料编号；单据来源不是销售订单时，已关联的销售订单号可补充显示。采购来源的列表显示首项采购物料与真实采购明细总数，不把关联产品记录混入该数字；其他多项来源显示首项与明确标注的关联内容总数，详情通过“关联内容”展开其余项。任务标题、单据入口、附件、完成条件和原有业务动作继续保留，处理页及回执仅保留识别摘要。

手机待办列表产品摘要旁显示 40px 主图，详情沿用 52px、桌面 64px，完整保留轮廓，不裁剪拉伸。列表与详情中的实际图片都可独立放大预览，不同时打开任务；任务仍通过卡片其他区域进入。详情首卡只在存在主图引用时显示图片，完整产品与来源区保留图片或占位。多款任务首图必须与首个产品名称对应；列表和完整产品摘要中没有可显示图片时，保留同尺寸的中性图标占位：产品标为“暂无图”，物料使用物料图标；无产品读取权限时不请求图片，也不推断是否已上传。图片加载失败保持占位并显示“加载失败”，不折叠图片区域，不借用辅图、其他款或任务附件。无图占位不提供放大按钮，点击列表占位仍进入任务；关联对象已不可用或任务没有产品 / 物料摘要时不补造对象。小图进入视口后读取，同账号权限范围内同附件去重，原图只在放大时加载。

身份信息复用后端只读 `display_context`，不新增手机私有字段；明确空值或来源失效不回填旧任务快照。仅状态更新的回执可以保留同一任务、同一来源绑定的已读摘要；来源切换或解除绑定后必须清空，下一次读取以服务端新投影为准。

## 权限、可见性与性能边界

- 列表只消费服务端已经授权的 `list_role_tasks` 结果。前端不得再按当前岗位二次删除跨岗位但明确指派给当前用户的任务。
- “待我审批”入口只在任一已登记审批能力同时通过 RBAC 与当前 effective action 时显示，并与全部、风险、超时共用同一筛选分段行；服务端仍按具体 capability、任务冻结 revision、责任池、owner / assignee 和状态决定每条任务是否可见与可办。
- 不再提供“我负责”主筛选：旧实现只在已加载的 `todo` 页内按当前 assignee 或未指派岗位池做客户端派生，既常与“全部”高度重复，也没有独立服务端游标和完整数量。未来若确需个人队列，应新增明确的服务端 assignee 视图，而不是恢复本地近似筛选。
- 可见不等于可处理。处理前继续消费后端 action explain，并在提交前复核权限、任务版本和幂等意图；确认失败时 fail closed。
- 返工生产安排入口同时要求任务可办、正式来源任务合同与来源意图校验通过，并命中 `production.wip.read + production.wip.assign`；选择外发时还必须具备 `outsourcing.order.read` 并关联已确认、未关闭的加工合同明细。手工仿造或来源锚点不完整的任务不展示入口。
- 初次客户运行态同步失败时不挂载任务页；后台刷新瞬时失败时保留最后一次有效投影并提供重试，不因临时网络抖动伪造撤权结果。
- 列表只提供一个“显示更多”入口：先展开已加载内容，已加载内容耗尽且服务端仍有下一页时，继续读取同一 `server_time` 快照并直接显示新批次。下拉刷新重新获取最新快照；过期请求保护、失败保留上次数据和刷新反馈继续沿用现有实现。
- 自动搜索只读取当前权限范围内的服务端分页结果，不下载全部任务做本地过滤；输入防抖减少请求次数，数据量增大时仍需按实际查询耗时评估服务端性能。

# 移动端岗位任务页改版 / Mobile Role Tasks Redesign

## 结论

岗位任务端采用有意组合的当前主路径：v1 列表继续负责“找到当前事项”，v2 负责选中任务后的“查看任务 → 处理任务 → 可信结果回执”，结束后恢复原列表。两份 HTML 都登记为 Current，分别描述列表基线和选中任务流程；v2 不替换 v1 列表。

移动端的通用任务动作只更新 Workflow 协同任务。完成、阻塞、退回、解除阻塞或催办均不代表库存、质检、生产、出货、应收、应付、开票或收付款 Fact 已过账。由正式 `production_rework.post` 生成、来源锚点完整且当前经办人同时具备 WIP 读取 / 安排权限的生产异常任务，详情可额外进入现有 WIP“安排本厂或外发”动作；该动作只保存当前返工批次的加工安排，不自动改变任务状态，也不登记后续完工、回仓、质检或库存事实。

## 当前工作流

1. 登录后从服务端刷新管理员、权限和客户 effective session。明确岗位深链优先；否则直接进入当前账号第一个可用移动岗位，不在登录入口重复选择岗位。
2. v1 列表首屏继续保留待办 / 已办 / 风险 / 我的四项主导航、服务端游标分页 / 分批展开和任务卡片。无审批权限时，待办主筛选为 `全部 / 风险 / 超时`；当前账号至少有一项有效审批能力时，同一分段行变为 `全部 / 审批 / 风险 / 超时`，其中“审批”的完整无障碍名称为“待我审批”，不增加独立审批卡或第五个底部导航。`todo / approval / risk / history` 使用各自服务端游标、快照和分页，不在前端合并成第二套任务真源。
3. 点选整张任务卡进入全屏详情。列表突出产品编号或款号，用单据图标和明确的查看入口辅助扫描；未设置截止时不显示无意义占位。详情先展示任务、产品、责任和阻塞原因，再展示真实任务附件、完成条件和补充业务信息；长标题、长来源和历史处理线索允许换行。旧动作留下的文本证据引用只作为“历史处理线索”只读展示。可信生产返工异常任务可在详情中先为其精确关联的在制批次安排本厂或外发，再回到任务处理页记录本次处理结论。
4. 有操作权限时进入独立全屏处理页；仅催办任务的详情主按钮标为“催办任务”，处理页只提供催办；只读任务不展示假动作。完成必须填写可核验反馈，阻塞、退回、解除阻塞和催办必须填写原因。处理页不再重复提供自由文本证据框或附件上传，附件统一回到详情页按权限查看或管理。
5. 提交后进入独立结果回执。回执区分 `confirmed / unknown / failed`，显示服务端确认的任务快照和本次反馈或原因；只有旧任务确有历史证据引用时才显示“历史处理线索”。没有可信来源时不补造处理人或处理时间。

列表顶部保留搜索和紧凑筛选，移除独立的“当前岗位任务状态”统计卡及数量口径说明。数量只在可操作的筛选、风险 / 已办入口及“已显示 / 共 N 项”列表范围中呈现；服务端仍维护完整计数合同。

搜索覆盖订单号、产品名称 / 编号、内部款号及物料名称 / 款号，在服务端分页前执行。搜索框复用共享控件，手机高度为 48px，只保留一层焦点边框；停输入 300 毫秒后自动查询，中文输入法组词期间不查询，回车可立即查询，清空立即恢复全量范围，无独立搜索按钮。相同关键词不重复查询，查询范围变化时清空旧游标；离开列表或切换岗位 / 账号权限范围时取消未触发的搜索，旧请求的结果和错误不会覆盖当前范围。

浏览器或系统返回键按“回执 → 列表”或“处理 → 详情 → 列表”恢复，并保留搜索词、列表筛选、已加载分页、滚动位置和焦点；处理草稿在处理路径内恢复。移动软键盘出现时使用 `visualViewport` 收敛可视高度；校验失败聚焦第一个缺失字段，`Ctrl/Cmd + Enter` 提交，`Escape` 返回详情。主要触控目标不小于 44px，底部主动作不随正文滚走。

## 任务识别与布局

沿用当前主题、岗位切换、四项导航和查看 / 处理 / 回执流程，示意图用于选择可验证的改进，不要求所有手机页面使用相同卡片、配色或留白。待办行按任务标题与状态、产品 / 物料及关联单据、任务时间与业务状态分层，避免固定三列把长名称挤成窄条；已办、风险和超时也展示相同的识别摘要。

工作台、任务看板、业务看板的关注任务和手机列表共用任务时间展示。待办最多显示“进入本岗”和“截止”两项时间，今天 / 昨天用相对日期，其余显示月日，跨年补全年份；详情和桌面悬停可查看精确年月日与时分。任务在创建时进入其负责岗位，`created_at` 是不可变的入岗时间；`owner_role_key` 在当前任务生命周期内不变，更换经办人、退回岗位共同待办、催办、附件更新及解除阻塞均不重置入岗时间，不使用 `updated_at`、单据创建或流程开始时间替代。新岗位的新任务使用自己的创建时间。缺少时间时列表不补造占位，详情明确“未记录”或“未设置截止”。

已完成 / 已退回 / 已撤回列表只显示对应的 `completed_at`，详情保留入岗、原截止和结束时间，终态不再展示当前逾期警告。阻塞详情仅在已有任务事件中找到当前这次进入阻塞的真实转换时显示“本次阻塞”，催办、转交或同状态更新不算新的阻塞；事件截断、缺失或不匹配时不猜测开始时间。列表不额外请求事件或单据，订单交期仍在关联单据中核对，不与任务截止混用。

有产品时显示名称和产品编号，有物料时显示名称和款号；缺少款号时明确提示未填写，不拿系统物料编号代替。详情与整项信息复制另外保留独立的内部款号或系统物料编号；单据来源不是销售订单时，已关联的销售订单号可补充显示。多项只在列表显示首项与总项数，详情通过展开查看其余项。任务标题、单据入口、附件、完成条件和原有业务动作继续保留，处理页及回执仅保留识别摘要。

列表产品摘要旁显示 52px 主图（桌面 64px），完整保留轮廓，不裁剪拉伸。点击列表图片仍进入该任务，详情图片提供放大预览。多款任务首图必须与首个产品名称对应；有产品或物料摘要但没有可显示图片时，保留同尺寸的中性图标占位：产品标为“暂无图”，物料使用物料图标；无产品读取权限时不请求图片，也不推断是否已上传。图片加载失败保持占位并显示“加载失败”，不折叠图片区域，不借用辅图、其他款或任务附件。无图占位不提供放大按钮，点击列表占位仍进入任务；关联对象已不可用或任务没有产品 / 物料摘要时不补造对象。小图进入视口后读取，同账号权限范围内同附件去重，原图只在放大时加载。

身份信息复用后端只读 `display_context`，不新增手机私有字段；明确空值或来源失效不回填旧任务快照。仅状态更新的回执可以保留同一任务、同一来源绑定的已读摘要；来源切换或解除绑定后必须清空，下一次读取以服务端新投影为准。

## 权限、可见性与性能边界

- 列表只消费服务端已经授权的 `list_role_tasks` 结果。前端不得再按当前岗位二次删除跨岗位但明确指派给当前用户的任务。
- “待我审批”入口只在任一已登记审批能力同时通过 RBAC 与当前 effective action 时显示，并与全部、风险、超时共用同一筛选分段行；服务端仍按具体 capability、任务冻结 revision、责任池、owner / assignee 和状态决定每条任务是否可见与可办。
- 不再提供“我负责”主筛选：旧实现只在已加载的 `todo` 页内按当前 assignee 或未指派岗位池做客户端派生，既常与“全部”高度重复，也没有独立服务端游标和完整数量。未来若确需个人队列，应新增明确的服务端 assignee 视图，而不是恢复本地近似筛选。
- 可见不等于可处理。处理前继续消费后端 action explain，并在提交前复核权限、任务版本和幂等意图；确认失败时 fail closed。
- 返工生产安排入口同时要求任务可办、正式来源任务合同与来源意图校验通过，并命中 `production.wip.read + production.wip.assign`；选择外发时还必须具备 `outsourcing.order.read` 并关联已确认、未关闭的加工合同明细。手工仿造或来源锚点不完整的任务不展示入口。
- 初次客户运行态同步失败时不挂载任务页；后台刷新瞬时失败时保留最后一次有效投影并提供重试，不因临时网络抖动伪造撤权结果。
- 列表只提供一个“显示更多”入口：先展开已加载内容，已加载内容耗尽且服务端仍有下一页时，继续读取同一 `server_time` 快照并直接显示新批次。顶部刷新才重新获取最新快照；过期请求保护、失败保留上次数据和刷新反馈继续沿用现有实现。
- 自动搜索只读取当前权限范围内的服务端分页结果，不下载全部任务做本地过滤；输入防抖减少请求次数，数据量增大时仍需按实际查询耗时评估服务端性能。

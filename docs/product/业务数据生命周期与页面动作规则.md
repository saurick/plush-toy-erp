# 业务数据生命周期与页面动作规则 / Business Data Lifecycle UI Policy

本文定义当前产品页面、原型和实现必须共同遵守的业务对象生命周期与动作口径。

## 结论

当前业务页面不提供通用删除、批量删除、回收站或还原删除入口。页面动作必须表达真实业务生命周期：主数据走启用 / 停用，源单据走提交 / 取消 / 关闭 / 归档，事实和台账走取消 / 冲正 / 调整或只读，Workflow 只走任务状态和事件。

正式主数据、销售订单、采购订单、委外订单、生产订单和 BOM 列表统一提供“当前记录 / 历史记录 / 全部记录”只读范围筛选。`当前记录` 是页面默认值；`历史记录` 复用对象已有的停用、关闭、取消或归档状态；`全部记录` 只取消范围约束，不改变对象状态。系统另提供只读“历史记录中心”，按当前账号已有菜单和读取权限汇总这些对象，负责筛选、查看摘要、查看详情和跳回所属模块，不提供跨对象归档、恢复、删除或状态流转。

正式业务列表页还必须遵守统一的动作可用性合同：账号真正无权、所选对象或来源不适用、动作已经完成或记录进入终态时隐藏；未选择记录时保留有权限的常用动作并置灰，提示先选择记录；选中后，尚待满足可继续推进的前置条件、正在加载 / 保存或运行态暂不可办理时保留入口并置灰，以岗位语言说明原因。动作集合可以随所选对象、来源和生命周期合法变化，但不能因短暂 loading、重复请求或局部读回无理由闪烁、重排或左右跳动。

本文是页面设计和实现规则，不替代 `AGENTS.md`、`docs/当前真源与交接顺序.md`、Ent schema、后端 usecase、RBAC、测试或运行时代码。reference 文档只作为输入资料，未在本文列出的冻结、合并、替代、通用删除权限和通用软删除字段，都不能直接进入当前 runtime。

## 列表信息顺序

默认列顺序按岗位判断的重要性、查看频率和字段关联安排。常用桌面窗口不横向滚动时，应能识别业务对象、看懂主状态，并看到该页最关键的交期、数量或金额；按实际列宽验收，不以固定列数代替可见性。

| 信息 | 默认安排 | 页面差异 |
| --- | --- | --- |
| 单号、编号 / 名称、客户 / 供应商 | 最前面的识别信息 | 库存余额优先材料 / 产品、规格和仓库；变动记录优先发生时间和存货对象 |
| 主生命周期状态 | 紧邻识别信息，通常在前 2–4 个业务列 | 工序可委外 / 可内制等能力标记不是主状态；质检判定、异常审批和执行结果按本页任务保持清楚、相邻 |
| 关键交期、到期日期 | 在付款条款、地址、追溯说明之前 | 采购到货、委外回货、销售交付和出货日期优先；工程版本的生效区间相邻 |
| 关键数量、金额、责任人 | 在详细条款和审计信息之前 | 库存先看可用量；金额与币种、数量与单位保持邻近；只展示已有真实字段 |
| 备注、详细地址、税费拆分、创建 / 更新时间 | 通常靠后 | 审计、历史查询或专门核对页面按其任务安排，不机械套用订单顺序 |

前置解决默认打开时的信息可见性；固定列只用于横向对照时仍需保留的识别信息。固定区域应保持窄，不因前置状态而自动固定所有状态或整组字段。窄屏保留表内横向滚动，不挤压成不可读的文本，也不让整个页面横向溢出。

业务列定义用可选 `defaultPriority` 显式声明默认优先级，数值小的靠前，同优先级和未声明列保持原始相对顺序。共享 `moduleTableColumns.mjs` 先按原始列定义确定标识，再编排默认顺序；不通过字段名猜测优先级，不为换默认顺序搬动展示列的原始标识。

选填不等于无用。简称、报关资料、税号、详细条款等字段应先核对搜索、带值、打印和业务核对用途；没有证据时不能删除真源或改动必填规则。名称与简称相同时，客户和供应商选项只显示一次名称；独立简称继续参与识别和搜索。

仅在详情、编辑或导出时需要的辅助列，用列定义的 `listHidden: true` 退出主列表和列顺序面板，仍保留原字段及完整导出。该标记不保存新的账号偏好，不改变客户字段策略；权限策略隐藏的字段仍不得进入详情或导出。销售列表的完整收货信息可下沉，但出货列表仍保留用于核对送达对象的收货信息；各页按实际岗位任务选择，不按字段名或当前空值比例全局隐藏。列表列的展示标识、剩余个人顺序和恢复默认行为保持稳定。

账号主动保存的列顺序优先于默认优先级；新增可见列按默认优先级追加。没有个人设置或点击“恢复默认”后使用当前推荐顺序。列顺序只表达展示偏好，不改变事实、权限、明细业务顺序、打印模板或服务端记录排序。

## 页面动作矩阵

| 对象类型 | 页面默认动作 | 禁止默认出现 | 说明 |
| --- | --- | --- | --- |
| MasterData 主数据 | 新建、编辑、启用、停用、查看引用或历史 | 通用删除、回收站、还原删除 | 例如客户、供应商、产品、SKU、材料、仓库、工序。停用后不再进入新业务选择，历史单据仍可回显。 |
| Source Document 源单据 | 保存草稿、提交、审批、关闭、取消、归档 | 提交后删除、回收站 | 例如销售订单、采购订单、委外订单。草稿明细行可以在表单内移除，但不等同于列表级删除。 |
| Fact / Ledger 事实与台账 | 过账、取消、冲正、调整、只读查询 | 删除事实、清空流水、回收站 | 例如入库、出库、库存流水、出货、应收、应付、发票、对账。事实纠错必须保留可追溯反向记录或调整记录。 |
| Workflow 协同任务 | 完成、阻塞、驳回、催办、记录原因 | 把任务完成写成事实过账、删除业务对象 | Workflow task done 只代表协同任务状态变化，不代表库存、出货、财务、开票或收付款事实完成。 |
| Audit / Evidence 审计与证据 | 筛选、查看详情、导出受控证据 | 普通业务删除、静默清理 | 审计数据用于追责、排障和交付证据，不能被业务页动作绕过。 |
| 临时草稿 / 表单明细 | 添加、移除、清空当前草稿明细 | 把明细删除包装成业务对象删除 | 只在尚未形成正式业务事实前可移除；提交、过账或被引用后按所属对象生命周期处理。 |

BOM 这类版本型工程资料在页面上使用“历史版本 / 设为历史版本”表达，底层状态仍为 `ARCHIVED`。历史版本可重新激活，但不直接编辑；需要改版时应复制新草稿后修改。

## 历史记录查询合同

| 查询入口 | 范围 | 允许动作 | 明确不做 |
| --- | --- | --- | --- |
| 模块内“当前 / 历史 / 全部”筛选 | 当前模块和对象自己的分页列表 | 筛选、导出当前筛选结果、查看详情、按对象既有 usecase 办理合法动作 | 不新增统一 `archived_at`，不把“历史”解释成软删除 |
| 历史记录中心 | 当前账号已有菜单且具备读取权限的客户、供应商、材料、产品、SKU、加工环节、销售订单、采购订单、委外订单、生产订单和 BOM | 按一种对象类型筛选、查看只读摘要与详情、跳回所属模块 | 不跨对象一键归档或恢复，不绕过所属模块的状态、RBAC 和引用检查 |
| Fact / Ledger 与审计记录 | 继续留在各自事实台账、库存流水、财务记录和系统操作记录 | 使用原页面查询、追溯、冲正或调整 | 不因历史中心而隐藏、复制或迁移事实与审计真源 |

列表 API 的 `lifecycle_scope` 只接受 `current / history / all`。未传该参数时保留原 API 读取合同，避免影响既有引用选择器和内部读取；正式业务列表页面会显式发送范围。显式状态筛选必须与范围兼容，例如“当前记录 + 已关闭”应拒绝或由页面清空冲突状态，不能静默返回误导数据。

历史中心不是新的数据台账。每次只读取当前选中的一个对象来源，沿用该来源原有分页、关键字、状态字段、读取权限和菜单可见性，避免在前端拼接不准确的跨对象总数。是否能重新启用、重新激活或重开，仍由所属对象自己的 usecase 和页面动作决定。

## 选择记录后的动作可用性合同

| 条件 | 页面处理 | 原因 |
| --- | --- | --- |
| 当前账号没有动作权限 | 隐藏动作入口 | 不泄露无权能力；后端 RBAC 仍是安全边界。 |
| 客户配置未开放、模块关闭或当前产品没有该能力 | 隐藏动作入口 | 不用禁用占位伪装未实现能力。 |
| 有能力但尚未选择记录 | 显示有权限的常用动作并置灰，提示“请先选择一条记录”；不显示清空已选 | 保留岗位操作入口，便于先了解能办理什么；按桌面 / 窄屏动作上限收纳，避免按钮铺满工作区。新建、筛选、导入、导出和列顺序仍在列表工具条。 |
| 所选记录的对象类型、来源类型或事实类型不适用 | 隐藏动作入口 | 结构上不属于当前对象的动作不占位，不用永久灰色按钮制造误导。 |
| 当前动作已经完成，或记录已进入不能再办理该动作的终态 | 隐藏动作入口，由状态列、详情或关联记录表达结果 | 例如已提交后隐藏“提交”、已关闭后隐藏流转动作、已生成退货后由关联退货记录表达。 |
| 有能力且动作仍可能继续推进，但当前状态、前置资料或版本尚未满足 | 保留动作入口并置灰 | 用岗位语言提示需要先完成的步骤；满足条件后在原位置启用。 |
| 有能力但正在加载、保存或办理 | 保留固定动作槽并置灰；完成后按最新读回恢复 | 防止重复提交或并发编辑，不因短暂等待改变布局。 |
| 当前状态允许办理 | 启用对应动作 | 点击后仍由后端 usecase、状态机、版本、幂等和 RBAC 再校验。 |
| 当前状态没有合法主生命周期动作 | 隐藏主状态动作 | 终态不保留没有业务含义的“状态办理”灰色占位。 |
| 当前状态没有合法次级生命周期动作 | 不展示对应状态动作 | 状态动作按各自权限与状态判断，不保留空的分类入口。 |

`BusinessActionTooltip` 是临时不可用原因的共享入口；鼠标悬停和键盘聚焦都应能读取原因。桌面最多常驻四个动作，平板两个，手机一个；按固定优先级选择，其他合法动作进入按钮旁的“更多操作”下拉菜单，沿用同一处理函数及确认弹窗。主动作跟随阶段：质检草稿先提交、待判定再判定，收付款先核对审批、批准后再核销，生产草稿先下达。清空已选放在当前记录标识旁，不挤占业务动作名额；明细、材料、加工明细顺序属于本单辅助动作，随选中记录显示，已知仅一行或无明细时不展示排序。源单的正常关闭、提前关闭、取消等次级状态动作直接与其他辅助动作同级排列，不再增加“其他状态操作”分类下拉；沿用原确认弹窗和原因必填规则。仅启用态变化不能参与窄屏排序，下拉菜单内当前合法动作的次序也不能因 loading 改变。切换业务对象类型、来源类型、事实类型、正式页签或生命周期阶段时，动作集合可以按当前对象合同变化；读权限只能展示“查看”入口，不能借只读权限展示“返工、过账、取消”等写操作文案。

## 正式页面覆盖矩阵

下表记录当前选择行操作条的覆盖面。它是交互合同清单，不替代各页面的后端状态机和权限真源。

岗位是当前默认分工的说明；实际入口由后端权限、客户有效配置、任务责任与当前记录共同决定。财务兼采购通过同时分配两个角色获得合同经办能力，不扩大纯财务权限。具体步骤见[业务与协同流程地图](../workflow/业务与协同流程地图.md)。

| 页面 / 对象 | 保留或补齐的按钮 | 默认办理岗位及条件 | 移除、隐藏或修正 |
| --- | --- | --- | --- |
| 主数据：客户、供应商、材料、产品、规格、仓库、工序 | 新建、编辑 / 查看、启用 / 停用、联系人和相关资料 | 各档案对应维护权限；读权限仅查看 | 不增加通用删除；停用不会抹除历史引用 |
| BOM 版本 | 新建、查看、编辑、复制、打印、激活、设为历史版本 | 工程；只编辑草稿，历史版本可按既有权限激活 | 已激活不再显示激活；不可编辑版本隐藏编辑；复制仍用于改版 |
| 销售订单 | 新建 / 导入、查看、编辑、明细顺序、工程与打样、用料汇总、预留库存、状态操作 | 业务建单；工程建档及提交用料；管理 / 财务办理用料审批；业务对生效订单预留 | 草稿显示提交，已生效显示合法关闭动作；终态隐藏流转和编辑。用料入口按能力称为“提交 / 审核 / 查看用料汇总” |
| 采购订单 | 查看详情、编辑、材料顺序、关联单据、登记到货、打印合同、状态操作 | 采购制单及合同办理；仓库按已批准订单登记实际到货；财务可按读权限核对 | 补上独立详情按钮；“生成入库”改为“登记到货”，生成待检记录，不代表库存入账；提交后隐藏编辑 |
| 采购入库 | 查看、关联单据、确认材料入库、退货、调整、生成 / 查看应付、取消 | 仓库 IQC 登记来料并可取消未入库错误登记；仓库在检验通过后确认入库；采购处理商务退货；财务登记应付 | IQC 的取消草稿权限不能冲正已入库单据；“确认材料入库”仍须仓库入库权限；已过账隐藏重复入库；退货和调整只在已过账记录出现 |
| 加工合同 / 委外订单 | 查看详情、编辑、加工明细顺序、关联事实、打印、状态操作 | 生产提出加工要求，财务兼采购补价和确认合同；仓库处理对应发料 / 回仓 | 补上独立详情按钮；已确认隐藏编辑和再次确认；合同确认不直接写库存、质检或应付 |
| 生产订单 | 查看、编辑、下达、工序办理 / 查看、完工申报、关联事实、关闭、取消 | PMC 建单与下达，生产申报；相关岗位查看路线；仓库确认完工入库 | 已下达隐藏编辑和再次下达；已关闭原批次只读，合法成品返工仍保留入口 |
| 生产工序弹窗 | 安排加工、拆分、开始工序、本厂完工、外发回仓、转下道、包材确认、返工 | 生产安排、开工、完工与转序；仓库登记外发回仓；业务确认包材；返工另受权限控制 | 按动作分别核对岗位；本厂与外发不互相展示完工按钮；已办理步骤、已拆分 / 取消批次隐藏对应动作；转序仍需质量通过 |

## 删除进入条件

只有同时满足以下条件，某个对象才可以单独评审删除或恢复：

1. 对象仍是草稿、误建或临时数据，尚未进入正式业务链路。
2. 后端 usecase 已实现状态检查、引用检查、权限检查和审计记录。
3. 已完成 RBAC、API、前端提示、错误码或错误提示、测试和浏览器回归。
4. 已被引用、已提交、已过账、已发货、已产生财务事实、已进入 Workflow 或审计链路时，删除必须拒绝，并给出可读原因和替代动作。

页面不能为了视觉完整性补本地删除、软删除假状态、回收站空态或禁用按钮。尚未满足条件时，直接不展示删除 / 回收站入口。

## 决策路径

```mermaid
flowchart TD
  A["用户想移除一条业务数据"] --> B{"是否只是当前表单草稿明细？"}
  B -->|是| C["允许在表单内移除明细，不生成业务对象删除"]
  B -->|否| D{"对象是否已提交、过账、引用或进入审计链路？"}
  D -->|是| E["禁止删除；按取消、关闭、冲正、调整、停用或归档处理"]
  D -->|否| F{"后端是否已有删除 usecase、RBAC、引用检查和审计？"}
  F -->|否| G["页面不展示删除 / 回收站入口"]
  F -->|是| H["按对象专项评审开放删除，并补齐测试和文档"]
```

## 原型吸收规则

- 标准业务页原型只表达筛选、列顺序、当前记录动作、分页和协同入口，不再内置通用回收站。
- 局部动作弹窗样板承接来源选择器、列顺序、危险动作确认和生命周期动作说明；只有完成真实软删除 / 恢复 usecase 的对象，才能在对象专项原型里单独设计回收站。
- 业务表单样板里的“删除”只允许表达草稿明细行移除，应在说明里明确它不是业务对象列表级删除。
- 原型中的静态按钮不能反推 API、RBAC、schema、migration 或事实写入能力；进入运行时前必须回到当前代码和测试复核。

## 主题模式 / Theme mode

桌面后台、统一登录页、岗位任务端和开发工作台支持「跟系统 / 浅色 / 暗色」三种主题模式，默认跟随系统偏好。开发工作台在共享侧栏操作区提供主题入口，所有 `/__dev/**` 页面复用同一运行时状态；用户手动选择会写入浏览器 `localStorage` 的 `plush_erp_theme_mode`，刷新后保持。`跟系统` 只决定视觉主题，不影响入口选择、权限判断或最终路由。

当前登录态 token 仍保存在浏览器侧认证存储中，并通过 `Authorization: Bearer` 发送，主要风险面是 XSS 后的 token 读取或泄露；不得把 token 写入 trace、日志、文档、截图或 QA 报告。生产侧已补基础 HTTP 安全响应头降低误嵌入、MIME sniff 和宽泛 referrer 风险，但这不等同于 HttpOnly Cookie 方案。当前内部系统不把 CSRF 作为近期安全待办；只有后续明确迁到浏览器自动携带的 Cookie 登录态时，才需要把 SameSite / CSRF、登录态刷新和前端 API client 改造放到同一轮专项评审。

主题主路径：

- 运行时状态由 `src/common/theme/erpTheme.jsx` 和 `src/common/theme/erpThemeMode.mjs` 维护。
- Ant Design 组件通过根 `ConfigProvider` 在 `defaultAlgorithm / darkAlgorithm` 间切换。
- 项目自定义壳层、岗位任务卡片和局部硬编码样式通过 `data-erp-theme` 与 `src/erp/styles/app.css` 入口及 `src/erp/styles/app/` 分区文件中的 ERP theme 变量覆盖。
- 新增状态类组件时必须同步覆盖暗色主题，包括 loading / empty / alert / message / notification / tooltip / popover / tag / badge / progress / pagination / drawer / table placeholder；优先复用全局 token 和页面级浏览器回归断言（Style L1），避免组件只在浅色模式可读。
- 打印、PDF、采购合同 / 加工合同纸面预览默认固定浅色，不跟随暗色主题，避免污染导出物。

## 共享控件样式边界 / Shared control style boundary

文字按钮的水平内边距由 `src/App.jsx` 的 Ant Design `Button` token 统一提供：普通和小号按钮均为 12px，大号按钮为 16px。工具栏、当前操作区、弹窗和浮层沿用这套基线；同一规格的主按钮、次按钮、禁用和 loading 状态不另设 padding。普通业务动作与状态动作统一按内容定宽，长文案自然伸展。嵌入列表的当前操作区在桌面统一使用 30px 按钮高度；窄屏允许长文案换行，保留内边距和至少 44px 触控高度。纯图标、行内文字链接和手机整行按钮按各自用途保留紧凑外形或触控布局，不用固定宽度修补普通按钮的留白。

`src/erp/styles/app.css` 的最后三层是输入框、选择器、日期框、数字框和 Ant Design portal 浮层控件的共享治理层。它们只处理控件基线，不承接单页布局、字段语义、业务状态或客户差异。

| 文件 | 职责 | 不应放入 |
| --- | --- | --- |
| `app/control-foundation.css` | ERP runtime 可见控件 token、圆角、wrapper 裁剪、portal 控件基线和嵌套原生输入透明化。 | 单页间距、业务字段宽度、表格布局、具体弹窗内容排列。 |
| `app/business-control-rhythm.css` | 业务表单、业务 action modal、业务筛选和业务记录弹窗的控件高度、真实 input / placeholder / search input 的 line-height、textarea 最小高度。 | focus 颜色、hover 状态、页面级 grid / flex 布局、业务保存逻辑。 |
| `app/control-focus.css` | 应用根与 portal 控件的 focus / focus-within ring、组合控件内层焦点清理、checkbox focus ring。 | 控件高度、圆角、字段语义、可见文案、权限或菜单规则。 |

维护规则：

- 改 caret、placeholder 垂直居中、input 高度时，优先改 `business-control-rhythm.css`，并确认真实 `input.ant-input`、Select placeholder/search input 和 wrapper 作为一个控件合同一起生效。
- AntD 输入控件的圆角只由 `control-foundation.css` 绘制；组合控件内侧接缝通过局部 `--erp-control-radius: 0` 表达，外层保持统一圆角。页面负责布局与尺寸规格，不重新声明同一控件的圆角。
- focus ring 只由 `control-focus.css` 绘制，颜色由 `--erp-control-focus-border / --erp-control-focus-ring` 提供；主题切换调整变量。使用 inset ring，避免被圆角容器或滚动区域裁掉。Select outlined 变体按 AntD 的 disabled / customize / pagination 条件覆盖，不通过重复类名提权。
- 不在业务页面 CSS 里重复写单字段 caret、line-height 或 focus ring 补丁；确有新控件类型时先补 `style:l1` 浏览器断言，再扩展共享层。
- 新增规则不能使用 `!important`，除非正在对抗不可控的第三方内联样式，并且必须在交付说明中写明原因。

Tailwind Forms 只生成显式 `form-*` 类，供原生表单控件按需使用，不对 AntD 内层 input 做全局重置。表头共享规则归 `common/components/table/app-table.css` 的 `.app-table` 作用域；业务页面 CSS 不定义全站 AntD 表头。模块打印使用命名 `@page`，对 body 的隔离仅在该模块打印根节点存在时生效。

`pnpm css` 通过 `scripts/stylelint/styleBoundaries.mjs` 检查模块作用域、重复类名、控件圆角与焦点归属、打印页作用域；全局基线文件的允许清单也由该规则维护。`!important` 例外只在必要声明附近附理由，现有 SVG 内联尺寸覆盖和 reduced-motion 无障碍覆盖保持局部范围。规则测试使用 CSS 输入验证允许与拒绝行为，避免绑定整份源码文本或行号。

浏览器回归复用 `style-l1/inputControlAssertions.mjs` 的内外层合同与 `styleIsolationAssertions.mjs` 的外观采集；访问其他模块后比较同一控件的默认、hover、focus 样式，保留已加载 CSS，不用刷新页面消除污染。业务场景只编排真实交互与状态，不重复实现颜色、圆角和几何判断；DEV 打印隔离留在 DEV 场景中，普通业务回归不依赖 DEV 路由。

## 表格对齐 / Table alignment

业务列表、弹窗明细和研发工作台的 Ant Design 表格统一使用 `common/components/table/AppTable.jsx`。表头和单元格默认上下居中；表头文字水平居中，排序、筛选和列设置控件保留操作空间。序号、编号、单位、日期、状态、短分类和操作列默认水平居中；品名、厂商、地址、备注和复合说明列通过 `align: 'left'` 保持扫读；数量、重量、单价和金额列通过 `align: 'right'` 方便核算。列定义明确语义，不按运行时文字长度或字段名称猜测对齐方式。

序号有逐行核对用途时独立成列，不拼入品名。可复制字段的按钮不挤偏居中文字；原生单据编辑表与 BOM 明细沿用相同表头、垂直对齐和数值输入规则。文档表格的正文保留长文本阅读方式，打印纸面按各模板正式版式单独维护。

## 前端实现与读取边界

- 桌面后台继续只保留一个入口
- 桌面后台不再保留角色切换、角色首页或角色入口菜单；统一登录页和 `/entry` 只做后台 / 岗位任务端入口选择
- 桌面后台管理员已接入 RBAC 权限中心；普通管理员通过 `roles` 获得 `permissions`，后端返回 `menus`，桌面菜单、岗位任务端入口和后端接口统一消费 permission code。权限清单按后端 `module_name` 展示“物料清单（BOM）/ 库存管理 / 生产执行 / 敏感字段”等业务分类，不在前端重复维护模块翻译；仅对未知或缺失分类合并显示一个“未分类功能”，避免多个技术模块同时冒充“其他功能”。分类导航只负责页内定位，不改变勾选结果或权限真源
- 桌面后台主业务菜单按当前产品设计保留看板中心、主数据、销售管理、产品工程、采购管理、质检管理、库存管理、委外管理、生产管理、出货管理、财务业务、运营工具和系统管理；系统管理当前包含权限管理和审计日志。客户档案 / 供应商与加工厂走正式 MasterData V1 API，销售订单走正式 SalesOrder V1 API，采购订单走正式 PurchaseOrder V1 API。正式业务列表统一为单击行选中、双击行进入整页编辑或当前主操作；详情抽屉只由显式详情入口打开。
- 正式业务主表只在显式白名单内的业务编号、名称、联系人、批次和可直接转交的短引用值上提供快捷复制。电脑端悬停单元格或用键盘聚焦时显示复制按钮，触屏端直接显示；鼠标复制后移出单元格即隐藏，键盘操作保留焦点。复制按钮只复制当前字段，不触发行选择或双击打开；空值、日期、金额、数量、状态、备注和内部 ID 不显示按钮，弹窗及明细子表继续使用系统文字选择能力。

- 手机列表不再展示独立岗位状态统计卡；保留可点击筛选数量与当前列表范围。顶部搜索通过 `list_role_tasks(keyword)` 在服务端分页前匹配订单 / 产品 / 款号 / 物料，关键词进入查询范围和返回状态，搜索变化时重置游标；保留现有主题、四项导航、全屏详情及底部操作。列表使用独立任务卡、产品名称与款号及整卡查看入口；未设置截止不显示占位符。详情首先展示任务、产品、责任和阻塞原因，再展示附件与补充信息；仅有催办权限时主按钮明确标为“催办任务”。结果回执采用紧凑状态提示，保留本次方式、状态、来源与反馈。
- `/erp/task-board` 任务看板的关键词、状态、角色、到期、来源、泳道和页码使用 URL query 保存，支持复制链接、刷新恢复和一键清空。页面读取服务端 `get_task_board` 全量投影，“常规待办 / 阻塞 / 到期提醒 / 已结束”四个互斥分类的数量直接展示在栏标题中，不再重复渲染顶部大指标。四项之和等于当前筛选的真实总数。首次进入看板才使用整卡加载；分类或翻页切换会保留同一筛选范围的分类数量，只让下方任务显示局部加载并在请求完成后替换结果。总览按内容区宽度显示四列（至少 1200px）、两列（至少 600px）或单列，每栏最多预览 2 项；任务卡单击或按 Enter / Space 直接打开共享详情抽屉，不保留“当前选中任务”侧栏。关闭抽屉保留筛选、滚动位置并将焦点返回原任务卡；通过“查看全部 N 项”进入该分类的完整任务列表；列表顶部使用带数量的紧凑分类标签，标题旁的返回箭头回到概览，不再提供重复的分类下拉框或通用说明句。完整列表采用三列宽表格，默认按 8 项分页，可切换为每页 20 / 50 项，单击任务行或在任务标题按 Enter / Space 进入共享抽屉，返回看板继续保留筛选；不再把 `list_tasks(limit: 200)` 的当前页长度冒充全量统计，也不在前端循环拉取全部任务。这些筛选和投影只影响看板展示，不写用户偏好、Workflow 任务状态或 Fact 表。

任务看板的“全部任务 / 待我审批”范围切换与标题同行。搜索和负责岗位常显，任务状态、截止时间和业务来源通过“筛选”展开；已选的收起条件仍显示为可逐项清除的标签。状态与日期选项按当前分类收窄，切换分类时清除不适用的组合，URL 读取和请求构造使用同一规范化规则。仅有筛选时显示“清空筛选”，清空保留当前分类、审批范围、排序和每页条数，页码回到第一页。

工作台、任务看板和岗位任务端的业务单据编号、产品编号、款号使用常显的行内复制图标；复制只取编号原值，不触发进入任务或改变筛选。详情提供“复制产品信息 / 物料信息”和“复制任务信息”，后者包含当前产品、单据、状态原因、已知责任及完整日期时间。共享展示投影已明确缺失或不可用时，不复制旧快照；空值和内部引用不提供复制入口。任务卡的打开按钮与复制按钮独立，手机复制点击范围至少 44px，支持键盘操作、成功提示及失败后的手动复制。剪贴板操作复用共享 helper，不写业务数据。

工作台和任务看板分类列表共用底部吸附分页栏：上一页 / 下一页配文字和方向图标，桌面点击区域至少 36px，窄屏至少 44px；显示当前范围与当前分类总数，可切换每页 8 / 20 / 50 项，默认 8 项。桌面超过 7 页时提供跳页输入，窄屏以可输入的当前页代替密集页码。改变每页条数回到第一页，任务看板将条数写入 URL，刷新及筛选后保留；翻页成功后定位列表首项，读取中禁用分页，失败可重新加载。移动岗位端继续使用原有分批展开。

- 桌面业务页标题区保留标题、已有按需帮助和必要的状态 / 数量，不常驻介绍页面用途或操作顺序。业务看板、系统操作记录和打印中心沿用同一原则；业务规则留在对应操作、表单或现有帮助中，数据范围、权限受限和失败反馈继续明确展示。共享 `PageHeaderCard` 不接收介绍文案，也不保留空段落及其间距。
- 正式业务列表页的 `PageHeaderCard.stats` 只接受非负安全整数计数，`0` 表示已成功读取且确实为零；数字字符串、视图名、模式名、文字状态、负数和不可用占位不会渲染为页头指标。当前视图和状态文字放在页签、标签或说明中；请求失败 / 尚未读取等 unavailable 语义继续由看板自己的 `— / 暂不可用` 状态承接，不伪装成 `0`。
- `docs/product/prototypes/business-module-page-standard-v1/` 仍按 `待实现 / To Implement` 登记。当前运行时已经由客户、供应商、产品、材料、SKU、BOM、销售订单、采购订单、采购入库、来料质检、委外订单和出货单等正式 V1 页面复用业务页骨架，收窄 Fact / Workflow 页面继续遵守各自事实边界。`/__dev/prototypes` 仍保留待实现队列，未获用户明确确认前不清空队列、不晋级 Current。
- 当前业务页、岗位任务端页面、桌面工作台、任务看板、异常闭环、业务看板和模板预览已经齐入口；业务数据分别落在领域专表、Source Document、Workflow 与 Fact 真源。采购合同 / 加工合同已支持业务页带值打开，桌面任务看板只处理 Workflow 协同任务，不直接写库存、出货、应收、开票、付款或其他事实表；真实客户数据批量导入、打印留档回写和尚未接入的细分领域专表继续 deferred

## 桌面业务编辑与弹窗约定

- 项目弹窗默认上下左右居中：JSX 版 `antd Modal` 由根 `ConfigProvider` 统一启用 `centered`，命令式 `modal.confirm/info/success/warning/error` 由 `AntdAppBridge` 的消费层统一补齐居中配置；`AppModal` 复用 Ant Design 的遮罩、键盘、焦点圈定和触发点恢复，并只补充业务面板外观与可访问名称。
- 菜单主列表的新增 / 编辑统一使用 `BusinessFormPage`，在当前模块路由内切换主内容区，保留列表筛选、选择与滚动位置。正文独立滚动，底部固定“返回列表 / 保存”；已支持的只读查看复用此骨架。内容、待上传附件或产品图片有修改时，返回、切换菜单、浏览器后退和刷新前提示；保存中阻止离开。适用客户、供应商、材料、产品、产品规格、加工环节、BOM、销售 / 采购 / 生产订单、加工合同、出货单、质检补建、收付款 / 红冲登记、生产事实草稿及员工账号创建 / 资料修改。编辑过程中的快捷新建、来源选择、预览，以及审批、核销、冲销、岗位分配等专项动作继续使用弹窗。详情抽屉只用于显式只读核对。排产确认和出货放行页只读取并处理来源生成的 Workflow 协同任务；生产记录内的异常处理以独立页签分开处置申请和待审批任务。三者都不提供通用任务创建弹窗，也不能把协同结果写成生产订单、生产异常执行、出货单、库存、财务或发票事实；来源、打印、删除等未接入真实 usecase 的动作不能写成真实业务动作。
- 整页业务表单的标题区和固定操作栏使用独立底色及清晰分隔线，正文保持独立内容底色，分组线弱于区域边界；底部操作栏带轻微上阴影。浅色采用灰绿底与白色正文，暗色复用主题表面色与边框色，统一由 `business-form-page.css` 管理。
- 桌面端业务录入表单默认按紧凑自适应栅格排布：文本字段在可用宽度内多列展示，数量类短字段进一步收口，备注、边界说明和明细区保留整行。
- BOM 使用连续表格：同一物料和单位的名称、厂商料号、规格及单位只展示一次，下面直接维护多个部位；支持同料增行、复制、移除与从 Excel 粘贴部位数据。损耗输入为百分比，总用量沿用精确十进制计算，片数不重复乘入单位用量。
- 其他明细条目按共享列宽预算展示，长文本字段保留较宽输入，数量 / 单价 / 金额等短数字字段收窄；数量后缀读取当前行已填单位，金额类字段默认显示 `CNY` 后缀，但不把空单位强行保存成 `pcs`。
- 可连续录入的明细在末行下方提供新增入口，销售订单、采购、加工合同、出货、联系人、生产订单及采购退货 / 调整共用新增后的定位与聚焦。复制行在原行后插入；光标进入新行首个可编辑控件，BOM 已指定的物料 / 部位焦点继续保留。新增按钮位于明细横向滚动区之外，随正文滚动。
- 单据级附件属于主对象证据字段，放在备注、交付、合同资料或凭证语义附近，并位于订单行、BOM 明细、出货明细等 item 区之前；未保存状态可先选择附件并在保存成功后自动上传绑定，单个附件上限 5MB，PNG / JPG / WEBP / GIF / PDF 可轻量预览，HEIC / HEIF、Office、ZIP、邮件证据和 WPS 文件下载后查看，无附件状态使用紧凑空态，不在明细末尾放置独立大区块，避免明细增多后必须滚到最后才看见上传入口。
- 产品图不是普通证据附件：产品表单内固定显示两个紧凑图片位，选择、替换或清空先留在当前表单会话，产品保存成功后才调用产品媒体接口；取消或产品保存失败不写图片，已打开打印草稿也不随主档后续替换而变化。
- 产品档案与产品规格、选款、工程 / BOM、生产和委外产品明细、成品库存、出货明细及产品 / 在制品质检复用 `ProductIdentity`：名称旁显示 48px 主图，选款候选使用 40px 静态缩略图，选中后再提供放大入口。只在可见区域按当前产品读权限批量读取主图引用（每批最多 80 款），随后懒加载缩略图；点击图片才读大图，关闭返回原位置和焦点，不触发行选择或编辑。无主图保留占位，读取失败支持重试 / 页面刷新；切换或清空产品、保存产品图片和手动刷新时更新展示。图片不增加导出列、不替代款号或质检证据，也不为材料、财务或汇总行推测产品。
- 弹窗壳层按主题区分：浅色主题保持 Ant Design 轻量基线；暗色主题必须提供可辨认的遮罩、独立边框、浮层阴影以及 header / body / footer 分隔，避免业务页背景和弹窗融成一片。
- 弹窗 body 内部接管纵向滚动，避免长表单溢出视口；明细横向滚动只允许收口在明细容器内，不外溢到整组 Modal。
- 输入控件的共享外层圆角由 `control-foundation.css` 的 `--erp-control-radius` 管理（12px）；普通弹窗使用 Ant Design 的 32px 高度，业务表单和搜索使用共享的 36px 高度，登录使用 56px 高度，尺寸与文字节奏由 `business-control-rhythm.css` 管理。组合输入框（密码、搜索、前后缀与清空按钮）只由外层绘制圆角、背景、边框和焦点环，内部原生 input 保持零圆角、零边框、零内边距、透明背景和无焦点阴影，并继承外层字体。页面及主题的外观选择器排除内层 input，避免依赖样式加载顺序或高优先级覆盖；登录样式集中在 `login.css`，不由打印样式文件提供。
- 下拉选项、标准操作菜单和“更多操作”共用基础控件样式：12px 浮层圆角、8px 项目圆角、轻分隔线、完整文字和长名称自动换行。悬停与键盘焦点清晰可见，选择型菜单保留当前选中态，命令型菜单保留危险操作颜色及禁用原因；手机项目至少 44px 高，任务端沿用更大的触控尺寸。表头图标入口、带搜索的选择器和既有业务分组按任务保留，不强制改成相同控件。
- 浅色焦点态保留 ERP 绿色，暗色普通 hover / focus 使用 slate / blue 交互色，绿色仅保留给品牌主按钮和状态强调。浏览器回归须在弹窗仍打开时检查默认、空值聚焦、明文切换、填写、校验错误、禁用和重新打开状态；公共焦点扫描同时检查内外层，不能仅凭外层圆角与焦点环通过判断输入完整。

# 页面来源生成入口规则 / Source-Generated Page Entry Policy

本文定义 ERP 业务页面的“新建 / 生成 / 登记”入口口径，避免来源生成单据、事实页和只读台账继续出现无来源的页面级新建按钮。

## 当前结论

来源生成的表单使用“从来源生成”入口，不保留无来源的页面级“新建”按钮。页面可以提供来源选择 / 来源导入控件或“从 X 生成 / 生成 X 草稿”动作，但必须让用户看到来源、余额、状态和不可生成原因；如果真实后端路径还没完成，前端不放占位按钮。

| 页面类型                 | 页面级入口口径                                    | 允许条件                                                             | 禁止口径                                                       |
| ------------------------ | ------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| MasterData / 主数据      | 可以“新建”                                        | 当前页面就是对象 owner，后端已完成 create / update / RBAC / 引用约束 | 不能用新建绕过启停、引用检查或客户配置                         |
| Source Document / 源单据 | 可以“新建”或“从来源导入明细”                      | 当前页面拥有草稿生命周期；来源导入只填明细，不直接写事实             | 不能把销售订单、采购订单、委外订单直接说成库存、质检或财务事实 |
| 来源生成单据             | 用“生成 X 草稿 / 从 X 生成”                       | 来源对象、来源行、剩余量、状态和后端校验都可见                       | 不使用无来源“新建 X”                                           |
| Fact Action / 事实动作   | 用“过账 / 取消 / 冲正 / 判定 / 释放 / 消耗”等动作 | 后端 usecase、RBAC、幂等和状态机已完成                               | 不用页面级“登记事实”代替来源生成                               |
| Read Model / Ledger      | 不显示创建入口                                    | 只读查询、筛选、导出或列配置                                         | 不放“新建 / 登记 / 生成”占位按钮                               |
| Future / 未闭环能力      | 不显示按钮或降级为只读说明                        | 后端合同、来源和测试未完成时先隐藏                                   | 不用前端本地表单伪造后端事实                                   |

## 正式业务页面血缘

`web/src/erp/config/businessPageLineage.mjs` 是可执行注册表，当前覆盖 24 个正式页面。每页只登记一次；下表用来找入口，具体动作、可用性和消费者由注册表及测试核对。

### 先区分数据流

| 类型 | 登记键 | 代表的事情 |
| --- | --- | --- |
| 目录与来源 | `catalog_fill / source_link / source_query` | 草稿带值、直接外键关联、服务端候选查询 |
| 生成与导入 | `domain_generate / unscoped_mutation / external_import` | 领域生成、尚未收口的无来源写入、外部导入 |
| 事实与生命周期 | `post_fact / fact_reversal / lifecycle_transition` | 过账、库存冲正、对象状态动作 |
| 流程与读取 | `process_orchestration / read_projection / source_navigation / print_snapshot` | 流程编排、只读投影、来源导航、打印快照 |

“能跳转”“有外键”“查到候选”和“生成事实”不能互相替代。`producerActions` 只登记真实 RPC / 聚合保存，直接外键关系登记上游页面。

血缘门禁从 JSON-RPC dispatcher 和页面 API 反查 action，包含 `customer_config` 的 ProcessRuntime wrapper。跨页查询、生成、过账、冲正、生命周期和编排必须登记 typed flow；本页普通 CRUD / 查询用精确 allowlist，失效 action 也会被拒绝。wrapper 按真实领域副作用归类，只有纯流程 / 门禁动作才算编排。

每个来源动作同时检查目标动作权限、精确来源读取权、来源及目标模块状态；查询 repo 之前就拒绝无读权，条件来源只在实际绑定时加权。创建下游的权限不授予猜 ID 或穿透读取。来源模块为 `disabled / read_only / 缺失` 时，不能继续写下游。registry 驱动 permission usage，缺权测试与 AST handler guard 同时检查实际接线。

`catalog_fill` 必须声明 `append / replace` 与重复策略 `allow / skip / reject`；选择器不代替领域去重，同 SKU / 材料可因交期、价格、批次或部位分行。带值不自动关联来源或过账。外部导入须有后端校验、幂等、审计和错误报告，当前 `external_import` 保持为空。

### 页面与来源速查

#### 基础资料与工程

| 页面 | 入口 | 主要来源 | 后续去向 |
| --- | --- | --- | --- |
| 客户档案 | 新建主数据 | 本页维护 | 销售订单 |
| 供应商与加工厂 | 新建主数据 | 联系人、类型与可加工工序 | 采购、委外 |
| 产品档案 | 新建产品与 SKU | 本页维护 | 销售、BOM、委外、生产、出货 |
| 材料档案 | 新建主数据 | 本页维护 | BOM、采购、委外、入库、库存 |
| 加工环节 | 新建标准环节 | 本页维护 | 委外；不承担完整路线或排程 |
| 物料清单（BOM） | 新建 / 复制版本草稿 | 产品、材料 | 生产订单显式关联；不自动生成采购或库存 |

#### 接单、采购与加工

| 页面 | 入口 | 主要来源 | 后续去向 |
| --- | --- | --- | --- |
| 销售订单 | 新建草稿 | 客户、产品 / SKU | 显式关联生产、预留、出货候选 |
| 采购订单 | 新建草稿 | 供应商、材料 | 审批后独立生成采购入库 |
| 采购入库 | 从已审核采购订单生成 | 正式采购行 | IQC、库存、退货 / 调整、应付 |
| 质量检验 | 从正式来源生成 / 补建 | 采购入库、委外回货、生产 WIP、草稿出货 | 批次、退货、工序放行 / 返工、应付、出货追溯 |
| 库存台账 | 查询及受控专项动作 | 事实流水、批次及预留投影 | 来源追溯、盘点、调拨、调整 |
| 委外订单 | 新建合同草稿；同页办理委外记录 | 供应商、产品 / 材料、加工环节 | 发料 / 回货事实，再到质检、库存、应付 |

#### 生产、协同与库存预留

| 页面 | 入口 | 主要来源 | 后续去向 |
| --- | --- | --- | --- |
| 生产订单 | 新建草稿 | 产品 / SKU，可显式关联销售订单与 BOM | 排产任务、冻结 WIP 路线、领料 / 完工草稿 |
| 排产确认 | 来源生成任务，无通用新建 | 生产订单发布 | 协同状态与事件，不写生产事实 |
| 生产记录 | 来源生成，无通用新建 | 已发布生产订单、WIP 与完工事实 | 领料、完工、返工、质检与库存 |
| 异常处理 | 来源申请及批准后的执行 | 报废、WIP 让步、超领；返工另有提醒任务 | 审批决定、显式执行 / 冲销或正常领料消费额度 |
| 出货放行 | 来源审批，无通用新建 | 草稿出货启动 `finished_goods_delivery` | 版本化财务门禁，之后仍需确认出货 |
| 库存预留 | 销售来源生成 / 释放 | 销售订单 | 出货确认消耗预留；预留本身不是流水 |

#### 出货与财务

| 页面 | 入口 | 主要来源 | 后续去向 |
| --- | --- | --- | --- |
| 出货单 | 新建草稿 / 导入来源候选 | 可出货销售行，另保留正式手工草稿范围 | 检验、财务放行、出库、应收、发票 |
| 应收管理 | 已出货来源生成 | `SHIPPED` 出货单 | 对账与收款核销 |
| 应付管理 | 已过账来源生成 | 采购入库或质检合格 / 让步的委外回货 | 对账与付款核销 |
| 收付款与核销 | 收付款 / 红冲专属入口，无通用事实新建 | 正式资金业务与应收 / 应付候选 | 审批、显式过账、核销及冲销 |
| 对账管理 | 来源生成 | 已过账应收、应付或发票 | 核对完成 / 取消，不是付款或会计凭证 |
| 发票管理 | 已出货来源生成 | `SHIPPED` 出货单 | 从已过账发票生成对账，不直接 settle，也不等于税控开票 |

### 采购、质检与库存的关键条件

| 办理环节 | 必须满足的条件 |
| --- | --- |
| 采购表单 | 供应商、材料、单位未 ready 或读取失败时，新建、编辑、添加和保存均阻断；仓库 readiness 只守生成入库，不反向封死采购表单。两条准备链都不读取库存批次 |
| 采购提交 | 只走 `material_supply` 的提交 → 审批 → 批准 → end；不生成收货、IQC、入库或应付 |
| 采购入库生成 | 公开新建只有 `create_purchase_receipt_from_purchase_order`；`add_purchase_receipt_item` 要求同一采购行并原子生成 IQC，正式 Web 无入口，登记为 `partial / backend-only` |
| 采购草稿作废 | 入库、退货、调整均零库存；入库还结清可取消 IQC，仅余额精确为零时停用预备批次 |
| 质检放行 | 生产 WIP 仅 `PASSED + PASS` 推进；判定不增减库存总量，也不代替 Workflow |
| 库存与批次 | 草稿可登记批次但不写流水 / 余额，作废不造零值流水；只有已过账事实或实际出货取消才走 `REVERSAL` |
| 人工库存调整 | 正式 InventoryOperation 经 `inventory_adjustment_approval`；提交和审批不写库存，仓库显式 post 才落交易与余额。旧 `approval_ref` 不属目标 schema |

### 委外、生产与异常的关键条件

委外“委外记录”同时展示 `MATERIAL_ISSUE / RETURN_RECEIPT`，按 `outsourcing.fact.read / post / cancel` 和 canonical RPC 办理，写后重读。`DRAFT` 可过账或作废，`POSTED` 可取消，`CANCELLED` 只读；草稿退出零库存，已过账取消恢复库存。

只有 `POSTED RETURN_RECEIPT` 开放质检 / 应付，应付还要求正式质检合格或让步。`source_order_no / product_order_no_snapshot` 只是追溯快照，不能当销售订单关联；`20260718125909_migrate.sql` 删除了目标 schema 的伪来源列 `source_sales_order_id`。

| 生产环节 | 关键条件 |
| --- | --- |
| 发布订单 | 本页 `create_production_order` 不是销售自动生成；发布原子生成 `production_scheduling`，为显式路线行冻结 WIP，不表示已领料或完工 |
| 排产确认 | PMC 从已发布订单动作或任务深链进入，保留路由与权限但不单列侧栏；完成任务后订单才可关闭 |
| 领料 / 完工 / 返工 | 正式来源坐标完整的 DRAFT 可取消且零库存，POSTED 取消才反向写库存；历史草稿缺坐标时过账、作废都禁用 |
| 下游依赖 | 完工受 active 返工约束，已过账返工受来源异常任务约束；包装批次未 `ACCEPTED` 不得生成 / 过账完工入库 |
| 工序与质量 | WIP 拆批、内制 / 外发、回货、移交、质检、返工和包材确认按正式路线办理，关口或回货按条件生成 `PRODUCTION_WIP` 检验 |
| 异常申请 | `ProductionExceptionDecision` 启动 `production_exception_approval`；老板任务 `production_exception_decision_approval` 只记录决定，报废 / 让步另显式执行，超领由正常领料消费 |
| 返工提醒 | REWORK 过账另原子生成 `production_exception` 提醒，与异常申请 / 审批分开，不互相补数 |

生产管理内按权限展示生产订单、生产执行、生产记录、异常处理四个工作区；排产从来源进入，审批统一在任务管理。入口组织不改变权限、审计或 Workflow / Fact 边界，也不引入 APS、工时或成本核算。源码接线不证明共享库或目标的 migration 已应用，须按目标另行读回。

### 出货与财务的关键条件

1. `list_shipment_source_candidates` 按关键词、销售订单与分页返回来源行、已出货、余量及不可选原因；余额只统计 `SHIPPED`，普通草稿不占用。
2. 来源绑定的新建事务校验 ACTIVE 销售单、同单 OPEN 行、客户、产品 / SKU、单位与余量；客户取不可变销售快照。重新新建必须清 `sales_order_id`、客户带值、候选及行选择缓存，手工草稿不继承旧来源锁定。
3. 出货审批先重验已有成品质检，通过后只写 Shipment 财务门禁并结束流程。责任来自审批设置，默认财务主办、老板升级。
4. 显式确认出货要求门禁 `APPROVED`，锁定重验质检、来源、累计量、预留与库存；写出货事实后才可生成应收 / 发票。
5. “作废草稿”只转 `CANCELLED`，库存不变；“撤销已出货”才冲正库存。active 流程、质检或财务依赖仍先阻断。

| 财务状态 / 对象 | 取消与结算规则 |
| --- | --- |
| 应收、应付、发票 | 有正式来源的 `DRAFT / POSTED` 可审计取消，active 对账子事实先阻断；缺正式来源的历史草稿同时禁用确认和作废 |
| 对账 | 正式来源草稿可带 actor / reason 作废，POSTED 可取消，SETTLED 不可直接取消 |
| 发票结算 | 不提供 `settle_finance_fact`；对账通过从已过账发票生成事实表达 |
| 收付款与核销 | `create_finance_payment / create_finance_credit_note`、审批、过账、核销及冲销分别登记，不把审批当资金过账；细则见[财务业务与核销](../finance/财务业务与核销.md) |


## 单据流、事实流与任务流

1. 销售主链：客户 / 产品 → 销售订单；生产订单可显式关联销售订单，库存预留可从销售订单行创建，出货草稿可从服务端可出货候选导入来源行，但三者都不是“销售订单自动生成事实”。草稿出货单可按送检批次发起出货前成品检验，已有检验必须合格或让步接收。随后启动 `finished_goods_delivery`，财务 approval 只写 Shipment 放行门禁；仓库仍须回出货单确认出货，才写库存流水，再按已出货来源生成应收 / 发票 → 收付款 / 对账。
2. 采购主链：供应商 / 材料 → 采购订单草稿 → ProcessRuntime 提交 / 审批 / 批准 → 独立创建采购入库草稿与逐行 IQC → 全部通过后入库确认 → 库存；采购入库还可继续办理退货 / 调整和应付。采购 approval 不生成收货、质检、库存或应付。入库、退货、调整草稿作废都是零库存终止；入库草稿还要结清 IQC / 预备批次，已过账取消才写反向流水。
3. 委外主链：供应商 / 产品 / 材料 / 加工环节 → 委外订单 → 由已确认合同行发起发料 / 回货草稿 → 在同页“委外记录”过账 / 作废 / 取消 → 已过账回货再进入质检、库存与应付。草稿作废零库存，已过账取消冲正；active 质检 / 应付或 WIP 分配仍先阻断。取消事实和关闭 / 取消源单分别走各自生命周期，不用删除、导航或父单动作代替冲正。
4. 生产主链：产品 / 显式销售订单关联 / BOM → 生产订单发布 → PMC 排程任务与显式路线行 WIP → 领料 / 工序执行 / 分段质检 / 完工 / 返工事实 → 库存；REWORK 过账同时生成生产异常任务。生产事实草稿作废零库存，已过账取消冲正并服从 active 下游；生产事实写入库存时，库存来源必须使用事实自身的 `PRODUCTION_FACT + fact.id`，不能回退成生产订单 ID；WIP、质检、排程或异常任务完成也不能代替事实过账。
5. 三类确定性来源任务统一保存 `workflow.source-task/v1 + source_task_producer + source_type + source_id + intent_hash`，使用确定性 task code；同意图重放返回原任务，不同意图冲突并回滚。

   公开 `workflow.create_task` 拒绝全部 19 个能驱动领域 transition 的 task group，其中包含 `production_scheduling / production_exception / shipment_release`；受信的内部 producer 仍可生成真实任务。试用任务只能使用 `trial_*` 组，普通协同任务不能猜测业务 ID。
6. 客户配置 ProcessRuntime 只是既有领域 usecase 的受控编排。销售和采购的 Source Document submit / activate / approve 由流程白名单命令执行；收付款、库存人工调整和生产异常分别先改变正式来源决定，再由独立过账 / 执行命令写 Fact。采购收货 / IQC / 入库与出货质检 / 确认出货 / 应收仍归回各自正式页面和领域事务。

   六条 start 均已接入对应正式 Web UI；旧长图 wrapper 只服务冻结在途 revision，不得计为当前页面链路。
7. 公开服务端流程启动保留六条精确来源绑定链：销售订单 → `sales_order_acceptance`、采购订单 → `material_supply`、出货单 → `finished_goods_delivery`、FinancePayment → `finance_payment_approval`、库存人工调整 → `inventory_adjustment_approval`、生产异常决定 → `production_exception_approval`。

   服务端锁定真实来源并复核状态、引用、版本与幂等，只允许完全相同的已创建流程重放。start 本身不等于 Source 已批准或任何 Fact 已过账；旧入库单起点 `start_material_supply_process` 已退役。

## 当前未闭环与停止线

- 三类来源任务已接入正式业务事件；生产订单关闭 / 取消、已过账 REWORK 冲销和实际出货继续按各自终态规则 fail closed。销售 / 采购来源取消会在同一事务把仍活跃的 linked task 写为内部终态 `withdrawn`，记录原因、actor、版本和事件，并同步结算流程；它不是公开任务动作，也不能用人工 `done / rejected` 替代。
- 入库页面与公开后端均已退出无来源新建：`create_purchase_receipt_draft / create_purchase_receipt_with_items` 返回 unknown method；正式新建只走 `create_purchase_receipt_from_purchase_order`，追加行必须绑定同一已审核采购订单行。内部 usecase 只供领域事务和测试准备复用，不能注册为公开无来源入口。
- 服务端具备不等于正式 Web 可达：`add_purchase_receipt_item` 和旧物料供应 / 成品交付长图 execute 只服务冻结在途 revision；当前正式页面已登记六条 ProcessRuntime start。

  直连销售 / 采购 submit / approve、Shipment finance release 及收付款、库存人工调整、生产异常三条流程的领域执行旁路不得回到页面双轨；`settle_finance_fact` 只允许对账事实，发票、应收和应付不支持直接 settle。
- 委外订单不存在可证明的销售订单外键链；公开 schema / API / 页面均不再接受或返回 `source_sales_order_id`，新 Atlas migration 只删除该伪来源列。可读的 `source_order_no / product_order_no_snapshot` 仍是打印 / 追溯快照，不提升为可用于导入、授权或结算的业务关联。
- 自动生成的初始逐行 IQC 与已过账入库后的追加检验必须分开：初始 IQC 的 `REJECTED` 只阻断入库，不形成库存退货；现有质检来源“退供应商”动作要求来源采购入库已 `POSTED`，不能把两者描述成同一步。
- 委外页面的 post / 草稿作废 / 已过账取消已经通过 canonical RPC 和写后重读接线；当前两个 mock 浏览器场景证明委外发料创建、过账、另一草稿作废和委外回货移动端创建可达，不等于真实后端库存反向流水或 PostgreSQL 并发已由浏览器证明。已过账取消按钮与状态矩阵由页面 / 组件合同覆盖，仍需真实后端岗位浏览器和数据库读回才能作为目标运行证据。
- 出货页用“作废草稿 / 撤销已出货”区分零库存退出与库存冲正，取消后重读列表；新建恢复态必须清空旧来源。mock Chromium 只能证明页面接线与交互，真实库存变化仍需后端及数据库读回。
- `SHIPMENT / FINISHED_GOODS` 是出货前检验侧链，不是“生产完工 → 成品质检 → 成品入库”主链。当前来源粒度是同一出货单内的产品 / SKU、仓库和批次组合；同组合的重复出货明细聚合为一个送检批次，不声称逐出货行留痕。若未来必须逐行审计，需要新增正式来源行锚点和 migration，不能用备注或前端映射伪造。
- `OUTSOURCING_FACT`、`FINANCE_FACT`、`PURCHASE_RETURN`、`PRODUCTION_ORDER_MATERIAL_REQUIREMENT` 等间接来源，要精确跳回最初单据时仍需后端返回可解析的来源投影；页面不得猜 ID 或用同名列表替代精确追溯。
- 没有真实 producer、状态规则、RBAC、幂等、审计和测试时，停止在只读 / deferred 口径；不能用前端表单补造业务来源。

## 新增按钮检查清单

新增或恢复业务页主按钮前，先回答：

1. 当前页面是不是该对象的唯一 owner。
2. 如果不是 owner，来源对象、来源行、剩余量、状态和不可生成原因是否可见。
3. 后端 usecase、JSON-RPC、RBAC、审计、幂等和状态机是否已经完成。
4. 按钮文案是否准确区分“新建”“生成草稿”“过账 / 冲正 / 取消 / 判定”“发起协同”。
5. 表单、表格、筛选、导出列是否只展示业务字段，不展示幂等键、内部主键、内部引用、trace / request ID、裸数据库 ID、`#123` 兜底、ID 选择控件或手填 `source_id` / `source_line_id`；这些字段如需提交，只能隐藏携带或由后端生成。
6. 页面级浏览器回归（Style L1）或静态测试是否断言了按钮存在 / 不存在，以及技术字段不会重新出现在用户可见层。

# 文档清单 / Document Inventory

本文按目录整理当前长期维护 Markdown 文档与归档入口，回答三个问题：

1. 当前有哪些长期文档，历史记录从哪里进入。
2. 每类文档大致负责什么。
3. 哪些文档是产品内入口、哪些只是过程记录、外部输入处理规则或子系统说明。

本文不是业务真源，不是 roadmap，不是 schema / migration / runtime 状态真源。判断当前能力、当前禁止项和当前下一步时，仍先读 `docs/当前真源与交接顺序.md`，再读对应正式文档和代码。

## 使用规则

- `docs/product/*` 和 `docs/architecture/*` 是正式产品 / 架构评审文档；当前不再镜像到前端文档中心。
- `docs/archive/*`、`progress.md` 只用于历史追溯；原 `docs/changes/*` 历史文件已删除，当前状态回到 `docs/当前真源与交接顺序.md`、正式产品 / 架构文档、代码和测试交叉确认。
- 其他项目、GPT/ChatGPT 和外部规划原文不在仓库维护；被采纳的结论必须先复核，再转化为本项目正式 docs、代码或测试。
- README / server docs / config docs / deployment docs 是目录、运行、部署或子系统维护说明。
- `docs/` 下长期维护目录的 `README.md` 只维护目录职责、非真源边界和更新规则，不维护每篇文档正文细节。
- 新增、删除、重命名长期维护 Markdown 文档，或调整文档用途、归属分类、入口状态时，必须同步更新本文；归档逐文件记录只同步最近的归档 README。
- 只改现有文档正文且不改变标题、职责、分类、路径或入口状态时，可以不更新本文；若“标题 / 当前用途”会失真，则必须同步更新。
- 本文“标题 / 当前用途”列默认使用中文主体 + English anchor；若原文档标题是英文，仍应补中文说明，避免清单变成只有英文的索引。
- `scripts/qa/docs-inventory.test.mjs` 会扫描 tracked 和未跟踪但未被 ignore 的当前维护 Markdown，并在 `fast.sh` / `strict.sh` 中分别拦截主清单或最近归档索引漏登记；它只检查索引同步，不判断文档内容是否为当前真源。

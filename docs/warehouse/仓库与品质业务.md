# 仓库与品质 / Warehouse Quality

仓库负责实物点数、收发存及查货包装；IQC 负责质量事实，业务决定生产质量异常方案并办理实际发货。桌面任务中心、手机岗位任务和业务页面使用同一领域动作。本文描述当前工作区合同，目标是否生效须核对迁移、客户配置和运行版本。

## 仓库

| 能力 | 业务入口与事实 |
| --- | --- |
| 采购到货点数 | 采购订单登记实际到货，生成采购收货草稿与 IQC 待办；实点数量归仓库，送货标示数量只作差异参考 |
| 材料正式入库 | 采购入库核对质量关口后确认 `POSTED`，形成库存 `IN` |
| 发料外发裁片 | 在生产订单关联裁片加工合同，正式发料后确认外发 |
| 工序回货点数 | 生产工序填写仓库实点数量，记录 `OUTSOURCE_RETURN` 后交 IQC；WIP 回货不增加成品库存 |
| 成品正式入库 | 在生产订单按已完成手工的批次登记收仓草稿，由仓库在成品入库核对并确认 `POSTED`；库存增加但待检 / 待包装数量禁止发货 |
| 查货与包装 | 对明确的已过账成品收仓记录安排包装，检验与业务包材确认通过后查货、包装；不重复增加库存 |
| 库存查看 | `inventory_txns` 为流水真源，`inventory_balances` 为余额，`inventory_lots` 为批次；待检 / 待包装 / 可发货数量来自收仓与工序事实 |
| 入库后异常处置 | 按批准方案执行库存处置及受限冲正；仓库数据范围同时约束首次执行、重放和冲正 |

## 仓储入口与库存口径

仓储管理的页签按当前账号权限显示。办理沿用原单据的权限，销售和生产也可从原入口进入。

| 想办理什么 | 入口与核对项 |
| --- | --- |
| 查看材料或产品 | 库存查询的「材料 / 产品」共用一列。点缩略图看大图，点材料名查规格书或色卡，查资料须具备材料查看权限。同一材料的档案跨仓库和批次共用。没有图片时保留名称、料号及规格。 |
| 选择存货和仓库 | 先选类型再选档案，换类型会清空原对象与规格。材料按库存类别选仓，产品选成品仓。 |
| 入库与出库 | 入库分采购收货、成品入库、委外回货、工序回货。出库分销售出货、生产领料、委外发料、库存预留。 |
| 工序回货与成品入库 | 工序回货按外发 WIP 批次点数后交品质，成品库存从正式收仓增加。成品收仓按待入库、待检、待查货包装和检验包装已完成查询。实收与草稿数量不符时先改原草稿。 |
| 查货包装与出货 | 原工序表单锁定所选收仓单，按安排、开始和完成分别办理，使用仓库包装权限。其他工序安排、拆批和取消仍用生产安排权限。检验包装完成后，可发数量仍要核对预留、批次和放行。列表与状态计数使用同一后端可读范围，计数按筛选后全量数据。 |
| 采购退货与入库调整 | 从原收货单「更多操作」生成退货，从「相关单据」查退货和调整记录。整页填写时核对原权限、状态与来源，退货草稿无再次编辑入口。 |
| 盘点、调拨、人工调整、委外发料或回货 | 登记和编辑草稿使用整页。来源只读，返回原列表或合同明细，失败保留输入。草稿、确认、过账和取消沿用各对象现有动作。 |

| 数量 | 计算与使用边界 |
| --- | --- |
| 账面数量 | 已过账流水汇总，包含受限批次及待检、待包装成品 |
| 已预留 | 当前有效的销售订单预留；释放预留不增加实物库存 |
| 未预留数量 | 账面数量减有效预留，下限为零；API 保留 `available_quantity`，不能据此断定允许领用或发货 |
| 可领用数量 | 材料的未预留数量，批次须为 ACTIVE；非材料或受限批次为零，具体领料仍核对业务来源、单位和权限 |
| 受限库存 | HOLD、REJECTED 或 DISABLED 批次的全部账面数量；未分批次库存按普通库存处理 |
| 待检 / 待包装 | 由成品收仓与工序事实确定，不能与其他数量列简单相加 |
| 可发货数量 | 成品未预留数量扣除待检、待包装限制并取非负值，受限批次为零；实际出货仍须满足来源单、放行和库存校验 |

仓库库存分布由服务端在与余额列表相同的仓库权限、存货和关键词筛选范围内聚合，每个仓库只返回一行。余额记录数按库存粒度计数，仓内存货项按存货类型、存货和产品规格去重；有无可用量沿用余额减去活动预留的现有算法。分布不合计不同单位的数量，包含有余额的停用仓库；点击仓库返回对应筛选列表。前端不再读取所有余额明细来生成分布。

库存余额的全部数据列均可排序，勾选列继续用于选行。材料 / 产品按编号，仓库、单位按名称，批次和产品规格按编号；按规格排序须有产品规格查看权限。列设置中的「库存项」按登记顺序，「存货类型」按主料、辅料、包材、其他材料、待分类、成品的顺序比较。

数量先按单位分组，再在组内比较数值。0 参与排序；无规格、无批次及不适用的数量排在最后。排序覆盖当前有权查看且符合筛选的全部记录，切换后从第 1 页查看，导出沿用当前顺序。取消排序恢复最近更新优先。库存批次仍可按批次号或接收日期排序；库存变动记录继续按发生时间倒序。

工序回货和成品入库可按本次数量在同一单位内比较，取消排序后恢复待办优先。找待检或待查货包装的单据仍使用状态筛选。

库存流水返回实际来源单号及可访问的来源入口。采购退货、入库更正定位原收货单，委外处置定位原回货；库存盘点、调拨及调整定位库存作业，生产异常定位异常单。来源编号与反向流水的原流水关联保留，不用前端猜单号；点击仍受来源单据权限限制。历史无来源或已无法解析的记录保持可查询，不伪造可打开的单据。

## 盘点复核与完成记录

1. 从库存查询勾选明确的库存行形成盘点范围，单次最多 200 行，逐行保留存货、规格、仓库、批次、单位及账面数量。当前范围是已存在的库存余额；不是全仓冻结或未入账物料的期初导入。
2. 填写实盘数量和原因，后端从真实余额核对账面数量并计算差异。同一库存粒度不能在一单重复登记，各单位精度分别校验。
3. 提交后冻结明细，复用库存审批流程。复核人查看逐行账面数、实盘数和差异；创建人不能审批自己的盘点或调整。电脑与手机办理均先读取完整明细，读取失败时不能批准。
4. 批准后由仓库确认过账。后端重新核对账面数量，期间发生出入库则整单拒绝过账，保留原快照，取消原作业后重新盘点并复核；不自动把旧实盘数套用到新余额。
5. 全部零差异也可以完成，保留已过账作业与复核证据，但不新增库存流水；混合明细只为非零差异生成流水。重复请求不重复入账。
6. 驳回不改变库存；纠错重新登记。取消未过账单不改变库存，取消已过账单按现有依赖、权限、预留及受限数量规则追加反向流水，保留原单与原流水。活动审批先按流程取消，再处理来源单。

调拨仍按来源、目标仓库与可用库存校验后直接过账；人工调整与盘点都必须复核。历史已过账或已取消的盘点事实保留原有证据，不补造审批人或审批时间；升级后新盘点统一经过复核。

## 品质

品质人员在正式检验单上记录检查与判定。需要纠正已生效的结果时，保留原判定并建复检单；复检必须完成新判定，待判定期间批次待检、出货受阻。

### 填写与查找检验单

| 查什么 | 填写或查询规则 |
| --- | --- |
| 谁检验 | 后端记录登录账号，页面和导出优先显示姓名，缺姓名显示登录名。拒绝客户端代报，历史缺失保留空值。 |
| 查了什么 | 采购来料、委外回货、出货前和生产分段检验逐项填写项目、要求或依据、实际情况、符合或异常、全检或抽检。抽检写范围或数量，不适用写原因。预填项目默认未检，不能据此判合格。不合格和让步都需记录异常项和处置理由。 |
| 怎样找原单 | 列表默认采购来料。从采购、委外回货或出货进入时保留检验类型与来源。「当前记录」、状态统计和 CSV 排除已替代单，仍包括待检和不合格。选「含已替代记录」可查替代标记、原结果、原因与前后单号，并在两单详情间往返。 |
| 各关口结果 | IQC 从 `quality_inspections` 查来料颜色、裁片颜色与尺寸、皮套及成品各关口。不良比例取 `defect_rate_operator / defect_rate_percent`，历史缺值保留；报废、退货及库存数量另行确认。 |

### 判定后怎样流转

| 情况 | 下一步与限制 |
| --- | --- |
| 出货前检验 | 正式送检单生成品质待办，品质回原单提交判定。业务从出货单查看财务放行条件。同一出货单以全部有效检验为准，重检保留原判定。 |
| 生产不合格 | 批次进入 `REJECTED`，业务决定处置。返工或重做建立带异常来源的新在制子批，再按目标工序点数和检验。成品检验、针检、抽检、条件客户验货各自保留，包装版面确认不能替代 IQC。 |
| 审批让步 | 只作用于审批关联的不合格检验。保留原事实，生成冻结路线的下一关；最后一个必需关口结束才放行。后续失败仍阻断。撤销仅可取消未提交的下一关草稿，已有后续提交、判定、在制子批或库存依赖时拒绝撤销。 |
| 响应丢失 | 原样重试返回原记录，即使批次进入下一关也不重复生成检验单或推进。更改检验人、检查内容、显式检验时间、不良比例或已提交理由会报冲突。 |

批次的 `HOLD / ACTIVE / REJECTED / DISABLED` 由命名动作和版本校验（CAS）更新，变更记入 `inventory_lot_status_events`。库存流水由库存动作单独记录。

## 主链关系

1. 采购安排到货，仓库点数，IQC 检验，通过材料入库门禁后正式入库。
2. 仓库按裁片合同发料外发；裁片回厂由仓库点数，再由 IQC 检查颜色及尺寸规格。
3. 生产经理安排车缝，可本厂或委外；外发回货由仓库点数，IQC 进行皮套检验。

生产经理安排手工，可在本厂或委外办理。以下从手工成品形成后开始：

```mermaid
flowchart LR
  hand["手工完成"] --> inbound["仓库确认成品入库"]
  inbound --> check["成品待检"]
  check -->|检验通过| pack["查货包装"]
  pack -->|质量与包装均完成| release["核对出货放行"]
  release -->|放行通过| ship["业务确认实际出货"]
```

包装批次通过 `finished_goods_receipt_id` 绑定本次收仓单、仓库与批次。不同仓库各自核对包装结果。库存 `OUT` 由实际出货 `SHIPPED` 写入，应收和开票也以它为来源。

出货明细按产品、SKU、所选成品仓和单位读取当前可发批次。批次必须有效且有可发数量；其他订单的预留、待检、冻结和待包装库存不参与可发量，本销售订单行自己的有效预留仍可用于该行。切换仓库、规格或单位后重新选批次，最终数量由确认出货事务重验。

## 异常分支与数量边界

| 方案 | 执行与追溯 |
| --- | --- |
| 原加工厂返工 | 冻结原厂与目标工序，生成新返工批和新合同，保留原质量结果 |
| 换加工厂返工 | 冻结其他厂商，对原货返工，不能执行时再换厂 |
| 补料重做 | 回到裁片工序，按新材料合同正式补发布料，不重复使用原批发料作为新料证明 |
| 放弃本批 / 报废 | 审批后执行正式处置；已有收仓事实的库存由仓库处理，不能仅关闭任务 |
| 让步、超领 | 沿用原有独立审批与领域执行边界 |

WIP 当前按整批回货并按整批不良处置。实点数量必须与本批数量一致；少收或多收须先核对，不能自动视为全批到货。分批回货、部分不良拆分未在本次提供。采购到货仍保留既有分批 / 分卷实际收货能力，两者不可混淆。

任务详情按正式单据关系展示当前账号可见的订单主链和异常分支；异常源单、原批次、子批与复检可追溯。看见处理链不产生其他岗位的办理权限。原任务、原检验、原收仓和执行事件保留；冲正必须没有后续加工、质检、合同等依赖并满足库存限制。

## 任务与事实

来源待办由领域事务同步。手动跟进、旧协同事件中的 `done / inbound_done / shipping_released` 只表示协同结果，不能充当检验完成、收仓过账或真实发货的证据。任务办理页进入对应正式业务表单，保存成功后返回原任务并重新读取状态；业务页面保留相同办理入口。

历史已过账、来源为已完成包装的收仓事实保持原样，并占用原手工容量，不能重复收仓。升级前须检查旧未完成包装、旧包装来源草稿和冻结于旧岗位的活动异常 / 出货流程；不能用改写历史流程责任绕过升级预检。

## 预警规则

- 质量不合格与业务异常进入异常处理分类；异常处于 `ready` 或逾期时仍保持异常可见，终态进入已结束。
- 逾期、缺料、点数差异与出货风险分别显示，不以催办或任务完成解除业务门禁。
- 库存查询和负向库存动作统一保护待检 / 待包装数量，不能通过普通调整绕过禁止发货。

## 当前不做

PDA、条码枪、复杂库位策略、WMS 波次、自动补货、图片识别和复杂 AQL 算法不在本次范围。

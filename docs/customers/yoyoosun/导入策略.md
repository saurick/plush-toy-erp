# 永绅导入策略 / Yoyoosun Import Strategy

本文是永绅来源资料、freeze、dry-run、BOM Excel 辅助录入、人工复核和停止条件的唯一阅读入口。工具参数见[导入准备工具](../../../scripts/import/README.md)，字段归属见[导入字段分类](导入字段分类.md)和[Excel 字段产品核心映射评审](Excel字段产品核心映射评审.md)。

## 当前结论

- 通用客户批量导入当前只有来源校验、只读提取、snapshot freeze 和 dry-run，不提供执行入口；BOM 版本页另有窄范围的 `.xlsx` 辅助录入。
- 真实 Excel、PDF、图片、私密 manifest 和未脱敏输出由永绅客户专属 Private 仓库管理；Product Core 普通构建和 CI 不依赖该仓库。
- Product Core 只保存通用工具、合成 / 脱敏 fixture、字段分类和类别映射，不保存真实 inventory、文件名、hash、原始行或人员信息。
- `canExecuteRealImport=false`、`noRealImport=true` 和 `executesImport=false` 是导入准备脚本的硬边界；freeze 或 dry-run 报告不等于导入批准、发布证据或客户签收，也不控制 BOM 页面内的受控草稿保存。
- 客户配置包与客户业务数据分离：品牌、菜单、字段和编号规则进入受控配置；客户、供应商、订单和事实只能进入独立客户数据库，并经过正式 usecase。

## 来源类别与允许用途

| 来源类别 | 允许用途 | 当前候选目标 | 禁止自动产生 |
| --- | --- | --- | --- |
| 客户 Excel | manifest 校验、只读提取、字段分类、dry-run | customers、suppliers、contacts、sales_orders/items、现有产品 / 材料 / 单位 / 仓库、BOM 候选 | 正式主数据、采购收货、库存、质检、出货、预留、生产和财务事实 |
| 采购 / 委外汇总 | 主体、材料、单位、采购或委外源单候选 | Supplier / Material / Purchase / Outsourcing 表单候选 | 入库、回货、库存、应付或付款事实 |
| 材料分析 / BOM | 本地解析、已有主数据匹配、人工复核和 BOM 草稿辅助录入 | existing Product / Material / Unit、new BOM `DRAFT`、可编辑草稿明细 | 自动创建主数据 / SKU、覆盖已启用版本或激活 BOM、采购、生产、库存和成本事实 |
| PDF、合同照片与打印样本 | 人工核对字段、抬头、条款和版式 | 打印模板输入、源单字段线索 | OCR 自动导入、结算或付款事实 |
| 页面截图、岗位图和流程图 | 需求、页面、角色和流程评审线索 | 客户差异、问题待办、Workflow 评审 | runtime 页面状态、权限、Workflow 或 Fact |
| seed / demo / 合成 fixture | 工具测试、演示和试用 | 本地 QA | 真实客户数据或业务事实 |

精确来源身份只由 Private 仓库 manifest 中的 `customerKey + sourceId + hash` 管理。Product Core 的 `config/customers/yoyoosun/rawSourceFormMap.mjs` 只锁住脱敏类别映射，不复写私有 inventory。

## BOM Excel 辅助录入

1. BOM 列表通过“新建 BOM”旁的“更多新建方式 → 从 Excel 新建”选择文件；新建或可编辑草稿在“材料分析明细表”标题区提供“从 Excel 导入”。列表下拉和材料区均可“查看 Excel 格式”，说明以实际下载文件的图示配合编号短句定位表头、明细和图片区；图示与工作簿同源校验。下载示例的面料单位为码、填充棉为千克，保留来源表的表头、材料分组、多个部位、小计、加工列和用量公式，在原表图片区放置同一虚构产品的正背面图、材料色卡及工艺示意，不在表内堆放制作标记，不要求把原文件重排成新模板。只接受 `.xlsx`，按 workbook / sheet 结构识别唯一的 `材料分析明细表` 或 `材料分析明细表-1`；可保留汇总、色卡和作业指导等其他页，这些页不参与本次导入。保留“物料名称”和“单位用量”表头，材料和单位需在保存前关联现有档案。不依赖固定文件名、固定单元格；不接受 PDF、独立图片或 OCR 结果作为明细文件，工作簿内嵌图片需另行添加为附件。
2. 单文件大小与普通附件统一为 200MB；BOM 最多 1000 个部位，实际读取的单个内部数据项最多 16MB、合计最多 64MB，不把跳过的内嵌图片或其他工作表计入解析预算。文件在浏览器本地解析并进入预览弹窗；取消不改动当前草稿。产品、材料、单位只在当前启用主数据中唯一匹配。未匹配或有歧义时字段保持空白，带入编辑页后、保存前必须人工选择。
3. 核对预览沿用原表列名、列序和数字显示格式，不把原表没有的损耗列插进原表核对表。单位用量是 BOM 数量真源，合计用量只作来源快照；BOM 单位用量与损耗按完整十进制精度参与计算和保存，不在导入、保存或中间汇总时舍入。完整原始数值、数字格式、行号和损耗依据随明细保存、读回及复制；编辑页按原表格式显示，聚焦时编辑保存用量，明细旁可查看完整原值。原表总用量保留作来源核对；当前总用量按保存的完整单耗、损耗和订单数量重新计算。损耗优先读取行内明确值；没有行内值时，用订单数量、单位用量和合计用量校对表头声明，一致时采用表头原值并注明来源，否则逐行反算；无可反算数值时才采用表头声明。证据冲突或无法确认时留空核对。公式使用工作簿上次保存的结果，导入前须在 Excel / WPS 中重算并保存；页面不会重算整个工作簿，也不会修复其他页的公式错误。
4. “从 Excel 新建”带入整张草稿，版本仍由用户确认；“从 Excel 导入”追加或明确替换当前可编辑草稿的明细，不覆盖产品、版本、备注和附件；当前订单数量为空且原表数量有效时一并带入，已有数量则保留。当前数量与原表不一致时，在预览和导入核对中提示，总用量按当前数量计算。原表合计用量作为核对证据保留；数量不同或缺失时清除导入行的适用总量快照，补入数量时也清除已有明细的旧适用总量快照。最多保留 1000 个部位，不自动去重或合并部位行。
5. 明细带入后、继续修改明细或订单数量前可“撤销本次导入”；撤销同时恢复导入前明细和订单数量，其他表头与附件保留当前内容。全部必填项通过后，沿用 `save_bom_with_items` 新建或更新 BOM `DRAFT`；更新仍检查并发版本，不允许修改已启用或历史版本，不自动激活或创建主数据。
6. 原始工作簿不会自动上传或被改写；新建导入把文件名和 sheet 写入 BOM 备注，明细来源快照只保留核对所需的原始数值和格式，不保存整个工作簿。只有关联了正确单位的材料首次匹配时可保留原表总量；之后修改材料、单位、用量、损耗或订单数量会使旧总量失效，来源原值仍可查。保存后须读回核对，缺失来源数据时保留输入并提示重试，不重复新建草稿。导入不产生采购、库存、质检、生产、成本、出货、财务或 Workflow 事实。

## 字段与主体处理规则

1. 每个字段先归入 Product Core、Industry Template、Customer Config、Import Adapter、Print Input、Deferred 或 Forbidden。
2. 客户、供应商、联系人、产品、材料、单位和仓库必须唯一匹配；同名不等于同一主体，缺失时不猜测创建。
3. 订单号、编码、日期、数量、单位和金额异常进入人工复核，不用默认值、备注或覆盖来隐藏冲突。
4. 颜色、尺寸、包装版本等 SKU 线索保持专项评审；客户导入不能自动创建 SKU。
5. 销售订单、采购订单、生产订单和委外订单是 Source Document；来源中的“完成、出货、入库、付款”等文字不能直接升级为 Fact。

## 未决与阻断规则

| 场景 | 处理 | 是否阻断后续真实导入设计 |
| --- | --- | ---: |
| 主体无法唯一识别、缺 owner 或必填字段 | 记录来源行、候选目标、负责岗位和处理结论 | 是 |
| 编码 / 名称重复或 existing 数据冲突 | 保留 duplicates / conflicts，人工决定合并、保留或跳过 | 是 |
| 日期、数量、单位无效 | 人工修正或跳过；不能伪造 | 是 |
| 金额或税务语义不清 | 保留为来源线索；不生成财务事实 | 视目标而定 |
| 字段未分类或仅属永绅习惯 | 进入问题待办或客户配置评审 | 否，但不得静默丢弃 |
| SKU、采购导入等尚未批准的目标 | Deferred，等待专项能力与数据治理评审 | 是 |
| shipment / inventory / quality / production / finance Fact，或 Workflow done → Fact posted | Forbidden，必须出现在禁止自动导入报告 | 是 |

未决项至少保留 source reference、domain、source field/value 的受控表示、target candidate、severity、owner role、resolution 和 decision note。报告不得复制不必要的敏感原值。

## 准备与复核流程

1. 在客户 Private 仓库登记 manifest：稳定 sourceId、相对路径、media type、hash、size、分类和结构化提取策略。
2. 从 tracked `sources/` 显式调用 Product Core 通用工具，校验未登记文件、路径逃逸、hash / size 漂移和 `canExecuteRealImport=false`。
3. 只读提取允许结构化处理的 Excel；PDF 和图片保持人工参考，不做 OCR。
4. freeze source snapshot 与 existing snapshot，记录 checksum、来源计数、边界风险和人工复核项。
5. dry-run 生成候选、未决、重复、冲突、禁止自动导入和汇总报告。
6. 业务人员按来源行复核主体、字段、跳过项和禁止项；未决项未关闭时在此停止。
7. Private 仓库推送后从远端新 clone 或 archive 回读，并以当前 `product.lock.json` 锁定 Product Core 版本重新验证。

## Evidence 输出

| 输出 | 用途 |
| --- | --- |
| `freeze-metadata.json` / `freeze-check-summary.json` / `freeze-check-report.md` | 证明输入已冻结、边界检查可读；不批准导入 |
| `source-references.json` / `normalized-rows.json` | 保留来源定位和规范化结果；真实版本只能在私有 ignored output |
| `candidates.json` | 展示 create / update / review / defer / forbidden 候选，不授权写库 |
| `unresolved-queue.json` | 记录 block / defer / review / warning 与负责层 |
| `duplicates.json` / `conflicts.json` | 暴露重复主体和更新冲突，禁止静默覆盖 |
| `forbidden-auto-import.json` | 明确阻断 Workflow / Fact 混淆和事实自动生成 |
| `validation-summary.json` / `dry-run-report.md` | 汇总人工复核状态，`canExecuteRealImport` 必须为 `false` |

`output/customers/yoyoosun/` 是本地 ignored evidence 目录；固定数量、hash 和一次试跑统计不是长期文档真源。

## 验收与验证

来源与 dry-run 准备只有同时满足以下条件才算可供人工评审：

- Private manifest 覆盖全部输入，本地 materialized 原件与 manifest hash / size 一致。
- 真实文件名、原始行、人员、对象地址、凭据和 DSN 未进入 Product Core 或普通 CI artifact。
- fixture / seed 明确标记 simulated，字段归属、主体歧义、重复和冲突均可追溯。
- 未生成库存、质检、生产、出货、预留或财务事实。
- `canExecuteRealImport=false`、`noRealImport=true`、`executesImport=false` 均保持成立。

Product Core 验证：

```bash
node --test \
  scripts/import/customerSourceManifestCheck.test.mjs \
  scripts/import/customerSourceExtract.test.mjs \
  scripts/import/customerSourceSnapshotFreezeCheck.test.mjs \
  scripts/import/customerImportDryRun.test.mjs \
  scripts/qa/test-data-isolation-boundary.test.mjs
```

Private 仓正式验证只在两边已经提交且工作树清洁、`product.lock.json` 指向当前 Product Core 提交时运行：

```bash
PRODUCT_ROOT="$(git rev-parse --show-toplevel)"
CUSTOMER_PRIVATE_ROOT="$(dirname "$PRODUCT_ROOT")/plush-toy-erp-customer-yoyoosun-private"
cd "$CUSTOMER_PRIVATE_ROOT"
FORMAL_PRODUCT_PIN=1 \
PRODUCT_ROOT="$PRODUCT_ROOT" \
bash scripts/validate.sh
```

本轮文档治理不运行 Private 正式验证，也不改变客户仓内容。

## 停止条件与未来真实导入

通用批量导入存在未确认来源、Private 仓远端完整性失败、主体歧义、冲突、未分类字段、客户未确认、需新增 schema 或目标环境备份恢复未验证时，只能停在 dry-run。BOM 页面辅助录入只在当前工作簿结构可识别、现有产品 / 材料 / 单位均已明确且表单校验通过时允许保存，否则停在检查弹窗。

未来通用客户批量导入必须另开明确授权的数据治理任务，并实现通用批次 usecase、服务端 RBAC、逐行来源、幂等、事务、审计、失败恢复、备份、forward-fix、导入后对账和客户签收。它必须写入 Product Core 的正式领域模型，不能硬编码 `yoyoosun`，也不能给现有 dry-run 工具增加隐藏 `--execute`；现有 BOM 页面入口不能扩作旁路批量写入器。

BOM 系数及新生成的生产用料系数快照使用无固定小数位的 `numeric`。工程用料先按完整精度逐部位计算并汇总，最后按计量单位精度向上取整；生产用料冻结完整单耗和损耗，并在生成可执行需求时按单位精度处理。采购、领料、库存事实仍执行各自的单位数量规则。升级只扩宽字段类型，不回填既有 BOM、不重算已提交或已批准用料申请、已下达生产快照及事实记录；已有舍入数据需明确编辑或重新导入，不能从来源记录自动覆盖。

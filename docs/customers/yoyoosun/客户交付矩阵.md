# yoyoosun 客户能力、交付与差异矩阵 / yoyoosun Capability, Delivery and Delta Matrix

本文是永绅 yoyoosun 唯一的客户能力状态真源，回答两类问题：当前能看到、试用、验收或暂不承诺哪些能力；已确认或待确认的客户差异如何处理。

它不反向定义 Product Core。产品通用能力成熟度看 `../../product/产品能力进度台账.md`，差异分类规则看 `../../product/客户差异策略.md`；已确认决策和未决问题分别回到 `决策日志.md` 与 `问题待办.md`。后续新增客户时，新建 `docs/customers/<customer-key>/客户交付矩阵.md`，不要追加到本文。

## 当前环境基线

- Product Core 当前工作树代码已包含后续审批办理、异常处置、真实收付款和多单核销；这些首先是本地能力，仍须以本轮实际测试结果判断是否可用。
- 当前配置编译 revision 为 `yoyoosun-customer-package-v7.local-836368528c0b1c77.runtime-v1`；出货财务放行绑定正式 `shipment_finance_approval`。旧 revision `yoyoosun-customer-package-v7.local-8ab8deaa7b7e9c6f.runtime-v1` 的本地激活 / 角色 smoke 证据不再代表当前配置。新 revision 必须重新完成隔离库激活、读回和全角色 smoke，不能把编译成功外推为 133 / 生产发布或甲方 UAT。
- 133 `customer-trial-133` 的较早固定 V5 证据绑定 release `80b77faeab566660c77fc23cc66c272096692f16`、migration `20260722000505` 和 active revision `yoyoosun-customer-trial-133-package-v5.runtime-manifest-v1`，包含 11 个测试账号登录、50 页浏览器和 5 份 PDF 技术试用记录。
- 当前唯一模拟数据合同为 `2026.08.15-v6 / 20260815-V6`，目标 revision 为 `yoyoosun-customer-trial-133-package-v8.runtime-manifest-v1`。目标若仍停在 package-v5，必须先由既有固定 release 通过正式 API 桥接并读回 package-v7，package-v8 后端才允许启动；随后仍须完成 V8 validate、publish、transition check、activate、effective-session readback 和岗位 smoke，才能替代上述较早 V5 运行证据。
- 当前代码后续切片及后续 migrations 尚未整体重新发布到 133；本文凡涉及新审批、新异常或收付款的目标状态均按“当前版本未发布”处理，latest revision 必须在发布前从当前迁移目录和目标 Atlas status 重新读取。
- 客户 UAT / 签收仍未完成。技术试用、页面可见和本地绿色都不能写成“已交付”。

| -------- | ------------------------------------------------------------------------------------------------------- |
| 未开始   | 当前不对该客户承诺，也没有可用入口                                                                      |
| 内部可用 | 代码或本地验证已有基础，但不直接对客户承诺                                                              |

| 已交付   | 已完成客户侧验收或交付确认                                                                              |

## 维护规则

- 客户是否能试用、是否能交付承诺、是否被阻塞，或客户差异的分类、处理方式、触发条件发生变化时，更新本文对应一行。
- 客户来源按[变更请求流程](变更请求流程.md)识别：只有项目负责人明确标注甲方提出 / 要求 / 反馈 / 确认时才归 `yoyoosun`；未标注输入归产品 / 研发与 Codex，明确其他客户名称或 key 时不得写入本文。
- 已确认事项同步 `决策日志.md`，未决事项同步 `问题待办.md`；本矩阵只保留当前结论，不堆讨论过程。
- 更新时只写业务模块或差异名称，不使用 CAP、DELTA、MATRIX、EVIDENCE 等内部编号作为主索引。
- “已交付”必须有客户侧验收或交付确认；内部模拟、目标环境 smoke、本地测试只能支撑“内部可用 / 可演示 / 可试用”。
- 客户状态不能反向定义 Product Core；通用能力成熟度只更新全局产品能力台账，差异是否进入内核仍按产品评审和客户差异策略决定。

## 新增决策规则

1. 分配唯一决策 ID，不改写历史行；变更时新增决策并写清替代关系。
2. “甲方已确认”必须有 Private 仓库中的会议纪要、签字版、邮件或等价受控来源。
3. 产品实现、客户配置、目标发布和 UAT 是不同类型的决策 / 证据，不合并成一条“已完成”。
4. 决策涉及系统变化、客户差异或交付状态时，同步[客户交付矩阵](客户交付矩阵.md)的对应分区和技术真源。
5. 产品决定与甲方决定分开：低风险、可逆的产品默认可以由项目评审确认，但必须写明适用范围和重新评审触发条件，不得标成甲方决定。
6. 从[问题待办](问题待办.md)关闭甲方决定时，必须保留推荐方案、确认来源和精确影响；未确认项只阻塞对应客户切片。
7. 只有项目负责人明确标注甲方来源的 Codex 输入才能归到对应客户；裸“甲方”当前指 `yoyoosun`，明确客户名称或 key 时不得串到其他客户。
8. 只有影响长期产品合同、用户行为或客户业务口径的重要选择才分配决策 ID；研发正确性、普通易用性和纯技术修复不逐项登记。
9. 已确认或已实施的业务决定发生变化时新增记录，写明替代关系、适用客户、生效范围和历史数据处理；尚未决定的澄清更新原问题或假设，不制造变更历史。

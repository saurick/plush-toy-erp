# 永绅 yoyoosun 演示造数执行手册 / Yoyoosun Demo Data Runbook

本手册用于在本地隔离验收库和 `demo-133` 重放同一版脱敏模拟数据，支持项目演示、培训、流程验证和回归。它不适用于甲方干净测试环境 `customer-test-133`，也不代表任何真实客户业务事实或签收。

## 1. 固定合同

| 项目 | 固定值 |
| --- | --- |
| 数据集 | `yoyoosun-manual-acceptance` |
| 数据合同版本 | `2026.08.15-v6` |
| 运行批次 | `20260815-V6` |
| 页面验收目标 | 51 项：2 个登录与入口、30 个电脑业务页、9 个岗位任务页、5 个打印预览和 5 个打印工作台 |
| 来源单可见前缀 | `YS6` |
| 岗位任务前缀 | 长期 Scenario 为 `YS-WB2`；隔离 Full Acceptance 为 `YS-V6` |
| 本地验收库 | 每批 `plush_erp_acceptance_<run-id>_dev`；真实写 companion 为同批 `*_browser_actions_dev` |
| 本地岗位账号 | 十个 `demo_*`；密码只从本机受控环境读取 |
| 部署 target | `demo-133` |
| 内部数据 target | `customer-trial-133`，只用于模拟数据合同，不是部署环境 |
| demo 数据库 | `plush_erp_demo_v1` |
| demo Compose project | `plush-toy-erp-demo-v1` |
| demo 端口 | PostgreSQL `55436` / 后端 `8325` / 前端 `5195` |
| demo 根目录 | `/home/simon/plush-toy-erp-demo-v1` |
| demo 公网入口 | `https://demo.yoyoosun.net` |

这些数据是 seed / fixture / 模拟业务事实，不得描述为真实客户、库存、出货、财务或验收结果。两端使用同一业务语义和数量合同，但数据库 ID 各自生成；禁止复制数据库行或把“编号相同”写成“两端内容身份相同”。

`test.yoyoosun.net` 是甲方干净测试/验收环境，必须使用独立数据库、上传、Compose project、端口、env、备份、rollback point、operation 与 smoke。demo 造数绝不能进入 test。`admin.yoyoosun.net` 不是部署环境，不参与本手册任何 target、清理、健康检查、发布或回滚动作。

## 2. 安全边界

- 造数只走正式 JSON-RPC / usecase；不复制表行，不运行临时 SQL，不把 Workflow payload 冒充 Fact。
- 不因模拟数据放宽权限、状态、幂等、客户配置、数据库身份或生命周期门禁。
- 本地只使用隔离端口和一次性数据库；成功或失败都停止服务、删除本批数据库并读回零残留。
- demo 只能命中 `plush_erp_demo_v1`。任何数据库、host、port、release、migration 或 PostgreSQL generation 漂移都停止。
- demo 重建前必须有 fresh backup、隔离恢复验证和精确 rollback point；旧物理数据代与 dump 不自动删除。
- `customer-test-133`、未来 `erp`、共享开发库、客户真实资料和其他项目数据库均不在写入范围。
- steady runtime env 不保存 bootstrap 密码；凭据、token、DSN 和客户正文不进入日志或 evidence。
- 写入门禁必须证明“fresh 空库基线已记录”；未取得当前回执时停止，不把历史空库结论复用于新候选。
- 客户配置用 `customer-config-effective-session-probe.mjs` 读回；未登录探针必须保持 `40302 未登录`，不得为造数放宽认证。
- 模拟数据不等于真实 import；本地或 demo 技术回执不证明目标环境发布、真实客户导入、客户签收、备份恢复或 release evidence 已完成。

## 3. 本地完整技术验收

优先使用统一生命周期入口。默认命令只生成计划，不连接数据库；真实执行必须使用该计划给出的 exact confirmation：

```bash
node scripts/qa/local-acceptance-lifecycle.mjs \
  --commit '<clean-40-character-commit>' \
  --run-id '<unique-run-id>'
```

生命周期创建同批只读验收库和 `browser_actions` 真实写 companion，完成 migration、九岗位造数、51 项页面/PDF 读回及登记真实写流程；无论成功失败都停服、删库并证明零残留。该回执只证明本地 exact commit，不证明 demo 已部署。

## 4. demo 部署与重建前置

开始远端造数前必须逐层证明：

1. exact SHA 已通过 canonical GitLab `CI Gate`。
2. v2 七资产不可变 Release 与同一 release rehearsal 完整。
3. `demo-133` 已 promotion 到该 release，Compose、image/content identity、migration、health、ready 与公网 SHA 一致。
4. 当前目标没有未结束的 promotion、rollback 或 database rebuild operation。
5. 需要重建时，controller 即时 preflight 为 `ready`，backup 已恢复验证，旧物理数据代与 rollback identity 已绑定。

受控重建：

```bash
node scripts/deploy/database-rebuild-controller.mjs \
  --release-manifest '<exact-release-manifest.json>' \
  --target demo-133 \
  --idempotency-key 'rebuild-database:demo-133:<release>:<change-id>' \
  --json

node scripts/deploy/database-rebuild-executor.mjs \
  --operation-id '<ready-operation-uuid>' \
  --release-manifest '<same-exact-release-manifest.json>' \
  --confirmation 'REBUILD_DATABASE:demo-133:<40-character-release>:<ready-operation-uuid>' \
  --json
```

`failed` 只表示旧运行态已被证明恢复；`not_proven` 必须先只读核对数据目录、容器、migration、release 与 rollback point，禁止重试。`passed` 只证明 fresh 物理库、首个管理员、空业务基线和基础运行态；不等于模拟数据、页面或客户验收已完成。

本轮环境登记不要求立即重建 demo，也绝不授权清理 test。

## 5. migration 与管理员初始化

所有 target 路径、project、数据库、端口和锁以 `scripts/deploy/deployment-targets.json` 为真源。demo migration 只通过：

```bash
DEPLOYMENT_TARGET_KEY=demo-133 \
  sh server/deploy/compose/prod/migrate_online.sh --status-only

DEPLOYMENT_TARGET_KEY=demo-133 \
  sh server/deploy/compose/prod/migrate_online.sh
```

写入仍须既有 prepare / confirmation / maintenance 门禁。fresh 数据库完成 migration 后、常驻 `app-server` 启动前，使用 `bootstrap-production-admin.sh --deployment-target demo-133` 的受控入口；成功后立即回到 `BOOTSTRAP_ADMIN_ONCE=false` 且不含 `APP_ADMIN_PASSWORD` 的 steady env。

## 6. 激活 demo 客户配置

模拟数据写入前，必须完成当前配置包的 `validate -> publish -> transition check -> activate -> effective-session readback`。demo 使用部署 target `demo-133`，数据入口仍传内部 `customer-trial-133`：

```bash
node scripts/qa/customer-config-runtime-manifest.mjs \
  --customer yoyoosun \
  --mode preview \
  --out output/qa/manual-acceptance-dataset/yoyoosun-runtime-manifest-preview.json
```

应用配置时必须同时绑定：

- `target=customer-trial-133`
- `databaseName=plush_erp_demo_v1`
- 当前 release、migration、data version 与 run id
- `ERP_ALLOW_CUSTOMER_TRIAL_CONFIG=1`
- `ERP_CUSTOMER_TRIAL_TARGET=customer-trial-133`

这些开关只允许 demo 使用。customer-test 与未来 erp 必须保持关闭。

## 7. 基础资料与模拟业务数据

先运行镜像内一次性 `bootstrap-manual-acceptance-core`，再运行正式 dataset runner。core 只创建或复用当前合同的单位和仓库；发现身份漂移时整批失败，不创建客户、订单、Workflow 或 Fact。

dataset runner 在写入前必须读回：

- exact release、migration、数据库与 PostgreSQL generation；
- active customer config revision / source；
- fresh baseline 或允许增量的长期 Scenario 身份；
- 当前 operation 与幂等批次；
- 受管业务对象计数。

完整模拟数据继续使用内部 target：

```bash
node scripts/qa/manual-acceptance-dataset.mjs \
  --target customer-trial-133 \
  --database-name plush_erp_demo_v1 \
  --data-version 2026.08.15-v6 \
  --run-id 20260815-V6 \
  --expected-release '<40-character-release>' \
  --expected-migration '<14-digit-migration>'
```

实际执行还需要脚本生成的 exact confirmation 与受控登录输入；不要把凭据写入命令历史、报告或仓库。

## 8. 凭据与 smoke

demo 测试账号合同以 `deployments/yoyoosun/env/credential.contract.json` 为真源。fresh / restore / rollback / 造数后：

1. 先创建并验证受控备份。
2. 运行 `deployments/yoyoosun/scripts/rotate-credentials-133.sh`，绑定 exact release、migration、operation id 和 backup identity。
3. 使用相同 operation id 处理未知输出，禁止重新发明一次轮换。
4. 运行 `deployments/yoyoosun/scripts/run-smoke.sh`，验证完整账号矩阵、health、ready、customer config effective session、PDF 与公网 exact SHA。

脚本只通过 stdin 向当前远端进程传递受控输入，报告不保存密码、token、手机号、HTML、PDF 正文或 raw response。

## 9. 浏览器验收

浏览器必须实际连接 demo 公网入口并核对：

- 登录与客户配置身份；
- 30 个电脑业务页和 9 个岗位任务页；
- 5 个打印预览和 5 个打印工作台；
- 受管对象数量、状态、来源单和 Workflow / Fact 边界；
- `system.version` 的 exact SHA / release；
- 目标 operation、备份与 rollback point。

本地截图、历史回执或单一健康页不能替代当前浏览器读回。测试结果不得表述为甲方签收。

## 10. 完成定义

只有以下证据全部绑定同一候选 SHA/digest，才能说“demo 模拟数据环境已完成”：

1. target registry、Compose、端口、数据库、上传、备份与 rollback identity 独立；
2. migration、管理员、客户配置和数据批次读回一致；
3. health、ready、system.version、完整账号矩阵、PDF 与 51 项浏览器验收绿色；
4. 公网 DNS/TLS/入口指向 demo，自身 operation 终态可读；
5. customer-test 未被写入或污染。

该结论不等于 `customer-test-133` 已恢复干净基线，也不等于未来 `erp` 已部署。

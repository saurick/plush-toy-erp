# 手测产品款式素材

此目录保存虚构毛绒产品的固定款式相册和可阅读附件。普通造数只读取这些文件，通过正式附件接口入库，不调用图片生成服务。

| 文件 | 用途 |
| --- | --- |
| `catalog.json` | 20 款产品的名称、主图和各视角素材、SHA-256、尺寸及生成提示；产品名称必须精确匹配 |
| `*.jpg` | 对应款式的产品主图。同款系列共用图组；图组不宣称覆盖每个 SKU 的颜色 |
| `views/` | 每款侧面辅图、斜俯视图、工艺细节和背面图；包含 JPEG、PNG 和 WebP |
| `cloud_bear.png` | PNG 上传、预览和下载样本 |
| `order-requirements.pdf` | 可正常阅读的一页中文产品与包装要求，含对应产品图 |
| `generate-documents.mjs` | 使用现有 Node / Playwright 渲染 PDF；仅素材维护时使用 |

素材由内置 `image_gen` 分款生成，未使用客户原件或外站商品图片。主图生成母版为 1254×1254，仓库保留原有 1280×1280 JPEG 编码。新增照片以原主图作参考，每款生成一张 1254×1254 四格图，按格裁为 627×627，不放大；逐款核对主体、颜色与配件后保存。它们用于本批手测，不代表真实客户样品。

维护图片时，先核对产品款式，再同步 `catalog.json` 的哈希与提示。造数阶段逻辑指纹包含相册目录和所有入库素材。已有批次只补缺的固定图，逐张下载核对；人工图片或哈希冲突、附图无剩余名额时停止该产品写入。一次性占位图修复仍只按显式产品 ID、旧文件名和固定 SHA-256 核对旧主图，已冻结的引用由正式接口保护。

PDF 的重建命令（使用项目已有的 Web 依赖与 Chromium）：

```bash
node scripts/qa/fixtures/plush-products/generate-documents.mjs --out /tmp/order-requirements.pdf
```

输出路径必须是新文件，生成器不会覆盖已固定的附件。先核看新 PDF，再按维护流程替换固定素材并核对受影响批次；普通造数始终读取仓库中的固定 PDF。
